الـ hook هو object بالشكل `{ name, preToolCall?, postToolCall?, preGenerate?, postGenerate? }` يشتغل داخل الـ agent loop، حول كل tool call وكل model call. استخدمه لكتابة audit log، أو لرفض tool، أو لحجب نتيجة أو قصّها، أو لحقن context قبل الـ model call، أو لتغيير الـ request اللي ينبعث (header أو `temperature`).

الـ hooks كود تكتبه إنت، مش policy ولا قرار بشري: للقواعد اللي تسمح أو ترفض أو تسأل على مستوى كل tool، ولموافقة شخص على call معيّن، استخدم `permissions` و`needsApproval` ([الموافقات](/ar/approvals)). الـ listeners مثل `onEvent` يراقبون الـ run فقط وما يقدرون يغيّروه ([Streaming](/ar/streaming#الاستماع-بدون-iterating))؛ الـ hook يقدر.

## أول hook لك

مرّر الـ hooks إلى `createAgent({ hooks })`. هذا الـ hook يسجّل كل tool call والنتيجة اللي رجّعت:

```ts
import { createAgent, defineTool, type AgentHook } from '@lousho/build-ai-agent';
import { mockModel } from '@lousho/build-ai-agent/testing';
import { z } from 'zod';

const auditHook: AgentHook = {
  name: 'audit',
  preToolCall(ctx) {
    console.log('calling', ctx.toolName, ctx.args);
  },
  postToolCall(ctx, result) {
    console.log('finished', ctx.toolName, result.error ?? 'ok');
  },
};

const lookup = defineTool({
  name: 'lookup',
  description: 'Look something up',
  input: z.object({ query: z.string() }),
  async execute({ query }) {
    return { answer: `result for ${query}` };
  },
});

const agent = createAgent({
  prompt: 'You answer questions.',
  provider: mockModel([{ toolCalls: [{ name: 'lookup', args: { query: 'hooks' } }] }, { text: 'Done.' }]),
  tools: [lookup],
  hooks: [auditHook],
});

await agent.send('Look up hooks');
```

كل method اختيارية: نفّذ النقاط اللي تحتاجها فقط. الـ hook اللي ما يرجع شيء يراقب فقط؛ وتعديل `ctx.args` أو `ctx.messages` أو `ctx.request` في مكانه يغيّر الـ run أيضًا.

## نقاط الـ hook الأربع

| النقطة | متى تشتغل | الـ context | ما يمكنها ترجعه |
| --- | --- | --- | --- |
| `preToolCall(ctx)` | قبل ما الـ tool يشتغل، وقبل قواعد الـ permissions والـ tool guardrails وفحص الموافقة. | `ToolCallHookContext`: `toolCallId` و`toolName` و`args` (live) و`toolCall`، زائد الحقول المشتركة تحت. | لا شيء، أو `{ deny }` أو `{ result }` أو `{ input }` (انظر [Hook outcomes](#hook-outcomes)). |
| `postToolCall(ctx, result)` | بعد ما يستقر الـ tool call: نجاح، أو error على مستوى الـ tool، أو موافقة مطلوبة. قيمة `result` هي `{ result, error?, requiresApproval? }`. | `ToolCallHookContext`. | لا شيء، أو `{ result }` عشان تستبدل اللي يشوفه الـ model. |
| `preGenerate(ctx)` | قبل كل model call. | `GenerateHookContext`: `request` (كائن الـ `GenerateOptions` الـ live اللي بينبعث) و`emit?`، زائد الحقول المشتركة. | لا شيء؛ عدّل `ctx.messages` أو `ctx.request`، أو ارمِ error. |
| `postGenerate(ctx, result)` | بعد ما يخلص كل model call، مع الـ `GenerateResult` الخاص به. | `GenerateHookContext`. | لا شيء؛ أو ارمِ error. |

الحقول المشتركة في كل context هي `agentId` و`agentName` و`sessionId` و`messages` (سجل المحادثة الـ live) و`metadata` (مساحة حرة تحط فيها اللي تريده) و`subagent` (تتعبّى داخل sub-agent). سياقات الـ tool call تحمل أيضًا `resumedAfterApproval`: تكون `true` فقط لما الـ hook يشتغل على call يُعاد تشغيله بعد ما شخص وافق على إيقافه، عشان hook عنده state (مثل loop guard أو عدّاد audit) يقدر يتخطى إعادة التشغيل بـ `if (ctx.resumedAfterApproval) return;`. ويوجد `ctx.emit` لما يكون للـ run listeners (`createAgent({ onEvent })` أو `onAgentEvent`) أو لما يكون فيه streaming، ويضيف حدثَي `compaction.start` و`compaction.done` إلى أحداث الـ run.

## Hook outcomes

الـ tool-call hook يقدر يغيّر ما يحدث، لا يراقبه فقط. الـ `preToolCall` hook يقدر يرجع:

- لا شيء: الـ call يكمل بدون تغيير (وتعديل `ctx.args` في مكانه يعمل أيضًا).
- `{ deny: reason }`: الـ call ما يشتغل. الـ model يوصله نفس خطأ الـ tool
  `kind: 'denied'` اللي ينتج عن رفض `needsApproval` (انظر
  [الموافقات](/ar/approvals#الموافقة-أو-المنع-أو-السؤال))، والـ streams تشوف `tool.error`،
  و`onPermissionDecision` يسجّل `decision: 'deny'` مع `hook` و`reason`.
- `{ result: value }`: الـ call ما يشتغل و`value` تصير نتيجته. حدث
  `tool.done` ورسالة `tool` في الـ transcript (`metadata`) يحملون
  `replacedByHook: '<hook name>'`.
- `{ input: args }`: الـ call يشتغل بـ `args`. ينعمل عليها validation مرة ثانية
  ضد الـ input schema الخاصة بالـ tool؛ وإذا ما طابقتها تصير خطأ tool من النوع `kind: 'validation'`
  رسالته تذكر اسم الـ hook، والـ tool ما يشتغل.

الـ `postToolCall` hook يقدر يرجع `{ result: value }` لاستبدال النتيجة اللي
يشوفها الـ model (يحجبها أو يقصّها)؛ ورجوع لا شيء يبقي النتيجة الأصلية. الـ hooks
تشتغل بترتيب تسجيلها: أول `deny` أو `result` من pre-hook يتخطى الـ pre-hooks اللي بعده،
وقيم `input` تتسلسل (كل hook يشوف قيمة اللي قبله في
`ctx.args`)، وكل post-hook يشوف النتيجة اللي استبدلها hook قبله. والـ hook
اللي يرمي error يفشّل الـ run مثل قبل. والـ sub-agents ترث hooks
الـ agent الرئيسي ونتائجها.

```ts
import { createAgent, type AgentHook } from '@lousho/build-ai-agent';
import { mockModel } from '@lousho/build-ai-agent/testing';

const provider = mockModel(['Done.']);

const guard: AgentHook = {
  name: 'guard',
  preToolCall(ctx) {
    if (ctx.toolName === 'shell') return { deny: 'Use the workspace tools instead' };
    if (ctx.toolName === 'search') return { input: { ...ctx.args, limit: 10 } };
    return undefined; // continue unchanged
  },
  postToolCall(_ctx, result) {
    return typeof result.result === 'string' ? { result: result.result.slice(0, 2000) } : undefined;
  },
};

const agent = createAgent({ provider, instructions: 'You research things.', hooks: [guard] });
```

## أمثلة

كل مثال برنامج كامل. كلها تشتغل على `mockModel`، فما في واحد منها يحتاج API key ولا model call حقيقي؛ ونفس النمط يختبر الـ hooks اللي كتبتها offline ([Testing](/ar/testing)). كل مثال يجهّز turn للـ model فيه tool call، وبعده جواب نهائي.

### امنع tool بالاسم

```ts
import { createAgent, defineTool, type AgentHook } from '@lousho/build-ai-agent';
import { mockModel } from '@lousho/build-ai-agent/testing';
import { z } from 'zod';

const shell = defineTool({
  name: 'shell',
  description: 'Run a shell command',
  input: z.object({ command: z.string() }),
  async execute({ command }) {
    return { ran: command };
  },
});

const noShell: AgentHook = {
  name: 'no-shell',
  preToolCall(ctx) {
    if (ctx.toolName === 'shell') return { deny: 'The shell is disabled here' };
    return undefined;
  },
};

const model = mockModel([{ toolCalls: [{ name: 'shell', args: { command: 'ls' } }] }, { text: 'I could not run it.' }]);
const agent = createAgent({ prompt: 'You help.', provider: model, tools: [shell], hooks: [noShell] });

const result = await agent.send('List the files');
console.log(result.text);
```

### أضف argument افتراضي

ارجع `{ input }` عشان تشغّل الـ tool بـ arguments مختلفة. ينعمل عليها validation مرة ثانية ضد الـ schema الخاصة بالـ tool.

```ts
import { createAgent, defineTool, type AgentHook } from '@lousho/build-ai-agent';
import { mockModel } from '@lousho/build-ai-agent/testing';
import { z } from 'zod';

const search = defineTool({
  name: 'search',
  description: 'Search the docs',
  input: z.object({ query: z.string(), limit: z.number().optional() }),
  async execute({ query, limit }) {
    return { query, limit };
  },
});

const defaultLimit: AgentHook = {
  name: 'default-limit',
  preToolCall(ctx) {
    if (ctx.toolName === 'search' && ctx.args.limit === undefined) {
      return { input: { ...ctx.args, limit: 5 } };
    }
    return undefined;
  },
};

const model = mockModel([{ toolCalls: [{ name: 'search', args: { query: 'hooks' } }] }, { text: 'Found it.' }]);
const agent = createAgent({ prompt: 'You search.', provider: model, tools: [search], hooks: [defaultLimit] });

await agent.send('Search for hooks');
```

### قصّ النتيجة أو احجبها

الـ `postToolCall` يستلم النتيجة المستقرة، ويقدر يرجع `{ result }` عشان يستبدل اللي يشوفه الـ model. الـ tool نفسه اشتغل بدون تغيير.

```ts
import { createAgent, defineTool, type AgentHook } from '@lousho/build-ai-agent';
import { mockModel } from '@lousho/build-ai-agent/testing';
import { z } from 'zod';

const readLog = defineTool({
  name: 'read_log',
  description: 'Read the log',
  input: z.object({}),
  async execute() {
    return 'user=ada email=ada@example.com ' + 'x'.repeat(5000);
  },
});

const redact: AgentHook = {
  name: 'redact',
  postToolCall(_ctx, result) {
    if (typeof result.result !== 'string') return;
    const masked = result.result.replace(/[\w.]+@[\w.]+/g, '[email]');
    return { result: masked.slice(0, 1000) };
  },
};

const model = mockModel([{ toolCalls: [{ name: 'read_log', args: {} }] }, { text: 'Read it.' }]);
const agent = createAgent({ prompt: 'You read logs.', provider: model, tools: [readLog], hooks: [redact] });

await agent.send('Read the log');
const toolMessage = model.calls[1].messages.at(-1);
console.log(toolMessage?.role); // 'tool': its content is the redacted text
```

### احقن context قبل الـ model call

الـ `preGenerate` يشوف `ctx.messages` و`ctx.request` الـ live. اعمل `push` لرسالة عشان تضيف context، أو غيّر حقل في الـ request.

```ts
import { createAgent, type AgentHook } from '@lousho/build-ai-agent';
import { mockModel } from '@lousho/build-ai-agent/testing';

const addDate: AgentHook = {
  name: 'add-date',
  preGenerate(ctx) {
    ctx.messages.push({ role: 'system', content: `Today is ${new Date().toISOString().slice(0, 10)}.` });
    ctx.request.temperature = 0;
  },
};

const model = mockModel(['Noted.']);
const agent = createAgent({ prompt: 'You help.', provider: model, hooks: [addDate] });

await agent.send('Hello');
console.log(model.calls.length); // 1
```

## الترتيب والتفاعل

للـ tool call الواحد، الترتيب هو: validation على الـ arguments، ثم `preToolCall` hooks،
ثم قواعد الـ permissions (`permissions`)، ثم الـ tool guardrails، ثم `needsApproval` الخاص بالـ tool،
ثم إيقاف الموافقة، ثم التنفيذ، ثم `postToolCall` hooks. الـ hooks تشتغل قبل كل
قرار موافقة، فالقواعد و`needsApproval` والشخص كلهم يشوفون
الـ input اللي أنتجه الـ hook ويوافقون عليه؛ و`args` في الموافقة المعلّقة تُظهره. ولما يُستأنف
call موافَق عليه، تشتغل الـ pre-hooks مرة ثانية: تظل قادرة على رفضه أو
تقديم نتيجته، لكن `{ input }` مختلف عن الـ input الموافَق عليه يُرفض
بخطأ tool بدل ما يشتغل. انظر [الموافقات](/ar/approvals) للإيقاف والاستئناف.

- **أكثر من hook** يشتغلون بترتيب مصفوفة `hooks`، واحد في كل مرة: كل واحد يُنتظر بـ `await` قبل اللي بعده، فالـ hook اللاحق يشوف اللي غيّره السابق.
- **hook يرمي error** يفشّل الـ run. الـ hooks كود موثوق: الـ error ما يتحوّل إلى tool result يشوفه الـ model.
- **Compaction.** `createAgent({ hooks })` يشغّل الـ hooks اللي كتبتها أول، وبعدها الـ compaction hook، فالـ compaction يشوف اللي أضافوه ([Context compaction](/ar/compaction)).
- **Sub-agents** ترث hooks الـ agent الرئيسي. `ctx.subagent` تتعبّى لما الـ hook يشتغل داخل واحد منهم، فيقدر الـ hook يرجع مبكر عشان يشوف الـ run الأعلى فقط ([الـ hooks داخل الـ sub-agents](/ar/sub-agents#hooks-داخل-sub-agents)).

## HookRegistry

`createAgent({ hooks })` يقبل array عادي. الكود اللي يستخدم الـ executor API ([executor API](/ar/executor-api)) يمرّر `HookRegistry`: مجموعة مرتّبة فيها `register` و`registerMany` و`get` و`has` و`list` و`unregister` و`clear` و`size()` — انتبه، `size` method (`hooks.size()`)، مش property بنمط `Map`. تسجيل hook ثاني بنفس الـ `name` يستبدل الأول ويطبع warning.

```ts
import { HookRegistry, type AgentHook } from '@lousho/build-ai-agent/hooks';

const redactPii: AgentHook = {
  name: 'redact-pii',
  async preToolCall(ctx) {
    // mutate ctx.args, or throw to abort the tool call before it runs
  },
};

const hooks = new HookRegistry();
hooks.register(redactPii);
console.log(hooks.list().map((hook) => hook.name)); // [ 'redact-pii' ]
```

`HookRegistry` و`AgentHook` وأنواع الـ context موجودة في جذر الـ package وفي الـ subpath `@lousho/build-ai-agent/hooks`. الـ hooks اللي تتكتب في محرر الـ canvas الخاص بـ Agent Forge تُترجَم إلى `HookRegistry` وتشتغل داخل sandbox بدل الـ host process: انظر [Agent Forge](/ar/agent-forge#hooks).
