الـ hook هو object بالشكل `{ name, preToolCall?, postToolCall?, preGenerate?, postGenerate? }` يعمل داخل الـ agent loop، حول كل tool call وكل model call. استخدمه لكتابة audit log، أو لرفض tool، أو لحجب نتيجة أو قصّها، أو لحقن context قبل الـ model call، أو لتغيير الـ request الذي سيُرسَل (header أو `temperature`).

الـ hooks كود تكتبه أنت، وليست policy ولا قرارًا بشريًا: للقواعد التي تسمح أو ترفض أو تسأل على مستوى كل tool، ولموافقة شخص على call معيّن، استخدم `permissions` و`needsApproval` ([الموافقات](/ar/approvals)). الـ listeners مثل `onEvent` تراقب الـ run فقط ولا تستطيع تغييره ([Streaming](/ar/streaming#الاستماع-بدون-iterating))؛ أما الـ hook فيستطيع.

## أول hook لك

مرّر الـ hooks إلى `createAgent({ hooks })`. هذا الـ hook يسجّل كل tool call والنتيجة التي أعادها:

```ts
import { createAgent, defineTool, type AgentHook } from 'lousho';
import { mockModel } from 'lousho/testing';
import { z } from 'zod';

const auditHook: AgentHook = {
  name: 'audit',
  preToolCall(ctx) {
    console.log('calling', ctx.toolName, ctx.args);
  },
  postToolCall(ctx, result) {
    console.log('finished', ctx.toolName, result.error ?? 'ok');
  },
};

const lookup = defineTool({
  name: 'lookup',
  description: 'Look something up',
  input: z.object({ query: z.string() }),
  async execute({ query }) {
    return { answer: `result for ${query}` };
  },
});

const agent = createAgent({
  instructions: 'You answer questions.',
  provider: mockModel([{ toolCalls: [{ name: 'lookup', args: { query: 'hooks' } }] }, { text: 'Done.' }]),
  tools: [lookup],
  hooks: [auditHook],
});

await agent.send('Look up hooks');
```

كل method اختيارية: نفّذ النقاط التي تحتاجها فقط. الـ hook الذي لا يعيد شيئًا يراقب فقط؛ وتعديل `ctx.args` أو `ctx.messages` أو `ctx.request` في مكانه يغيّر الـ run أيضًا.

## نقاط الـ hook الأربع

| النقطة | متى تعمل | الـ context | ما يمكنها أن تعيده |
| --- | --- | --- | --- |
| `preToolCall(ctx)` | قبل أن يعمل الـ tool، وقبل قواعد الـ permissions والـ tool guardrails وفحص الموافقة. | `ToolCallHookContext`: `toolCallId` و`toolName` و`args` (live) و`toolCall`، إضافة إلى الحقول المشتركة أدناه. | لا شيء، أو `{ deny }` أو `{ result }` أو `{ input }` (انظر [Hook outcomes](#hook-outcomes)). |
| `postToolCall(ctx, result)` | بعد أن يستقر الـ tool call: نجاح، أو error على مستوى الـ tool، أو موافقة مطلوبة. قيمة `result` هي `{ result, error?, requiresApproval? }`. | `ToolCallHookContext`. | لا شيء، أو `{ result }` لكي تستبدل ما يراه الـ model. |
| `preGenerate(ctx)` | قبل كل model call. | `GenerateHookContext`: `request` (كائن الـ `GenerateOptions` الـ live الذي سيُرسَل) و`emit?`، إضافة إلى الحقول المشتركة. | لا شيء؛ عدّل `ctx.messages` أو `ctx.request`، أو ارمِ error. |
| `postGenerate(ctx, result)` | بعد أن ينتهي كل model call، مع الـ `GenerateResult` الخاص به. | `GenerateHookContext`. | لا شيء؛ أو ارمِ error. |

الحقول المشتركة في كل context هي `agentId` و`agentName` و`sessionId` و`messages` (سجل المحادثة الـ live) و`metadata` (مساحة حرة تضع فيها ما تريد) و`subagent` (تُملأ داخل sub-agent). سياقات الـ tool call تحمل أيضًا `resumedAfterApproval`: تكون `true` فقط عندما يعمل الـ hook على call يُعاد تشغيله بعد أن وافق شخص على إيقافه، لكي يستطيع hook لديه state (مثل loop guard أو عدّاد audit) تخطي إعادة التشغيل بـ `if (ctx.resumedAfterApproval) return;`. ويوجد `ctx.emit` عندما يكون للـ run listeners (`createAgent({ onEvent })` أو `onAgentEvent`) أو عندما يكون هناك streaming، ويضيف حدثَي `compaction.start` و`compaction.done` إلى أحداث الـ run. وداخل run الـ executor، يحصل `preGenerate` أيضًا على `ctx.generate(provider, request, purpose)`: model call جانبي (يستخدمه الـ summarizer الخاص بالـ compaction) له `chat` span خاص به موسوم بـ `lousho.call.purpose`، ويُحسب ضمن `usage` الخاص بالـ run وضمن الـ budgets.

## Hook outcomes

الـ tool-call hook يستطيع أن يغيّر ما يحدث، لا أن يراقبه فقط. الـ `preToolCall` hook يستطيع أن يعيد:

- لا شيء: يستمر الـ call دون تغيير (وتعديل `ctx.args` في مكانه يعمل أيضًا).
- `{ deny: reason }`: لا يعمل الـ call. يصل إلى الـ model خطأ الـ tool نفسه
  `kind: 'denied'` الذي ينتج عن رفض `needsApproval` (انظر
  [الموافقات](/ar/approvals#الموافقة-أو-المنع-أو-السؤال))، وترى الـ streams `tool.error`،
  و`onPermissionDecision` يسجّل `decision: 'deny'` مع `hook` و`reason`.
- `{ result: value }`: لا يعمل الـ call وتصبح `value` نتيجته. حدث
  `tool.done` ورسالة `tool` في الـ transcript (`metadata`) يحملان
  `replacedByHook: '<hook name>'`.
- `{ input: args }`: يعمل الـ call بـ `args`. يُجرى عليها validation مرة أخرى
  مقابل الـ input schema الخاصة بالـ tool؛ وإذا لم تطابقها تصبح خطأ tool من النوع `kind: 'validation'`
  تذكر رسالته اسم الـ hook، ولا يعمل الـ tool.

الـ `postToolCall` hook يستطيع أن يعيد `{ result: value }` لاستبدال النتيجة التي
يراها الـ model (يحجبها أو يقصّها)؛ وإعادة لا شيء تُبقي النتيجة الأصلية. الـ hooks
تعمل بترتيب تسجيلها: أول `deny` أو `result` من pre-hook يتخطى الـ pre-hooks التي تليه،
وقيم `input` تتسلسل (كل hook يرى قيمة الذي قبله في
`ctx.args`)، وكل post-hook يرى النتيجة التي استبدلها hook قبله. والـ hook
الذي يرمي error يُفشل الـ run كما كان من قبل. والـ sub-agents ترث hooks
الـ agent الرئيسي ونتائجها.

```ts
import { createAgent, type AgentHook } from 'lousho';
import { mockModel } from 'lousho/testing';

const provider = mockModel(['Done.']);

const guard: AgentHook = {
  name: 'guard',
  preToolCall(ctx) {
    if (ctx.toolName === 'shell') return { deny: 'Use the workspace tools instead' };
    if (ctx.toolName === 'search') return { input: { ...ctx.args, limit: 10 } };
    return undefined; // continue unchanged
  },
  postToolCall(_ctx, result) {
    return typeof result.result === 'string' ? { result: result.result.slice(0, 2000) } : undefined;
  },
};

const agent = createAgent({ provider, instructions: 'You research things.', hooks: [guard] });
```

## أمثلة

كل مثال برنامج كامل. جميعها تعمل على `mockModel`، فلا يحتاج أيٌّ منها إلى API key ولا إلى model call حقيقي؛ والنمط نفسه يختبر الـ hooks التي كتبتها offline ([Testing](/ar/testing)). كل مثال يجهّز turn للـ model فيه tool call، تليه إجابة نهائية.

### أوقف run لا يتقدّم

`createProgressGuard()` يوقف run ينفق الـ budget الخاص به على calls لا تؤدي إلى شيء. وهو معطّل ما لم تُضِفه:

- ابتداءً من الفشل الثاني لـ tool بالخطأ نفسه، يضيف `hint` إلى النتيجة، فيه نصيحة بحسب نوع الفشل (`classifyToolFailure()`: input خاطئ، أو timeout، أو قدرة ناقصة، أو صلاحية، أو غير معروف).
- بعد `maxFailures` من حالات الفشل بالخطأ نفسه (الافتراضي 3)، يرفض هذا الـ tool لبقية الـ run. الأرقام في الرسالة لا تجعل الخطأ مختلفًا.
- بعد `maxRepeats` من الـ calls المتطابقة التي تعيد النتيجة نفسها (الافتراضي 3)، يرفض هذا الـ call. الـ call الذي تتغيّر نتيجته ليس تكرارًا.
- بعد أن تعيد `maxSameResults` من الـ calls لـ tool النتيجة نفسها (الافتراضي 5)، يرفض هذا الـ tool، حتى لو اختلفت الـ arguments في كل call. هذا يكشف الـ model عندما يعيد صياغة بحث يظل يجد الشيء نفسه.
- بعد `maxDenials` من حالات الرفض (الافتراضي 3)، يوقف الرفض التالي الـ run بـ `LOUSHO_RUN_NO_PROGRESS`، ولا يعيد `agent.recover()` محاولته.

```ts
import { createAgent, createProgressGuard, defineTool } from 'lousho';
import { mockModel } from 'lousho/testing';
import { z } from 'zod';

const lookup = defineTool({
  name: 'lookup',
  description: 'Look up an order',
  input: z.object({ id: z.string() }),
  async execute() {
    return { status: 'unknown' };
  },
});

const call = { toolCalls: [{ name: 'lookup', args: { id: 'A-1' } }] };
const agent = createAgent({
  provider: mockModel([call, call, call, call, 'I could not find that order.']),
  tools: [lookup],
  hooks: [createProgressGuard({ ignoreTools: ['poll_job'], fallbacks: { lookup: 'search_orders' } })],
});

for await (const event of agent.stream('Where is order A-1?')) {
  if (event.type === 'heal.action') console.log(event.action, event.toolName);
}
```

كل action يُبث كحدث `heal.action`. النتيجة التي استبدلها تُعلَّم على الـ span الخاص بالـ tool بـ `lousho.tool.replaced_by_hook`، ويُسجَّل الرفض كخطأ في الـ span. الـ guard يعدّ من سجل محادثة الـ run، فيحتفظ الـ run المستأنَف بتاريخه. الـ calls الموجودة في batch واحدة لا تُعدّ إلا بعد أن تنتهي الـ batch، وقد يُزيل ضغط السياق (compaction) calls قديمة من العدّ.

### افحص ما أخرجته الـ tool

الكتابة الناجحة لا تثبت أن الـ output صالح للاستخدام. `createOutputCheck()` يشغّل الفحص الخاص بك بعد أن تنجح الـ tool. إذا أعاد مشكلة، أو رمى خطأً، يراها الـ model كـ `outputCheckFailed` على النتيجة ويستطيع إصلاح الـ output. الفحص هو كودك، فاجعله مستقلًا عما كتبه الـ model.

```ts
import { createAgent, createOutputCheck, defineTool } from 'lousho';
import { mockModel } from 'lousho/testing';
import { z } from 'zod';

const files = new Map<string, string>();
const writeFile = defineTool({
  name: 'write_file',
  description: 'Write a file',
  input: z.object({ path: z.string(), text: z.string() }),
  async execute({ path, text }) {
    files.set(path, text);
    return { path };
  },
});

const agent = createAgent({
  provider: mockModel([{ toolCalls: [{ name: 'write_file', args: { path: 'report.md', text: '' } }] }, 'Done.']),
  tools: [writeFile],
  hooks: [
    createOutputCheck({
      write_file: (args) => (files.get(String(args.path)) ? undefined : `${String(args.path)} is empty`),
    }),
  ],
});

await agent.send('Write the report');
```

### امنع tool بالاسم

```ts
import { createAgent, defineTool, type AgentHook } from 'lousho';
import { mockModel } from 'lousho/testing';
import { z } from 'zod';

const shell = defineTool({
  name: 'shell',
  description: 'Run a shell command',
  input: z.object({ command: z.string() }),
  async execute({ command }) {
    return { ran: command };
  },
});

const noShell: AgentHook = {
  name: 'no-shell',
  preToolCall(ctx) {
    if (ctx.toolName === 'shell') return { deny: 'The shell is disabled here' };
    return undefined;
  },
};

const model = mockModel([{ toolCalls: [{ name: 'shell', args: { command: 'ls' } }] }, { text: 'I could not run it.' }]);
const agent = createAgent({ instructions: 'You help.', provider: model, tools: [shell], hooks: [noShell] });

const result = await agent.send('List the files');
console.log(result.text);
```

### أضف argument افتراضي

أعِد `{ input }` لكي تشغّل الـ tool بـ arguments مختلفة. يُجرى عليها validation مرة أخرى مقابل الـ schema الخاصة بالـ tool.

```ts
import { createAgent, defineTool, type AgentHook } from 'lousho';
import { mockModel } from 'lousho/testing';
import { z } from 'zod';

const search = defineTool({
  name: 'search',
  description: 'Search the docs',
  input: z.object({ query: z.string(), limit: z.number().optional() }),
  async execute({ query, limit }) {
    return { query, limit };
  },
});

const defaultLimit: AgentHook = {
  name: 'default-limit',
  preToolCall(ctx) {
    if (ctx.toolName === 'search' && ctx.args.limit === undefined) {
      return { input: { ...ctx.args, limit: 5 } };
    }
    return undefined;
  },
};

const model = mockModel([{ toolCalls: [{ name: 'search', args: { query: 'hooks' } }] }, { text: 'Found it.' }]);
const agent = createAgent({ instructions: 'You search.', provider: model, tools: [search], hooks: [defaultLimit] });

await agent.send('Search for hooks');
```

### قصّ النتيجة أو احجبها

الـ `postToolCall` يستلم النتيجة المستقرة، ويستطيع أن يعيد `{ result }` لكي يستبدل ما يراه الـ model. الـ tool نفسه عمل دون تغيير.

```ts
import { createAgent, defineTool, type AgentHook } from 'lousho';
import { mockModel } from 'lousho/testing';
import { z } from 'zod';

const readLog = defineTool({
  name: 'read_log',
  description: 'Read the log',
  input: z.object({}),
  async execute() {
    return 'user=ada email=ada@example.com ' + 'x'.repeat(5000);
  },
});

const redact: AgentHook = {
  name: 'redact',
  postToolCall(_ctx, result) {
    if (typeof result.result !== 'string') return;
    const masked = result.result.replace(/[\w.]+@[\w.]+/g, '[email]');
    return { result: masked.slice(0, 1000) };
  },
};

const model = mockModel([{ toolCalls: [{ name: 'read_log', args: {} }] }, { text: 'Read it.' }]);
const agent = createAgent({ instructions: 'You read logs.', provider: model, tools: [readLog], hooks: [redact] });

await agent.send('Read the log');
const toolMessage = model.calls[1].messages.at(-1);
console.log(toolMessage?.role); // 'tool': its content is the redacted text
```

### احقن context قبل الـ model call

الـ `preGenerate` يرى `ctx.messages` و`ctx.request` الـ live. نفّذ `push` لرسالة لكي تضيف context، أو غيّر حقلًا في الـ request.

```ts
import { createAgent, type AgentHook } from 'lousho';
import { mockModel } from 'lousho/testing';

const addDate: AgentHook = {
  name: 'add-date',
  preGenerate(ctx) {
    ctx.messages.push({ role: 'system', content: `Today is ${new Date().toISOString().slice(0, 10)}.` });
    ctx.request.temperature = 0;
  },
};

const model = mockModel(['Noted.']);
const agent = createAgent({ instructions: 'You help.', provider: model, hooks: [addDate] });

await agent.send('Hello');
console.log(model.calls.length); // 1
```

## الترتيب والتفاعل

للـ tool call الواحد، الترتيب هو: validation على الـ arguments، ثم `preToolCall` hooks،
ثم قواعد الـ permissions (`permissions`)، ثم الـ tool guardrails، ثم `needsApproval` الخاص بالـ tool،
ثم إيقاف الموافقة، ثم التنفيذ، ثم `postToolCall` hooks. الـ hooks تعمل قبل كل
قرار موافقة، فالقواعد و`needsApproval` والشخص جميعهم يرون
الـ input الذي أنتجه الـ hook ويوافقون عليه؛ و`args` في الموافقة المعلّقة تُظهره. وعندما يُستأنف
call موافَق عليه، تعمل الـ pre-hooks مرة أخرى: تظل قادرة على رفضه أو
تقديم نتيجته، لكن `{ input }` المختلف عن الـ input الموافَق عليه يُرفض
بخطأ tool بدلًا من أن يعمل. انظر [الموافقات](/ar/approvals) للإيقاف والاستئناف.

- **أكثر من hook** تعمل بترتيب مصفوفة `hooks`، واحدًا تلو الآخر: يُنتظر كل واحد بـ `await` قبل الذي يليه، فيرى الـ hook اللاحق ما غيّره السابق.
- **hook يرمي error** يُفشل الـ run. الـ hooks كود موثوق: لا يتحوّل الـ error إلى tool result يراه الـ model.
- **Compaction.** `createAgent({ hooks })` يشغّل الـ hooks التي كتبتها أولًا، ثم الـ compaction hook، فيرى الـ compaction ما أضافته ([Context compaction](/ar/compaction)).
- **Sub-agents** ترث hooks الـ agent الرئيسي. `ctx.subagent` تُملأ عندما يعمل الـ hook داخل أحدها، فيستطيع الـ hook أن يعود مبكرًا لكي يرى الـ run الأعلى فقط ([الـ hooks داخل الـ sub-agents](/ar/sub-agents#hooks-داخل-sub-agents)).

## HookRegistry

`createAgent({ hooks })` يقبل array عاديًا. الكود الذي يستخدم الـ executor API ([executor API](/ar/executor-api)) يمرّر `HookRegistry`: مجموعة مرتّبة فيها `register` و`registerMany` و`get` و`has` و`list` و`unregister` و`clear` و`size()` — انتبه، `size` هي method (`hooks.size()`)، وليست property بنمط `Map`. تسجيل hook ثانٍ بالـ `name` نفسه يستبدل الأول ويطبع warning.

```ts
import { HookRegistry, type AgentHook } from 'lousho/hooks';

const redactPii: AgentHook = {
  name: 'redact-pii',
  async preToolCall(ctx) {
    // mutate ctx.args, or throw to abort the tool call before it runs
  },
};

const hooks = new HookRegistry();
hooks.register(redactPii);
console.log(hooks.list().map((hook) => hook.name)); // [ 'redact-pii' ]
```

`HookRegistry` و`AgentHook` وأنواع الـ context موجودة في جذر الـ package وفي الـ subpath `lousho/hooks`. الـ hooks التي تُكتب في محرر الـ canvas الخاص بـ Agent Forge تُترجَم إلى `HookRegistry` وتعمل داخل sandbox بدلًا من الـ host process: انظر [Agent Forge](/ar/agent-forge#hooks).
