## من يحتاج هذه الصفحة

أي شخص عنده كود مكتوب على `1.0.0-alpha.8` أو إصدار `1.0.0-alpha.*`
أقدم. بين آخر إصدارات alpha و`1.0.0-rc.0` أعدنا تنظيم السطح العام
للحزمة. الـ imports انتقلت إلى subpaths. حذفنا الـ APIs الميتة أو
اللي صار لها بديل. والـ patch guardrails صار اسمها patch checks.
`createAgent()` وخياراتها لم تتغير — الـ agent اللي ما يعمل إلا
`createAgent({ model, instructions, tools })` و`agent.send()` يترقّى
بتغيير رقم الإصدار فقط.

```bash
npm install @lousho/build-ai-agent@^1.0.0-rc.0
```

## مسارات الـ import اللي انتقلت

جذر الحزمة الآن فيه `createAgent()` والأسماء اللي تستخدمها إعداداتها
ونتائجها. كل اللي تحت انتقل إلى subpath خاص فيه. التعريفات نفسها لم
تتغير، بس مكانها تغيّر.

| الاسم (الأسماء) | الـ import القديم | الـ import الجديد |
| ------- | ---------- | ---------- |
| `AgentExecutor`, `AgentBuilder`, `ExecuteOptions`, `ResumeExecuteOptions`, `ResumeRequest`, `resumeAfterApproval()`, `streamResumeAfterApproval()`, `resumeRequest()` | `@lousho/build-ai-agent` أو `@lousho/build-ai-agent/core` | `@lousho/build-ai-agent/executor` |
| `ToolRegistry`, `globalToolRegistry` | `@lousho/build-ai-agent` أو `@lousho/build-ai-agent/core` | `@lousho/build-ai-agent/executor` (وما زال موجود في `@lousho/build-ai-agent/tools`) |
| `ExecutionResult`, `ExecutionFinishReason` (أنواع الـ executor) | `@lousho/build-ai-agent/core` | `@lousho/build-ai-agent/executor` (و`ExecutionResult` ما زال في الجذر، مكان نوع نتيجة `createAgent()`) |
| `FlowBuilder`, `FlowExecutor`, `validateFlow` وكل أنواع الـ flow (`AgentFlow`, `EditorStep`, `FlowExecutionEvent`, ...) | `@lousho/build-ai-agent` أو `@lousho/build-ai-agent/types` | `@lousho/build-ai-agent/flows` |

يصدّره صار تحت `/executor`.

```ts
import { AgentExecutor, AgentBuilder, ToolRegistry } from '@lousho/build-ai-agent/executor';
import { FlowBuilder, validateFlow } from '@lousho/build-ai-agent/flows';
import { createSlackTool } from '@lousho/build-ai-agent/integrations';

```

## APIs محذوفة وبدائلها

- **`AgentType` و`AgentTypeDescriptor` و`AgentConfig.agentType`
  و`AgentBuilder.setType()` والـ agent-type registry**
  (`agentTypesRegistry`, `getAgentTypeDescriptor`, `getAllAgentTypeDescriptors`,
  `isValidAgentType`, `validateAgentConfig`, `validateAgentTools`). ما
  كان لها أي أثر في الـ runtime: احذف استدعاء `setType(...)` وحقل
  `agentType`. الـ checkpoint (نقطة الحفظ) المحفوظ مع `agentType`
  ينفتح عادي؛ الحقل يُتجاهَل.
- **`ExecuteOptions.onEvent`** ونوعا `ExecutionEvent` /
  `ExecutionEventType`. مرّر `onAgentEvent` لـ
  `AgentExecutor.execute()` / `stream()` / `resumeAfterApproval()`
  بدلها؛ الأحداث اللي توصلك الآن هي `AgentEvent`. جدول مقابلة أسماء
  الأحداث في
  [Streaming](/ar/streaming#الانتقال-من-onevent-executionevent). ومع `createAgent()`، الـ `onEvent`
  أصلاً يستقبل `AgentEvent` ولم يتغير.
- **`createDelegateTool()`** و`DelegateAgentOptions` و`DelegateAgentResult`
  و`DelegationDepthExceededError`. استخدم خيار `subagents` في
  `createAgent()` أو `AgentExecutor.execute()`: الـ model يحصل على
  tool باسم `task` لكل sub-agent (وكيل فرعي)، مع حد للعمق
  (`maxSubagentDepth`، الافتراضي `1`) بدل الخطأ اللي كان يُرمى. شوف
  [Sub-agents](/ar/sub-agents).
- **أنواع ما نفّذها ولا استخدمها أي كود**: واجهات الـ repository
  (`IRepository`, `IAgentRepository`, `ISessionRepository`, `IResultRepository`,
  `SessionData`, `ResultData`, `SDKRepositories`)، و`DataLoadingStatus`،
  و`PaginationParams`، و`PaginatedResponse`، و`DeepPartial`، و`Timestamped`،
  و`IdEntity`، و`AgentExecutionOptions`، و`AgentExecutionResult`، و`AgentDefinition`
  و`ToolSetting`. لو كودك يستخدم واحد منها، انسخ تعريفه إلى مشروعك.

```ts
// Before (alpha):
import { createDelegateTool } from '@lousho/build-ai-agent';
const delegate = createDelegateTool({ agent: billing, name: 'billing' });
```

```ts
// After (1.0): the lead gets a `task` tool per sub-agent.
import { createAgent } from '@lousho/build-ai-agent';

const billing = createAgent({ model: 'openai/gpt-4o-mini', instructions: 'You answer billing questions.' });
const lead = createAgent({
  model: 'openai/gpt-4o-mini',
  instructions: 'Route questions to the right specialist.',
  subagents: { billing },
});
```

## APIs بأسماء جديدة

الـ patch guardrails صار اسمها patch checks، عشان كلمة guardrail
ما تعني إلا الـ guardrails الخاصة بالمدخلات والمخرجات والأدوات في
`createAgent({ guardrails })`. المعاملات والنتائج والسلوك نفسها لم
تتغير. و`SECRET_PATTERNS` احتفظ باسمه. شوف

## Deprecated لكنها ما زالت تشتغل في 1.x

هذه الأسماء تشتغل في 1.x وتنحذف في 2.0. انتقل عنها أول ما تعدّل
الكود؛ ولن ينكسر شيء لو لم تفعل.

## تغييرات أخرى في السلوك منذ alpha.8

القائمة الكاملة في [CHANGELOG](/changelog). هذه البنود اللي تغيّر
سلوك الـ runtime أو أنواع ممكن كودك يعتمد عليها، سطر لكل بند:

- النقل والحذف وإعادة التسمية اللي فوق هي قسم `### Breaking`.
  والملاحظات اللي تحت هي بنود `### Changed` اللي تغيّر السلوك.
- لو `execute` في tool يرجّع async generator، صار يُستهلك بالتكرار -
  آخر قيمة يطلّعها هي النتيجة - و`AgentEvent` صار فيه `tool.partial`
  (`ToolPartialEvent`). لو قصدك ترجّع generator كقيمة، غلّفه:
  `{ items: generator }`. شوف [Tools](/ar/tools)
  و[Stream events](/ar/stream-events).
- `AgentEvent` صار فيه حدث `handoff`، و`ExecutionResult` صار فيه
  الحقل الاختياري `agentName`: لو عندك `switch` شامل على `event.type`
  لازم تضيف case لـ`handoff`. شوف [Handoffs](/ar/handoffs).
- `McpServerStatus` صار فيه `'needs-auth'`، و`AgentOAuth` صار فيه
  `mcpSignInUrl(server)`: الـ `switch` الشامل على
  `connectMcp().status()` يحتاج الـ case الجديدة. شوف
  [MCP](/ar/mcp-integration) و[OAuth](/ar/oauth).
- `ToolExecutionContext` صار فيه `getToken(provider)`
  و`requireAuth(provider)`، و`ApprovalKind` صار فيه `'sign-in'`:
  لو تبني tool context بنفسك في test، لازم تضيف الدالتين (أو تعمل
  cast). شوف [OAuth](/ar/oauth).
- مع listener (`createAgent({ onEvent })`, `onAgentEvent`)، صار
  `send()` و`execute()` يبثّون استدعاءات الـ model: نص الخطوة يوصلك
  على عدة أحداث `text.delta` بدل حدث واحد.
  `execute({ streamModelCalls: false })` يرجّع الشكل القديم. شوف
  [Stream events](/ar/stream-events).
- `MockLLMProvider` / `createMockProvider()`: `stream()` صار يبث
  نفس الخطوة اللي يرجعها `generate()` - نفس الـ tool calls والـ
  finish reason والـ usage - فالـ run المبثوث بـmock يستدعي الـ
  tools مثل `send()`. شوف [Testing](/ar/testing).
- الـ runs في Agent Forge تبث استدعاءات نماذجها؛ عروض الشات والسجلات
  والـ trace ما تغيّرت. شوف [Agent Forge](/ar/agent-forge).
- `lousho init --provider ollama` صار يجهّز `ai@^7` مع
  `ollama-ai-provider-v2@^4` و`zod@^4` (كان `ai@^4` مع
  `ollama-ai-provider@^1` وzod 3). المشاريع القائمة ما تتأثر. شوف
  [Installation](/ar/installation#حزم-الـ-providers).
- لما run يتوقف داخل sub-agent، عند الاستئناف يقارن الـ sub-agent
  بتعريفه الحالي، حسب `onAgentDrift` عند الـ lead - ومع `'error'`
  صار الـ sub-agent المتغيّر يرفض `agent.approvals.resolve()` كمان.
  شوف
  [Durable execution](/ar/durable-execution#استئناف-run-بعد-ما-يتغير-الـ-agent).
- `lousho add` يفرض الـ permission manifest الخاص بالـ registry وقت
  التثبيت، ومجلد الـ agent المحمَّل يشغّل tools كل عنصر داخل الـ
  manifest المقبول الخاص فيه (الـ approval شغال دائمًا لعناصر
  `exec`/`needsApproval`/غير الموثقة، و`fetch` و`process.env`
  محصورين بنطاق التصريح المعلن)؛ الكود غير المطابق يُرفض بـ
  `LOUSHO_REGISTRY_MANIFEST_MISMATCH`، و`--yes` يحتاج `--allow`
  للصلاحيات المرتفعة. شوف [Registry](/ar/registry#بيان-الصلاحيات).
- متابعة run محفوظ بـcheckpoint وغير مكتمل بـ`principal` مختلف عن
  اللي انحفظ معه صارت ترمي `LOUSHO_CONFIG_INVALID`؛ الـ checkpoints
  وsnapshots الخاصة بالـ approval تخزّن الـ principal الخاص بالـ run.
  شوف [Route auth and principals](/ar/auth).
- الحزمة المنشورة صارت أصغر: ملفات الاختبار لم تعد تُشحن، والـ
  source maps لم تعد تضمّن `sourcesContent` (بس `sources` فيها ما
  زالت تحل على `src/` المشحون). ما فيه تغيير في الـ API.

## ما تعد به 1.0

من إصدار 1.0، الحزمة تتبع semver على سطحها العام:

- **عام (public)**: كل entry point يعلنه `exports` - الجذر
  `@lousho/build-ai-agent` والـ subpaths `/executor` و`/tools` و`/flows`
  و`/integrations` و`/utils` و`/mcp` و`/types` و`/testing` و`/otel` و`/hooks`
  و`/sqlite` و`/auth` و`/kv` و`/worker` و`/traces` و`/triggers` و`/react`
  و`/vue` و`/svelte` - وكل اسم في تقارير الـ API المودعة في المستودع
  (`api/index.api.md`, `api/executor.api.md`, ... في المستودع).
  حذف واحد منها أو إعادة تسميته أو تغيير توقيعه يحتاج major version.
- **داخلي (internal)**: كل شي ثاني، بما فيه الـ deep imports داخل
  `dist/` أو `src/` (أي مسار ما يذكره `exports`) والأسماء اللي
  يستخدمها توقيع عام بس ما يصدّرها (بنود `ae-forgotten-export` في
  التقارير). هذه ممكن تتغير في أي إصدار.
- **Deprecated**: الأسماء المعلّمة بـ`@deprecated` تبقى تشتغل طوال
  1.x وتنحذف في 2.0.

الـ CI يقارن التقارير في كل pull request، فأي تغيير في السطح العام
يكون دائمًا diff مقصود ومُراجَع.
