## من يحتاج هذه الصفحة

أي شخص عنده كود مكتوب على `1.0.0-alpha.8` أو إصدار `1.0.0-alpha.*`
أقدم. بين هذه الإصدارات وخط 1.0 (التغييرات المذكورة تحت
`1.0.0-alpha.19` في الـ changelog، والتي نُشرت أول مرة في `1.0.0-alpha.15`)
أعدنا تنظيم السطح العام للحزمة. الـ imports انتقلت إلى subpaths. حذفنا
الـ APIs الميتة أو التي أصبح لها بديل. وأصبح اسم الـ patch guardrails
patch checks. `createAgent()` وخياراتها لم تتغير — الـ agent الذي لا يستخدم إلا
`createAgent({ model, instructions, tools })` و`agent.send()` يترقّى
بتغيير رقم الإصدار فقط.

أنت أصلاً على `1.0.0-alpha.19`؟ انتقل مباشرة إلى
[الترقية من alpha.19](#الترقية-من-alpha-19) لتعرف ما تغيّر على `main`
بعده.

```bash
npm install lousho@^1.0.0-alpha.19
```

## مسارات الـ import التي انتقلت

جذر الحزمة الآن فيه `createAgent()` والأسماء التي تستخدمها إعداداتها
ونتائجها. كل ما في الجدول أدناه انتقل إلى subpath خاص به. التعريفات نفسها لم
تتغير، لكن مكانها تغيّر.

| الاسم (الأسماء) | الـ import القديم | الـ import الجديد |
| ------- | ---------- | ---------- |
| `AgentExecutor`, `AgentBuilder`, `ExecuteOptions`, `ResumeExecuteOptions`, `ResumeRequest`, `resumeAfterApproval()`, `streamResumeAfterApproval()`, `resumeRequest()` | `lousho` أو `lousho/core` | `lousho/executor` |
| `ToolRegistry`, `globalToolRegistry` | `lousho` أو `lousho/core` | `lousho/executor` (وما زال موجودًا في `lousho/tools`) |
| `ExecutionResult`, `ExecutionFinishReason` (أنواع الـ executor) | `lousho/core` | `lousho/executor` (و`ExecutionResult` ما زال في الجذر، مكان نوع نتيجة `createAgent()`) |
| `FlowBuilder`, `FlowExecutor`, `validateFlow` وكل أنواع الـ flow (`AgentFlow`, `EditorStep`, `FlowExecutionEvent`, ...) | `lousho` أو `lousho/types` | `lousho/flows` |
| `createJiraTools`, `createGitHubTools`, `createSlackTool`, `slackTool`, `postSlackAlert`, `createEmailTool` وأنواعها | `lousho` أو `lousho/tools` | `lousho/integrations` |
| `EncryptionUtils`, `DTOEncryptionFilter`, `DecryptionError`, `sha256`, `generatePassword` | `lousho` | `lousho/utils` |
| `StorageService`, `StorageServiceApprovalStore`, `LocalStorageCheckpointStore` | `lousho` | `lousho/utils` (مع الـ stores الخاصة بـ`createAgent()`، الأفضل `fileStore(dir)` من الجذر) |
| `validateWithSchema`, `safeValidate`, `isValidEmail` وبقية الـ validators | `lousho` | `lousho/utils` |

الـ subpath `lousho/core` لم يعد موجودًا؛ كل ما كان
يصدّره أصبح تحت `/executor`.

```ts
import { AgentExecutor, AgentBuilder, ToolRegistry } from 'lousho/executor';
import { FlowBuilder, validateFlow } from 'lousho/flows';
import { createSlackTool } from 'lousho/integrations';
import { EncryptionUtils, validateWithSchema } from 'lousho/utils';
```

## APIs محذوفة وبدائلها

- **`AgentType` و`AgentTypeDescriptor` و`AgentConfig.agentType`
  و`AgentBuilder.setType()` والـ agent-type registry**
  (`agentTypesRegistry`, `getAgentTypeDescriptor`, `getAllAgentTypeDescriptors`,
  `isValidAgentType`, `validateAgentConfig`, `validateAgentTools`). لم
  يكن لها أي أثر في الـ runtime: احذف استدعاء `setType(...)` وحقل
  `agentType`. الـ checkpoint (نقطة الحفظ) المحفوظ مع `agentType`
  يُفتح بشكل عادي؛ الحقل يُتجاهَل.
- **`ExecuteOptions.onEvent`** ونوعا `ExecutionEvent` /
  `ExecutionEventType`. مرّر `onAgentEvent` لـ
  `AgentExecutor.execute()` / `stream()` / `resumeAfterApproval()`
  بدلها؛ الأحداث التي تصلك الآن هي `AgentEvent`. جدول مقابلة أسماء
  الأحداث في
  [Streaming](/ar/streaming#الانتقال-من-onevent-/-executionevent). ومع `createAgent()`، الـ `onEvent`
  أصلاً يستقبل `AgentEvent` ولم يتغير.
- **`createDelegateTool()`** و`DelegateAgentOptions` و`DelegateAgentResult`
  و`DelegationDepthExceededError`. استخدم خيار `subagents` في
  `createAgent()` أو `AgentExecutor.execute()`: الـ model يحصل على
  tool باسم `task` لكل sub-agent (وكيل فرعي)، مع حد للعمق
  (`maxSubagentDepth`، الافتراضي `1`) بدل الخطأ الذي كان يُرمى. انظر
  [Sub-agents](/ar/sub-agents).
- **أنواع لم ينفّذها ولم يستخدمها أي كود**: واجهات الـ repository
  (`IRepository`, `IAgentRepository`, `ISessionRepository`, `IResultRepository`,
  `SessionData`, `ResultData`, `SDKRepositories`)، و`DataLoadingStatus`،
  و`PaginationParams`، و`PaginatedResponse`، و`DeepPartial`، و`Timestamped`،
  و`IdEntity`، و`AgentExecutionOptions`، و`AgentExecutionResult`، و`AgentDefinition`
  و`ToolSetting`. لو كودك يستخدم واحد منها، انسخ تعريفه إلى مشروعك.

```ts
// Before (alpha):
import { createDelegateTool } from 'lousho';
const delegate = createDelegateTool({ agent: billing, name: 'billing' });
```

```ts
// After (1.0): the lead gets a `task` tool per sub-agent.
import { createAgent } from 'lousho';

const billing = createAgent({ model: 'openai/gpt-4o-mini', instructions: 'You answer billing questions.' });
const lead = createAgent({
  model: 'openai/gpt-4o-mini',
  instructions: 'Route questions to the right specialist.',
  subagents: { billing },
});
```

## الانتقال من الـ triggers

حذفنا `WebhookTriggerAdapter` و`SlackTriggerAdapter` و`CronTriggerAdapter` وأنواع الخيارات والـ handle الخاصة بها من `lousho/triggers`. أما `TriggerAdapter` و`TriggerRegistry` وhelpers الخاصة بـ`WebhookAuth` و`verifySlackSignature()` و`parseCronExpression()` فباقية. انظر [Triggers](/ar/triggers).

| المحذوف | البديل |
| ------- | ----------- |
| `WebhookTriggerAdapter`, `WebhookTriggerAdapterOptions`, `WebhookTriggerHandle` | `webhookChannel()`، تُركَّب بـ`mountChannels()`؛ وتأخذ نفس خيار `auth`. انظر [Channels](/ar/channels) |
| `SlackTriggerAdapter`, `SlackTriggerAdapterOptions` | `slackChannel()`، تُركَّب بـ`mountChannels()` - sessions (جلسات) لكل thread، وأزرار approval (موافقة). انظر [Channels](/ar/channels#slack) |
| `CronTriggerAdapter`, `CronTriggerAdapterOptions`, `CronIntervalOptions`, `CronExpressionOptions` | `defineSchedule()` مع `startSchedules()`، أو `schedules/` في مجلد الـ agent، أو cron triggers في ملف spec. لا يوجد `intervalMs`: اكتب تعبير الـ cron (`*/5 * * * *`). انظر [Schedules](/ar/schedules) |

## تغييرات أخرى في السلوك منذ alpha.8

القائمة الكاملة في [CHANGELOG](/changelog). هذه هي البنود التي تغيّر
سلوك الـ runtime أو أنواعًا قد يعتمد عليها كودك، سطر لكل بند:

- النقل والحذف وإعادة التسمية الواردة أعلاه هي قسم `### Breaking`.
  والملاحظات الواردة أدناه هي بنود `### Changed` التي تغيّر السلوك.
- إذا كانت `execute` في tool تُرجع async generator، فأصبح يُستهلك بالتكرار -
  آخر قيمة يُخرجها هي النتيجة - وأصبح `AgentEvent` يحتوي `tool.partial`
  (`ToolPartialEvent`). إذا كنت تقصد إرجاع generator كقيمة، فغلّفه:
  `{ items: generator }`. انظر [Tools](/ar/tools)
  و[Stream events](/ar/stream-events).
- أصبح `AgentEvent` يحتوي حدث `handoff`، وأصبح `ExecutionResult` يحتوي
  الحقل الاختياري `agentName`: إذا كان لديك `switch` شامل على `event.type`
  فيجب أن تضيف case لـ`handoff`. انظر [Handoffs](/ar/handoffs).
- أصبح `McpServerStatus` يحتوي `'needs-auth'`، وأصبح `AgentOAuth` يحتوي
  `mcpSignInUrl(server)`: الـ `switch` الشامل على
  `connectMcp().status()` يحتاج الـ case الجديدة. انظر
  [MCP](/ar/mcp-integration) و[OAuth](/ar/oauth).
- أصبح `ToolExecutionContext` يحتوي `getToken(provider)`
  و`requireAuth(provider)`، وأصبح `ApprovalKind` يحتوي `'sign-in'`:
  إذا كنت تبني tool context بنفسك في test، فيجب أن تضيف الدالتين (أو تُجري
  cast). انظر [OAuth](/ar/oauth).
- مع listener (`createAgent({ onEvent })`, `onAgentEvent`)، أصبحت
  `send()` و`execute()` تبثّان استدعاءات الـ model: يصلك نص الخطوة
  على عدة أحداث `text.delta` بدل حدث واحد.
  `execute({ streamModelCalls: false })` يُعيد الشكل القديم. انظر
  [Stream events](/ar/stream-events).
- `MockLLMProvider` / `createMockProvider()`: أصبحت `stream()` تبث
  الخطوة نفسها التي تُرجعها `generate()` - نفس الـ tool calls والـ
  finish reason والـ usage - فالـ run المبثوث بـmock يستدعي الـ
  tools مثل `send()`. انظر [Testing](/ar/testing).
- الـ runs في Agent Forge تبث استدعاءات نماذجها؛ عروض المحادثة والسجلات
  والـ trace لم تتغيّر. انظر [Agent Forge](/ar/agent-forge).
- `lousho init --provider ollama` أصبح يجهّز `ai@^7` مع
  `ollama-ai-provider-v2@^4` و`zod@^4` (كان `ai@^4` مع
  `ollama-ai-provider@^1` وzod 3). لا تتأثر المشاريع القائمة. انظر
  [Installation](/ar/installation#حزم-الـ-providers).
- عندما يتوقف run داخل sub-agent، يُقارَن الـ sub-agent عند الاستئناف
  بتعريفه الحالي، حسب `onAgentDrift` لدى الـ lead - ومع `'error'`
  أصبح الـ sub-agent المتغيّر يرفض `agent.approvals.resolve()` أيضًا.
  انظر
  [Durable execution](/ar/durable-execution#استئناف-run-بعد-تغيّر-الـ-agent).
- `lousho add` يفرض الـ permission manifest الخاص بالـ registry وقت
  التثبيت، ومجلد الـ agent المحمَّل يشغّل tools كل عنصر داخل الـ
  manifest المقبول الخاص به (الـ approval مفعّل دائمًا لعناصر
  `exec`/`needsApproval`/غير الموثقة، و`fetch` و`process.env`
  محصورين بنطاق التصريح المعلن)؛ الكود غير المطابق يُرفض بـ
  `LOUSHO_REGISTRY_MANIFEST_MISMATCH`، و`--yes` يحتاج `--allow`
  للصلاحيات المرتفعة. انظر [Registry](/ar/registry#بيان-الصلاحيات).
- متابعة run محفوظ بـcheckpoint وغير مكتمل بـ`principal` مختلف عن
  الذي حُفظ معه أصبحت ترمي `LOUSHO_CONFIG_INVALID`؛ الـ checkpoints
  وsnapshots الخاصة بالـ approval تخزّن الـ principal الخاص بالـ run.
  انظر [Route auth and principals](/ar/auth).
- أصبحت الـ memory slots تخزّن عناصرها تحت `<slot name>#<scope key>`
  (`notes#global`) بدل مفتاح النطاق وحده (`global`)، فلم يعد slotان لهما
  النطاق نفسه يتشاركان العناصر. العناصر التي كتبها `1.0.0-alpha.19` أو أقدم
  لم تعد تُقرأ؛ شغّل `migrateMemoryKeys(slot)` مرة واحدة لكل slot
  لتنسخها. انظر
  [Memory](/ar/memory#عناصر-من-قبل-مفاتيح-اسم-الـ-slot).
- أصبحت الحزمة المنشورة أصغر: ملفات الاختبار لم تعد تُشحن، والـ
  source maps لم تعد تضمّن `sourcesContent` (لكن `sources` فيها ما
  زالت تشير إلى `src/` المشحون). لا يوجد تغيير في الـ API.

## الترقية من alpha.19

`1.0.0-alpha.19` هو آخر إصدار على npm. التغييرات على `main` من بعده
(قسم `[Unreleased]` في [CHANGELOG](/changelog)) أغلبها إصلاحات
وإضافات، لكن بعضها يغيّر قيمة افتراضية أو سلوكًا قد يعتمد عليه كودك.
كلٌّ منها مذكور أدناه مع طريقة الرجوع إلى السلوك القديم، إن وُجدت.
التغيير المعلَّم بـ"لا يمكن تعطيله" سدّ ثغرة أمنية أو خللًا يضيّع البيانات.

### الـ HTTP routes والسيرفرات والـ channels

| التغيير | طريقة التعطيل |
| ------ | ------- |
| مع route auth وبدون `authorizeSession`، تصبح الـ session ملكًا لأول principal يرسل لها دورة (القراءة لا تُثبت ملكية)؛ وأي principal آخر يحصل على `403 LOUSHO_SESSION_FORBIDDEN`. المالك يُحفظ في الذاكرة لكل agent (آخر 100,000 session مستخدمة)؛ والـ session المخزّنة التي مالكها غير مسجّل (بعد إعادة تشغيل، أو بعد تجاوز هذا الحد) تُرفض للجميع، فمرّر `authorizeSession` إذا كان لديك أكثر من instance أو store يعيش أطول من العملية. الـ bearer token الواحد يمثّل متصلًا واحدًا ولا يتحقق من أي مالك. انظر [من يحق له استخدام الـ session](/ar/auth#من-يستطيع-استخدام-الـ-session). | `authorizeSession: () => true` |
| الـ session routes (`createRouteHandler()` و`createDeployedServer()` والـ Worker و`lousho dev`) ترفض الـ POST القادم من موقع آخر (`403 LOUSHO_REQUEST_FORBIDDEN`) وجسم POST الذي ليس `Content-Type: application/json` (`415 LOUSHO_UNSUPPORTED_MEDIA_TYPE`). والخيار الجديد `allowedHosts` (مطفأ افتراضيًا) يرفض ترويسات `Host` غير المدرجة. انظر [الطلبات من مواقع أخرى](/ar/auth#الطلبات-بين-المواقع). | `allowedOrigins: ['*']`، `requireJsonBody: false` (أو أضف origin الواجهة الأمامية في `allowedOrigins`) |
| `POST /chat/:sessionId/approvals/:id` يرد بـ`404` إلا إذا كانت الـ approval تابعة لهذه الـ session، ولا يقرّر فيها إلا المتصل الذي يعمل الـ run المتوقف نيابةً عنه. | `authorizeApproval` لتسمح لغيره (مشرف مثلًا) بالقرار |

| الـ routes ترسل `name` و`code` الخاصين بالخطأ مع رسالة عامة بدل نصه الخام (في أحداث `error`، وأجسام `500`، وأحداث `provider.retry` / `provider.fallback`)؛ ويذهب الخطأ الكامل إلى `console.error`. | `exposeErrors: true` (`lousho dev` يضبطه) |
| العميل الذي ينقطع في منتصف الدورة لم يعد يُلغي الدورة: تكمل إلى نهايتها وتُحفظ. انظر [Next.js routes](/ar/nextjs#المسارات). | `onDisconnect: 'abort'` |
| `lousho dev` يرد بـ`403` على أي طلب `Host` فيه ليس اسم loopback (أو، خارج الـ loopback، عنوان IP أو اسم `--host`)، للحماية من DNS rebinding؛ وهذا يشمل `/channels/<name>` لأي channel بدون `verify`. | `--allowed-hosts a,b` (تُضاف إلى القيم الافتراضية) |
| الـ channel بدون `verify` يرفض طلب المتصفح القادم من موقع آخر (`403 LOUSHO_REQUEST_FORBIDDEN`)، و`httpChannel()` بدون `verify` يرفض الجسم الذي ليس `Content-Type: application/json` (`415 LOUSHO_UNSUPPORTED_MEDIA_TYPE`). انظر [Channels](/ar/channels). | أعطِ الـ channel دالة `verify` (وأرسل نوع محتوى JSON من السكربتات: `curl -H 'Content-Type: application/json'`) |
| الـ Cloudflare Worker يرفض كل routes `/chat` (الدورة، والـ transcript، وقرار الـ approval؛ `403`) عندما لا يوجد secret اسمه `LOUSHO_API_TOKEN`. أما `/health` والـ OAuth callback والـ channels فتبقى مفتوحة. انظر [Cloudflare Workers](/ar/cloudflare-workers). | المتغيّر `LOUSHO_ALLOW_OPEN_SESSIONS` (أو `LOUSHO_ALLOW_OPEN_TRANSCRIPTS` الأقدم) بقيمة `"true"` |
| `serveMcp()` عبر HTTP يتحقق من `Host` و`Origin` للحماية من DNS rebinding؛ والـ loopback هو بالضبط `localhost` أو عنوان `127.x.x.x` أو `::1` (والأمر نفسه لـ`webhookChannel()`). | `allowedHosts` / `allowedOrigins` على الـ HTTP transport الخاص بـ`serveMcp()` (`['*']` يطفئ الفحص) |
| Agent Forge (`lousho studio`) لا يرسل ترويسات CORS، ويرفض أي `Origin` أجنبي أو `Host` ليس loopback، ويحتاج الـ token الذي يطبعه عند كل تشغيل. انظر [Access token](/ar/agent-forge#رمز-الوصول). | لا يمكن تعطيله |

| فحوص توقيع Slack وDiscord تقبل timestamp متقدمًا بدقيقة كحد أقصى (كانت خمس دقائق في الاتجاهين)، ويُقرأ بالثواني. | لا يمكن تعطيله |
| `telegramChannel` و`teamsChannel` لم يعودا ينشران رابط تسجيل دخول OAuth في محادثة جماعية. | لا يمكن تعطيله |
| الـ channels بدون `store` تحفظ الـ transcripts في `createAgent({ store })` الخاص بالـ agent عندما يحتوي على `sessions`. | مرّر للـ channel الـ `store` الخاص به |
| الـ node-server المبني (وصورة Docker) يشترط `LOUSHO_API_TOKEN` / `auth.ts` على `/channels/<name>` للـ channel الذي لا يملك `verify` عندما يكون token أو `auth.ts` مضبوطًا؛ والـ channels التي تتحقق من نفسها لم تتغيّر. | أعطِ الـ channel دالة `verify` |

## ما تعد به 1.0

من إصدار 1.0، الحزمة تتبع semver على سطحها العام:

- **عام (public)**: كل entry point يعلنه `exports` - الجذر
  `lousho` والـ subpaths `/executor` و`/tools` و`/flows`
  و`/integrations` و`/utils` و`/mcp` و`/types` و`/testing` و`/otel` و`/hooks`
  و`/sqlite` و`/auth` و`/kv` و`/worker` و`/traces` و`/triggers` و`/react`
  و`/vue` و`/svelte` - وكل اسم في تقارير الـ API المودعة في المستودع
  (`api/index.api.md`, `api/executor.api.md`, ... في المستودع).
  حذف واحد منها أو إعادة تسميته أو تغيير توقيعه يحتاج major version.
- **داخلي (internal)**: كل شيء آخر، بما فيه الـ deep imports داخل
  `dist/` أو `src/` (أي مسار لا يذكره `exports`) والأسماء التي
  يستخدمها توقيع عام لكن لا يصدّرها (بنود `ae-forgotten-export` في
  التقارير). هذه قد تتغير في أي إصدار.
