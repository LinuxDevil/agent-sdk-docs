الـ target `docker` في [النشر](/ar/deployment) هو Dockerfile عادي مع سيرفر مُجمَّع (bundled)،
لذلك يشتغل على أي host فيه Docker، ومنها Hostinger VPS.
والمثال [hostinger-deploy](https://github.com/LinuxDevil/agent-sdk/tree/main/examples/hostinger-deploy)
يقدّم وصفة كاملة ومُختبَرة: `deploy.mjs` يتحقق من الـ VM عبر
Hostinger API، ويبني محليًا، وينقل الـ context عبر SSH، ويشغّل
الحاوية، ثم يثبت أن النشر نجح عبر `/health` ودورة `/chat` حقيقية واحدة.

```bash
export HOSTINGER_API_TOKEN=...   # developers.hostinger.com -> API tokens
export OPENROUTER_API_KEY=...    # the agent's model key
export LOUSHO_API_TOKEN=...      # bearer protecting the deployed server
node examples/hostinger-deploy/deploy.mjs --vm <id|hostname|ip>
```

ما يفعله، خطوة بخطوة:

1. **التحقق من الـ VM.** `GET /api/vps/v1/virtual-machines` يجد الـ VM بالـ id
   أو الـ hostname أو عنوان IPv4، ويرفض أي جهاز حالته ليست `running`.
   والـ MCP server `hostinger-api-mcp` يغلّف نفس الـ API، فيقدر الـ agent
   أيضًا أن يتحكم فيه بشكل تفاعلي: دورة حياة الـ VM، ومفاتيح SSH،
   وقواعد الـ firewall، وسكربتات ما بعد التثبيت.
2. **البناء.** `lousho build ./agent --target=docker --out <dir>` ينتج
   context مكتفيًا بذاته (`dist/server.js` مُجمَّع، و`Dockerfile`).
3. **النقل والتشغيل.** ينقل الـ context بـ `tar`/`scp` إلى `/opt/lousho-agent`، ثم عبر
   SSH: `docker build`، و`docker rm -f lousho-agent` إن كانت موجودة، و
   `docker run -d --restart unless-stopped -p 3000:3000 -e ...`.
4. **الإثبات.** يستعلم `/health` بشكل متكرر، ثم يرسل POST لدورة `/chat` واحدة مع الـ bearer
   token.

متغيرات البيئة في المثال تستحق أن تنسخها:

- `-e LOUSHO_STORE=sqlite:/data/lousho.db -v lousho-data:/data`: الـ sessions
  والـ approvals المتوقفة مؤقتًا تبقى بعد إعادة تشغيل الحاوية (`/data` هو named volume).
- `-e LOUSHO_API_TOKEN=...`: إلزامي، فكل route ما عدا `/health` يصبح
  محميًا بـ bearer auth. المنفذ 3000 هو HTTP عادي؛ ضع Traefik (قالب الـ VPS
  يثبّته) أو أي TLS terminator آخر أمامه.

أما التجهيز (provisioning) نفسه، أي شراء VM أو إعادة إنشائه أو تغيير حجمه، فهو
*ليس* في السكربت عن قصد: هذه استدعاءات Hostinger API مدفوعة أو مدمِّرة، والأفضل
تركها لعمليات صريحة (أو للـ MCP server، حيث يظهر كل استدعاء).
