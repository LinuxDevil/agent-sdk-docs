`@lousho/build-ai-agent/testing` يوفّر `mockModel`: ‏`LLMProvider` يشتغل بسكربت deterministic للـ unit tests. تكتب ماذا يفترض أن يقول الـ model في كل turn، تشغّل الـ agent، وبعدين تتحقق بالضبط ماذا أرسل الـ agent للـ model. بلا network، بلا API keys، بلا flakiness.

```bash
npm install --save-dev vitest
```

## رد نصي

لو كتبت string بس، فهو اختصار لـ `{ text }`.

```ts
import { createAgent } from '@lousho/build-ai-agent';
import { mockModel } from '@lousho/build-ai-agent/testing';

const model = mockModel(['Hello! How can I help?']);
const agent = createAgent({ prompt: 'You are friendly.', provider: model });

const result = await agent.send('hi');

console.log(result.text); // Hello! How can I help?
console.log(model.calls.length); // 1
model.assertExhausted();
```

## flow مع tool call

كل عنصر في السكربت هو turn واحد للـ model. الـ turn الأول يطلب tool. الـ agent ينفّذه ويستدعي الـ model مرة ثانية. الـ turn الثاني يعطي الجواب النهائي. معرّفات الـ tool calls تتولّد بشكل deterministic ‏(`call_1`، `call_2`، ...) إلا إذا مرّرت `id`.

```ts
import { describe, it, expect, vi } from 'vitest';
import { z } from 'zod';
import { createAgent, defineTool } from '@lousho/build-ai-agent';
import { mockModel } from '@lousho/build-ai-agent/testing';

describe('weather agent', () => {
  it('calls get_weather and reports the result', async () => {
    const execute = vi.fn(async ({ city }: { city: string }) => ({ city, tempC: 21 }));
    const getWeather = defineTool({
      name: 'get_weather',
      description: 'Get the weather for a city',
      input: z.object({ city: z.string() }),
      execute,
    });
    const model = mockModel([
      { toolCalls: [{ name: 'get_weather', args: { city: 'Paris' } }] }, // turn 1
      { text: 'It is 21°C in Paris.' },                                  // turn 2
    ]);
    const agent = createAgent({
      prompt: 'You report the weather.',
      provider: model,
      tools: [getWeather],
    });

    const result = await agent.send('Weather in Paris?');

    expect(result.text).toBe('It is 21°C in Paris.');
    expect(execute).toHaveBeenCalledWith({ city: 'Paris' }, expect.anything());
    expect(model.calls).toHaveLength(2);
    expect(model.calls[1].messages.at(-1)).toMatchObject({ role: 'tool', toolCallId: 'call_1' });
    model.assertExhausted(); // fails if scripted turns were never used
  });
});
```

## turn فيه خطأ

‏`{ error }` تخلي استدعاء الـ model يفشل بـ reject. يعني تقدر تختبر كيف يتصرف الـ agent لما يقع الـ provider.

```ts
import { it, expect } from 'vitest';
import { createAgent } from '@lousho/build-ai-agent';
import { mockModel } from '@lousho/build-ai-agent/testing';

it('surfaces a provider failure', async () => {
  const model = mockModel([{ error: new Error('upstream 503') }]);
  const agent = createAgent({ prompt: 'x', provider: model });

  await expect(agent.send('hi')).rejects.toThrow();
  expect(model.calls).toHaveLength(1); // the failed request is still recorded
});
```

## التحقق من الـ requests

‏`model.calls` يحتفظ بـ snapshot مجمّدة (deep-frozen) لكل request، بالترتيب. أي تعديل لاحق من الـ agent ما يقدر يعيد كتابة اللي سُجّل. استخدم `model.lastCall` لآخر request.

```ts
expect(model.calls[0].messages[0]).toMatchObject({ role: 'system' });
expect(model.lastCall?.tools?.map((t) => t.function.name)).toContain('get_weather');
// `createAgent()` has no `temperature` option; it reaches the request through a
// `preGenerate` hook (`ctx.request.temperature`) or `ExecuteOptions.temperature`.
expect(model.calls[0].temperature).toBe(0.2);
```

## turns ديناميكية

مرّر function تحسب الـ turn من الـ request. يمكن تكون async، وترجع string أو أي turn object.

```ts
import { mockModel } from '@lousho/build-ai-agent/testing';

const model = mockModel([(req) => `You said: ${req.messages.at(-1)?.content}`]);
const result = await model.generate({ messages: [{ role: 'user', content: 'ping' }] });

console.log(result.text); // You said: ping
```

## مرجع الـ turn

| الحقل          | المعنى                                                                         |
| -------------- | ------------------------------------------------------------------------------ |
| `text`         | نص رد الـ assistant (الافتراضي `''`).                                           |
| `toolCalls`    | `[{ name, args?, id? }]`. الـ args تُرمَّز JSON؛ والـ ids الافتراضية `call_N`.   |
| `error`        | يخلي `generate()` / `stream()` يفشلان بهذا الخطأ (rejection).                   |
| `usage`        | `{ inputTokens, outputTokens }`؛ إذا حذفته الـ turn ما يبلّغ عن أي usage إطلاقًا (`undefined`، مثل backend يحذف عدد الـ tokens، فيقدّر الـ executor ويضع `usage.estimated`). |
| `finishReason` | الافتراضي `'tool_calls'` إذا فيه tool calls، و`'stop'` غير ذلك.                  |
| `delayMs`      | ينتظر قبل ما يرد (يشتغل مع `vi.useFakeTimers()`).                              |

## لما تخلص الـ turns

إذا استدعى الـ agent الـ model أكثر مما كتبت في السكربت، يرمي `mockModel` خطأ يذكر رقم الاستدعاء غير المتوقع، ويعرض آخر message في الـ request، ويقول لك أضف turn. عشان تعيد آخر turn للأبد (مفيد في اختبارات الـ loop وحدود الخطوات)، مرّر `{ onExhausted: 'repeat-last' }`:

```ts
import { mockModel } from '@lousho/build-ai-agent/testing';

const looping = mockModel([{ toolCalls: [{ name: 'again' }] }], { onExhausted: 'repeat-last' });
```

في helpers ثانية: `model.reset()` ترجع السكربت للبداية وتمسح الـ calls المسجّلة، و`model.assertExhausted()` ترمي خطأ إذا بقي في السكربت turns ما استُخدمت.

## Streaming

‏`mockModel` ينفّذ `stream()` أيضًا: نص السكربت ينبعث على شكل `text-delta` chunks (مقسّمة على حدود الكلمات)، تتبعها أي `tool-call` chunks ثم `finish` chunk أخير. يعني تقدر تختبر مستهلكي الـ streaming أيضًا.

## Record و replay

‏`mockModel` تكتب الـ turns يدويًا. `recordReplay` هي الأداة المكمّلة: VCR لسلوك الـ model الحقيقي. شغّل اختبارك مرة واحدة مع الـ provider الحقيقي، وكل تبادل `generate()` / `stream()` ينكتب في ملف cassette. في الـ CI نفس الاختبار يسوّي replay للـ cassette بلا network، بلا API key، وبلا تثبيت الـ peer package الخاصة بالـ provider. بادئة `vendor/` في اسم الـ model تحدد الـ provider؛ ومع OpenRouter استخدم `openrouter/<vendor>/<model>` (مثال `openrouter/openai/gpt-4o-mini`).

```ts
import { createAgent, resolveProvider } from '@lousho/build-ai-agent';
import { recordReplay } from '@lousho/build-ai-agent/testing';

const provider = recordReplay(() => resolveProvider('openai/gpt-4o-mini'), {
  cassette: './__cassettes__/refund-flow.json',
  mode: process.env.LOUSHO_RECORD ? 'record' : 'replay', // or 'auto'
});
const agent = createAgent({ provider, prompt: 'You handle refund requests.' });
```

الوسيط الأول هو الـ provider الحقيقي، أو factory بشكل `() => provider` ما تُستدعى إلا وقت التسجيل (يعني الـ replay ما ينشئها أبدًا). ويمكن تكون `undefined` إذا بتسوي replay بس.

### خطوات العمل

1. سجّل محليًا بمفتاح: `LOUSHO_RECORD=1 OPENAI_API_KEY=... npx vitest run`.
2. راجع الـ cassette وسوِّ له commit (ملف JSON ثابت بإزاحة مسافتين، فالـ diffs مقروءة).
3. الـ CI يشغّل `npx vitest run` ويسوّي replay. ما يحتاج أي شيء ثاني.
4. لما تغيّر الـ prompt أو الـ tools أو الـ flow، يفشل الـ replay بـ `CassetteMismatchError`؛ أعد التسجيل بـ `LOUSHO_RECORD=1`.

‏`mode: 'auto'` يسوّي replay إذا ملف الـ cassette موجود، ويسجّل في الحالة الثانية.

في evals معرّفة بـ `defineEval()` ما تحتاج تغلّف الـ provider بنفسك: `lousho eval --record` يكتب cassette لكل eval case، و`--replay` يشغّل منها، و`--drift` يبيّن كيف تغيّر مسار كل case. شوف [التسجيل وإعادة التشغيل والـ drift](/ar/evals#record-replay-and-drift).

### ماذا يفحص الـ replay

افتراضيًا الـ call رقم N يُجاب عليها بالـ entry رقم N، لكن بشرط يكون الـ request مطابقًا للي سُجّل: الـ model، دور كل message ومحتواها والـ tool calls فيها، أسماء الـ tools والـ parameter schemas حقّها، و`temperature` و`maxTokens`. عند عدم التطابق الخطأ يعرض أول اختلاف مع تلميح لإعادة التسجيل:

```text
Call #2 does not match the recorded request in ./__cassettes__/refund-flow.json.
First difference at request.messages[1].content:
  recorded: "Refund order 1234"
  actual:   "Refund order 9999"
If the change is intentional, re-record the cassette (run with LOUSHO_RECORD=1, or set mode: 'record').
```

للـ calls المتوازية أو غير المرتّبة مرّر `match: 'request'`: كل call يلاقي أول entry غير مستخدمة بطلب مطابق تمامًا، بأي ترتيب. ونفاد الـ entries برضو `CassetteMismatchError`.

القيم المتقلّبة ما تكسر المطابقة. الـ timestamps والتواريخ (`2026-10-01` و`October 1, 2026`) والـ UUIDs والمعرّفات ذات البادئات (`call_...` و`toolu_...` و`chatcmpl_...`) تُستبدل بـ placeholders على الطرفين، ومعرّفات الـ tool calls تُتجاهل (تتطابق الـ tool calls بالاسم والـ arguments). الـ parameter schema حقّة الـ tool تتطابق بما كتبته فيها (أسماء الخصائص والأنواع و`optional` وقيم الـ enum والفحوص مثل `min` أو `int` والأوصاف)، مو بطريقة طباعة major version معيّن من zod. فالـ cassette المسجّلة بـ zod 3 تشتغل replay مع zod 4 والعكس؛ وتغيير الـ schema نفسها يفشّل المطابقة. لأي شيء ثاني، مرّر `normalize`:

```ts
import { mockModel, recordReplay } from '@lousho/build-ai-agent/testing';

const provider = recordReplay(mockModel(['ok']), {
  cassette: './__cassettes__/users.json',
  normalize: (request) => ({
    ...request,
    messages: request.messages.map((m) =>
      typeof m.content === 'string' ? { ...m, content: m.content.replace(/user-\d+/g, 'user-N') } : m
    ),
  }),
});
```

### الأخطاء والـ streaming والـ usage

- رفض الـ provider يُسجَّل ويُعاد كرفض بنفس الـ `name` والـ `message`.
- `stream()` يسجّل الـ chunks ويعيدها كـ async iterable بلا تأخيرات؛ مرّر `replayTiming: true` عشان تسترجع التوقيت بين الـ chunks. وأثناء التسجيل يُقرأ الـ stream الحقيقي للنهاية قبل ما يُرجَع.
- استهلاك الـ tokens يُسجَّل ويُعاد، فميزات التكلفة والـ usage تتصرف نفس الشيء في الـ replay.

### متى تُكتب الـ cassette

التسجيل يكتب الـ cassette بشكل atomic (ملف مؤقت ثم rename) بعد كل call. يعني الاختبار اللي يفشل بنص الطريق يترك cassette صالحة فيها كل الـ calls اللي صارت، مو cassette نص مكتوبة. `await provider.save()` يفرض الكتابة. ما فيه hook عند خروج الـ process. وكل session تسجيل تبدأ cassette جديدة وتستبدل الملف القديم.

### تنقيح البيانات (اقرأ هذا قبل الـ commit)

الـ cassettes مفروض تدخل الـ repo، فالـ wrapper يكتب بس مجموعة ثابتة من حقول الـ request (أبدًا مو headers ولا option bags الخاصة بالـ provider)، وما يكتب `rawResponse` أبدًا، ويستبدل الـ strings اللي تشبه API keys ‏(`sk-...` و`sk-ant-...` ورموز `Bearer ...` وصيغ شائعة ثانية) بـ `[REDACTED]`. هذا safety net، مو ضمانة: الـ prompts وردود الـ model تُخزَّن حرفيًا، يعني البيانات الشخصية والـ URLs الداخلية ونصوص العملاء تنتهي في الملف. مرّر `redact` عشان تنقّيها (تشتغل على كل string مسجّلة، في الـ requests والـ responses مع بعض، والـ replay يطبّقها عند المطابقة):

```ts
import { mockModel, recordReplay } from '@lousho/build-ai-agent/testing';

const provider = recordReplay(mockModel(['ok']), {
  cassette: './__cassettes__/support.json',
  redact: (text) => text.replace(/[\w.+-]+@[\w-]+\.[\w.]+/g, '<email>'),
});
```

### `mockModel` ولا cassettes؟

استخدم `mockModel` للـ unit tests على منطقك إنت: تتحكم بكل turn، تقدر تحقن أخطاء وتأخيرات، وما فيه شيء يعتمد على model. استخدم الـ cassettes لما تكون النقطة هي سلوك الـ model الحقيقي (هل الـ prompt وهذي الـ tools يوصلون فعلًا للـ tool call الصح؟) ولما كتابة الـ turns يدويًا بس تثبّت افتراضاتك في الاختبار. الـ cassettes تحتاج إعادة تسجيل لما تتغيّر الـ prompts؛ واختبارات `mockModel` تتغيّر بس إذا تغيّر السلوك اللي تتحقق منه.
