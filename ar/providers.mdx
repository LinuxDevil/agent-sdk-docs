الـ `LLMProvider` هو اللي الـ agent يولّد من خلاله. الـ SDK يجي مع
providers لـ OpenAI وAnthropic وOpenRouter وOllama و`pi` (كل واحد وراه
peer package اختيارية، شوف [التثبيت](/ar/installation#حزم-الـ-providers)) ومع
mock ثابت النتائج للاختبارات. تسمّيه بـ string بصيغة `provider/model`، أو
تمرّر instance من الـ provider. البادئة `vendor/` في اسم الـ model هي اللي
تختار الـ provider؛ ومع OpenRouter تكتب `openrouter/<vendor>/<model>` (مثال
`openrouter/openai/gpt-4o-mini`).

```ts
import { resolveProvider, LLMProviderRegistry } from '@lousho/build-ai-agent';

// The convenient way — reads the credential from the environment
const openai = resolveProvider('openai/gpt-4o-mini');       // OPENAI_API_KEY
const anthropic = resolveProvider('anthropic/claude-sonnet-5-5'); // ANTHROPIC_API_KEY
const openrouter = resolveProvider('openrouter/openai/gpt-4o-mini'); // OPENROUTER_API_KEY
const ollama = resolveProvider('ollama/llama3.1');           // OLLAMA_BASE_URL
// pi runs one catalog through `pi/<pi-provider>/<model>` (nested slashes ok):
const pi = resolveProvider('pi/openrouter/openai/gpt-4o-mini');    // OPENROUTER_API_KEY

// Or construct a provider directly via the registry
const custom = LLMProviderRegistry.create('openai', {
  apiKey: process.env.OPENAI_API_KEY,
  defaultModel: 'gpt-4o-mini',
});
```

## اختيار الـ provider في `createAgent()`

`createAgent()` ياخذ واحد فقط من التالي:

1. **`model: 'provider/model'`** - ينحلّ بـ `resolveProvider()`؛ والمفتاح
   يجي من متغير البيئة المعتاد للـ provider (شوف
   [بيانات اعتماد الـ providers](/ar/configuration#بيانات-اعتماد-الـ-providers)).
2. **`provider: <LLMProvider>`** - provider كتبته إنت، أو built-in مضبوط،
   أو mock. وتقدر تمرّر معه `model` (id مجرّد مثل `'gpt-4o'`): يصير هو
   model هذا الـ agent ويطغى على default الـ provider.
3. **ولا واحد** - ينحلّ من البيئة: `LOUSHO_MODEL` (string بصيغة
   `provider/model`) لو مضبوط، وإلا أول واحد موجود من `OPENAI_API_KEY` و
   `ANTHROPIC_API_KEY` و`OPENROUTER_API_KEY` و`OLLAMA_BASE_URL`. لو ما
   فيه ولا واحد، يرمي خطأ يعدّد الحلول.

```ts
import { createAgent, createMockProvider, resolveProvider } from '@lousho/build-ai-agent';

const fromString = createAgent({ model: 'anthropic/claude-sonnet-5-5' });
const fromInstance = createAgent({ provider: resolveProvider('openai/gpt-4o-mini'), model: 'gpt-4o' });
const offline = createAgent({ provider: createMockProvider({ responses: ['Hi! How can I help?'] }) });
```

أخطاء الإعداد الغلط تقول لك كيف تصلّحها: المفتاح الناقص يسمّي المتغير،
والبادئة المجهولة تعدّد المدعوم منها وتقترح الأقرب، والـ peer package
الناقصة تطبع أمر `npm install` الصحيح بالضبط.

### Retry ونماذج fallback

`createAgent()` يعيد محاولة الـ call الفاشلة على الـ model (rate limit،
timeout، خطأ شبكة، 5xx) مرتين افتراضيًا. ولو ضبطت `fallbackModels` ينتقل
للـ model التالي لما الـ call يفضل فاشل:

```ts
import { createAgent } from '@lousho/build-ai-agent';

const agent = createAgent({
  model: 'openai/gpt-4o-mini',
  retry: { maxRetries: 3 }, // or false
  fallbackModels: ['anthropic/claude-haiku-4-5', 'openrouter/meta-llama/llama-3.3-70b-instruct'],
});
```

string الـ `model` وكل fallback ينحلّون والـ retries المدمجة في `ai`
مقفلة، فيبقى `retry` هو طبقة الـ retry الوحيدة. أما instance الـ
`provider` فينلفّ بس لو ضبطت `retry`. `agent.stream()` يطلّع أحداث
`provider.retry` و`provider.fallback`. التفاصيل في
[Provider retries وfallback](/ar/configuration#الـ-retry-والـ-fallback-عند-الـ-provider).

## أي model يشتغل؟

بالترتيب: `settings.model` الخاص بالـ agent (يتضبط بـ
`AgentBuilder.setSettings({ model })`، أو بـ `model` جنب `provider` في
`createAgent()`)، بعده الـ model اللي اتبنى عليه الـ provider
(`resolveProvider('openai/gpt-4o-mini')`، أو `provider.model` في spec، أو
`defaultModel`)، وبعده الـ default المدمج في الـ provider. الـ default
الأخير ينطبق بس لما ما يكون شي ضبط model — الـ model اللي إنت ضبطته ما
تتجاوزه أبدًا قيمة hard-coded.

## إدخال multimodal

`Message.content` يكون string أو قائمة parts: `{ type: 'text', text }`،
و`{ type: 'image', image, mimeType? }` (رابط `http(s)`، أو `data:` URL، أو
الـ bytes نفسها في `Uint8Array`) و`{ type: 'file', data, mimeType, filename? }`.
`agent.send()` و`agent.stream()` و`session.send()` / `stream()` و`t.send()` في
الـ evals و`send()` الخاصة بالـ React hook كلها تاخذ `AgentInput`: string، أو
قائمة parts (تترسل كرسالة `user` واحدة) أو `Message[]` (تتمرّر كما هي).
إرسال parts عبر `createAgent()`:

```ts
import { readFileSync } from 'node:fs';
import { createAgent } from '@lousho/build-ai-agent';

const agent = createAgent({ instructions: 'Describe images briefly.', model: 'openai/gpt-4o-mini' });

// Parts become one user message.
const answer = await agent.send([
  { type: 'text', text: 'What is in these pictures?' },
  { type: 'image', image: 'https://example.com/cat.png' },
  { type: 'image', image: new Uint8Array(readFileSync('dog.png')), mimeType: 'image/png' },
]);
console.log(answer.text);
```

الـ `Message[]` تتمرّر كما هي؛ و`textOf()` ترجّع الـ parts النصية من الرسالة:

```ts
import { createAgent, textOf, type Message } from '@lousho/build-ai-agent';

const agent = createAgent({ instructions: 'Describe images briefly.', model: 'openai/gpt-4o-mini' });
const messages: Message[] = [
  {
    role: 'user',
    content: [
      { type: 'text', text: 'What is in this picture?' },
      { type: 'image', image: 'https://example.com/cat.png' },
    ],
  },
];

const result = await agent.send(messages);
console.log(textOf(messages[0]), '->', result.text);
```

- **الصور** توصل للـ model داخل رسائل `user` مع كل الـ built-in providers
  (مع Anthropic وOllama حزمة `ai` تنزّل رابط الصورة الأول؛ و`pi` يرسل
  `data:` URLs والـ bytes بس — رابط `http(s)` يتحوّل لملاحظة نصية مع تحذير
  يطلع مرة واحدة). اختار model يدعم vision: Ollama يتجاهل الصور مع
  model نصي فقط، وOpenRouter يرفضها له.
- **الملفات** (`{ type: 'file', data, mimeType }`) تترسل كـ parts من نوع
  `file` لأنواع الوسائط التالية، حسب الـ provider وmajor نسخة `ai`:

  | Provider | `ai` 4 | `ai` 6 / 7 |
  | -------- | ------ | ---------- |
  | `openai` | ملاحظة نصية | `application/pdf` |
  | `anthropic` | ملاحظة نصية | `application/pdf`، `text/plain` |
  | `openrouter` | ملاحظة نصية | `application/pdf` |
  | `ollama` | ملاحظة نصية | ملاحظة نصية |
  | `pi` | ملاحظة نصية | ملاحظة نصية (pi ما عنده file part) |

  أي file part آخر يترسل كملاحظة نصية
  (`[file report.pdf (application/pdf) not sent]`)، والـ provider يحذّر مرة
  واحدة لكل media type ويسمّي النوع وmajor نسخة `ai`. على `ai` 4 نطاق
  `@ai-sdk/*` المقبول يشمل حزم 0.0.x اللي ما عندها file parts، فكل file
  يصير ملاحظة هناك. ولو كتبت subclass لـ provider وmodel الخاص فيه يقبل
  أنواع أكثر، تتجاوز `protected fileMediaTypes(): readonly string[]`
  لتعدّدها، أو تضبط `protected readonly acceptsFileParts = true` ليرسل كل
  الأنواع.
- رسائل `system` و`assistant` و`tool` تترسل بأجزائها النصية.
- كل اللي يقرأ نص الرسائل يستخدم `textOf()`: `estimateTokens()` (كل
  image أو file part يتحسب 1,000 token بشكل ثابت)، والـ compaction،
  وcassettes الخاصة بـ `recordReplay()` (تخزّن النص وdigest لكل صورة أو
  ملف، أو رابطه) و`mockModel()`. `FileSessionStore` يخزّن الـ bytes بـ
  base64 (`{ "$bytes": "..." }`) ويرجّعها `Uint8Array` عند التحميل؛
  و`SqliteStore` (للـ sessions والـ checkpoints) يعمل نفس الشيء.

#### متقدم: executor API

`AgentExecutor.execute()` ياخذ نفس الرسائل في `input` (شوف [executor API](/ar/executor-api)):

```ts
import { AgentBuilder, AgentExecutor } from '@lousho/build-ai-agent/executor';
import { resolveProvider, type Message } from '@lousho/build-ai-agent';

const agent = AgentBuilder.create().setName('vision').setPrompt('Describe images briefly.').build();
const input: Message[] = [
  {
    role: 'user',
    content: [
      { type: 'text', text: 'What is in this picture?' },
      { type: 'image', image: 'https://example.com/cat.png' },
    ],
  },
];

const result = await AgentExecutor.execute({ agent, input, provider: resolveProvider('openai/gpt-4o-mini') });
console.log(result.text);
```

## Provider classes

| Export | الوصف |
| ------ | ----------- |
| `resolveProvider('p/model')` | يبني provider حقيقي من credentials البيئة. |
| `LLMProviderRegistry` | registry فيه factories للـ providers: `create(type, config)`، `register(type, factory)`، `has(type)`. |
| `OpenAIProvider`, `AnthropicProvider`, `OllamaProvider`, `OpenRouterProvider`, `PiProvider` | كلاسات الـ providers. شوف [examples/openrouter](https://github.com/LinuxDevil/agent-sdk/blob/main/examples/openrouter) لميزات OpenRouter الخاصة. `PiProvider` هو الـ adapter الخاص بـ `pi/...` أدناه. |
| `createMockProvider()`, `MockLLMProvider` | ردود جاهزة للـ demos؛ يحاكي tool call لما الرسالة تسمّي tool. |
| `mockModel(script)` | provider بسكريبت للاختبارات يتحقق من التسلسل (من `/testing`)؛ شوف [Testing](/ar/testing). |
| `withRetry()`, `withFallback()` | يعيد محاولة الفشل المؤقت مع backoff ويحوّل للـ provider التالي؛ شوف [Provider retries وfallback](/ar/configuration#الـ-retry-والـ-fallback-عند-الـ-provider). |
| `fromAiSdk(model, options?)` | أي `LanguageModel` من AI SDK (Google، Bedrock، Azure، Mistral، الـ Gateway، ...) كـ provider؛ شوف [أدناه](#أي-model-من-ai-sdk-fromaisdk). |

لو عندك backend آخر، شوف الأول إذا له provider package في AI SDK:
لو موجودة، غلّف الـ model الخاص فيها بـ `fromAiSdk()` (أدناه). وإلا
implement الـ interface `LLMProvider` (`name` و`generate()` و`stream()` و
`supportsTools()` و`supportsStreaming()` و`getModels()`، واختياريًا
`defaultModel`) ومرّر الـ instance كـ `provider`، أو سجّل factory بـ
`LLMProviderRegistry.register(name, factory)`.

### أي model من AI SDK: `fromAiSdk()`

`fromAiSdk(model)` تحوّل أي language model من provider package في AI SDK
إلى `LLMProvider`، فما تضطر تكتب adapter بنفسك:

```ts
import { createOpenAI } from '@ai-sdk/openai';
import { createAgent, fromAiSdk } from '@lousho/build-ai-agent';

const openai = createOpenAI({ apiKey: process.env.OPENAI_API_KEY });
const agent = createAgent({
  provider: fromAiSdk(openai.chat('gpt-4o-mini'), { fileMediaTypes: ['application/pdf'] }),
  instructions: 'You are a helpful assistant.',
});
```

نفس الشيء يشتغل مع `@ai-sdk/google` (`google('gemini-2.5-flash')`)
و`@ai-sdk/amazon-bedrock` و`@ai-sdk/azure` و`@ai-sdk/mistral` والـ AI
Gateway (`gateway('openai/gpt-4o')` من `ai` 7 أو `@ai-sdk/gateway`). الـ
calls تعدّي على نسخة `ai` المثبّتة عندك، فثبّت الـ major المناسب لها من
حزمة الـ provider (شوف [إصدارات Vercel AI SDK](#إصدارات-vercel-ai-sdk)).

| الخيار | الافتراضي | الوصف |
| ------ | ------- | ----------- |
| `name` | حقل `provider` في الـ model، وإلا `'ai-sdk'` | اسم الـ provider في الـ events والـ spans والتحذيرات. |
| `fileMediaTypes` | `[]` | أنواع الوسائط اللي تترسل كـ parts من نوع `file`؛ باقي الـ file parts تصير ملاحظة نصية. الصور تترسل دائمًا. |
| `replaysReasoning` | `false` | يرجّع بلوكات الـ reasoning الموقّعة في turns الـ assistant (models من Anthropic). |
| `maxRetries` | `0` | عدد الـ retries الخاصة بـ AI SDK لكل call؛ أما `createAgent()` فيعيد المحاولة عبر خيار `retry`. |

الـ provider يقدّم الـ model الواحد اللي يلفّه بس، مع tools وstreaming
شغّالين، ويترك إعدادات الـ reasoning للـ model اللي بنيته إنت (خيار
`reasoning` بدون mapping). كل حالة من التالية ترمي `LOUSHO_CONFIG_INVALID`:

- string فيه model id (`fromAiSdk('openai/gpt-4o')`): مرّر الـ model اللي
  ترجعه دالة الـ provider بدلها؛
- model مبني لـ major آخر من `ai` غير المثبّت عندك (model
  `specificationVersion: 'v1'` مع `ai` 6 / 7، أو model أحدث مع
  `ai` 4)؛
- run بـ `model` id مختلف عن اللي متغلّف (داخل الـ run هذا يكون سبب خطأ
  `LOUSHO_PROVIDER_REQUEST_FAILED`): غلّف كل model بـ `fromAiSdk()`
  وادمجهم بـ `withFallback()`.

### الـ provider `pi`

`pi/<pi-provider>/<model>` يمرّر الـ call عبر
[`@earendil-works/pi-ai`](https://www.npmjs.com/package/@earendil-works/pi-ai)
(المحرك اللي `pi-coding-agent` شغّال عليه)، وهو peer اختياري ما يحتاج حزمة
`ai`:

```bash
npm install @earendil-works/pi-ai@1.0.3
```

```ts
import { createAgent } from '@lousho/build-ai-agent';

// OpenRouter's `openai/gpt-4o-mini`, through pi's openrouter adapter:
const agent = createAgent({ model: 'pi/openrouter/openai/gpt-4o-mini' });
```

الجزء اللي بعد `pi/` هو **pi provider** (`openrouter`، `anthropic`،
`openai`، `google`، ...)؛ والباقي هو id الـ model في الـ catalog حرفيًا،
بالسلاشات وكل شيء. الـ credentials لكل provider متداخل: pi يقرأ متغير
البيئة المعتاد لكل واحد (`OPENROUTER_API_KEY` و`ANTHROPIC_API_KEY` و...)،
فمواصفة `pi/anthropic/...` ما تشوف مفتاح OpenRouter أبدًا. `lousho init
--provider pi` يجهّز `pi/openrouter/...` كافتراضي. لو مفتاح الـ provider
المتداخل ناقص، الـ call يفشل بـ `LOUSHO_PROVIDER_MISSING_API_KEY` يسمّي
المتغير، ولو `@earendil-works/pi-ai` ناقصة يفشل بـ
`MissingPeerDependencyError` المعتاد.

اللي يتحوّل في كل call:

- الرسائل: `system` تروح لـ `systemPrompt` الخاص بـ pi،
  و`user`/`assistant`/`tool` تفضل في مكانها؛ بلوكات `reasoning` في الـ
  assistant تصير thinking parts، و`toolCallId` في رسالة `tool` يربطها
  بالـ call الخاصة فيها؛
- الـ tools: `parameters` تترسل كـ JSON Schema - مدخلات raw JSON Schema
  وzod 3 وzod 4 وStandard Schema تتحوّل مرة واحدة وتنحفظ في الـ cache؛
- الـ streams: أحداث `text_delta`/`thinking_delta`/`toolcall_*`/`done`/`error`
  الخاصة بـ pi تصير نفس الـ chunks `text-delta`/`reasoning-*`/`tool-call`/
  `finish`/`error` اللي يطلّعها providers الـ `ai`، فأحداث `agent.stream()`
  و`result.usage` ما تتغيّر؛
- الـ usage والتكلفة: usage الخاص بـ pi لكل call (بما فيه `cacheRead`)
  يدخل في مجموع الـ run، وأسعار الـ catalog تسجّل الـ model في
  `usage.costUsd` الخاص بالـ run؛
- الـ retries: `maxRetries` الخاص بـ pi نفسه مثبّت على مقفل -
  `retry`/`fallbackModels` يفضلون طبقة الـ retry الوحيدة، مثل كل built-in.

`PiProviderConfig.models` تحقن مداخل في الـ catalog (الـ faux provider
الخاص بـ pi، أو catalog خاص) قبل القائمة المدمجة. `pi` يشتغل على Node
فقط: الـ target `cloudflare-worker` يرفض مواصفات `pi/...`، والـ bundle
يحوّل الحزمة لـ shim مكتوب.

## إصدارات Vercel AI SDK

كل built-in provider ما عدا `pi` هو adapter فوق Vercel AI SDK (`ai`). اللي
يشتغل على كل major اليوم:

| `ai` | `generate()` | `stream()` | ملاحظات |
| ---- | ------------ | ---------- | ----- |
| v4 (`^4.3.19`) | نعم | نعم | كل ما في هذه الوثائق. |
| v6 (`^6.0.0`), v7 (`^7.0.0`) | نعم، عبر طبقة توافق | نعم، عبر نفس الطبقة | Ollama يحتاج zod 4 مثبّت (أدناه). |

نطاقات الـ peer تقبل الـ majors الثلاثة. قرّن كل واحد بحزم الـ provider
المناسبة له:

| `ai` | `@ai-sdk/openai`، `@ai-sdk/anthropic` | حزمة Ollama |
| ---- | ------------------------------------- | -------------- |
| `^4.3.19` | `^0.0.42` أو `^1.0.0` | `ollama-ai-provider@^1.2.0` |
| `^6.0.0` | `^3.0.0` | `ollama-ai-provider-v2@^3.0.0` |
| `^7.0.0` | `^4.0.0` | `ollama-ai-provider-v2@^4.0.0` |

تلميح التثبيت لحزمة provider ناقصة و`lousho doctor` يسمّون الإصدار
المناسب لنسخة `ai` اللي عندك، و`lousho doctor` ينبّهك على الاقتران غير
المتوافق (مثال `ai` 7 مع `@ai-sdk/openai` 1.x). `OllamaProvider` يحمّل
`ollama-ai-provider` على `ai` 4 و`ollama-ai-provider-v2` على `ai` 6/7؛
حزمة v2 عندها peer dependency على zod 4، والـ SDK يقبله، فثبّت zod 4
معها (مشاريع zod 3 تستخدم Ollama مع `ai` 4). `lousho init` يجهّز `ai@^7.0.0`
مع `@ai-sdk/*@^4.0.0` لـ OpenAI وAnthropic وOpenRouter، و`ai@^7.0.0` مع
`ollama-ai-provider-v2@^4.0.0` وzod 4 لـ Ollama.

الـ CI يثبّت ويختبر `ai` 4 و6 و7، كل واحد مع zod 3 وzod 4 (ست اقترانات؛
اقتران `ai` 4 مع zod 4 هو الوحيد اللي حزم الـ providers ما تعلنه)، مع
`ollama-ai-provider-v2` الحقيقية على `ai` 6 و7 في الـ jobs الخاصة بـ zod 4.

OpenRouter يستخدم `@ai-sdk/openai` موجّهة على الـ base URL الخاص بـ
OpenRouter. من `@ai-sdk/openai` 2 وفوق، الـ call الافتراضي `openai(modelId)`
يستهدف Responses API، اللي OpenRouter ما ينفّذه، فـ `OpenRouterProvider`
يطلب model الـ Chat Completions (`provider.chat(modelId)`) على كل major؛
ويشتغل على `ai` 4 و6 و7 مع الاقتران اللي فوق.

`OllamaProvider` ياخذ الـ base URL الخاص بالسيرفر (`baseURL`، أو
`OLLAMA_BASE_URL` مع `resolveProvider()`) ويلحق `/api` بالـ host المجرّد،
لأن حزمتي Ollama الاثنتين يتوقعونه بهذا الشكل: `http://host:11434`
و`http://host:11434/` يصيرون `http://host:11434/api`. الرابط اللي منتهي
أصلًا بـ `/api` (أو `/api/`)، أو فيه أي مسار آخر مثل prefix لـ reverse
proxy، يُستخدم كما هو.

`generate()` و`stream()` يختارون شكل الـ call حسب وحدة `ai` المثبّتة: لما
تصدّر `stepCountIs` (v5 وأحدث)، الـ request يترسل بشكل v6/v7 والنتيجة
تُقرأ وترجع لنفس `GenerateResult` أو `StreamResult`:

- الرسائل تصير `ModelMessage`s: وسائط الـ tool call تصير `input` الخاص
  به، ونتيجة الـ tool تصير `output` (`json` أو `text`، و`error-json` أو
  `error-text` لما الـ tool يفشل)، و`mimeType` في الـ image أو file part
  يصير `mediaType`. رسائل الـ system تفضل في مكانها
  (`allowSystemInMessages`).
- `maxTokens` يترسل باسم `maxOutputTokens`، والخطوة الواحدة كـ `stopWhen:
  stepCountIs(1)`، والـ tools كـ `inputSchema` (zod schema كما هو، وJSON
  Schema عبر `jsonSchema()`) بدون `execute`، و`responseFormat` كـ
  `output` في وضع JSON ما يمسّ نص الرد.
- الـ usage يجي من `inputTokens` / `outputTokens` / `totalTokens`، مع
  `cachedInputTokens` من `inputTokenDetails.cacheReadTokens`
  و`reasoningTokens` من `outputTokenDetails.reasoningTokens`.
- `stream()` يقرأ `fullStream` الخاص بالـ SDK على أي من الـ majorين
  ويحوّله لنفس الـ chunks: `text-delta` (في v6/v7 الحقل `text`، وفي v4
  `textDelta`)، و`tool-call` (الـ call الكامل اللي v6/v7 يرسله بعد
  `tool-input-start`/`-delta`/`-end`، أو واحد يتجمّع من ذلك الـ input لما
  الـ model ما يرسل واحد)، و`finish` مع سبب الإنهاء اللي يعطيه الـ SDK
  والـ usage المذكور أعلاه (في v6/v7 الحقل `totalUsage`). جزء `error`
  يجعل الـ stream يرفض بخطئه، على v4 كذلك (كان v4 ينهي stream كهذا بسبب
  إنهاء `error`)، وجزء `abort` يرفضه بسبب الـ signal. تغيّرات الـ
  reasoning الجزئية تتبلّغ كـ chunks من نوع `reasoning-delta` وتطلع
  كأحداث `reasoning.*` (شوف [Reasoning](/ar/reasoning)).

على v6/v7 لازم الـ model يجي من provider package خاصة بنفس الـ major
(الجدول أعلاه)؛ حزم `0.0.x`/`1.x` تنتج models يرفضها `ai` v7. الـ image
parts تترسل كـ `file` parts بـ media type صور (وهو الشكل اللي `ai` v6/v7
يقبله للصور، فما يطلع تحذير deprecation). `ai` v5 غير مدعوم.

## أين يشتغل كل provider

كل الـ providers يشتغلون على Node. الـ deploy target `cloudflare-worker`
يدعم `mock` و`openai` و`anthropic` و`openrouter` (المفتاح من binding باسم
`OPENROUTER_API_KEY`)؛ أما `ollama` و`pi` فيحتاجون target `node-server` أو
`docker` (شوف [Cloudflare Workers](/ar/cloudflare-workers)).
