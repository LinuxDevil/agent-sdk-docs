الـ `LLMProvider` هو ما يولّد الـ agent من خلاله. يأتي الـ SDK مع
providers لـ OpenAI وAnthropic وGoogle (Gemini) وOpenRouter وOllama و`pi` (لكلٍّ منها
peer package اختيارية، راجع [التثبيت](/ar/installation#حزم-الـ-providers)) ومع
mock ثابت النتائج للاختبارات. تسمّيه بـ string بصيغة `provider/model`، أو
تمرّر instance من الـ provider. البادئة `vendor/` في اسم الـ model هي التي
تحدد الـ provider؛ ومع OpenRouter تكتب `openrouter/<vendor>/<model>` (مثال
`openrouter/openai/gpt-4o-mini`).

```ts
import { resolveProvider, LLMProviderRegistry } from 'lousho';

// The convenient way — reads the credential from the environment
const openai = resolveProvider('openai/gpt-4o-mini');       // OPENAI_API_KEY
const anthropic = resolveProvider('anthropic/claude-sonnet-5-5'); // ANTHROPIC_API_KEY
const google = resolveProvider('google/gemini-2.5-flash');   // GOOGLE_GENERATIVE_AI_API_KEY
const openrouter = resolveProvider('openrouter/openai/gpt-4o-mini'); // OPENROUTER_API_KEY
const ollama = resolveProvider('ollama/llama3.1');           // OLLAMA_BASE_URL
// pi runs one catalog through `pi/<pi-provider>/<model>` (nested slashes ok):
const pi = resolveProvider('pi/openrouter/openai/gpt-4o-mini');    // OPENROUTER_API_KEY

// Or construct a provider directly via the registry
const custom = LLMProviderRegistry.create('openai', {
  apiKey: process.env.OPENAI_API_KEY,
  defaultModel: 'gpt-4o-mini',
});
```

تحتاج البادئة `google/` إلى الحزمة الاختيارية `@ai-sdk/google` (`^1.2.0` مع
`ai` 4، و`^3.0.0` مع `ai` 6، و`^4.0.0` مع `ai` 7) وتقرأ
`GOOGLE_GENERATIVE_AI_API_KEY`، وهو المتغير نفسه الذي تستخدمه `@ai-sdk/google`.

### Vendors بدون بادئة

البادئة التي لا يعرفها الـ SDK تفشل بالخطأ
[`LOUSHO_PROVIDER_UNKNOWN`](/ar/errors#lousho_provider_unknown). الخطأ الإملائي القريب
(`anthopic/...`) يحصل على اقتراح "did you mean"؛ وأي vendor آخر تظهر له الطرق التي
يمكنك الوصول إليه بها رغم ذلك:

- `openrouter/<vendor>/<model>`: يخدم OpenRouter أغلب الـ vendors بمفتاح واحد
  `OPENROUTER_API_KEY` (مثال `openrouter/mistralai/mistral-large`؛ قد تختلف أسماء الـ
  vendors لدى OpenRouter عن أسمائها في AI SDK).
- `pi/<vendor>/<model>`، إذا كان pi يخدم هذا الـ vendor (`xai`، `groq`، `mistral`،
  `deepseek`، `amazon-bedrock`، `azure`، ...)؛ راجع [الـ provider `pi`](#الـ-provider-pi).
- حزمة AI SDK الخاصة بالـ vendor نفسه مع
  [`fromAiSdk()`](#أي-model-من-ai-sdk-fromaisdk)، مثال
  `createAgent({ provider: fromAiSdk(mistral('mistral-large-latest')) })`.

## اختيار الـ provider في `createAgent()`

يأخذ `createAgent()` واحدًا فقط مما يلي:

1. **`model: 'provider/model'`** - يُحلّ باستخدام `resolveProvider()`؛ ويأتي المفتاح
   من متغير البيئة المعتاد للـ provider (راجع
   [بيانات اعتماد الـ providers](/ar/configuration#بيانات-اعتماد-الـ-providers)).
2. **`provider: <LLMProvider>`** - provider كتبته أنت، أو built-in مضبوط،
   أو mock. ويمكنك أن تمرّر معه `model` (id مجرّد مثل `'gpt-4o'`): فيصبح هو
   model هذا الـ agent ويتقدّم على الـ default الخاص بالـ provider.
3. **لا شيء** - يُحلّ من البيئة: `LOUSHO_MODEL` (string بصيغة
   `provider/model`) إذا كان مضبوطًا، وإلا فأول ما يوجد من `OPENAI_API_KEY` و
   `ANTHROPIC_API_KEY` و`OPENROUTER_API_KEY` و`OLLAMA_BASE_URL`. وإذا لم
   يوجد أيٌّ منها، يرمي خطأً يعدّد الحلول.

```ts
import { createAgent, createMockProvider, resolveProvider } from 'lousho';

const fromString = createAgent({ model: 'anthropic/claude-sonnet-5-5' });
const fromInstance = createAgent({ provider: resolveProvider('openai/gpt-4o-mini'), model: 'gpt-4o' });
const offline = createAgent({ provider: createMockProvider({ responses: ['Hi! How can I help?'] }) });
```

تخبرك أخطاء الإعداد الخاطئ بكيفية إصلاحها: المفتاح الناقص يسمّي المتغير،
والبادئة المجهولة تعدّد البادئات المدعومة وتقترح الأقرب، والـ peer package
الناقصة تطبع أمر `npm install` الصحيح بالضبط.

### Retry ونماذج fallback

يعيد `createAgent()` محاولة الاستدعاء الفاشل للـ model (rate limit،
timeout، خطأ شبكة، 5xx) مرتين افتراضيًا. وإذا ضبطت `fallbackModels` ينتقل
إلى الـ model التالي عندما يظل الاستدعاء فاشلًا:

```ts
import { createAgent } from 'lousho';

const agent = createAgent({
  model: 'openai/gpt-4o-mini',
  retry: { maxRetries: 3 }, // or false
  fallbackModels: ['anthropic/claude-haiku-4-5', 'openrouter/meta-llama/llama-3.3-70b-instruct'],
});
```

يُحلّ string الـ `model` وكل fallback وتُعطَّل الـ retries المدمجة في `ai`،
فيبقى `retry` هو طبقة الـ retry الوحيدة. ويُغلَّف instance الـ provider
الـ built-in والـ provider المبني بـ `fromAiSdk()` بالطريقة نفسها (باستخدام
`maxRetries` الخاص بهما، والافتراضي 2، عندما لا يكون `retry` مضبوطًا)، ثم تُعطَّل
الـ retries الخاصة بـ `ai` فيهما (`retry: false` يرسل كل استدعاء مرة واحدة). أما أي
instance `provider` آخر فلا يُغلَّف إلا إذا ضبطت `retry`. والخطوة المبثوثة التي
تفشل قبل أي نص أو tool call (بعد reasoning فقط) تُعاد محاولتها أيضًا.
يُصدر `agent.stream()` أحداث `provider.retry` و`provider.fallback`. التفاصيل في
[Provider retries وfallback](/ar/configuration#الـ-retry-والـ-fallback-عند-الـ-provider).

## أي model يعمل؟

بالترتيب: `settings.model` الخاص بالـ agent (يُضبط باستخدام
`AgentBuilder.setSettings({ model })`، أو باستخدام `model` بجانب `provider` في
`createAgent()`)، ثم الـ model الذي بُني عليه الـ provider
(`resolveProvider('openai/gpt-4o-mini')`، أو `provider.model` في spec، أو
`defaultModel`)، ثم الـ default المدمج في الـ provider. لا يُطبَّق الـ default
الأخير إلا عندما لا يضبط أي شيء model — فالـ model الذي ضبطته أنت لا
تتجاوزه أبدًا قيمة hard-coded.

## إدخال multimodal

يكون `Message.content` إما string أو قائمة parts: `{ type: 'text', text }`،
و`{ type: 'image', image, mimeType? }` (رابط `http(s)`، أو `data:` URL، أو
الـ bytes نفسها في `Uint8Array`) و`{ type: 'file', data, mimeType, filename? }`.
تأخذ `agent.send()` و`agent.stream()` و`session.send()` / `stream()` و`t.send()` في
الـ evals و`send()` الخاصة بالـ React hook كلها `AgentInput`: string، أو
قائمة parts (تُرسل كرسالة `user` واحدة) أو `Message[]` (تُمرَّر كما هي؛
ويُضاف الـ system prompt الخاص بالـ agent في بدايتها ما لم تكن القائمة تبدأ به
أصلًا، لذا يمكنك إعادة إرسال `result.messages` ومعها رسالة user جديدة).
إرسال parts عبر `createAgent()`:

```ts
import { readFileSync } from 'node:fs';
import { createAgent } from 'lousho';

const agent = createAgent({ instructions: 'Describe images briefly.', model: 'openai/gpt-4o-mini' });

// Parts become one user message.
const answer = await agent.send([
  { type: 'text', text: 'What is in these pictures?' },
  { type: 'image', image: 'https://example.com/cat.png' },
  { type: 'image', image: new Uint8Array(readFileSync('dog.png')), mimeType: 'image/png' },
]);
console.log(answer.text);
```

تُمرَّر الـ `Message[]` كما هي؛ وتُرجع `textOf()` الـ parts النصية من الرسالة:

```ts
import { createAgent, textOf, type Message } from 'lousho';

const agent = createAgent({ instructions: 'Describe images briefly.', model: 'openai/gpt-4o-mini' });
const messages: Message[] = [
  {
    role: 'user',
    content: [
      { type: 'text', text: 'What is in this picture?' },
      { type: 'image', image: 'https://example.com/cat.png' },
    ],
  },
];

const result = await agent.send(messages);
console.log(textOf(messages[0]), '->', result.text);
```

- **الصور** تصل إلى الـ model داخل رسائل `user` مع كل الـ built-in providers
  (مع Anthropic وOllama تنزّل حزمة `ai` رابط الصورة أولًا؛ ويرسل `pi`
  `data:` URLs والـ bytes فقط - يتحوّل رابط `http(s)` إلى ملاحظة نصية مع تحذير
  يظهر مرة واحدة). اختر model يدعم vision: يتجاهل Ollama الصور مع
  model نصي فقط، ويرفضها OpenRouter له.
- **الملفات** (`{ type: 'file', data, mimeType }`) تُرسل كـ parts من نوع
  `file` لأنواع الوسائط التالية، حسب الـ provider والإصدار الـ major من `ai`:

  | Provider | `ai` 4 | `ai` 6 / 7 |
  | -------- | ------ | ---------- |
  | `openai` | لا شيء | `application/pdf` |
  | `anthropic` | لا شيء | `application/pdf`، `text/plain` |
  | `google` | لا شيء | `application/pdf`، `text/plain` |
  | `openrouter` | لا شيء | `application/pdf` |
  | `ollama` | لا شيء | لا شيء |
  | `pi` | لا شيء (دائمًا ملاحظة نصية) | لا شيء (دائمًا ملاحظة نصية؛ ليس لدى pi أي file part) |

  أي file part آخر يرفض الاستدعاء بالخطأ
  [`LOUSHO_UNSUPPORTED_CONTENT`](/ar/errors#lousho_unsupported_content)
  قبل إرسال أي شيء، لذا لا يجيب الـ model أبدًا بدون الملف (وتحت
  `withFallback()` ينتقل الاستدعاء إلى الـ provider التالي). وإذا أردت ملاحظة نصية
  في مكانه بدلًا من ذلك (`[file report.pdf (application/pdf) not sent]`، مع تحذير
  واحد لكل media type)، فاضبط في إعداد الـ provider
  `unsupportedFiles: 'text-note'` (ويأخذ `fromAiSdk()` الخيار نفسه). على
  `ai` 4 يشمل نطاق `@ai-sdk/*` المقبول حزم 0.0.x التي لا تدعم file parts،
  لذا يكون كل ملف غير مدعوم هناك. ولا يزال الـ provider `pi` يرسل كل file part
  كملاحظة نصية مع تحذير يظهر مرة واحدة. وإذا كتبت subclass لـ provider
  يقبل الـ model الخاص به أنواعًا أكثر، فتجاوز
  `protected fileMediaTypes(): readonly string[]` لتعدادها، أو اضبط
  `protected readonly acceptsFileParts = true` لإرسال كل الأنواع.
- تُرسل رسائل `system` و`assistant` و`tool` بأجزائها النصية.
- كل ما يقرأ نص الرسائل يستخدم `textOf()`: `estimateTokens()` (يُحسب كل
  image أو file part بقيمة ثابتة هي 1,000 token)، والـ compaction،
  وcassettes الخاصة بـ `recordReplay()` (تخزّن النص وdigest لكل صورة أو
  ملف، أو رابطه) و`mockModel()`. يخزّن `FileSessionStore` الـ bytes بصيغة
  base64 (`{ "$bytes": "..." }`) ويُعيدها `Uint8Array` عند التحميل؛
  ويفعل `SqliteStore` (للـ sessions والـ checkpoints) الشيء نفسه.

#### متقدم: executor API

يأخذ `AgentExecutor.execute()` الرسائل نفسها في `input` (راجع [executor API](/ar/executor-api)):

```ts
import { AgentBuilder, AgentExecutor } from 'lousho/executor';
import { resolveProvider, type Message } from 'lousho';

const agent = AgentBuilder.create().setName('vision').setPrompt('Describe images briefly.').build();
const input: Message[] = [
  {
    role: 'user',
    content: [
      { type: 'text', text: 'What is in this picture?' },
      { type: 'image', image: 'https://example.com/cat.png' },
    ],
  },
];

const result = await AgentExecutor.execute({ agent, input, provider: resolveProvider('openai/gpt-4o-mini') });
console.log(result.text);
```

## Provider classes

| Export | الوصف |
| ------ | ----------- |
| `resolveProvider('p/model')` | يبني provider حقيقيًا من credentials البيئة. |
| `LLMProviderRegistry` | registry يحتوي على factories للـ providers: `create(type, config)`، `register(type, factory)`، `has(type)`. |
| `OpenAIProvider`, `AnthropicProvider`, `GoogleProvider`, `OllamaProvider`, `OpenRouterProvider`, `PiProvider` | كلاسات الـ providers. راجع [examples/openrouter](https://github.com/LinuxDevil/lousho/blob/main/examples/openrouter) لميزات OpenRouter الخاصة. `PiProvider` هو الـ adapter الخاص بـ `pi/...` أدناه. |
| `createMockProvider()`, `MockLLMProvider` | ردود جاهزة للعروض التجريبية؛ يحاكي tool call عندما تسمّي الرسالة tool. |
| `mockModel(script)` | provider يعمل بسكربت للاختبارات ويتحقق من التسلسل (من `/testing`)؛ راجع [Testing](/ar/testing). |
| `withRetry()`, `withFallback()` | يعيد محاولة الفشل المؤقت مع backoff وينتقل إلى الـ provider التالي؛ راجع [Provider retries وfallback](/ar/configuration#الـ-retry-والـ-fallback-عند-الـ-provider). |
| `fromAiSdk(model, options?)` | أي `LanguageModel` من AI SDK (Google، Bedrock، Azure، Mistral، الـ Gateway، ...) كـ provider؛ راجع [أدناه](#أي-model-من-ai-sdk-fromaisdk). |

إذا كان لديك backend آخر، فتحقق أولًا مما إذا كانت له provider package في AI SDK:
إذا كانت موجودة، فغلّف الـ model الخاص بها باستخدام `fromAiSdk()` (أدناه). وإلا
فنفّذ الـ interface `LLMProvider` (`name` و`generate()` و`stream()` و
`supportsTools()` و`supportsStreaming()` و`getModels()`، واختياريًا
`defaultModel`) ومرّر الـ instance بوصفه `provider`، أو سجّل factory باستخدام
`LLMProviderRegistry.register(name, factory)`؛ وبعد ذلك يعمل الاسم المسجّل
في string الـ model (`model: 'name/model-id'`)، ويستلم الـ factory
`defaultModel` ويقرأ الـ credentials الخاصة به بنفسه. يمكن للـ factory أن يأخذ
نوع config خاصًا به، وهو interface يوسّع `LLMProviderConfig` (مثال `BedrockConfig`
الذي يحتوي على `region`):
`register('bedrock', (config: BedrockConfig) => new BedrockProvider(config))`،
ثم `LLMProviderRegistry.create('bedrock', { region: 'eu-west-1' })`.
الاسم الـ built-in (`'openai'`، `'anthropic'`، `'google'`، `'openrouter'`، `'ollama'`، `'pi'`،
`'mock'`) يأخذ نوع الـ config الخاص بذلك الـ provider (`BuiltinProviderConfigs`)، لذا يكون
`create('openai', { baseUrl: '...' })` خطأً في الأنواع (type error)؛ وإذا سجّلت factory
خاصًا بك تحت اسم built-in، فمرّر نوع الـ config الخاص به:
`create<MyOpenAIConfig>('openai', ...)`.

### مهلة الـ request

خيار `timeout` (بالـ ms) في الـ built-in providers هو أطول مدة انتظار حتى يبدأ
رد الـ model، وبين أي chunkين منه. الاستدعاء الذي ينتظر أكثر من ذلك يفشل بـ
`TimeoutError` قابل لإعادة المحاولة (`compacted.category: 'timeout'`)، و
يعيد `retry` محاولته. ولا يقطع أبدًا ردًا لا يزال يُبث. الافتراضي
10 دقائق؛ و`0` أو `Infinity` يعطّله.

تُطبَّق المهلة على كل محاولة، والمحاولة التي انتهت مهلتها تُعاد محاولتها
(فالاتصال المعلّق غالبًا مؤقت)، لذا يفشل الـ provider الذي لا يرد أبدًا بعد
مدة تصل إلى `timeout` × (`maxRetries` + 1) إضافةً إلى الـ backoff: نحو 30 دقيقة
بالقيم الافتراضية (10 دقائق، وإعادتا محاولة). والـ stream الذي يتعلّق بعد أن أرسل
نصًا لا تُعاد محاولته، فيفشل بعد `timeout` واحد. إذا أردته أن يفشل أسرع، فخفّض
`timeout` أو `retry.maxRetries`.

```ts
import { OpenAIProvider } from 'lousho';

const provider = new OpenAIProvider({ apiKey: process.env.OPENAI_API_KEY!, timeout: 60_000 });
```

### تخزين ردود OpenAI (`store`)

على Responses API (الـ `api` الافتراضي، على `ai` 6/7)، يرسل `OpenAIProvider`
`store: false`، لذا لا تحتفظ OpenAI بالاستدعاءات على الخادم: يرسل الـ SDK
الـ transcript كاملًا في كل استدعاء ولا يرجع أبدًا إلى رد مخزّن.
مرّر `store: true` إذا أردت أن تخزّنها OpenAI (لسجلات الـ dashboard لديها أو
للـ evals). ويُتجاهَل `store` مع `api: 'chat'`.

```ts
import { OpenAIProvider } from 'lousho';

const provider = new OpenAIProvider({ apiKey: process.env.OPENAI_API_KEY!, store: true });
```

### Models محلية بطيئة: `fetch` مخصّص

تأخذ `OpenAIProvider` و`AnthropicProvider` و`OpenRouterProvider` و
`OllamaProvider` خيار `fetch` تمر عبره استدعاءات الـ model الخاصة بها.
يستسلم الـ `fetch` المدمج في Node مع الرد الذي تستغرق headers الخاصة به أكثر من 300
ثانية (`Headers Timeout Error`)، وهذا قد يحدث مع model محلي كبير في
توليد طويل بدون streaming. يصنّف الـ SDK هذا الفشل كـ `timeout` قابل
لإعادة المحاولة، لكن كل retry يبدأ التوليد من الصفر، لذا من الأفضل رفع الحد
بدلًا من ذلك. ثبّت `undici` ومرّر الـ `Agent` الخاص به بوصفه dispatcher:

```ts
import { Agent } from 'undici';
import { createAgent, OpenAIProvider } from 'lousho';

// Wait up to 15 minutes for the response headers and between body chunks.
const dispatcher = new Agent({ headersTimeout: 15 * 60_000, bodyTimeout: 15 * 60_000 });

const agent = createAgent({
  provider: new OpenAIProvider({
    apiKey: 'lm-studio',
    baseURL: 'http://localhost:1234/v1',
    defaultModel: 'qwen3-32b',
    fetch: (input, init) => fetch(input, { ...init, dispatcher } as RequestInit),
    timeout: 15 * 60_000, // the provider's own limit (default 10 minutes) too
  }),
  retry: { maxRetries: 2 },
});
```

### `fetch` مخصّص للـ proxies والاختبارات

إلى جانب المهل الأطول، `fetch` هو المكان الذي تركّب فيه proxy الشركة، أو تسجّل
كل request، أو تحقن أعطالًا في الاختبارات. تأخذه `OpenAIProvider` و
`AnthropicProvider` و`OpenRouterProvider` و`OllamaProvider` كلها
بالطريقة نفسها، وتستخدمه `OpenRouterProvider` و`OllamaProvider` أيضًا
لـ requests كتالوج الـ models. تغلّف معالجة الأخطاء وتعديلات الـ request لديها
الدالة الخاصة بك، لذا يُصنَّف الفشل الذي تُرجعه منها كأنه آتٍ من الشبكة
الحقيقية:

```ts
import { OpenRouterProvider } from 'lousho';

let failures = 1;
const provider = new OpenRouterProvider({
  apiKey: 'test-key',
  // Fail the first request with a 503, then pass through (to exercise retries).
  fetch: async (input, init) =>
    failures-- > 0 ? new Response('upstream down', { status: 503 }) : fetch(input, init),
});
```

### أي model من AI SDK: `fromAiSdk()`

تحوّل `fromAiSdk(model)` أي language model من provider package في AI SDK
إلى `LLMProvider`، لذا لا تضطر إلى كتابة adapter بنفسك:

```ts
import { createOpenAI } from '@ai-sdk/openai';
import { createAgent, fromAiSdk } from 'lousho';

const openai = createOpenAI({ apiKey: process.env.OPENAI_API_KEY });
const agent = createAgent({
  provider: fromAiSdk(openai.chat('gpt-4o-mini'), { fileMediaTypes: ['application/pdf'] }),
  instructions: 'You are a helpful assistant.',
});
```

يعمل الشيء نفسه مع `@ai-sdk/google` (`google('gemini-2.5-flash')`)
و`@ai-sdk/amazon-bedrock` و`@ai-sdk/azure` و`@ai-sdk/mistral` والـ AI
Gateway (`gateway('openai/gpt-4o')` من `ai` 7 أو `@ai-sdk/gateway`). تمر
الاستدعاءات عبر نسخة `ai` المثبّتة لديك، لذا ثبّت الإصدار الـ major المناسب لها من
حزمة الـ provider (راجع [إصدارات Vercel AI SDK](#إصدارات-vercel-ai-sdk)).

| الخيار | الافتراضي | الوصف |
| ------ | ------- | ----------- |
| `name` | حقل `provider` في الـ model، وإلا `'ai-sdk'` | اسم الـ provider في الـ events والـ spans والتحذيرات. |
| `fileMediaTypes` | `[]` | أنواع الوسائط التي تُرسل كـ parts من نوع `file`. تُرسل الصور دائمًا. |
| `unsupportedFiles` | `'error'` | أي file part آخر: يرفض الاستدعاء بالخطأ `LOUSHO_UNSUPPORTED_CONTENT` (`'error'`)، أو يرسل ملاحظة نصية في مكانه (`'text-note'`). |
| `replaysReasoning` | `false` | يعيد إرسال بلوكات الـ reasoning الموقّعة في turns الـ assistant (models من Anthropic). |
| `maxRetries` | `0` (الاستدعاء المباشر)، `2` (تحت `createAgent()`) | عندما تستدعيه مباشرة، هي الـ retries الخاصة بـ AI SDK لكل استدعاء. وتحت `createAgent()` بدون `retry`، هي retries الـ `withRetry()` الذي يُغلَّف به الـ provider. |

يقدّم الـ provider الـ model الواحد الذي يغلّفه فقط، مع tools وstreaming
مفعّلين، ويترك إعدادات الـ reasoning للـ model الذي بنيته أنت (خيار
`reasoning` بدون mapping). كل حالة مما يلي ترمي `LOUSHO_CONFIG_INVALID`:

- string يحتوي على model id (`fromAiSdk('openai/gpt-4o')`): مرّر بدلًا منه الـ model الذي
  تُرجعه دالة الـ provider؛
- model مبني لإصدار major آخر من `ai` غير المثبّت لديك (model
  `specificationVersion: 'v1'` مع `ai` 6 / 7، أو model أحدث مع
  `ai` 4)؛
- run بـ `model` id مختلف عن المغلَّف (داخل الـ run يكون هذا سببًا للخطأ
  `LOUSHO_PROVIDER_REQUEST_FAILED`): غلّف كل model باستخدام `fromAiSdk()`
  وادمجها باستخدام `withFallback()`.

تنتقل الـ tools المكتوبة لـ AI SDK (`tool({ ... })`) باستخدام `fromAiSdkTools()`؛ راجع
[الانتقال من AI SDK](/ar/migrating-from-ai-sdk#الـ-tools-fromaisdktools).

### الـ provider `pi`

يمرّر `pi/<pi-provider>/<model>` الاستدعاء عبر
[`@earendil-works/pi-ai`](https://www.npmjs.com/package/@earendil-works/pi-ai)
(المحرك الذي يعمل عليه `pi-coding-agent`)، وهو peer اختياري لا يحتاج حزمة
`ai`:

```bash
npm install @earendil-works/pi-ai@^1.0.3
```

```ts
import { createAgent } from 'lousho';

// OpenRouter's `openai/gpt-4o-mini`, through pi's openrouter adapter:
const agent = createAgent({ model: 'pi/openrouter/openai/gpt-4o-mini' });
```

الجزء الذي يلي `pi/` هو **pi provider** (`openrouter`، `anthropic`،
`openai`، `google`، ...)؛ والباقي هو id الـ model في الـ catalog حرفيًا،
بما في ذلك الشرطات المائلة. الـ credentials لكل provider متداخل: يقرأ pi متغير
البيئة المعتاد لكلٍّ منها (`OPENROUTER_API_KEY` و`ANTHROPIC_API_KEY` و...)،
لذا لا ترى مواصفة `pi/anthropic/...` مفتاح OpenRouter أبدًا. يجهّز `lousho init
--provider pi` القيمة `pi/openrouter/...` كافتراضي. إذا كان مفتاح الـ provider
المتداخل ناقصًا، يفشل الاستدعاء بالخطأ `LOUSHO_PROVIDER_MISSING_API_KEY` الذي يسمّي
المتغير، وإذا كانت `@earendil-works/pi-ai` ناقصة يفشل بالخطأ
`MissingPeerDependencyError` المعتاد.

ما يُحوَّل في كل استدعاء:

- الرسائل: تذهب `system` إلى `systemPrompt` الخاص بـ pi،
  وتبقى `user`/`assistant`/`tool` في مكانها؛ وتصبح بلوكات `reasoning` في الـ
  assistant أجزاء thinking، ويربط `toolCallId` في رسالة `tool` الرسالة
  بالـ call الخاص بها؛
- الـ tools: تُرسل `parameters` بصيغة JSON Schema - تُحوَّل مدخلات raw JSON Schema
  وzod 3 وzod 4 وStandard Schema مرة واحدة وتُحفظ في الـ cache؛
- الـ streams: تصبح أحداث `text_delta`/`thinking_delta`/`toolcall_*`/`done`/`error`
  الخاصة بـ pi هي نفس الـ chunks `text-delta`/`reasoning-*`/`tool-call`/
  `finish`/`error` التي تُصدرها providers الـ `ai`، لذا لا تتغيّر أحداث `agent.stream()`
  و`result.usage`؛
- الـ usage والتكلفة: يدخل usage الخاص بـ pi لكل استدعاء (بما فيه `cacheRead`)
  في مجموع الـ run، وتسجّل أسعار الـ catalog تكلفة الـ model في
  `usage.costUsd` الخاص بالـ run؛
- الـ retries: يُثبَّت `maxRetries` الخاص بـ pi نفسه على وضع التعطيل -
  ويبقى `retry`/`fallbackModels` طبقة الـ retry الوحيدة، مثل كل built-in.

تحقن `PiProviderConfig.models` مُدخلات في الـ catalog (الـ faux provider
الخاص بـ pi، أو catalog خاص) قبل القائمة المدمجة. لا يعمل `pi` إلا على Node:
يرفض الـ target `cloudflare-worker` مواصفات `pi/...`، ويستبدل الـ bundle
الحزمة بـ shim مكتوب.

## السيرفرات المحلية والمتوافقة مع OpenAI

LM Studio، و`/v1` الخاص بـ Ollama، وvLLM، و`llama-server` الخاص بـ llama.cpp، والـ APIs
المستضافة المتوافقة مع OpenAI (Groq، DeepSeek، Together، ...) كلها تتحدث
wire format الخاص بـ OpenAI. وجّه `OpenAIProvider` إلى رابط `/v1` الخاص بالخادم واختر
الـ API الذي ينفّذه باستخدام `api`:

```ts
import { createAgent, OpenAIProvider } from 'lousho';

const agent = createAgent({
  provider: new OpenAIProvider({
    name: 'openai',
    baseURL: 'http://localhost:1234/v1', // LM Studio
    apiKey: 'any', // local servers ignore the key, but one is required
    api: 'chat', // POST /v1/chat/completions
    defaultModel: 'qwen3-8b',
  }),
  compaction: { contextWindow: 8_192 }, // the window the model is loaded with
  instructions: 'You are a helpful assistant.',
});
```

| السيرفر | الـ Base URL | الـ API |
| ------ | -------- | --- |
| LM Studio | `http://localhost:1234/v1` | `'chat'` أو `'responses'` |
| Ollama | `http://localhost:11434/v1` | `'chat'` (أو استخدم الـ provider الأصلي `ollama/<model>`) |
| vLLM (`vllm serve`) | `http://localhost:8000/v1` | `'chat'` |
| llama.cpp (`llama-server`) | `http://localhost:8080/v1` | `'chat'` |

- قيمة `api` الافتراضية هي `'responses'` (`POST /v1/responses`، الذي يقدّمه
  api.openai.com). أغلب السيرفرات المتوافقة تنفّذ Chat Completions فقط، وعندها
  يفشل الاستدعاء بـ 404، لذا اضبط `api: 'chat'`. مع `'chat'` تُرفض الـ hosted tools
  المدمجة (`webSearch()`، `codeInterpreter()`، `fileSearch()`)، لأنها
  tools خاصة بـ Responses API؛ أما `hostedTool()` فيمر بشكل عادي، و
  يرسل `reasoning` الـ effort فقط (بدون `summary`).
- المفتاح وهمي: يحتاج الـ provider إلى `apiKey` غير فارغ، والسيرفرات المحلية
  تتجاهله.
- المخرجات المنظَّمة: لا يفرض `/v1/responses` في LM Studio الـ JSON
  schema، لذا يتبعه الـ model من الـ prompt فقط. استخدم `api: 'chat'`، الذي
  يرسل الـ schema بوصفه `response_format`.
- اضبط الـ context window. لا يعرف الـ model registry الـ models المحلية، لذا
  يفترض الـ compaction قيمة `128_000` token ويحذّر مرة واحدة. مرّر
  `compaction: { contextWindow }`، أو استدعِ
  `registerModel({ id, provider: 'openai', contextWindow })` مرة واحدة (راجع
  [الـ models المحلية وغير المعروفة](/ar/compaction#الـmodels-المحلية-وغير-المعروفة)).

**الـ string `openai/<model>` مع `OPENAI_BASE_URL`.** يمرّر `OpenAIProvider`
`OPENAI_BASE_URL` إلى `@ai-sdk/openai` عندما لا يكون `baseURL` مضبوطًا (على كل
إصدار major، بما في ذلك خط 1.x الذي يُقرَن مع `ai` 4)، لذا فإن `createAgent({ model: 'openai/qwen3-8b' })` مع
`OPENAI_BASE_URL=http://localhost:1234/v1` ومفتاح وهمي `OPENAI_API_KEY=any`
يستدعي الخادم المحلي بدون أي تغيير في الكود. يستخدم هذا المسار Responses
API ما لم تضبط `LOUSHO_OPENAI_API=chat` أيضًا، الذي يختار Chat Completions
لكل `OpenAIProvider` ليس فيه `api` صريح (وهذا ما يحتاجه vLLM وllama.cpp و
`/v1` الخاص بـ Ollama).

**أي model من AI SDK.** يغلّف `fromAiSdk()` model Chat Completions مبنيًا باستخدام
`@ai-sdk/openai` مباشرة (أو `@ai-sdk/openai-compatible`، إذا كنت تستخدمها):

```ts
import { createOpenAI } from '@ai-sdk/openai';
import { createAgent, fromAiSdk } from 'lousho';

const local = createOpenAI({ baseURL: 'http://localhost:8080/v1', apiKey: 'any' });
const agent = createAgent({ provider: fromAiSdk(local.chat('qwen3-8b')), instructions: 'You are a helpful assistant.' });
```

يعرض `npx lousho doctor` قيمة `OPENAI_BASE_URL` عندما تكون مضبوطة، و
يستدعي `npx lousho doctor --ping` المسار `GET <base>/models` على كل provider
مضبوط لكي يتأكد من أن الخادم يرد.

## إصدارات Vercel AI SDK

كل built-in provider باستثناء `pi` هو adapter فوق Vercel AI SDK (`ai`). ما
يعمل على كل إصدار major اليوم:

| `ai` | `generate()` | `stream()` | ملاحظات |
| ---- | ------------ | ---------- | ----- |
| v4 (`^4.3.19`) | نعم | نعم | كل ما في هذه الوثائق. |
| v6 (`^6.0.0`), v7 (`^7.0.0`) | نعم، عبر طبقة توافق | نعم، عبر الطبقة نفسها | يحتاج Ollama إلى zod 4 مثبّتًا (أدناه). |

تقبل نطاقات الـ peer الإصدارات الـ major الثلاثة. اقرن كل واحد منها بحزم الـ provider
المناسبة له:

| `ai` | `@ai-sdk/openai`، `@ai-sdk/anthropic` | `@ai-sdk/google` | حزمة Ollama |
| ---- | ------------------------------------- | ---------------- | -------------- |
| `^4.3.19` | `^0.0.42` أو `^1.0.0` | `^1.0.0` | `ollama-ai-provider@^1.2.0` |
| `^6.0.0` | `^3.0.0` | `^3.0.0` | `ollama-ai-provider-v2@^3.0.0` |
| `^7.0.0` | `^4.0.0` | `^4.0.0` | `ollama-ai-provider-v2@^4.0.0` |

يسمّي تلميح التثبيت لحزمة provider ناقصة و`lousho doctor` الإصدار
المناسب لنسخة `ai` لديك، وينبّهك `lousho doctor` إلى الاقتران غير
المتوافق (مثال `ai` 7 مع `@ai-sdk/openai` 1.x). لا يتحقق من الاقتران إلا `lousho doctor` و
`fromAiSdk()`: أما الـ built-in provider (string `model`) فيحمّل
أي إصدار major مثبّت بدون التحقق منه، لذا شغّل `lousho doctor` لكي تكتشف عدم
التوافق قبل أول استدعاء. يحمّل `OllamaProvider`
`ollama-ai-provider` على `ai` 4 و`ollama-ai-provider-v2` على `ai` 6/7؛
ولحزمة v2 peer dependency على zod 4، والـ SDK يقبله، لذا ثبّت zod 4
معها (مشاريع zod 3 تستخدم Ollama مع `ai` 4). يجهّز `lousho init` الإصدار `ai@^7.0.0`
مع `@ai-sdk/*@^4.0.0` لـ OpenAI وAnthropic وGoogle وOpenRouter، و`ai@^7.0.0` مع
`ollama-ai-provider-v2@^4.0.0` وzod 4 لـ Ollama.

يثبّت الـ CI ويختبر `ai` 4 و6 و7، كلٌّ منها مع zod 3 وzod 4 (ستة اقترانات؛
اقتران `ai` 4 مع zod 4 هو الوحيد الذي لا تعلنه حزم الـ providers)، مع
`ollama-ai-provider-v2` الحقيقية على `ai` 6 و7 في الـ jobs الخاصة بـ zod 4.

يستخدم OpenRouter حزمة `@ai-sdk/openai` موجّهة إلى الـ base URL الخاص بـ
OpenRouter. بدءًا من `@ai-sdk/openai` 2، يستهدف الاستدعاء الافتراضي `openai(modelId)`
الـ Responses API، الذي لا ينفّذه OpenRouter، لذا يطلب `OpenRouterProvider`
model الـ Chat Completions (`provider.chat(modelId)`) على كل إصدار major؛
ويعمل على `ai` 4 و6 و7 مع الاقتران المذكور أعلاه.

يأخذ `OllamaProvider` الـ base URL الخاص بالخادم (`baseURL`، أو
`OLLAMA_BASE_URL` مع `resolveProvider()`) ويُلحق `/api` بالـ host المجرّد،
لأن حزمتي Ollama كلتيهما تتوقعانه بهذا الشكل: `http://host:11434`
و`http://host:11434/` يصبحان `http://host:11434/api`. أما الرابط المنتهي
أصلًا بـ `/api` (أو `/api/`)، أو الذي يحتوي على أي مسار آخر مثل prefix لـ reverse
proxy، فيُستخدم كما هو.

يختار `generate()` و`stream()` شكل الاستدعاء حسب وحدة `ai` المثبّتة: عندما
تُصدّر `stepCountIs` (v5 وأحدث)، يُرسل الـ request بشكل v6/v7 وتُقرأ النتيجة
وتُعاد إلى `GenerateResult` أو `StreamResult` نفسها:

- تصبح الرسائل `ModelMessage`s: تصبح وسائط الـ tool call هي `input` الخاص
  به، وتصبح نتيجة الـ tool هي `output` (`json` أو `text`، و`error-json` أو
  `error-text` عندما يفشل الـ tool)، ويصبح `mimeType` في الـ image أو file part
  هو `mediaType`. تبقى رسائل الـ system في مكانها
  (`allowSystemInMessages`).
- يُرسل `maxTokens` باسم `maxOutputTokens`، والخطوة الواحدة بصيغة `stopWhen:
  stepCountIs(1)`، والـ tools بصيغة `inputSchema` (zod schema كما هو، وJSON
  Schema عبر `jsonSchema()`) بدون `execute`، و`responseFormat` بصيغة
  `output` في وضع JSON لا يمسّ نص الرد.
- يأتي الـ usage من `inputTokens` / `outputTokens` / `totalTokens`، مع
  `cachedInputTokens` من `inputTokenDetails.cacheReadTokens`
  و`reasoningTokens` من `outputTokenDetails.reasoningTokens`.
- يقرأ `stream()` قيمة `fullStream` الخاصة بالـ SDK على أيٍّ من الإصدارين
  ويحوّلها إلى الـ chunks نفسها: `text-delta` (في v6/v7 الحقل `text`، وفي v4
  `textDelta`)، و`tool-call` (الـ call الكامل الذي يرسله v6/v7 بعد
  `tool-input-start`/`-delta`/`-end`، أو call يُجمَّع من ذلك الـ input عندما
  لا يرسل الـ model واحدًا)، و`finish` مع سبب الإنهاء الذي يعطيه الـ SDK
  والـ usage المذكور أعلاه (في v6/v7 الحقل `totalUsage`). يجعل جزء `error`
  الـ stream يُرفض بخطئه، على v4 أيضًا (كان v4 ينهي stream كهذا بسبب
  إنهاء `error`)، ويرفضه جزء `abort` بسبب الـ signal. تُبلَّغ تغيّرات الـ
  reasoning الجزئية كـ chunks من نوع `reasoning-delta` وتظهر
  كأحداث `reasoning.*` (راجع [Reasoning](/ar/reasoning)).

على v6/v7 يجب أن يأتي الـ model من provider package خاصة بالإصدار الـ major نفسه
(الجدول أعلاه)؛ فحزم `0.0.x`/`1.x` تنتج models يرفضها `ai` v7. تُرسل الـ image
parts كـ `file` parts بـ media type للصور (وهو الشكل الذي يقبله `ai` v6/v7
للصور، لذا لا يظهر تحذير deprecation). `ai` v5 غير مدعوم:
يُفشل `lousho doctor` الإصدار `ai` 5 المثبّت مع تلميح للترقية (انتقل إلى `ai` 6
أو 7 والإصدار الـ major المطابق من `@ai-sdk/*`).

## أين يعمل كل provider

تعمل كل الـ providers على Node. يدعم الـ deploy target `cloudflare-worker`
`mock` و`openai` و`anthropic` و`openrouter` (المفتاح من binding باسم
`OPENROUTER_API_KEY`)؛ أما `google` و`ollama` و`pi` فتحتاج إلى target `node-server` أو
`docker` (راجع [Cloudflare Workers](/ar/cloudflare-workers)).
