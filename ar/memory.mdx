الـ [session](/ar/sessions) (الجلسة) تتذكّر محادثة واحدة. الذاكرة هي اللي الـ agent يحتفظ فيه **عبر** المحادثات: تفضيلات المستخدم، حقائق انقالت له، قرارات اتخذت الأسبوع الماضي. تعطي الـ agent واحد أو أكثر من **memory slots** بأسماء؛ كل slot يخزّن عناصر نصية قصيرة عن طريق provider، ومفتاحها **scope**: ذاكرة وحدة للجميع، أو وحدة لكل session، أو وحدة لكل مستخدم.

لكل slot، `createAgent({ memory })` تسوّي شيئين:

1. **تسترجع** في بداية كل run (`send()`، `stream()`، كل turn في session): في أول model call في الـ run، تنحط أحدث العناصر في الـ system prompt داخل بلوك `<memory name="...">`. البلوك يظل لآخر الـ run وما ينحفظ في الـ transcript تبع الـ session.
2. تعطي الـ model أداة **`remember_<name>`** (input `{ text }`) يخزّن فيها عنصر جديد، وأداة **`recall_<name>`** (input `{ query?, limit? }`) يبحث فيها في الـ slot، الأحدث أول.

## الذاكرة في الكود

البادئة `vendor/` في اسم الـ model هي اللي تختار الـ provider؛ مع OpenRouter استخدم `openrouter/<vendor>/<model>` (مثال: `openrouter/openai/gpt-4o-mini`).

```ts
import { createAgent, defineMemory, fileMemory } from '@lousho/build-ai-agent';

const preferences = defineMemory({
  name: 'preferences',
  description: "the user's preferences: language, tone, tools they like",
  scope: 'session',
  provider: fileMemory({ dir: './.lousho/memory' }),
});

const agent = createAgent({
  model: 'openai/gpt-4o-mini',
  instructions: 'You are a helpful assistant. Save lasting preferences with remember_preferences.',
  memory: [preferences],
});

await agent.session({ id: 'user-42' }).send('Please always answer in French.');
// Later, in a new conversation with the same id, the preference is in the system prompt:
const { text } = await agent.session({ id: 'user-42' }).send('What is the capital of Japan?');
```

الـ system prompt تبع المحادثة الثانية ينتهي بـ:

```text
<memory name="preferences">
- The user wants answers in French.
</memory>
```

## Scopes

الـ run يقرأ ويكتب عناصر الـ scope key تبعه:

| `scope` | الـ scope key | ذاكرة وحدة لكل |
|---|---|---|
| `'global'` | `'global'` | agent (تتشاركها كل الـ runs) |
| `'session'` | `'session:<id>'`: الـ `id` في `agent.session({ id })`، أو `sessionId` الممرَّر لـ `send()` / `stream()` | session |
| `({ sessionId, metadata }) => string \| undefined` | اللي الدالة ترجعه | أي شي تعمل عليه key، مثل مستخدم |

دالة الـ scope تشوف `sessionId` تبع الـ run والـ `metadata` اللي اتمرّرت لـ `send()` / `stream()`، فينفعك تحتفظ بذاكرة وحدة لكل مستخدم عبر كل الـ sessions تبعته:

```ts
import { createAgent, defineMemory, inMemoryMemory } from '@lousho/build-ai-agent';
import { mockModel } from '@lousho/build-ai-agent/testing';

const userFacts = defineMemory({
  name: 'user_facts',
  scope: ({ metadata }) => (typeof metadata?.userId === 'string' ? `user:${metadata.userId}` : undefined),
  provider: inMemoryMemory(),
});

const agent = createAgent({ provider: mockModel(['Hello!']), memory: [userFacts] });
await agent.send('Hi again!', { metadata: { userId: 'u-42' } });
```

لما الـ run ما يكون إله scope key (slot من نوع `'session'` في `send()` بدون `sessionId`، أو دالة scope ترجع `undefined`)، الـ slot يكون مطفي لذلك الـ run: ما ينسترجع شي وما تنعرض الـ tools تبعتها.

دالة الـ scope تشوف كمان `principal`، وهو المتصل اللي auth المسار تحقّق منه، وأأمن تعمل عليه key من `metadata` لأن المتصل يقدر يرسل أي metadata: شوف [قراءة الـ principal في الـ run](/ar/auth#قراءة-الـ-principal-في-الـ-run).

## خيارات الإعداد

`defineMemory(options)` ترجع `MemorySlot`:

| الخيار | النوع | الافتراضي | الوصف |
|---|---|---|---|
| `name` | `string` | إلزامي | من 1 إلى 55 حرف من `A-Za-z0-9_-`؛ الأداتان `remember_<name>` و`recall_<name>`. فريد لكل agent. |
| `description` | `string` | ما فيه | اللي الـ slot تحتويه؛ ينضاف لوصف الـ tools. |
| `scope` | `'global' \| 'session' \| (ctx) => string \| undefined` | إلزامي | شوف [Scopes](#scopes). |
| `provider` | `MemoryProvider` | إلزامي | مكان تخزين العناصر: `inMemoryMemory()`، `fileMemory({ dir })`، أو واحد من عندك. |
| `recall.onSessionStart` | `boolean` | `true` | استرجاع للـ system prompt في أول model call لكل run. |
| `recall.maxItems` | `number` | `10` | أقصى عدد عناصر تُسترجع للـ prompt، والـ `limit` الافتراضي لـ `recall_<name>`. |
| `recall.query` | `'last-input' \| 'none'` | `'none'` | `'last-input'` تمرّر آخر رسالة مستخدم في الـ run للـ provider كـ `query`، عشان يسترجع العناصر ذات الصلة بدل الأحدث. |
| `expose.remember` | `boolean` | `true` | يعرض tool الـ `remember_<name>`. |
| `expose.recall` | `boolean` | `true` | يعرض tool الـ `recall_<name>`. |

الـ slot اللي فيها `expose: { remember: false }` read-only للـ model: إنت تملاها من الكود بـ `provider.add(scopeKey, { text })`.

## Providers

| Provider | التخزين |
|---|---|
| `inMemoryMemory({ maxItems? })` | هالعملية؛ يضيع عند إعادة التشغيل. للاختبارات والديمو. |
| `fileMemory({ dir, maxItems? })` | ملف JSON لكل scope key في `dir` (المفتاح URI-encoded)، والكتابة atomic. |
| `kvMemory({ binding?, maxItems? })` | KV namespace في Cloudflare Workers — الـ binding `AGENT_CHECKPOINTS` أو اللي تسمّيه `binding` — لملفات `memory/` تبع agent directory من نوع cloudflare-worker؛ مربوط بـ `env` لكل request. شوف [Cloudflare Workers](/ar/cloudflare-workers#build-and-deploy). |
| `sqliteMemory(store, { maxItems? })` (من `/sqlite`) | جدول `memory_items` في ملف `SqliteStore` تبع الـ agent، مصفوفة JSON لكل scope key. |
| `inMemoryVectorMemory({ embedder, maxItems?, minScore? })` | هالعملية؛ يسترجع بالمعنى. شوف [Semantic recall](#semantic-recall). |
| `sqliteVectorMemory(store, { embedder, maxItems?, minScore? })` (من `/sqlite`) | جدول `memory_vectors` في ملف `SqliteStore` تبع الـ agent؛ يسترجع بالمعنى. |

أول ثلاثة providers يحتفظون بحد أقصى `maxItems` عنصر لكل scope key (الافتراضي 1000؛ إذا زدت عنصر ينحذف الأقدم)، ويطابقون الـ `query` بالكلمات المفتاحية: العنصر يطابق إذا فيه كلمة من كلمات الـ query بطول 3 أحرف أو أكثر، بدون تمييز بين الأحرف الكبيرة والصغيرة.

### SQLite

مرّر نفس الـ `SqliteStore` للـ agent وللـ provider، فتتشارك الـ sessions والـ checkpoints والذاكرة ملف قاعدة بيانات واحد. الملف الموجود يكسب الجدول لما ينفتح. خلّي الـ store مفتوح ما دام الـ agent شغّال. ولو تبي الاسترجاع بالمعنى بدل الكلمات المفتاحية، استخدم `sqliteVectorMemory()`: شوف [Semantic recall](#semantic-recall).

```ts
import { createAgent, defineMemory } from '@lousho/build-ai-agent';
import { SqliteStore, sqliteMemory } from '@lousho/build-ai-agent/sqlite';

const store = new SqliteStore('./.lousho/agent.db');
const notes = defineMemory({ name: 'notes', scope: 'global', provider: sqliteMemory(store) });
const agent = createAgent({ model: 'openai/gpt-4o-mini', store, memory: [notes] });
```

لو تبي store مستضاف أو ترتيب من عندك، نفّذ `MemoryProvider`:

```ts
import type { MemoryItem, MemoryProvider } from '@lousho/build-ai-agent';

const items = new Map<string, MemoryItem[]>();
const myProvider: MemoryProvider = {
  async list(scopeKey, { limit, query } = {}) {
    // Newest first; use `query` to rank (e.g. by embedding similarity).
    return (items.get(scopeKey) ?? []).slice(0, limit);
  },
  async add(scopeKey, { text, metadata }) {
    const item: MemoryItem = { id: crypto.randomUUID(), text, createdAt: new Date().toISOString(), metadata };
    items.set(scopeKey, [item, ...(items.get(scopeKey) ?? [])]);
    return item;
  },
  async remove(scopeKey, id) {
    items.set(scopeKey, (items.get(scopeKey) ?? []).filter((item) => item.id !== id));
  },
};
```

## اختبار الذاكرة

مع [`mockModel`](/ar/testing)، تحقّق من الـ system prompt تبع أول request، وحرّك الـ tools بـ tool calls مكتوبة في السكربت:

```ts
import { createAgent, defineMemory, inMemoryMemory } from '@lousho/build-ai-agent';
import { mockModel } from '@lousho/build-ai-agent/testing';

const store = inMemoryMemory();
await store.add('global', { text: 'The user likes tea.' });
const notes = defineMemory({ name: 'notes', scope: 'global', provider: store });

const model = mockModel([{ toolCalls: [{ name: 'remember_notes', args: { text: 'Lives in Oslo.' } }] }, 'Noted.']);
await createAgent({ provider: model, memory: [notes] }).send('I moved to Oslo.');

console.log(model.calls[0].messages[0].content); // ends with <memory name="notes">\n- The user likes tea.\n</memory>
console.log((await store.list('global')).map((item) => item.text)); // ['Lives in Oslo.', 'The user likes tea.']
```

## القيود

- الاسترجاع وtools الذاكرة يشتغلون على runs الـ agent نفسه، مو على الـ sub-agents تبعته. ولما `agent.approvals.resolve()` يكمّل run بعد وقفة approval، البلوك المسترجَع يظل في الـ prompt بس tools الذاكرة ما تنعرض لبقية ذلك الـ run.
- مجلد `memory/` في الـ agent directory جزء من الـ agent: شوف [Agent directories](/ar/agent-directories#memory).

## Semantic recall

الـ providers بالكلمات المفتاحية اللي فوق ما تلاقي عنصر إلا إذا شارك الـ query كلمة. الـ vector provider يلاقيه بالمعنى: يحوّل كل عنصر وكل query إلى vector بـ embedding model، ويرتّب العناصر حسب cosine similarity — فسؤال "what does the user like to eat?" يلاقي "Sam is vegetarian".

الـ **embedder** (`EmbeddingProvider`) يحوّل النصوص إلى vectors. و`aiSdkEmbedder(model)` تغلّف أي embedding model في AI SDK، عن طريق `embedMany` من حزمة `ai` المثبّتة (4 أو 6 أو 7؛ ابنِ الـ model بحزمة الـ provider اللي تلائم الـ major version تبع `ai` عندك، نفس قاعدة نماذج اللغة). وما تضيف dependency: `ai` أصلًا peer dependency، وحزمة الـ provider من عندك.

```ts
import { createAgent, defineMemory, aiSdkEmbedder, inMemoryVectorMemory } from '@lousho/build-ai-agent';
import { createOpenAI } from '@ai-sdk/openai';

const openai = createOpenAI({ apiKey: process.env.OPENAI_API_KEY });

const facts = defineMemory({
  name: 'facts',
  scope: 'global',
  provider: inMemoryVectorMemory({
    embedder: aiSdkEmbedder(openai.embedding('text-embedding-3-small')),
    minScore: 0.3,
  }),
  recall: { query: 'last-input' },
});
const agent = createAgent({ model: 'openai/gpt-4o-mini', memory: [facts] });
```

في اثنين من الـ providers يرتّبون بالمعنى، بنفس الخيارات:

- `inMemoryVectorMemory({ embedder, maxItems?, minScore? })` يحتفظ بالعناصر في هالعملية.
- `sqliteVectorMemory(store, { embedder, maxItems?, minScore? })` (من `@lousho/build-ai-agent/sqlite`) يحتفظ بها في ملف SQLite تبع الـ agent، في جدول `memory_vectors` ينضاف للملف الموجود لما ينفتح. والـ vectors تعيش بعد إعادة التشغيل.

مع query، `list()` تعمل لها embed، وتعطي عناصر ذلك الـ scope key درجات، وترمي اللي تحت `minScore` (cosine similarity، الافتراضي `0.2`)، وترتّب حسب الدرجة (الأحدث أول عند التعادل) وترجع `limit` منها. كل عنصر راجع إله درجته في `metadata.score`. وبدون query، أو مع query فاضية، تسرد الأحدث أول مثل أي provider. وقتها وصف tool الـ `recall_<name>` يصير "Search the "&lt;name>" memory by meaning, most relevant first."

لو تبي الاسترجاع بالمعنى في بداية الـ run، اضبط `recall: { query: 'last-input' }` على الـ slot: آخر رسالة مستخدم في الـ run تصير هي الـ query، فبلوك `<memory>` يحتوي العناصر الأقرب لها بدل الأحدث. وبدونها، البلوك يحتوي أحدث `maxItems` عنصر، والترتيب الوحيد يصير عن طريق tool الـ `recall_<name>`.

العناصر ما تنقارن إلا داخل الـ scope key تبعها، وبس إذا نفس الـ embedder (الـ `id` تبعه) هو اللي سوّاها. الـ `id` ينخزّن مع كل vector: بعد ما تغيّر الـ model أو الـ `id`، العناصر القديمة تتخطّى عند الترتيب (بس تظل تطلع في السرد بدون query) لحد ما تنادي `await provider.reindex()`، اللي يعيد لها الـ embed على دفعات ويرجع كم وحدة غيّر. و`reindex(scopeKey)` تعالج scope key واحد بس.

`hashEmbedder()` من `@lousho/build-ai-agent/testing` هو embedder حتمي يشتغل offline للاختبارات: bag من جذوع الكلمات بعد hash، فالنصوص اللي تتشارك كلمات تطلع قريبة من بعض. هو مو نموذج دلالي وما يعرف إن "vegetarian" و"eat" لهم علاقة ببعض.

```ts
import { inMemoryVectorMemory } from '@lousho/build-ai-agent';
import { hashEmbedder } from '@lousho/build-ai-agent/testing';

const memory = inMemoryVectorMemory({ embedder: hashEmbedder() });
await memory.add('global', { text: 'Sam is vegetarian' });
await memory.add('global', { text: 'The office is in Oslo' });

const [best] = await memory.list('global', { query: 'vegetarian food' });
console.log(best.text, best.metadata?.score); // Sam is vegetarian, a score of about 0.5
```

التكاليف والحدود:

- كل `add` يسوّي embedding call وحدة وكل query كذلك، فكتابات الذاكرة والاسترجاع يكلّفون model calls ويضيفون latency. الـ embedding call الفاشلة ما تخزّن شي؛ وtool الـ `remember_<name>` تبلّغ الـ model بالخطأ.
- التقييم brute force في JavaScript على عناصر scope key واحد، بدون vector index. انتبه لـ `maxItems` (الافتراضي 5000 لكل scope key؛ عنصر زيادة يحذف الأقدم): آلاف العناصر لكل key عادي، مئات الآلاف لا.
- `fileMemory()` و`sqliteMemory()` وstore الـ Cloudflare KV ما يدعمون vectors. اكتب `MemoryProvider` من عندك لقاعدة بيانات vectors.
