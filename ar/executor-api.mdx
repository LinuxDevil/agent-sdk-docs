`createAgent()` هي نقطة الدخول الموصى بها (راجع [البدء السريع](/ar/quickstart)). هذه الصفحة للكود الذي يحتاج الخيارات الأدنى مستوى التي لا تأخذها `createAgent()`. ولنقل كود executor موجود إلى `createAgent()`، راجع [الانتقال إلى createAgent()](/ar/migrating-to-create-agent).

## `AgentBuilder` و`AgentExecutor`

`createAgent()` مجرد wrapper بسيط فوق `AgentBuilder` والـ static `AgentExecutor.execute()`. استخدمهما مباشرة فقط لما لا تقبله `createAgent()`: `temperature` و`maxTokens` (`exporter` و`captureContent` و`redactContent` خيارات في `createAgent()` أيضًا). و`createAgent()` تأخذ أصلًا `maxSteps` و`limits` و`onEvent` وapprovals و`store` (checkpoints) و`hooks` و`compaction`. `AgentExecutor` واجهة static، أي لا يوجد `new AgentExecutor()`.

```ts
import {
  AgentBuilder,
  AgentExecutor,
} from 'lousho/executor';
import { createMockProvider } from 'lousho';

const agent = AgentBuilder.create()
  .setName('Customer Support Agent')
  .setPrompt('You are a helpful customer support assistant.')
  .build();

const events: string[] = [];
const result = await AgentExecutor.execute({
  agent,
  input: 'My order arrived damaged.',
  provider: createMockProvider({ responses: ["I'm sorry to hear that - what's your order number?"] }),
  maxSteps: 5,
  onAgentEvent: (event) => events.push(event.type),
});

console.log(result.text);
console.log(result.usage.totalTokens, result.finishReason, result.steps);
console.log(events); // includes 'run.start' and 'run.done'
```

## مشاركة الـ tools عبر `ToolRegistry`

*متقدم: `ToolRegistry`.* لمشاركة tools بين عدة agents أو لتسجيل `ToolDescriptor` خام، استخدم `registry.register(tool)` إذا كان الـ tool معرَّفًا، أو `registry.register(name, descriptor)` إذا كان لديك descriptor. ثم مرّر الـ registry كـ `toolRegistry` إلى `AgentExecutor.execute()`. راجع [Tools](/ar/tools#متقدم-toolregistry) لمثال كامل.

## خيارات `AgentExecutor.execute()`

`AgentExecutor` static: استدعِ `AgentExecutor.execute(options)`. المطلوب فقط `agent` و`input` و`provider`. وأكثر الخيارات استخدامًا:

| الخيار                                  | الوصف                                                           |
| --------------------------------------- | --------------------------------------------------------------- |
| `agent`                                 | قيمة `AgentConfig`، تبنيها عادة بـ `AgentBuilder`.              |
| `input`                                 | رسالة مستخدم كنص، أو محادثة `Message[]`.                         |
| `provider`                              | الـ `LLMProvider` الذي يولّد الرد.                               |
| `toolRegistry`                          | `ToolRegistry` يضم الـ tools التي تشير إليها إعدادات الـ agent.   |
| `maxSteps`                              | الحد الأعلى لخطوات الـ LLM والـ tools.                           |
| `limits`                                | ميزانيات الـ run من tokens وتكلفة ووقت وخطوات؛ راجع [الميزانيات](/ar/configuration#الميزانيات). |
| `temperature`, `maxTokens`              | معاملات التوليد.                                                |
| `onAgentEvent`                          | listener لأحداث `AgentEvent` الخاصة بالـ run (`run.start`، `tool.start`، `run.done`، وغيرها)؛ راجع [Streaming](/ar/streaming#الاستماع-بدون-iterating). |
| `streamModelCalls`                      | مع listener، يعمل stream لكل model call فيصل النص على عدة أحداث `text.delta` (الافتراضي `true`)؛ `false` يولّد كل خطوة كاملة بحدث `text.delta` واحد. `stream()` يتجاهله. |
| `approvalStore`, `sessionId`            | approvals بأسلوب human-in-the-loop (راجع `resumeAfterApproval()`). |
| `checkpointStore`                       | يحفظ checkpoints التنفيذ ويكمّل منها.                            |
| `exporter`                              | `TraceExporter` للـ tracing spans (conventions الخاصة بـ OpenTelemetry GenAI، راجع [observability](/ar/observability)). |
| `captureContent`, `redactContent`       | تسجيل محتوى الرسائل والـ tools في سمات الـ span `gen_ai.*` (opt-in) / حذف سمات المحتوى الـ deprecated. |
| `onLLMRequest`, `onLLMResponse`, `onToolCall`, `onToolResult` | hooks للـ observability.                  |
| `toolSearch`                            | يضبط [tool search](/ar/tool-search) للـ tools المعلَّمة بـ `deferLoading`، أو `false` لإرسال كل tool في كل call. |

الاستدعاء يُرجع نتيجة من نوع `ExecutionResult`: `{ text, reasoning?, messages, toolCalls,
usage, stepUsage?, finishReason, steps, approvalId?, object?, outputError?,
backgroundTasks?, budget?, guardrail?, agentName? }`.
