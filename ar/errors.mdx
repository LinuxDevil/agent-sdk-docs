- `code`: نص ثابت بصيغة `LOUSHO_<AREA>_<NAME>`. فرّع عليه، لا على نص الرسالة — الرسالة ممكن تصير أوضح مع الوقت.
- `hint`: جملة واحدة عن طريقة الحل.
- `docs`: رابط لقسم هذا الكود في الصفحة.

الرسالة تنتهي بنفس المعلومات في سطر لحاله، فالخطأ اللي يطلع بدون `catch` يقول لك إيش تسوّي:

```text
ConfigurationError: createAgent: no model configured. Do one of the following: (1) pass a model: ...
[LOUSHO_CONFIG_MISSING_PROVIDER] Pass a model string such as createAgent({ model: 'openai/gpt-4.1-mini' }), a provider instance, or set LOUSHO_MODEL or a provider API key. (https://github.com/LinuxDevil/agent-sdk/blob/main/docs/errors.md#lousho_config_missing_provider)
```

الـ run اللي ينرفض (`send()`، أو `result` تبع `stream()`، أو دورة session، أو `AgentExecutor.execute()`) يحط اللي صرفه على الخطأ في `error.usage`، وهو `RunUsage` مثل `result.usage` (ومعه الـ sub-agents تبعه)، فما تضيع tokens وتكلفة الـ run اللي فشل. ينضبط على أي خطأ ينرفض فيه الـ run — `SDKError` أو `PropagatingToolError` أو خطأ من عندك — إلا إذا كان للخطأ خاصية `usage` خاصة فيه، وهو غير enumerable (تسجيل الخطأ أو تحويله لـ JSON ما يتغيّر). وما يكون موجود إذا الـ run فشل قبل ما يبدأ.

```ts
import { createAgent, type RunUsage } from 'lousho';

try {
  await createAgent({ provider }).send('Go');
} catch (error) {
  const spent = (error as { usage?: RunUsage }).usage;
  if (spent) console.error(`failed after ${spent.modelCalls} model calls, $${spent.costUsd ?? '?'}`);
  throw error;
}
```

`error.detail` هو الرسالة بدون هالسطر. أخطاء الـ tools والـ providers (`ToolExecutionError` و`LLMProviderError` و`TimeoutError` و`RateLimitError`) تخلي رسالتها مثل ما هي، لأن الـ model يشوفها كنتيجة tool أو خطأ provider مضغوط؛ بس `toString()` لسّا تضيف السطر.

الاستثناءات شوية subclasses مسماة من `Error` بدون `code`، مبقاة عادية عن قصد: `PropagatingToolError` والـ subclasses تبعتها (الـ tool يرميها عشان يوقف الـ run)، و`WorkspaceError` (عملية على الـ workspace رُفضت أو فشلت — الـ model يشوفها كخطأ tool)، و`McpToolError` (أداة MCP محمّلة والسيرفر تبعها رجّع `isError`؛ برضه خطأ tool)، و`AuthError` (مدخل من `lousho/auth` يرفض الطلب بـ 401 أو 403 تبعه)، و`CronExpressionError` (`parseCronExpression()` اللي `defineSchedule()` تغلّفها كـ `LOUSHO_SCHEDULE_INVALID`)، و`DecryptionError` (`EncryptionUtils` و`DTOEncryptionFilter`).

أما `CassetteMismatchError` (replay في `recordReplay`؛ راجع [الاختبار](/ar/testing#ماذا-يفحص-الـ-replay)) فليست منها: هي `SDKError` بكود [`LOUSHO_CASSETTE_INVALID`](#lousho_cassette_invalid) وحقلين `.cassette` / `.callNumber`.

```ts
import { createAgent, SDKError } from 'lousho';

try {
  await createAgent({ provider, instructions: 'Be brief.' }).send('hi');
} catch (error) {
  if (error instanceof SDKError && error.code === 'LOUSHO_SESSION_AWAITING_APPROVAL') {
    console.log(error.hint, error.docs);
  } else {
    throw error;
  }
}
```

`ERROR_CODES` (مصدَّر) يربط كل كود بالـ hint تبعه. في test يحافظ على تطابقه مع الأكواد المستخدمة في الكود ومع الأقسام أدناه. وفي test ثاني يفشل لو كود جديد في الـ SDK رمى `new Error(...)` حرفي بدل `SDKError`؛ المواضع القليلة الباقية داخلية ومسردة في `src/utils/plainErrors.test.ts` مع سبب كل واحد.

لو بتبدأ من العَرَض بدل الكود، راجع [استكشاف الأخطاء](/ar/troubleshooting).

## الإعدادات

### LOUSHO_CONFIG_INVALID

**المعنى:** خيار أو معامل فيه قيمة الـ SDK ما يقدر يستخدمها. هذا الكود الافتراضي لـ `ConfigurationError`؛ و`error.field` يسمّي الخيار إذا كان معروف.

**الحل:** غيّر الخيار اللي تسمّيه الرسالة.

**مثال:** `withFallback([])` يرمي "withFallback() needs at least one provider". ونفس الكود مع `new NodeWorkspace({ root })` لما الـ root مفقود أو مو مجلد، ومع اسم tool مكرر في `ToolRegistry`، وقيمة `toolConcurrency` غلط، و`serveMcp()` بدون `name`، و`lousho studio` بدون ملفات Agent Forge.

### LOUSHO_CONFIG_MISSING_PROVIDER

**المعنى:** ما في model يشتغل: `createAgent()` وصل بدون `model` ولا `provider` وما لقى شيء في البيئة، أو `AgentExecutor.execute()` / `stream()` انستدعوا بدون `provider`.

**الحل:** مرّر `model: 'openai/gpt-4.1-mini'` (أي `<provider>/<model>`)، أو مرّر `provider` instance، أو اضبط `LOUSHO_MODEL` أو مفتاح provider مثل `OPENAI_API_KEY`. البادئة `vendor/` في اسم الـ model هي اللي تختار الـ provider؛ ومع OpenRouter استخدم `openrouter/<vendor>/<model>` (مثلاً `openrouter/openai/gpt-4.1-mini`). راجع [المزوّدون](/ar/providers).

**مثال:** `createAgent({ instructions: 'x' })` بدون أي env var للـ provider.

### LOUSHO_CONFIG_MISSING_AGENT

**المعنى:** `AgentExecutor.execute()` / `stream()` انستدعوا بدون `agent`.

**الحل:** مرّر الـ agent، مثلاً `AgentBuilder.create().setName('a').build()`، أو استخدم `createAgent()` اللي ما يحتاج كائن agent منفصل.

**مثال:** `AgentExecutor.execute({ input: 'hi', provider })`.

### LOUSHO_CONFIG_MISSING_INPUT

**المعنى:** `AgentExecutor.execute()` / `stream()` انستدعوا بدون `input`.

**الحل:** مرّر رسالة المستخدم كنص أو `Message[]`.

**مثال:** `AgentExecutor.execute({ agent, provider })`.

### LOUSHO_CONFIG_CONFLICTING_OPTIONS

**المعنى:** مرّرت خيارين بنفس المعنى مع بعض.

**الحل:** أبقِ واحد منهم. في `createAgent()` الخيار `prompt` هو alias مُهمَل (deprecated) لـ `instructions`: أبقِ `instructions`.

**مثال:** `createAgent({ provider, instructions: 'a', prompt: 'b' })`.

### LOUSHO_CONFIG_MISSING_CHECKPOINT_STORE

**المعنى:** `send()` أو `stream()` أخذوا `sessionId`، وهذا يخلي الـ run durable (الـ run يكمل بعد ما العملية تقع)، بس الـ agent ما عنده checkpoint store (مخزن نقاط حفظ).

**الحل:** مرّر `createAgent({ store: memoryStore() })` (أو `SqliteStore`، أو `store` فيه `checkpoints`)، أو احذف `sessionId`. راجع [Durable execution](/ar/durable-execution).

**مثال:** `createAgent({ provider }).send('hi', { sessionId: 'job-1' })`.

### LOUSHO_CONFIG_RESOLVER_FAILED

**المعنى:** خيار من خيارات `createAgent()` معطى كدالة تعتمد على الـ run (`model` أو `instructions` / `prompt` أو `tools`) رمى أثناء حل إعدادات الـ run. الـ run ما بدأ أصلاً: `send()` ينرفض، و`stream()` ينتهي بحدث `error`، وسجل محادثة الـ session يبقى مثل ما هو. `error.field` يسمّي الخيار، و`error.cause` هو اللي رمته الدالة.

**الحل:** صلّح الدالة اللي تسمّيها الرسالة. راجع [الإعدادات الديناميكية](/ar/api-overview#dynamic-config).

**مثال:** `createAgent({ provider, model: ({ metadata }) => plans[metadata.plan].model })` مع خطة غير معروفة.

## الـ providers والـ peer dependencies

### LOUSHO_PROVIDER_SPEC_INVALID

**المعنى:** نص الـ model ليس بصيغة `<provider>/<model>`.

**الحل:** اكتب الجزأين، مثلاً `'openai/gpt-4.1-mini'` أو `'anthropic/claude-sonnet-4-5'`.

**مثال:** `resolveProvider('gpt-4o')`.

### LOUSHO_PROVIDER_UNKNOWN

**المعنى:** بادئة الـ provider في نص الـ model ليست من اللي يعرفها الـ SDK. الرسالة تسرد البادئات المدعومة وتقترح أقربها.

**الحل:** استخدم بادئة مدعومة (`openai` أو `anthropic` أو `google` أو `openrouter` أو `ollama` أو `pi` أو `mock`)، أو مرّر `provider` instance من عندك. ولـ vendor ما له بادئة، الرسالة تسرد الطرق الثانية: `openrouter/<vendor>/<model>`، أو `pi/<vendor>/<model>` إذا pi يخدم هذا الـ vendor، أو حزمة AI SDK تبع الـ vendor عن طريق `fromAiSdk()` (راجع [المزوّدون](/ar/providers#vendors-بدون-بادئة)).

**مثال:** `createAgent({ model: 'opnai/gpt-4o' })` يقول "Did you mean 'openai/gpt-4o'?".

### LOUSHO_PROVIDER_MISSING_API_KEY

**المعنى:** متغير البيئة اللي يحمل credentials الـ provider (`OPENAI_API_KEY` أو `ANTHROPIC_API_KEY` أو `OPENROUTER_API_KEY`) غير مضبوط.

**الحل:** اضبطه، أو مرّر provider instance مهيّأ.

**مثال:** `createAgent({ model: 'openai/gpt-4.1-mini' })` بدون `OPENAI_API_KEY`.

### LOUSHO_PROVIDER_REQUEST_FAILED

**المعنى:** استدعاء model فشل (`LLMProviderError`، وكذلك `CompactedLLMProviderError` اللي `compacted.category` تبعه تشرح السبب: `timeout` أو `context-length-exceeded` أو `quota-exceeded` أو `auth-failure` أو `unknown`؛ أما فشل `rate-limit` فله كود خاص فيه، [`LOUSHO_PROVIDER_RATE_LIMITED`](#lousho_provider_rate_limited)).
الرد المتوافق مع OpenAI اللي يبلّغ عن فشل داخل 200 (`finish_reason: "error"` من OpenRouter، أو chunk فيه `error` في نص الـ stream) يفشل كـ 502 قابل لإعادة المحاولة بدل ما يرجّع النص المقطوع.
تجاوز السياق يكون `context-length-exceeded` (غير قابل لإعادة المحاولة) مهما كانت الـ status، ومنه "exceeds the available context size" و"Context size has been exceeded" من llama.cpp / LM Studio، وسواء وصل من الطلب أو كخطأ في الـ stream. فشل الاتصال يكون `timeout` ويسمّي السبب، مثلاً `connection refused (ECONNREFUSED) at http://localhost:1234/v1/responses - is the server running?`. وإذا ما انقرى body الخطأ من الـ provider (والرسالة بس `Bad Request`)، ينضاف مقطع قصير من الـ body.

**الحل:** مع `quota-exceeded` (الـ 429 `insufficient_quota` من OpenAI، أو 402 مثل "Insufficient credits" من OpenRouter؛ غير قابل لإعادة المحاولة، لأن إعادة المحاولة ما تضيف رصيد) اشحن الحساب أو حوّل لـ provider ثاني؛ ومع `auth-failure` صلّح الـ API key؛ ومع `context-length-exceeded` قصّر المحادثة (راجع [Context compaction](/ar/compaction))؛ ومع الفشل العابر استخدم `withRetry()` / `fallbackModels` (راجع [المزوّدون](/ar/providers)).

**مثال:** رد 401 من الـ provider بمفتاح ملغي.

### LOUSHO_PROVIDER_RATE_LIMITED

**المعنى:** الـ provider قيّد معدل طلبات المستدعي: استدعاء model فشل بـ `compacted.category: 'rate-limit'` (`CompactedLLMProviderError`، وهو برضه `LLMProviderError`)، أو `RateLimitError`.

**الحل:** أعد المحاولة بعد `compacted.retryAfterMs` (`withRetry()` يسوي هذا، لحد `backoff.maxMs`؛ و`Retry-After` أطول من كذا يفشل فورًا مع ضبط `compacted.retryAfterMs`)، أو أرسل طلبات أقل.

**مثال:** رد 429 (الـ 429 `insufficient_quota` من OpenAI لما يخلص الرصيد هو `quota-exceeded`، يعني `LOUSHO_PROVIDER_REQUEST_FAILED`).

### LOUSHO_PEER_MISSING

**المعنى:** ميزة تحتاج حزمة اختيارية غير مثبتة (`MissingPeerDependencyError`، أو SDK خاص بـ provider مثل `@ai-sdk/openai`).

استدعاء model حزمة الـ provider تبعه ناقصة يفشل بهذا الكود (`CompactedLLMProviderError` الـ `cause` تبعه هو `MissingPeerDependencyError`)، مو بـ `LOUSHO_PROVIDER_REQUEST_FAILED`، والـ server routes ترسل رسالته (أمر التثبيت) للعميل بدل الرسالة العامة.

**الحل:** نفّذ أمر `npm install` اللي في الرسالة (موجود كمان في `error.installCommand`). راجع [التثبيت](/ar/installation).

**مثال:** `SubprocessSandbox` بدون `dockerode`: `npm install dockerode@^5.0.1`.

### LOUSHO_HOSTED_TOOL_UNSUPPORTED

**المعنى:** الـ agent عنده hosted tool (`webSearch()` أو `codeInterpreter()` أو `fileSearch()` أو `hostedTool()`) والـ provider تبعه ما يقدر يرسلها: إما الـ provider ما عنده hosted tools (Ollama، أو `LLMProvider` مخصص بدون `supportsHostedTool()`)، أو المثبّت `ai` 4 (الـ hosted tools تحتاج `ai` 6 أو 7)، أو حزمة الـ provider المثبّتة ما فيها هالأداة. الرسالة تسمّي الـ provider والأداة وما اللي رح يشتغل.

**الحل:** شغّل الأداة على provider وحزمة يدعمونها (راجع [Hosted tools عند الـ provider](/ar/hosted-tools))، أو احذفها من `tools` لهذا الـ provider.

**مثال:** `createAgent({ model: 'ollama/llama3.2', tools: [webSearch()] })` يرفض أول `send()` له.

### LOUSHO_UNSUPPORTED_CONTENT

**المعنى:** رسالة مستخدم فيها جزء ملف (`{ type: 'file', data, mimeType }`) الـ provider ما يقدر يرسله: نوع الوسائط تبعه مو من الأنواع اللي يرسلها الـ provider على إصدار `ai` الرئيسي عندك (راجع [المدخلات متعددة الوسائط](/ar/providers#إدخال-multimodal)). الاستدعاء ينرفض قبل ما ينرسل أي شيء، فالـ model ما يجاوب أبدًا بدون الملف. ومع `withFallback()` (أو `fallbackModels`) الـ provider اللي بعده ياخذ الاستدعاء. `agent.send()` و`agent.stream()` ينرفضوا بهذا الكود.

**الحل:** أرسل الملف لـ provider وإصدار `ai` رئيسي يقبلون نوعه (أو اذكر النوع في `fromAiSdk(model, { fileMediaTypes })`)، أو حط نص الملف في الرسالة، أو اضبط `unsupportedFiles: 'text-note'` على الـ provider عشان يرسل `[file <name> (<type>) not sent]` مكانه، مثل قبل.

**مثال:** ملف PDF منرسل لـ `new OllamaProvider({ name: 'ollama' })`.

## ملفات الـ AgentSpec

### LOUSHO_SPEC_NOT_FOUND

**المعنى:** `loadSpec()` أخذ مسار غير موجود.

**الحل:** تأكد من المسار اللي في الرسالة — غلطة كتابة، أو مجلد عمل غلط، أو spec ما أُنشئ أصلاً.

**مثال:** `loadSpec('agent.yaml')` وما في `agent.yaml` في الـ cwd.

### LOUSHO_SPEC_INVALID

**المعنى:** `loadSpec()` لقى حقول ما عدّت الـ validation. كل مشكلة تنسرد كـ `'<path>': <problem>`، زائد أي حقل top-level باين عليه غلطة كتابة، مع اقتراح.

**الحل:** صلّح كل حقل مسرد. راجع [الإعدادات](/ar/configuration).

**مثال:**

```text
loadSpec: 'agent.yaml' failed validation - 'prompt': missing required field 'prompt'; unknown field 'promt' (did you mean 'prompt'?)
```

### LOUSHO_SPEC_UNKNOWN_FIELD

**المعنى:** الـ spec صالح غير كذا، بس في حقل top-level غالبًا غلطة كتابة لحقل من حقول الـ spec، وكان رح يتجاهل. باقي الحقول المجهولة لسّا تتجاهل.

**الحل:** سمّيه بالحقل المقترح، أو احذفه.

**مثال:** `tool: [http]` يعطي "unknown field 'tool' (did you mean 'tools'?)".

### LOUSHO_SPEC_UNSUPPORTED_FORMAT

**المعنى:** امتداد ملف الـ spec ليس `.yaml` ولا `.yml` ولا `.json`.

**الحل:** سمّي الملف من جديد، أو حوّله.

**مثال:** `loadSpec('agent.toml')`.

## الأدوات

### LOUSHO_TOOL_NOT_FOUND

**المعنى:** عنصر `tools` في الـ spec يسمّي tool ليست من الأدوات المدمجة.

**الحل:** استخدم واحدة من الأدوات اللي تسردها الرسالة، أو ابنِ الـ agent بـ `createAgent({ tools: [...] })` مع أداتك. راجع [الأدوات](/ar/tools).

**مثال:** `tools: [not-a-real-tool]` في spec.

### LOUSHO_TOOL_NEEDS_CREDENTIALS

**المعنى:** الـ spec يسمّي tool (`github` أو `jira`) تحتاج credentials وملف الـ spec ما فيه حقل لها.

**الحل:** ابنِ الـ agent بـ `createAgent()` ومرّر الأداة مهيّأة، مثلاً `createGitHubTools(config)` من `lousho/integrations`.

**مثال:** `tools: [github]` في spec.

### LOUSHO_TOOL_EXECUTION_FAILED

**المعنى:** `ToolExecutionError` (أو subclass منه مثل `ToolArgumentsValidationError`). داخل الـ run الـ model يوصله كنتيجة tool والـ run يكمل.

**الحل:** افحص `error.toolName` و`error.cause`، وصلّح الأداة أو المدخلات اللي انعطت لها.

**مثال:** `execute` تبع أداة رمت. الأدوات المدمجة (`http` و`email` و`github` و`jira` و`slack` و`ask_question`) ترمي `SDKError` بهذا الكود عند فشل الاستدعاء؛ رسالتها هي نتيجة الأداة، فما يلحقها سطر `[code] hint (docs)`.

### LOUSHO_TOOL_ARGS_INVALID

**المعنى:** الـ model نادى tool بـ arguments ما تطابق الـ input schema تبعها (`ToolArgumentsValidationError`). داخل الـ run الـ model توصله المشاكل كنتيجة tool ويقدر يعيد المحاولة، فنادرًا ما ينتهي run عليها.

الـ arguments اللي مو JSON صالح (مقطوعة مثلاً) ياخذون نفس الخطأ، مع مشكلة وحدة على `(root)`: `arguments are not valid JSON: <parse error>; received: <the
text, truncated>`. الأداة ما تشتغل. قبلها تنجرّب تصليحة صغيرة: code fence من markdown حوالين النص، والفواصل الزائدة في الآخر، والـ JSON المشفّر مرتين، كلها تتصلّح إذا كانت النتيجة object JSON. والـ arguments الفاضية (`""`) تعني `{}`. وحدث `tool.start` تبع الاستدعاء يحمل `rawArgs`، النص اللي أرسله الـ model، كل ما انصلّح أو فشل الـ parse.

**الحل:** لو إنت اللي ناديت الأداة، صلّح الـ arguments اللي تسمّيها الرسالة؛ ولو الـ model ظل يغلط فيها، خلّي نص `.describe()` للحقل أوضح. `error.issues` يسرد كل مسار ومشكلته. راجع [الأدوات](/ar/tools).

**مثال:** الـ model يرسل `{ to: 42 }` لأداة حقلها `to` نص.

### LOUSHO_MCP_START_FAILED

**المعنى:** سيرفر MCP من نوع stdio (عنصر في `mcpServers` فيه `command`) ما اشتغل: الأمر ما انلقى، أو العملية طلعت أثناء مصافحة `initialize`، أو ما ردّت خلال `connectTimeoutMs` (الافتراضي 60 ثانية). الخطأ (`McpStartError`) يحمل `exitCode` (أو `signal`) و`stderr`، آخر 20 سطر كتبتها العملية هناك، والرسالة تعرض الاثنين. `connectMcp()` و`agent.ready()` (أو أول `send()`) يفشلون فيه.

**الحل:** اقرأ أسطر الـ stderr اللي في الرسالة، أو شغّل الـ `command` مع `args` تبعه بنفسك. تأكد من اسم الحزمة وإصدارها لسيرفر `npx`، ومن الـ `env` اللي يحتاجه، ومن `cwd`. ومع `stderr: 'inherit'` أو `'ignore'` ما في أسطر تنعرض. راجع [MCP](/ar/mcp-integration#استخدام-سيرفرات-mcp-داخل-agent).

**مثال:** `npx -y some-mcp-server` لحزمة مو موجودة يطلع وعلى الـ stderr سطر `npm error 404`.

### LOUSHO_MCP_CALL_FAILED

**المعنى:** استدعاء أداة MCP محمّلة فشل على مستوى البروتوكول: السيرفر طلع أو سكّر الاتصال (`MCP error -32000: Connection
closed`)، أو الطلب خلص وقته، أو السيرفر ردّ بخطأ JSON-RPC. الرسالة تسمّي الأداة مثل ما يشوفها الـ model (`<server>__<tool>`)؛ و`cause` هو خطأ MCP SDK نفسه، والـ `code` الرقمي تبعه هو كود JSON-RPC. الأداة اللي اشتغلت وبلّغت `isError: true` مو هذا الخطأ (الـ model يوصله نصها كـ `McpToolError`)، ولا طلب تسجيل دخول ([`LOUSHO_MCP_AUTH_REQUIRED`](#lousho_mcp_auth_required)) ولا الإلغاء. أثناء الـ run النتيجة خطأ tool والـ run يكمل؛ وخطوة flow فيها `retry: { maxAttempts }` تشتغل مرة ثانية، والسيرفر المتصل بـ `lazy` (الافتراضي) يعيد الاتصال في الاستدعاء اللي بعده.

**الحل:** تأكد إن السيرفر اللي تسمّيه الرسالة شغّال ويرد؛ ولسيرفر stdio، شغّل أمره بنفسك واقرأ الـ stderr تبعه. ارفع `timeoutMs` تبع السيرفر إذا الطلب خلص وقته.

**مثال:** سيرفر stdio يطيح وهو يعالج `files__read`.

## الـ approvals والـ sessions

### LOUSHO_APPROVAL_STORE_MISSING

**المعنى:** أداة عليها `needsApproval` اننادت في run من `AgentExecutor.execute()` ما عنده `approvalStore` يوقف فيه.

**الحل:** مرّر `approvalStore: new InMemoryApprovalStore()` (أو store دائم)، أو استخدم `createAgent()` اللي عنده واحد افتراضيًا. راجع [Approvals](/ar/approvals).

**مثال:** `AgentExecutor.execute({ agent, input, provider, toolRegistry })` مع أداة `needsApproval`.

### LOUSHO_APPROVAL_NOT_FOUND

**المعنى:** `resumeAfterApproval()` أو `agent.approvals.resolve()` أخذوا id ما يقابل approval معلّقة: إما مجهول أو انحسم قبل كذا.

**الحل:** احسم id من `agent.approvals.list()` (أو `approvalId` في النتيجة المتوقفة)؛ كل approval تنحسم مرة وحدة.

**مثال:** نداء `agent.approvals.resolve({ id, approved: true })` مرتين.

route الـ approvals (`POST /chat/:sessionId/approvals/:id`) يرد بهذا الكود مع `404` كمان لما الـ approval تخص session غير اللي في الـ URL.

### LOUSHO_APPROVAL_ORPHANED

**المعنى:** `agent.approvals.resolve()` (أو `streamResolve()`، أو `resumeAfterApproval()`) أخذ approval الـ run المتوقف تبعها ما عاد ينتظرها: الـ checkpoint تبع الـ run (`<id>.turn-<n>` لـ turn في session، أو checkpoint run من `send(msg, { sessionId })`) انحذف (بـ `checkpoints.delete(id)`، أو `discardPending()`، أو TTL، أو باليد) أو استبدله run أحدث تحت نفس الـ id. الأداة ما اشتغلت، والـ approval تنسحب: ما عادت تنسرد، وحسمها مرة ثانية يفشل بـ `LOUSHO_APPROVAL_NOT_FOUND`.

**الحل:** ابدأ turn جديدة في الـ session (أو run جديد) بدالها؛ ما في شيء باقي تكمّله. `SqliteStore.prune()` يحتفظ بالـ turns المتوقفة، فهذا يحتاج إن الـ checkpoint ينشال بطريقة ثانية.

**مثال:** تحذف `cust-7.turn-2` من الـ checkpoint store، وبعدين توافق على الاسترداد اللي وقفت عليه هذي الـ turn.

### LOUSHO_APPROVAL_CONFLICT

**المعنى:** `409` من route الـ approvals: طلب ثاني حسم نفس الـ approval قبلك، والتكملة تبعه لسّا شغّالة (على عملية السيرفر هذي).

**الحل:** لا تحسم مرة ثانية؛ اقرأ الـ session (`GET /chat/:sessionId`) وشوف كيف كمّلت الـ turn.

**مثال:** مشرفين يضغطون "Approve" على نفس الاسترداد بنفس اللحظة.

### LOUSHO_APPROVAL_FORBIDDEN

**المعنى:** `403` من route الـ approvals: `authorizeApproval` تبع الـ route رفض هذا المستدعي. افتراضيًا ما يقدر يحسمها إلا المستدعي اللي الـ run المتوقف يشتغل لحسابه (راجع [مصادقة الـ routes](/ar/auth#من-يقدر-يحسم-الـ-approval)).

**الحل:** احسمها كمستدعي يقبله `authorizeApproval`، أو غيّر `authorizeApproval`.

**مثال:** المستخدم `bob` يرسل قرار على approval تخص run تبع `alice`.

### LOUSHO_APPROVAL_DECISION_INVALID

**المعنى:** `400` من route الـ approvals: الـ body ما فيه لا `approved` (boolean) ولا `answer` (نص).

**الحل:** أرسل `{ "approved": true }` (أو `false`، مع `note` اختياري)، أو `{ "answer": "..." }` لتوقف `ask_question`.

**مثال:** إرسال `{ "approve": "yes" }` لـ `/chat/alice-1/approvals/ap-1`.

### LOUSHO_APPROVAL_KIND_MISMATCH

**المعنى:** `400` من route الـ approvals: انرسل `answer` لتوقف مو سؤال. توقف السؤال ياخذ `answer` — أو `approved` والجواب في `note` (و`approved: false` للرفض)؛ وتوقف الـ tool call ياخذ `approved`؛ وتوقف تسجيل الدخول يكمل لحاله أول ما المستخدم يسجّل دخوله.

**الحل:** أرسل الحقل اللي يناسب نوع التوقف؛ `GET /chat/:sessionId` يعرض `approvalKind` للتوقف المعلّق.

**مثال:** إرسال `{ "approved": true }` لتوقف ينتظر جواب الـ model على `ask_question`.

### LOUSHO_SESSION_FORBIDDEN

**المعنى:** `403` من route session: `authorizeSession` تبع الـ route رفض على هذا المستدعي الإجراء (`read` أو `chat` أو `approve`) على هذي الـ session.

**الحل:** استخدم session يملكها هذا المستدعي، أو غيّر `authorizeSession`.

**مثال:** المستخدم `bob` يقرأ `GET /chat/alice-1` اللي استخدمته `alice` أول (هذا الافتراضي لما ما يكون في `authorizeSession`)، أو `authorizeSession` ما يسمح إلا بالـ ids اللي تبدأ بـ id المستدعي.

### LOUSHO_REQUEST_FORBIDDEN

**المعنى:** `403` من route session قبل ما يشتغل: طلب POST جاي من صفحة على origin ثاني (الـ `Origin` تبعه مو origin السيرفر نفسه وما هو في `allowedOrigins`، أو المتصفح علّمه `Sec-Fetch-Site: cross-site`)، أو الـ header `Host` مو من اللي يسمح فيها السيرفر (`allowedHosts`، أو أسماء الـ loopback على `lousho dev`).

**الحل:** نادِ من origin السيرفر نفسه، أو ضيف origin الصفحة لـ `allowedOrigins` (راجع [مصادقة الـ routes](/ar/auth#الطلبات-بين-المواقع))؛ ولرفض `Host`، ضيف الاسم لـ `allowedHosts` (`--allowed-hosts` على `lousho dev`).

**مثال:** صفحة على `https://evil.example` ترسل POST لـ `/api/agent/chat` مع cookie الـ session تبع المستخدم.

### LOUSHO_REQUEST_INVALID

**المعنى:** `400` من route session: الـ body مو JSON صالح، أو ناقصه حقل يحتاجه الـ route (`POST /chat` بدون `sessionId` و`input`، أو `input` فاضي، أو `input` ما فيه رسالة `user`).

**الحل:** أرسل الحقول اللي تسمّيها رسالة الخطأ، مثلاً `{ "sessionId": "chat-1", "input": "Hello" }` (راجع [HTTP API](/ar/deployment#http-api)).

**مثال:** `POST /chat` مع `{ "sessionId": "chat-1", "input": [] }`.

### LOUSHO_UNSUPPORTED_MEDIA_TYPE

**المعنى:** `415` من route session: body الـ POST ما انرسل كـ JSON. الـ bodies من نوع form و`text/plain` مرفوضة لأن أي موقع ثاني يقدر يرسلها بدون CORS preflight.

**الحل:** أرسل `Content-Type: application/json` (`curl -H 'Content-Type:
application/json'`)، أو مرّر `requireJsonBody: false`.

**مثال:** `curl -d '{"sessionId":"a","input":"hi"}' /chat` بدون `-H` يرسل `application/x-www-form-urlencoded`.

### LOUSHO_SESSION_AWAITING_APPROVAL

**المعنى:** `SessionAwaitingApprovalError`: الـ session أو الـ run تبع `sessionId` واقف على approval (`error.approvalId`)، فما يقدر ياخذ input جديد الحين.

**الحل:** احسم الـ approval بـ `agent.approvals.resolve()` (أو `resumeAfterApproval()` مع نفس `checkpointStore`)، وبعدين ابعث مرة ثانية. راجع [Durable execution](/ar/durable-execution).

وعبر HTTP، `POST /chat` لـ session بهذي الحالة يرجّع `409` بهذا الكود مع الـ approvals اللي لازم تنحسم (`approvalId` و`approvalIds`).

**مثال:** `session.send('next')` والـ turn السابق لسّا منتظر approval.

### LOUSHO_SESSION_ID_INVALID

**المعنى:** معرّف الـ session ليس من 1 إلى 128 حرف من الحروف والأرقام و`_` و`-` (المعرّفات تصير أسماء ملفات، فـ `../` و`/` مرفوضة). أو معرّف run (`sessionId` تبع `agent.send()` / `agent.stream()`، أو id في checkpoint store) ليس من 1 إلى 200 حرف من الحروف والأرقام و`_` و`-` و`.` (وما يبدأ ولا ينتهي بـ `.`)، وهي نفس القاعدة على كل store؛ أو ينتهي بـ `.turn-<n>` أو `.paused`، وهذي مفاتيح checkpoints خاصة بالـ session (run تحت `'victim.turn-2'` كان رح يكتب في turn الـ session `victim`)، أو بـ `.fire` (claim إطلاق تبع schedule). الرسالة تقول أي القاعدتين تنطبق: id فيه `.` أو أطول من 128 حرف هو معرّف run صالح بس مو معرّف session صالح.

**الحل:** استخدم معرّف مثل `'chat-9f2c4e7a1b'`، أو اتركه ويتولّد واحد تلقائيًا. وعلى route يخدم أكثر من مستخدم، لا تخلّي الـ ids سهلة التخمين من اسم المستخدم أو رقمه (راجع [مين يقدر يستخدم session](/ar/auth#من-يقدر-يستخدم-الـ-session)).

**مثال:** `agent.session({ id: '../etc' })`، أو `agent.send(msg, { sessionId: 'chat.turn-2' })`.

### LOUSHO_SESSION_FILE_CORRUPT

**المعنى:** سجل محادثة مخزّن (ملف `FileSessionStore`، أو صف في `SqliteStore`) ليس JSON صالح أو ليس مصفوفة JSON من الرسائل، مثلاً كتابة انقطعت بالنص.

**الحل:** استعد الملف من نسخة احتياطية، أو احذفه وتبدأ الـ session من جديد: `session.clear()` يشيله.

**مثال:** `sessions/user-42.json` ومحتواه `{}`.

### LOUSHO_SESSION_BUSY

**المعنى:** ناديت `session.compact()` أو `session.clear()` أو `session.fork()` وفي turn من هالـ session شغّال أو بالطابور. ومن `send()` / `stream()`: كاتب ثاني ما يشوفه الطابور داخل العملية (عملية ثانية، أو كائن store ثاني فوق نفس البيانات) ثبّت turn وهذي الـ turn شغّالة، فهذي الـ turn ما انثبّتت (بشكل ذرّي مع store فيه `saveIf`: الذاكرة والملفات وSQLite؛ وبأفضل جهد مع KV). استدعاءات الـ tools في الـ turn اللي اشتغلت تنحفظ: الـ turn لحد نتائجها تنضاف بعد turn الكاتب الثاني. وكمان من `send()` و`resume()` و`agent.send(msg, { sessionId })` و`agent.resume()` و`approvals.resolve()`: الـ run اللي عليه checkpoint (أو turn الـ session) شغّال الحين في عملية أو replica أو كائن store ثاني، وهو ماسك الـ run lease تبعه (راجع [Durable execution](/ar/durable-execution#run-leases))؛ ما اشتغل شيء هنا، والـ approval المحسومة تبقى معلّقة. وعبر HTTP، `409` من `POST /chat`: طلب بنفس `Idempotency-Key` لسّا يشغّل الـ turn تبعه من هذي الـ session على هذا السيرفر (راجع [إعادة إرسال turn](/ar/deployment#إعادة-إرسال-turn)).

**الحل:** انتظر `send()` تبع الـ turn (أو ألغِه)، وبعدين نادِ مرة ثانية. وبعد `send()` فشل بهالشكل، أرسل مرة ثانية: الـ session تقرأ سجل المحادثة الحالي في بداية كل نداء. الـ lease اللي تركته عملية ماتت ينسحب أول ما تخلص مدته (30 ثانية، زائد لحد 30 ثانية سماح لفرق الساعات على stores الملفات وSQLite)، أو فورًا لما يكون أكيد إن العملية طلعت على نفس الـ host ونفس PID namespace. والـ run اللي علّق لحد ما فاتت مدة الـ lease تبعه يفشل بهذا الكود عند الـ checkpoint اللي بعده بدل ما يكتب فوق الـ run اللي استلم مكانه.

### LOUSHO_SESSION_TURN_PENDING

**المعنى:** ناديت `session.compact()` وفي session durable فيها turn منقطعة، والـ checkpoint تبعها مربوط بطول سجل المحادثة.

**الحل:** أكملها بـ `session.resume()` أو تخلّص منها بـ `session.discardPending()`، وبعدين نادِ مرة ثانية.

### LOUSHO_SESSION_TURN_FAILED

**المعنى:** `send()` / `stream()` في session durable لقى turn الـ session اللي ما خلصت، وآخر محاولة لها فشلت بخطأ provider ما تصلّحه إعادة المحاولة (فشل في طول السياق أو المصادقة، أو 4xx ثاني). الـ checkpoint تبع الـ turn يسجّله كـ `lastError` و`attempts`؛ والـ turn ما تنعاد.

**الحل:** تخلّص من الـ turn بـ `session.discardPending()` وأرسل مرة ثانية، أو صلّح السبب وأعد محاولتها بـ `session.resume()`.

### LOUSHO_SESSION_STREAM_UNSUPPORTED

**المعنى:** ناديت `stream()` على `AgentSession` مبنية باليد بدون runner يدعم streaming.

**الحل:** خذ الـ session من `agent.session()` اللي تقدر تعمل stream، أو نادِ `send()`.

**مثال:** `new AgentSession(run).stream('hi')`.

### LOUSHO_SESSION_STEP_NOT_FOUND

**المعنى:** `session.fork({ fromStep })` أخذت خطوة ليست عدد صحيح من 0 إلى عدد الخطوات في `session.history()`. الخطأ `ConfigurationError` (`field: 'fromStep'`) ورسالته تسرد النطاق الصحيح.

**الحل:** اختر خطوة من `session.history()`، أو `0` لو ما تبي تحتفظ بشيء.

**مثال:** `session.fork({ fromStep: 9 })` على session فيها ثلاث خطوات.

### LOUSHO_SESSION_EXISTS

**المعنى:** `session.fork({ id })` أخذت id إله سجل محادثة أصلاً في store الـ session (أو turn عليها checkpoint كان الـ fork رح يلتقطها)، أو هو نفس معرّف الـ session. الخطأ `ConfigurationError` (`field: 'id'`).

**الحل:** اختر id غير مستخدم، أو اترك `id` وينتج `<id>-fork-<n>`.

**مثال:** `session.fork({ fromStep: 1, id: session.id })`.

### LOUSHO_SESSION_FORK_UNSUPPORTED

**المعنى:** ناديت `fork()` على `AgentSession` مبنية باليد بدون الدالة اللي تنشئ sessions شقيقة.

**الحل:** خذ الـ session من `agent.session()` اللي تدعم fork.

**مثال:** `new AgentSession(run).fork({ fromStep: 0 })`.

### LOUSHO_REMOTE_UNAUTHORIZED

**المعنى:** `lousho eval --url` أو `remoteTarget()` أو sub-agent من نوع `remoteAgent()` وصلهم `401` من الـ agent المنشور: الـ bearer token مفقود أو غلط. حالة الـ eval تفشل (والـ run يكمل)؛ والـ lead model يوصله خطأ tool منظَّم. الـ token ما يدخل الرسالة أبدًا.

**الحل:** مرّر `LOUSHO_API_TOKEN` الخاصة بالنشر عبر `--token` أو متغير البيئة `LOUSHO_EVAL_TOKEN`. راجع [تشغيل الـ evals على نشر قائم](/ar/evals#تشغيل-evals-على-deployment).

**مثال:** `lousho eval --url https://agent.example.com` على نشر عليه token.

### LOUSHO_REMOTE_REQUEST_FAILED

**المعنى:** حالة eval عن بُعد (`lousho eval --url` أو `remoteTarget()`) أو مهمة `remoteAgent()` ما قدرت تشتغل: النشر ما كان واصل، أو ردّ بحالة مو 2xx، أو الطلب انلغى، أو بث الأحداث انقطع أو انقصّ (بدون `run.done`). ومهمة `remoteAgent()` اللي الـ run البعيد تبعها ينتهي بخطأ تفشل فيه كمان، والرسالة تقول "the remote run ended in an error". الـ lead model يوصله كخطأ tool منظَّم؛ والـ bearer token ما يكون جزء منه أبدًا.

**الحل:** اقرأ الرسالة (تسمّي الـ url، ومع الـ sub-agent تسمّي معرّف الـ session البعيدة)؛ تأكد من الـ URL ومن `GET <url>/health` ومن سجلات النشر.

**مثال:** `lousho eval --url http://localhost:1` ولا شيء يستمع على المنفذ.

### LOUSHO_SUBAGENT_TASK_NOT_FOUND

**المعنى:** نداء `task` طلب يستأنف أو يعمل fork لـ `taskId` هالـ session الرئيسية ما عندها محادثة له (ما بدأ أبدًا، أو بدأ في session رئيسية ثانية أو run ثاني، أو ما خلّص)، أو يخص sub-agent ثاني. الـ lead model يوصله كخطأ tool منظَّم.

**الحل:** استخدم `taskId` من نتيجة `task` سابقة لنفس الـ session الرئيسية، ومع نفس `agent`؛ أو اترك `taskId` وتبدأ مهمة جديدة. راجع [الـ sub-agents](/ar/sub-agents#تكملة-مهمة).

**مثال:** `task({ agent: 'researcher', taskId: 'task_7', prompt })` والـ session ما عندها غير `task_1`.

### LOUSHO_SUBAGENT_TASK_BUSY

**المعنى:** نداء `task` طلب يستأنف أو يعمل fork لمهمة الـ sub-agent تبعها لسّا شغّال، مثلاً مهمة في الخلفية ما خلصت.

**الحل:** انتظرها بـ `agent_await` (أو وقّفها بـ `agent_cancel`)، وبعدين تابعها.

**مثال:** `task({ agent: 'researcher', taskId: 'task_1', prompt })` مباشرة بعد بدء `task_1` بـ `background: true`.

### LOUSHO_CHECKPOINT_NOT_FOUND

**المعنى:** `AgentExecutor.fork()` أو `agent.fork()` انطلب منهم خطوة ليست موجودة في سجل الـ checkpoints تبع الـ session: الـ session مجهولة، أو الخطوة ما انوصلت أبدًا، أو مدخلاتها انحذفت لما تجاوزت `historyLimit` تبع الـ store. الرسالة تسرد الخطوات المحفوظة.

**الحل:** اعمل fork عند وحدة من الخطوات المسردة، أو ارفع `historyLimit` في الـ store. راجع [Durable execution](/ar/durable-execution#fork-و-replay).

**مثال:** `agent.fork('job-1', { fromStep: 9 })` بعد run من 3 خطوات.

### LOUSHO_CHECKPOINT_CORRUPT

**المعنى:** checkpoint مخزّن ما ينقرأ: مو JSON صالح أو مو checkpoint، وعادةً كتابة انقطعت بسبب crash أو انقطاع كهرباء على store ما عنده كتابة durable. `send()` و`resume()` و`agent.resume()` يفشلون عليه، و`agent.pending()` يسرد الـ run كـ `'in-progress'` وهذا الكود في `lastError` تبعه (`retryable: false`).

**الحل:** تخلّص منه: `session.discardPending()` (أو `session.clear()`) لـ turn session، و`checkpointStore.delete(id)` لـ run. الـ run المنقطع ما يقدر يُستأنف.

**مثال:** ملف `checkpoints/chat.turn-2.json` حجمه 0 بايت بقى بعد انقطاع الكهرباء.

### LOUSHO_AGENT_DRIFT

**المعنى:** run متوقف مؤقتًا أو منقطع استأنفه agent مختلف عن اللي حفظه، و`onAgentDrift` قيمتها `'error'`. الرسالة تسمّي اللي تغيّر: الـ model، أو tools انضافت أو انحذفت أو تغيّر الـ input schema تبعها، أو الـ instructions. الخطأ يترمى قبل أي نداء model أو تشغيل tool؛ والـ checkpoint (ومع الـ approval، السجل المعلّق) تبقى مثل ما هي.

**الحل:** استأنف بنفس الـ agent اللي وقّف الـ run، أو عيّن `onAgentDrift` إلى `'warn'` (الافتراضية) أو `'ignore'` وتكمل على أي حال. راجع [Durable execution](/ar/durable-execution#استئناف-run-بعد-ما-يتغير-الـ-agent).

**مثال:** `createAgent({ store, onAgentDrift: 'error' })` بعد نشر غيّر اسم tool، وبعدين `agent.resume('job-1')`.

### LOUSHO_RESUME_TOOL_MISSING

**المعنى:** run مستأنَف منتظر tool call (call عليها موافقة، أو call من آخر turn للـ model ما طلعت نتيجتها بعد) والـ agent اللي يستأنف ما عنده هالـ tool. هذا خطأ مهما كانت قيمة `onAgentDrift`، لأن الـ call ما تقدر تشتغل.

**الحل:** رجّع الـ tool بنفس الاسم، أو تخلّص من الـ run المتوقف (احذف الـ checkpoint تبعه، ارفض الـ approval تبعه). راجع [Durable execution](/ar/durable-execution#استئناف-run-بعد-ما-يتغير-الـ-agent).

**مثال:** run متوقف عند `charge_card`، وبعدين نشر يحذف هالـ tool و`agent.approvals.resolve({ id, approved: true })` يننادى.

### LOUSHO_RUN_ALREADY_ITERATED

**المعنى:** `AgentRun` من `session.stream()` اجتُوز عليه مرة ثانية.

**الحل:** اجمع الأحداث في أول حلقة `for await`، أو نادِ `stream()` من جديد لـ run جديد. راجع [البث](/ar/streaming).

**مثال:** حلقتين `for await (const event of run)` على نفس الـ `run`.

## الجداول الزمنية

### LOUSHO_SCHEDULE_INVALID

**المعنى:** `defineSchedule()` أخذت تعريف غير صالح: تعبير cron يفشل parse (الرسالة تسمّي الحقل)، أو ليس بالضبط واحد من `prompt` و`run`. مجلدات الـ agents تواجه هذا أثناء تحميل `schedules/`.

**الحل:** صحّح التعبير أو أعطِ الـ schedule واحد من `prompt` / `run`. راجع [الجداول الزمنية](/ar/schedules).

**مثال:** `defineSchedule({ cron: '61 * * * *', prompt: 'hi' })`.

### LOUSHO_SCHEDULE_RUN_INCOMPLETE

**المعنى:** turn schedule من نوع prompt انتهت بـ `finishReason` غير `'stop'`؛ والرسالة تسمّيه. `startSchedules()` يمرّره لـ `onError`، و`fireSchedule()` ينرفض فيه، و`scheduled()` في الـ Worker يسجّله. ومع `'awaiting-approval'` الرسالة تسمّي الـ approval، وهي تبقى معلّقة.

**الحل:** احسم الـ approval المعلّقة بـ `agent.approvals.resolve()`، أو غيّر الـ prompt أو الـ tools أو مخطط `output` أو الحدود عشان turn بدون إشراف تقدر تخلص. راجع [الجداول الزمنية](/ar/schedules).

**مثال:** schedule الـ prompt تبعه يخلي الـ agent ينادي tool عليها `needsApproval`.

## القنوات

### LOUSHO_CHANNEL_INVALID

**المعنى:** ملف في `channels/` داخل مجلد agent ما يسوي default export لـ channel (كائن فيه `parse` و`reply`). الرسالة تسمّي الملف.

**الحل:** اعمل default export لـ channel مبنية بـ `defineChannel()` أو `httpChannel()` أو `webhookChannel()` أو `slackChannel()` أو `discordChannel()` أو `telegramChannel()` أو `githubChannel()` أو `teamsChannel()`. راجع [القنوات](/ar/channels).

**مثال:** `export default { cron: 'x' }` في `channels/sms.ts`.

### LOUSHO_MEMORY_INVALID

**المعنى:** ملف في `memory/` داخل مجلد agent ما يسوي default export لخانة memory (كائن فيه `scope` و`provider`). الرسالة تسمّي الملف.

**الحل:** اعمل default export لـ `defineMemory({ ... })`، أو نفس الخيارات بدون `name` (يُستخدم اسم الملف). راجع [الذاكرة](/ar/memory) و[مجلدات agent](/ar/agent-directories#memory).

**مثال:** `export default { cron: 'x' }` في `memory/notes.ts`.

## السجل

### LOUSHO_REGISTRY_UNREACHABLE

**المعنى:** `lousho add` ما قدر يقرا مستند من الـ registry: الـ URL ما ردّ بالوقت أو رجّع خطأ، أو الملف المحلي مفقود، أو الـ scheme ليس `http(s)`، أو المستند أكبر من السقف.

**الحل:** تأكد من قيمة `--registry` (أو `LOUSHO_REGISTRY`) ومن اتصالك. راجع [السجل](/ar/registry).

**مثال:** `lousho add x --registry https://example.invalid/index.json`.

### LOUSHO_REGISTRY_ITEM_NOT_FOUND

**المعنى:** فهرس الـ registry ما فيه عنصر بهذا الاسم. الرسالة تقترح أقرب اسم إذا في.

**الحل:** نفّذ `lousho add --list` واستخدم واحد من الأسماء.

**مثال:** `lousho add web-serach` واسم العنصر `web-search`.

### LOUSHO_REGISTRY_INVALID

**المعنى:** فهرس registry أو مستند عنصر فيه ليس JSON صالح أو ما يطابق الصيغة (حقل ناقص، أو نوع عنصر مجهول، أو عنصر مستنده يسمّي عنصر ثاني).

**الحل:** صلّح المستند اللي تسمّيه الرسالة. راجع [السجل](/ar/registry#الصيغة).

**مثال:** مستند عنصر بدون `files`.

### LOUSHO_REGISTRY_UNSAFE_PATH

**المعنى:** عنصر يطلب يكتب ملف مساره مطلق، أو فيه `..` أو backslashes أو حرف قرص، أو خارج المجلد اللي نوعه يقدر يكتب فيه، أو يحل خارج مجلد الـ agent عبر symlink، أو أكبر من سقوف الحجم. ما انكتب شيء.

**الحل:** لا تثبّت العنصر؛ وقل للي مستضيف الـ registry. راجع [السجل](/ar/registry#قواعد-الأمان).

**مثال:** عنصر tool فيه ملف `../../.bashrc`.

### LOUSHO_REGISTRY_FILE_EXISTS

**المعنى:** ملف كان العنصر رح يكتبه موجود أصلاً. ما انكتب شيء.

**الحل:** مرّر `--overwrite`، أو حرّك ملفك من الطريق أولاً.

**مثال:** `lousho add web-search` مرتين.

### LOUSHO_REGISTRY_MANIFEST_MISMATCH

**المعنى:** كود عنصر يمد إيده لشيء الـ permission manifest تبعه ما يعلنه: يستورد `child_process` بدون `exec: true`، أو يكتب ملفات بدون `filesystem: "write"`، أو ينادي `fetch()` أو يسمّي host URL ليس في `network`، أو يقرا متغير بيئة ليس في `env`، أو يستخدم `eval` أو `new Function` أو `process.env[...]` محسوب أو `import()` / `require()` ديناميكي — وهذه ما تتسمّح أبدًا. الرسالة تسرد كل مخالفة كـ `<file>:<line>: <what> (<fix>)`. ما انكتب شيء. `--dry-run` يبلّغ عنها كمان.

**الحل:** لا تثبّت العنصر؛ وقل للي يستضيف الـ registry. مؤلفه يصلّح الكود أو يعلن الصلاحية. راجع [السجل](/ar/registry#بيان-الصلاحيات).

**مثال:** عنصر tool ملفه يستورد `node:child_process` والـ manifest تبعه خالٍ من `exec`.

## الـ sandbox

### LOUSHO_SANDBOX_EGRESS_UNSUPPORTED

**المعنى:** `SubprocessSandbox` مع `network: { allow }` و`broker` ما يقدر على الـ Docker daemon هذا يخلّي الـ credential broker الطريق الوحيد للحاوية للخارج، فما شغّل أي حاوية بدل ما يعطي egress مفتوح. الرسالة تسمّي السبب: Docker Desktop (الحاويات تشتغل داخل VM، فالـ host ما إله عنوان على الشبكة الداخلية)، أو Docker rootless، أو daemon على جهاز ثاني (الـ broker ما يقدر يسمع على بوابة الشبكة)، أو شبكة مُعاد استخدامها مو داخلية، أو Engine أقدم من 25.0.5 يمرّر DNS من الشبكات الداخلية.

**الحل:** شغّل الـ agent على مضيف Linux اللي عليه Docker Engine 25.0.5 أو أحدث، أو استخدم `network: 'none'`. راجع [أدوات الـ workspace](/ar/workspace-tools#sandboxed-shell-sandboxshell).

**مثال:** `new SubprocessSandbox({ network: { allow: ['api.github.com'] }, broker })` مع Docker Desktop.

### LOUSHO_SANDBOX_PATH_DENIED

**المعنى:** `SubprocessSandbox.writeFile()` أخذ مسار برّا `root` تبع الـ sandbox (عن طريق `..`، أو مسار مطلق في مكان ثاني، أو symlink يطلّع برّا)، أو الـ root نفسه. ما انكتب شيء.

**الحل:** اكتب تحت الـ root، أو ابنِ الـ sandbox بالـ `root` اللي لازم يحتوي الملف (`new SubprocessSandbox({ root })`؛ والافتراضي هو مجلد العمل وقت الإنشاء). راجع [حواجز الحماية](/ar/guardrails#sandboxed-tools).

**مثال:** `sandbox.writeFile('/etc/profile.d/x.sh', ...)` مع الـ root الافتراضي.

## مجلدات الـ agents والـ skills والـ flows

### LOUSHO_AGENT_DIR_INVALID

**المعنى:** `loadAgentDir()` (أو `lousho dev` و`lousho build` اللي يستخدموه) ما قدر يحمّل مجلد: المجلد مفقود أو غير مقروء، أو ملف فاضي، أو ملف `tools/` ما فيه export صالح، أو ملف إعدادات يفشل parse، أو مجلد sub-agent بنيته خربانة. الرسالة تسمّي الملف.

**الحل:** صلّح الملف اللي تسمّيه الرسالة. راجع [مجلدات agent](/ar/agent-directories).

**مثال:** `loadAgentDir('./agents/support')` و`instructions.md` فاضي.

### LOUSHO_SKILL_INVALID

**المعنى:** skill بنيته غلط (`defineSkill()` أو مجلد `skills/`، ومنه `loadSkills()` على ملف الـ frontmatter تبعه غلط)، أو `withSkills()` أخذ أسماء مكررة، أو اسم skill يتصادم مع الأداة `load_skill` أو `read_skill_file`.

**الحل:** أعطِ كل skill اسم فريد ووصف ومحتوى؛ وغيّر اسم أي أداة اسمها `load_skill`. راجع [Skills](/ar/skills).

**مثال:** `defineSkill({ name: 'x', description: '', content: '...' })`.

### LOUSHO_FLOW_INVALID

**المعنى:** تعريف flow فيه غلط: اسم input ناقص أو مكرر، أو اسم الـ flow أو كوده ناقص، أو node من نوع مجهول.

**الحل:** صلّح الجزء اللي تسمّيه الرسالة من الـ flow. راجع [Flows](/ar/flows).

**مثال:** نداءين `.input('city')` على `FlowBuilder` واحد.

### LOUSHO_FLOW_TOOL_DENIED

**المعنى:** خطوة `toolCall` في flow ما اشتغلت. قاعدة صلاحيات أو سياسة `needsApproval` تبع الأداة رفضتها، أو الاستدعاء يحتاج approval والـ callback `approve` في سياق الـ flow رفضه، أو رجّع `'defer'` (الـ flow ما يقدر يتوقف مؤقتًا)، أو ما انمرّر أصلاً.

**الحل:** مرّر `approve` في سياق الـ flow عشان يحسم الاستدعاءات اللي تحتاج approval، أو غيّر القاعدة اللي رفضت الاستدعاء. راجع [Flows](/ar/flows#استدعاءات-الـtool).

**مثال:** خطوة flow تنادي أداة دفع عليها `needsApproval: true`، تشتغل بدون callback `approve`.

### LOUSHO_FLOW_CHANGED

**المعنى:** `FlowExecutor.resume()` انستدعى مع flow تغيّرت خطواته (انضافت، أو انحذفت، أو تحرّكت، أو تغيّر نوع خطوة أو id أو الأداة أو الـ agent تبعها) من وقت ما انحفظ الـ run. الخطوات المكتملة تنحفظ حسب مكانها في الـ flow، فالنتائج المحفوظة كانت رح تنزل على خطوات غلط. الـ prompts وباقي الإعدادات تقدر تتغيّر براحتها.

**الحل:** استأنف بإصدار الـ flow اللي بدأ الـ run، أو ابدأ run جديد تحت `runId` ثاني. راجع [Flows](/ar/flows).

**مثال:** run انحفظ بعد `charge` في `[charge, notify]`، واستُؤنف مع `[audit, charge, notify]`.

## الـ storage والنشر والتكاملات

### LOUSHO_STORAGE_FAILED

**المعنى:** التخزين فشل: قاعدة SQLite ما انفتحت (الـ `cause` فيه خطأ الـ driver)، أو انستخدمت بعد `close()`، أو الـ schema تبعها أحدث مما يعرف هالـ SDK، أو `node:sqlite` مفقود؛ أو ملف تجاوز حد حجم التخزين؛ أو ملف `fileStore()` / `FileSessionStore` ما انقرأ أو ما انستبدل لأن handle ثاني ماسكه مفتوح (`EPERM` / `EACCES` / `EBUSY` على Windows لمدة أطول من ~1.3 ثانية اللي يعيد فيها الـ store المحاولة؛ والـ `cause` هو آخر خطأ)؛ أو تغيير في `fileMemory` انتظر أكثر من 10 ثواني ملف القفل `<key file>.lock` تبع كاتب ثاني.

**الحل:** تأكد من المسار والصلاحيات، واستخدم Node >= 22.13 مع `SqliteStore` (أو store مبني على ملفات)، واعمل store جديد بعد ما تقفل واحد.

**مثال:** `new SqliteStore('/read-only/agent.db')`.

### LOUSHO_STORAGE_BUSY

**المعنى:** كتابة في `SqliteStore` ما قدرت تاخذ قفل الكتابة على قاعدة البيانات لأن اتصال أو عملية ثانية (replica ثانية، أو نسخة احتياطية، أو transaction طويلة) ماسكته. الـ driver ينتظر شوي بس (50 ms) عشان ما يتجمّد الـ event loop؛ وبعدها الكتابات الـ transactional في الـ stores (حفظ الـ checkpoints والـ approvals، و`resolve()`، و`saveIf()`، وclaims تسجيل الدخول بـ OAuth، وتحديثات الـ memory في SQLite) تعيد المحاولة مع backoff لحوالي 5 ثواني قبل ما تستسلم بهذا الخطأ. `prune()` ما يعيد المحاولة. وخطأ الـ driver الأصلي هو الـ `cause`.

**الحل:** أعد النداء. وإذا ظل يصير، دوّر على اللي ماسك القفل وقت طويل.

**مثال:** عمليتين يحفظون في نفس `agent.db` ووحدة منهم تشغّل transaction تاخذ كم ثانية.

### LOUSHO_TRIGGER_INVALID

**المعنى:** trigger adapter أخذ خيارات غلط: cron adapter بدون بالضبط واحد من `intervalMs` / `cron`، أو كتلة `auth` لـ webhook فيها secret فاضي أو نوع مجهول، أو trigger Slack ما يقدر يتحقق من الطلبات.

**الحل:** اتبع المثال اللي في الرسالة. راجع [القنوات](/ar/channels) و[الجداول الزمنية](/ar/schedules).

**مثال:** `webhookChannel({ auth: { type: 'hmac', secret: '' } })`.

### LOUSHO_CHANNEL_REQUEST_FAILED

**المعنى:** نداء لـ API منصة محادثة (Slack أو Discord أو Telegram أو GitHub) فشل؛ الرسالة تسمّي النداء وحالة HTTP أو خطأ المنصة.

**الحل:** تأكد من token البوت وصلاحياته، ومن حالة المنصة. راجع [القنوات](/ar/channels).

**مثال:** `chat.postMessage` في Slack يرد `channel_not_found`، أو `sendMessage` في Telegram يرد 400 لمحادثة مجهولة، أو `POST /repos/{owner}/{repo}/issues/{number}/comments` في GitHub يرد 403 لـ token ما عنده صلاحية كتابة.

### LOUSHO_DEPLOY_FAILED

**المعنى:** `lousho build` / `lousho dev` / الـ node-server runtime ما قدروا يحزّموا أو يشغّلوا الـ agent: `--agent` ناقص، أو مسار الـ agent ما موجود أو ليس مجلد agent، أو فشل في التحزيم (import ما ينحل؛ ثبّته، أو اضبط `LOUSHO_BUILD_VERBOSE=1` عشان السجل الكامل)، أو قيمة `LOUSHO_STORE` غلط، أو مصادر الـ runtime ناقصة، أو tool هدف Cloudflare Worker ما عنده.

**الحل:** اتبع الرسالة. راجع [النشر](/ar/deployment).

**مثال:** `lousho build --target node-server` بدون `--agent`.

## الاختبارات والـ evals

### LOUSHO_EVALS_INVALID

**المعنى:** مساعد eval انستخدم غلط: `defineEval()` خارج vitest، أو `t.judge()` قبل `t.send()` أو بدون judge، أو `llmJudge()` خارج الـ judge runner.

**الحل:** اتبع الرسالة. راجع [Evals](/ar/evals).

**مثال:** نداء `t.judge('polite')` قبل `t.send('hi')`.

### LOUSHO_TEST_FAILED

**المعنى:** فحص يسويه مساعد test ما انعقد: eval ما نجح، أو سكربت `mockModel()` ظل فيه turns غير مستخدمة بالنهاية.

**الحل:** اقرأ الرسالة؛ صلّح الـ agent أو احذف الـ turns الزائدة من السكربت. راجع [الاختبار](/ar/testing).

**مثال:** `mockModel([...three turns])` والـ agent وقّف بعد turnين.

### LOUSHO_CASSETTE_INVALID

**المعنى:** cassette للـ record/replay مفقود، أو ليس JSON صالح، أو ما يطابق الطلب المسجّل. الرسالة تسمّي الملف. وعدم التطابق داخل run يوصل `send()` كـ `CassetteMismatchError` نفسه (من `lousho/testing`، مع `.cassette` و`.callNumber`) — هو فشل في تجهيزات الاختبار، فما ينضغط أبدًا في `CompactedLLMProviderError`.

**الحل:** سجّله من جديد (`lousho eval --record <file>`، أو `recordReplay()` مع `mode: 'record'`). راجع [الاختبار](/ar/testing).

**مثال:** `lousho eval --replay` لـ eval ما اتسجّل أبدًا.

## عام

### LOUSHO_GENERIC_ERROR

**المعنى:** `SDKError` مبني بدون `code`.

**الحل:** اقرأ الرسالة؛ تقول لك إيش فشل.

**مثال:** `new SDKError('Something failed')`.

### LOUSHO_AGENT_EXECUTION_FAILED

**المعنى:** `AgentExecutionError`: تشغيل agent فشل.

**الحل:** افحص `error.cause` لسبب الفشل الأصلي.

**مثال:** `new AgentExecutionError('Agent failed', agentId, cause)`.

### LOUSHO_FLOW_EXECUTION_FAILED

**المعنى:** `FlowExecutionError`: خطوة في flow فشلت.

**الحل:** افحص `error.step` و`error.cause`. راجع [Flows](/ar/flows).

**مثال:** خطوة في flow رمى الـ agent تبعها.

### LOUSHO_VALIDATION_FAILED

**المعنى:** `ValidationError`: الـ input ما عدّى الـ validation.

**الحل:** صلّح الحقول المسردة في `error.errors`.

**مثال:** `new ValidationError('Validation failed', { email: ['Invalid email'] })`.

### LOUSHO_OPERATION_TIMEOUT

**المعنى:** `TimeoutError`: عملية (`error.operation`) ما خلّصت ضمن `error.timeoutMs`.

**الحل:** ارفع المهلة، أو خلّي العملية أسرع.

**مثال:** خطوة flow فيها `timeoutMs` ومحاولتها تاخذ أطول من كذا (`error.operation` قيمته `flow.node <type>`).

### LOUSHO_OUTPUT_INVALID

**المعنى:** محجوز. الرد غير الصالح في الـ structured output ما يترمى اليوم: الـ run ينتهي بـ `finishReason: 'output-invalid'` و`outputError`.

**الحل:** راجع [Structured output](/ar/structured-output).

**مثال:** رد ما يطابق `output: zodSchema` بعد خطوة الإصلاح.

### LOUSHO_BUDGET_EXCEEDED

**المعنى:** ميزانية `limits` تبع run أو session (`maxTokens` أو `maxCostUsd` أو `maxDurationMs` وغيرها) تجاوزت الحد تحت `onExceeded: 'throw'`. `BudgetExceededError` يحمل `budget: { limit, value, max, scope }`. مع الافتراضي `onExceeded: 'stop'` ما يترمى شيء: الـ run ينتهي بـ `finishReason: 'budget-exceeded'`.

**الحل:** ارفع الحد اللي تسمّيه الرسالة، أو احذف `onExceeded: 'throw'`. راجع [الميزانيات](/ar/configuration#الميزانيات).

**مثال:** `createAgent({ provider, limits: { maxCostUsd: 0.01, onExceeded: 'throw' } })` والـ run تبعه يكلف أكثر من سنت.

### LOUSHO_GUARDRAIL_TRIPPED

**المعنى:** guardrail للـ input أو output أو tool وقّف run تحت `onTripped: 'throw'`. `GuardrailError` يحمل `guardrail: { name, kind, reason, toolName? }`. مع الافتراضي `onTripped: 'stop'` ما يترمى شيء: الـ run ينتهي بـ `finishReason: 'guardrail'`.

**الحل:** افحص `error.guardrail` لتعرف أي guardrail وقّف وليش، أو احذف `onTripped: 'throw'`. راجع [guardrails الـ input والـ output](/ar/guardrails#input-و-output-guardrails).

**مثال:** `createAgent({ provider, guardrails: { input: [maxLengthGuardrail({ maxChars: 10 })], onTripped: 'throw' } })` انبعت له رسالة أطول.

## المصادقة

### LOUSHO_AUTH_CONFIG_INVALID

**المعنى:** مساعد route auth من `lousho/auth` (`jwt()` أو `oidc()` أو `basic()` أو `apiToken()`) أخذ خيارات ما يقدر يتحقق فيها، ورفضها وقت إنشائه، مو عند أول طلب. الرسالة تسمّي الخيار: لا مصدر مفاتيح أو مصدرين، أو `secret` HMAC أقصر من 32 بايت، أو خوارزمية ما تناسب المفتاح (`secret` مع `RS256`، أو مفتاح عام مع `HS256`)، أو لا `audience` (ولا `allowAnyAudience: true`)، أو `clockToleranceSec` فوق 300، أو URL مجموعة مفاتيح أو issuer ليس https، أو قائمة مستخدمين أو token فاضي (ومنه `createRouteHandler({ auth: '' })` و`serveFetch(request, ctx, '')`).

**الحل:** غيّر الخيار اللي تسمّيه الرسالة. راجع [Route auth والـ principals](/ar/auth).

**مثال:** `jwt({ secret: process.env.JWT_SECRET! })` بدون `audience`.

## OAuth

### LOUSHO_TOKEN_KEY_MISSING

**المعنى:** store ملف أو SQLite أو KV طُلب منه يخزّن OAuth token أو sign-in معلّق أو client مسجّل (أو يقرا واحد موجود)، وما عنده مفتاح للـ tokens: لا خيار `tokenKey` ولا متغير البيئة `LOUSHO_TOKEN_KEY` مضبوطين. الـ tokens ما تنخزّن إلا مشفّرة، وما في مفتاح افتراضي. قراءة سجلات غير موجودة ما تحتاج مفتاح.

**الحل:** ولّد مفتاح مرة وحدة بـ `generateTokenKey()` (32 بايت عشوائي base64)، وخلّيه سرّي، ومرّره كـ `tokenKey` أو اضبط `LOUSHO_TOKEN_KEY`. وعلى Cloudflare Workers ضيفه بـ `wrangler secret put LOUSHO_TOKEN_KEY`. راجع [تخزين الـ tokens](/ar/oauth#تخزين-tokens).

**مثال:** `new SqliteStore('./agent.db').tokens.set('github', { owner: 'app' }, token)` و`LOUSHO_TOKEN_KEY` غير مضبوط.

### LOUSHO_TOKEN_DECRYPT_FAILED

**المعنى:** سجل OAuth مخزّن ما انفك تشفيره: مفتاح الـ store ليس اللي انكتب فيه، أو السجل اتغيّر أو اتنسخ لمالك ثاني. الرسالة تسمّي الـ provider، الـ token ما تسمّيه أبدًا.

**الحل:** استخدم المفتاح اللي انكتبت فيه الـ tokens. أثناء الـ rotation حط المفتاح القديم بعد الجديد (`tokenKey: [newKey, oldKey]`، أو `LOUSHO_TOKEN_KEY="<new>,<old>"`). ولو المفتاح القديم ضاع، احذف السجل (`tokens.delete(provider, owner)`) وسجّل الدخول من جديد. راجع [تخزين الـ tokens](/ar/oauth#تخزين-tokens).

**مثال:** ملف `SqliteStore` انكتب بـ `tokenKey` وانفتح بمفتاح ثاني.

### LOUSHO_OAUTH_PRINCIPAL_REQUIRED

**المعنى:** tool نادت `ctx.getToken()` (أو `requireAuth()`) لـ provider الـ credential تبعه لكل مستخدم (`credentialOwner: 'user'`، الافتراضي)، بس الـ run بدون principal (هوية المستخدم)، فما في مستخدم يملك الـ token. النداء يفشل بهذا الخطأ؛ والـ run ما يوقف ولا يتعمل رابط sign-in.

**الحل:** قدّم الـ agent خلف route auth أو channel، عشان كل run يكون إله principal ([المصادقة](/ar/auth))، أو عرّف الـ provider بـ `credentialOwner: 'app'` لما تكون credential وحدة للكل. راجع [أدوات تحتاج sign-in](/ar/oauth#أدوات-تحتاج-تسجيل-دخول).

**مثال:** `agent.send('List my repositories')` بدون `{ principal }`، مع tool تنادي `ctx.getToken(github)`.

### LOUSHO_OAUTH_APP_SIGNIN_REQUIRED

**المعنى:** tool طلبت credential التطبيق نفسه (`credentialOwner: 'app'`) وما في شيء مخزّن (أو انسحب). مستخدم الـ chat ما يوصله رابط sign-in التطبيق أبدًا، فالنداء يفشل بدل ما يوقف.

**الحل:** سجّل دخول التطبيق مرة وحدة: افتح الـ URL اللي ترجعه `agent.oauth.signInUrl(provider)` وخلّي الـ callback يخزّن الـ token. راجع [credentials التطبيق](/ar/oauth#أدوات-تحتاج-تسجيل-دخول).

**مثال:** أداة `post_update` تنادي `ctx.getToken(slackBot)` قبل ما المشغّل يربط Slack.

### LOUSHO_OAUTH_STORE_MISSING

**المعنى:** tool نادت `ctx.getToken()`، أو `agent.oauth` انستخدمت، على agent بدون token store، فما في مكان يتقرى أو ينحفظ فيه token. الـ run يوقف بهذا الخطأ. وسيرفر MCP على HTTP مع `oauth` يحتاج الـ store كمان: توصيله (`ready()`، أو `connectMcp()` بدون `tokens`) يفشل بهذا الخطأ.

**الحل:** مرّر `createAgent({ store })` فيه `tokens`: `memoryStore()` أو `fileStore()` أو `SqliteStore` أو `KVStore` (الدائمة منها تحتاج `tokenKey`). راجع [تخزين الـ tokens](/ar/oauth#تخزين-tokens).

**مثال:** `createAgent({ provider, tools: [listRepos] })` بدون `store`.

### LOUSHO_OAUTH_STATE_INVALID

**المعنى:** `agent.oauth.complete()` (مسار `/oauth/callback`) أخذت `state` مجهول، أو مستخدم قبل، أو أقدم من 10 دقائق، أو (مع طلب callback موثّق) sign-in بدأ لمستخدم ثاني. المسار يرد 400.

**الحل:** ابدأ من جديد برابط جديد: لا توافق على شيء، ودع الـ tool تطلب مرة ثانية (الوقفة الجديدة إلها رابط جديد)، أو نادِ `agent.oauth.signInUrl()` من جديد لـ sign-in التطبيق. راجع [مسار الـ callback](/ar/oauth#مسار-callback).

**مثال:** فتح redirect الـ provider نفسه مرتين، أو بعد 10 دقائق.

### LOUSHO_SIGNIN_PENDING

**المعنى:** `agent.approvals.resolve({ id, approved: true })` اننادت على وقفة sign-in (`kind: 'sign-in'`) قبل ما ينخزّن token المستخدم. الوقفة تبقى مثل ما هي. وعلى `POST /chat/:id/approvals/:approvalId` هذا HTTP 409.

**الحل:** افتح رابط الـ sign-in أول ودع الـ provider يوجّهك للـ callback، وبعدين وافق مرة ثانية؛ أو وافق بـ `false` لإلغاء النداء. راجع [إيش يشوف المستخدم](/ar/oauth#ما-يراه-المستخدم).

**مثال:** الضغط على "I've signed in" قبل ما تخلص صفحة الـ provider.

### LOUSHO_OAUTH_TOKEN_EXCHANGE_FAILED

**المعنى:** نقطة نهاية الـ token عند الـ provider رفضت تبدّل الـ authorization code (أو طلب لها فشل)، أو الـ callback جاي بدون code، أو ما في provider باسم الـ sign-in المعلّق معرّف في هالعملية. الرسالة تسمّي الـ provider وحالة HTTP وكود `error` الخاص بـ OAuth، وأبدًا ما تسمّي الـ code ولا جسم الرد. مسار الـ callback يرد 502. ولسيرفر MCP مع `oauth` الرسالة تسمّي السيرفر وكود `error` الخاص بـ OAuth.

**الحل:** تأكد من `tokenUrl` و`clientId` و`clientSecret` و`clientAuth`، وأن `redirectUri` يطابق تمامًا اللي مسجّل عند الـ provider، وأن الوحدة اللي تعرّف الـ provider محمّلة في العملية اللي تخدم الـ callback. وبعدين سجّل الدخول من جديد. راجع [مسار الـ callback](/ar/oauth#مسار-callback).

**مثال:** `invalid_client` من GitHub بعد تدوير سر العميل.

### LOUSHO_MCP_AUTH_REQUIRED

**المعنى:** سيرفر MCP على HTTP مع `oauth` رفض الاتصال أو tool call لأن التطبيق ما عنده token صالح له: لسّا ما حدا سجّل دخول التطبيق، أو الـ grant انسحبت، أو `url` السيرفر تغيّر منذ الـ sign-in (الـ token ينرسل بس للـ url اللي اتوخذ له). حالة السيرفر تصير `'needs-auth'`. عند التوصيل `ready()` (و`connectMcp()`) تفشل بهذا الخطأ؛ وأثناء run نتيجة الـ tool call هي هذا الخطأ والـ run يكمل. ومستخدم الـ chat ما يُطلب منه sign-in لسيرفر MCP أبدًا، والرسالة ما فيها authorization URL أبدًا.

**الحل:** سجّل دخول التطبيق مرة وحدة: افتح الـ URL من `agent.oauth.mcpSignInUrl('<server>')` ودع الـ provider يوجّهك لمسار الـ callback. الاتصال الجاي أو الـ tool call الجاي يستخدم الـ token المخزّن. راجع [سيرفرات MCP مع OAuth](/ar/oauth#خوادم-mcp-مع-oauth).

**مثال:** `createAgent({ mcpServers: { linear: { url, oauth: { redirectUri } } }, store })` و`await agent.ready()` قبل ما المشغّل يسجّل الدخول.
