تقدر تعرّف الـ agent كمجلد. `loadAgentDir()` تقرأه وتستدعي `createAgent()` بالخيارات التي تصفها الملفات، فترجع بالضبط ما ترجعه `createAgent()`. يبقى الـ typed code API هو المرجع الأساسي: المجلد طريقة ثانية لكتابة نفس الخيارات، وتقدر تنتقل إلى الكود في أي وقت بدون إعادة كتابة.

> **أمان:** تحميل مجلد agent **يشغّل الكود الذي فيه** (`agent.ts` وكل شيء في `tools/`). لا تحمّل إلا مجلدات تثق فيها. لا يوجد أي sandbox ضمني؛ الملفات تعمل بكامل صلاحيات العملية.

```ts
import { loadAgentDir } from '@lousho/build-ai-agent';

const agent = await loadAgentDir('./my-agent');
const { text } = await agent.send('Hello!');
```

## بنية المجلد

```text
my-agent/
  agent.{ts,mts,js,mjs,cjs,json,yaml,yml}          # optional config
  instructions.md                                  # system prompt
  instructions/<family>.md                         # appended to the prompt when the model id contains <family>
  hooks.{ts,mts,cts,js,mjs,cjs}                    # hooks file (or any path `hooks` names), exports a hook or a list
  approve.{ts,mts,cts,js,mjs,cjs}                  # approver file (or any path `approve` names), exports a function
  tools/*.{ts,mts,cts,js,mjs,cjs}                  # defineTool() tools
  skills/                                          # same layouts as loadSkills()
  subagents/<name>/                                # nested agent directories
  schedules/*.{ts,mts,cts,js,mjs,cjs}              # defineSchedule() cron schedules (see schedules.md)
  channels/*.{ts,mts,cts,js,mjs,cjs}               # a channel each: defineChannel(), webhookChannel(), ... (see channels.md)
  memory/*.{ts,mts,cts,js,mjs,cjs}                 # a memory slot each: defineMemory() (see memory.md); part of the agent
  auth.{ts,mts,cts,js,mjs,cjs}                     # route auth for the deployed server: jwt(), oidc(), basic(), ... (see auth.md)
```

مسموح بملف config واحد فقط. الملفات داخل `tools/` وعناصر `skills/` و`subagents/` تُقرأ مرتّبة، فيكون التحميل deterministic ويعطي نفس النتيجة كل مرة.

### ملف الـ config

```ts
// agent.ts
export default {
  model: 'openai/gpt-4o-mini',
  description: 'Triages bug reports',
  maxSteps: 8,
  toolConcurrency: 2,
};
```

| المفتاح | يقابل |
| --- | ------- |
| `name` | `createAgent({ name })` (الافتراضي: اسم المجلد) |
| `description` | `manifest.description` — محمّل المجلد لا يمرّرها إلى `createAgent` (مع أن `createAgent({ description })` تقبلها)؛ وهي ما يقرؤه الـ agent الأب عن الـ sub-agent (مطلوبة هناك) |
| `model` | `createAgent({ model })`؛ وبادئة `vendor/` تختار الـ provider — مع OpenRouter استخدم `openrouter/<vendor>/<model>` |
| `provider` | `createAgent({ provider })` (في ملفات config برمجية فقط) |
| `instructions` | `createAgent({ instructions })` (استخدم هذا أو `instructions.md`، لا الاثنين) |
| `maxSteps` | `createAgent({ maxSteps })` |
| `toolConcurrency` | `createAgent({ toolConcurrency })` |
| `projectInstructions` | `createAgent({ projectInstructions })` |
| `permissionMode` | `createAgent({ permissionMode })`: `'default'` أو `'plan'` أو `'acceptEdits'` أو `'dontAsk'` (دالة في config برمجي) |
| `permissions` | `createAgent({ permissions })`، بصيغة قواعد serializable الموضحة أدناه |
| `compaction` | `createAgent({ compaction })`: `true` أو كائن خيارات |
| `hooks` | `createAgent({ hooks })`: مسار (نسبي إلى المجلد) لملف يصدّر افتراضيًا hook أو قائمة hooks، أو الـ hooks مضمّنة في config برمجي |
| `approve` | `createAgent({ approve })`: مسار لملف يصدّر افتراضيًا دالة الـ approver، أو الدالة مضمّنة في config برمجي |
| `approvalTtlMs` | `createAgent({ approvalTtlMs })`: المللي ثانية قبل أن تنتهي approval (موافقة) بلا رد؛ و`ttlMs` في قاعدة `ask` يغلب عليه |
| `limits` | `createAgent({ limits })`، مثل `{ "maxCostUsd": 0.05 }` |
| `store` | `createAgent({ store })`: القيمة `{ "dir": "./.lousho" }` (تُحَلّ نسبةً إلى مجلد الـ agent) تصبح `fileStore()` — الـ sessions والـ checkpoints والـ approvals المعلّقة تبقى بعد إعادة التشغيل؛ ويمكن ضبط `historyLimit` و`tokenKey` أيضًا. وفي config برمجي يمكن تمرير كائن `AgentStore` بدلًا منها. Node فقط |

أي مفتاح غير معروف يعتبر خطأ مع اقتراح (`'modle' (did you mean 'model'?)`).

قاعدة `permissions` هي `{ "tool", "when"?, "action", "reason"?, "ttlMs"? }`. `tool` اسم، أو قائمة أسماء (`'*'` تغطي كل الـ tools)، أو `RegExp` في config برمجي. `action` قيمتها `'allow'` أو `'ask'` أو `'deny'`. `ttlMs` مسموح فقط في قواعد `'ask'` — المدة التي تنتظرها الوقفة للحصول على قرار قبل أن تنتهي ('approval expired')، وهو يغلب على `approvalTtlMs` الخاصة بالـ agent. في JSON/YAML يكون `when` سجلًا من أسماء المعاملات إلى matchers، وكلها يجب أن تتحقق. السلسلة المجرّدة regular expression تُختبر على `String(args[name])`؛ والكائن يختار عمليات: `eq`/`ne` تقارن المعامل بالقيمة بـ `===`/`!==`، و`lt`/`lte`/`gt`/`gte` تقارن `Number(args[name])` بالقيمة (المعامل غير الرقمي لا يطابق أبدًا)، و`matches` هي regular expression. عدة عمليات على معامل واحد يجب أن تتحقق كلها، فـ `{ "replicas": { "gte": 1, "lte": 10 } }` تطابق من 1 إلى 10. وفي config برمجي يمكن تمرير الـ predicate نفسه. أول قاعدة تطابق هي التي تحسم.

```json
// agent.json
{
  "permissions": [
    { "tool": "shell", "when": { "command": "\\brm\\b" }, "action": "deny", "reason": "No deletes" },
    { "tool": "deploy", "when": { "environment": { "eq": "staging" }, "replicas": { "lte": 10 } }, "action": "ask" },
    { "tool": ["read_file", "shell"], "action": "allow" },
    { "tool": ["write_file", "edit_file"], "action": "ask" }
  ],
  "hooks": "hooks.ts",
  "approve": "approve.ts",
  "limits": { "maxCostUsd": 0.05 }
}
```

```ts
// hooks.ts — the default export is a hook or a list of them
import type { AgentHook } from '@lousho/build-ai-agent';
const audit: AgentHook = {
  name: 'audit',
  postToolCall(ctx) {
    console.log(ctx.toolName);
  },
};
export default audit;
```

```ts
// approve.ts — the default export decides every `ask`ed call
import type { ApproveToolCall } from '@lousho/build-ai-agent';
const approve: ApproveToolCall = ({ args }) => !String(args.path ?? '').endsWith('.test.js');
export default approve;
```

مسار `hooks` / `approve` لازم يكون نسبيًا ويبقى داخل المجلد. `lousho build` يحزّم ملفات `hooks.*` و`approve.*` الجذرية بجانب الـ config ويحلّ ملف `.js` المصرَّف المجاور، فتظل مسارات `.ts` تعمل بعد البناء.

`instructions/<family>.md` تُلحَق بـ `instructions.md` إذا كان معرّف الـ model المحسوب يحتوي `<family>`: فـ `instructions/openai.md` تنطبق على `openai/gpt-4o-mini` وعلى `openrouter/openai/gpt-4o-mini`. أول تطابق بالترتيب الأبجدي يفوز؛ ومعرّف model لا علاقة له يحصل على الـ prompt الأساسي فقط.

### Tools

كل ملف في `tools/` يصدّر افتراضيًا tool مبني بـ `defineTool()`، ويمكنه أيضًا تصدير tools أخرى بالاسم (أو مصفوفة tools). باقي التصديرات تُتجاهَل، لكن ملفًا لا يصدّر أي tool إطلاقًا يعتبر خطأ، وكذلك وجود tool اثنين بنفس الاسم (يُذكَر الملفان كلاهما في الرسالة).

```ts
// tools/send_email.ts
import { z } from 'zod';
import { defineTool } from '@lousho/build-ai-agent';

export default defineTool({
  name: 'send_email',
  description: 'Send an email',
  input: z.object({ to: z.string(), body: z.string() }),
  execute: async ({ to, body }) => ({ sent: true, to, length: body.length }),
});
```

### Skills

`skills/` يقبل ما تقبله `loadSkills()`: `skills/<name>/SKILL.md` و`skills/<name>.md`، ولكل منها `description` في الـ frontmatter. راجع [Skills](/ar/skills).

### Sub-agents

كل مجلد داخل `subagents/` هو نفسه مجلد agent (ويمكن أن يكون له `subagents/` خاص به). لازم يحتوي `description` في الـ config. يحصل الأب على tool باسم `delegate_to_<name>` تشغّل الـ sub-agent بنص المهمة وترجع إجابته النهائية. الـ sub-agent يستخدم `model` الخاص فيه إن حدّده، وإلا ورث موديل الأب؛ أما `provider` override الممرَّر إلى `loadAgentDir()` فيصل إلى الجميع.

مجلد sub-agent يضبط `"engine": "pi"` في الـ config يصير بدلًا من ذلك sub-agent من نوع Pi coding-agent: ينتهي في خريطة `subagents` الخاصة بالأب (tool الـ `task`) بدل الحصول على tool باسم `delegate_to_<name>`، والـ sessions (الجلسات) فيه تعمل داخل مجلد الأب — مساحة العمل التي تتشاركها file tools الخاصة بالأب وجلسة Pi. `model` يأخذ المعرّف المعتاد `pi/<provider>/<model>`، وقواعد `permissions` تتحكم في tool calls الخاصة بجلسة Pi (`read` و`bash` و`edit` و`write` وغيرها). باقي مفاتيح الـ config تُتجاهَل: Pi يحمل system prompt الخاص فيه وcoding tools الخاصة به. تشغيل sub-agent من نوع `pi` يحتاج الـ peer dependency الاختيارية `@earendil-works/pi-coding-agent` والـ Node runtime — هدف Cloudflare Worker يرفضه.

```json
// subagents/coder/agent.json
{
  "description": "Implements code changes in this workspace.",
  "engine": "pi",
  "model": "pi/openrouter/openai/gpt-4o-mini",
  "permissions": [
    { "tool": "bash", "when": { "command": "\\brm\\b" }, "action": "deny" },
    { "tool": "*", "action": "allow" }
  ]
}
```

`loadAgentDir(dir, { piAgent: { ... } })` تحقن خيارات `piAgent()` في كل sub-agent من نوع `engine: 'pi'` (مثل `modelRuntime` وهمي في الاختبارات، أو `sessionDir` لإبقاء الـ approvals بعد إعادة التشغيل)؛ والمجلد دائمًا يفوز في `cwd` و`name` و`description`.

### Channels

كل ملف في `channels/` يصدّر افتراضيًا [channel](/ar/channels) مبني بـ `defineChannel()` أو بأحد المصانع المدمجة (`webhookChannel()` و`httpChannel()` و`slackChannel()` و`discordChannel()` و`telegramChannel()` و`githubChannel()` و`teamsChannel()`). اسم الـ channel هو الاسم الذي تحدّده هي، وإلا فاسم الملف. ملف لا يصدّر channel يفشل بخطأ `LOUSHO_CHANNEL_INVALID` مع ذكر الملف. `resolveAgentDir()` ترجعها في `channels` (وأسماءها في `manifest.channels`)؛ أما `loadAgentDir()` فلا تركّبها. خادم node الذي يولّده `lousho build --target=node-server` يركّبها تحت `/channels` بجانب مسارات الدردشة (`createDeployedServer(agent, { channels })`، وهو helper داخلي في الحزمة المولَّدة)؛ ومع خادمك الخاص استخدم `mountChannels()`:

```ts
import { createServer } from 'node:http';
import { createAgent, mountChannels, resolveAgentDir } from '@lousho/build-ai-agent';

// channels/support.ts: export default webhookChannel({ secret: process.env.HOOK_SECRET ?? '' })
const { config, channels } = await resolveAgentDir('./my-agent');
const handler = mountChannels(createAgent(config), channels);
createServer((req, res) => void handler(req, res).then((handled) => handled || res.writeHead(404).end())).listen(3000);
```

`lousho dev` يركّبها أيضًا، و`lousho build` ينشرها (انظر أدناه).

### Memory

كل ملف في `memory/` يصدّر افتراضيًا [memory slot](/ar/memory): ناتج `defineMemory({ ... })`، أو نفس الخيارات بدون `name` وحينها يكون اسم الملف هو اسم الـ slot. بخلاف الـ schedules والـ channels، الـ slots جزء من الـ agent: `loadAgentDir()` تمرّرها إلى `createAgent({ memory })`، فتعمل الـ tools `remember_<name>` / `recall_<name>` والاسترجاع داخل الـ prompt بدون أي كود إضافي، و`manifest.memory` يسرد أسماءها. كل slot يستخدم `provider` الخاص فيه. ملف لا يصدّر slot يفشل بخطأ `LOUSHO_MEMORY_INVALID` مع ذكر الملف. وأي override لـ `memory` يُمرَّر إلى `loadAgentDir(dir, { overrides })` يُدمَج مع slots المجلد بالاسم: عند التعارض يفوز الـ override.

```ts
import { defineMemory, fileMemory, resolveAgentDir } from '@lousho/build-ai-agent';

// memory/notes.ts: export default { scope: 'global', provider: fileMemory({ dir: './.lousho/memory' }) }
const { manifest } = await resolveAgentDir('./my-agent', {
  memory: [defineMemory({ name: 'notes', scope: 'global', provider: fileMemory({ dir: './.lousho/memory' }) })],
});
console.log(manifest.memory); // names found in memory/
```

## كيف يقابل `createAgent()`

| المجلد | خيار `createAgent()` |
| --------- | ---------------------- |
| `instructions.md` | `instructions` |
| مفاتيح `agent.*` | الخيارات في الجدول أعلاه |
| `tools/` | `tools: [...]` |
| `skills/` | `skills: await loadSkills('./skills')` |
| `subagents/<name>/` | مدخل `delegate_to_<name>` واحد ضمن `tools` |

`resolveAgentDir()` ترجع الخيارات المجمَّعة وmanifest، وهذا مفيد للاختبارات والأدوات:

```ts
import { resolveAgentDir, createAgent } from '@lousho/build-ai-agent';

const { config, manifest } = await resolveAgentDir('./my-agent');
console.log(manifest.tools, manifest.skills, manifest.subagents);
const agent = createAgent({ ...config, maxSteps: 3 });
```

عندما يحتوي المجلد إيصال تثبيت `lousho-registry.json` ([Registry](/ar/registry))، يخبرك `manifest.registry` ما إذا كانت ملفات كل عنصر مثبَّت ما زالت تطابقه، وتعمل tools أي عنصر من الإيصال داخل الـ permission manifest الذي ثُبِّتت معه.

## Overrides

الوسيط الثاني يأخذ نفس خيارات `createAgent()` ويغلب على الملفات. استخدمه لتبديل الـ model في الاختبارات:

```ts
import { loadAgentDir } from '@lousho/build-ai-agent';
import { mockModel } from '@lousho/build-ai-agent/testing';

const agent = await loadAgentDir('./my-agent', { provider: mockModel(['Hi there.']) });
```

overrides الخاصة بـ `tools` و`skills` تستبدل المكتشَفة من المجلد (لا تُدمَج معها). وسلسلة `provider/model` الواردة في ملف تُسقَط عندما تعمل override لـ `provider`، فيُستخدَم الكائن الممرَّر كما هو. `approve: null` / `hooks: null` يزيلان ربط المجلد (الملف الذي يسمّيه الـ config لا يُستورَد أصلًا)؛ أما `undefined` فيُبقيه.

## الانتقال من الملفات إلى الكود

استدعِ `resolveAgentDir()` واطبع `config` والصق ما تحتاجه في استدعاء `createAgent()`؛ أو حمّل المجلد واعمل override فقط للأجزاء التي تريد تملّكها في الكود. الـ tools قيم `defineTool()` عادية، فيمكن استيراد ملف tool من الكود بدون أي تغيير.

## تحميل TypeScript

ملفات `.ts` تُحمَّل بـ `import()` ديناميكي، فيجب أن تكون العملية تعمل أصلًا تحت TypeScript loader: `npx tsx your-script.ts` (أو ts-node أو bun أو deno أو type stripping المدمج في Node). بدون ذلك يفشل التحميل بخطأ يوضّح ذلك. صرّف المجلد أولًا، أو استخدم tools بصيغة `.js`/`.mjs` مع config بصيغة `agent.json` / `agent.yaml` فهي تعمل في كل مكان. وtool بامتداد `.js` يستخدم صيغة `import` يحتاج `"type": "module"` في أقرب `package.json` (أو امتداد `.mjs`).

## شغّله بـ `lousho dev`

```bash
npx lousho dev ./my-agent
```

يقدّم واجهة الدردشة و`POST /chat` للمجلد، ويعيد تحميله عندما يتغيّر `instructions.md` أو ملف الـ config أو `tools/` أو `skills/` أو `subagents/` (راجع [`lousho dev`](/ar/cli#lousho-dev) للتفاصيل). ملف الـ tool يُستورَد من جديد في كل reload، فيسري أي تعديل على `tools/*.ts` من الرسالة التالية. وإعادة التحميل الفاشلة (خطأ syntax أو `instructions.md` فارغ) تُسجَّل وتُعرَض في صفحة الدردشة، والـ agent السابق يواصل الإجابة.

`channels/` الخاصة بالمجلد تُركَّب تحت `/channels` و`schedules/` تُشغَّل، والـ reload يبدّل الاثنين: الـ schedules القديمة تتوقّف قبل أن تبدأ الجديدة، فلا يعيش مؤقّت ولا مسار بعد زوال ملفه. مرّر `--no-schedules` لتركيب الـ channels بدون إطلاق الـ crons (راجع [Schedules في dev](/ar/schedules#في-lousho-dev)).

## انشره بـ `lousho build`

```bash
npx lousho build ./my-agent --target=node-server    # or docker
```

مجلد الـ agent هو وحدة النشر: الخادم المبني يحمّله بـ `resolveAgentDir()` عند الإقلاع، ويشغّل `schedules/` ويركّب `channels/` تحت `/channels`، ويحمي مسارات الدردشة بـ `auth.ts` إن وُجدت ([مصادقة المسارات والهويات](/ar/auth))، ويطبع ما وجده منها. ملفات الكود (الـ config، و`auth.ts`، وملف `hooks.*` / `approve.*` الجذري، و`tools/`، و`schedules/`، و`channels/`، و`memory/`، ومثلها في كل sub-agent) تُحزَّم إلى `dist/agent/**.js`، وتُنسَخ `instructions.md` (مع `instructions/<family>.md`) و`skills/` وملفات config بصيغة JSON/YAML بجانبها، فالخادم لا يحتاج TypeScript loader ولا مصادر ولا `node_modules`. راجع [النشر](/ar/deployment#مجلدات-الـagent). هدف Cloudflare Worker يبني مجلدًا أيضًا مع تضمين كل مجلد فرعي: `subagents/` تصبح `delegate_to_` tools، و`schedules/` تصبح cron triggers، و`channels/` تُركَّب تحت `/channels`، و`memory/` slots تعمل على `kvMemory()` ([Cloudflare Workers](/ar/cloudflare-workers#build-and-deploy)).

## ما لا يغطيه هذا

`lousho mcp` ما زال يأخذ ملف spec للـ agent ([الإعداد](/ar/configuration))، لا مجلدًا.
