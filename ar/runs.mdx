## أسباب الانتهاء

`result.finishReason` تقول لك لماذا انتهى الـrun. يمكن أن يكون سبب الـmodel نفسه لدورته الأخيرة: `'stop'` أو `'length'` أو `'tool_calls'` أو `'content_filter'` أو `'error'`. أو `'awaiting-approval'` إذا توقف الـrun على tool call تحتاج approval من إنسان. أو `'aborted'` إذا ألغيته بـ`signal`. أو `'max-steps'`. أو `'output-invalid'` إذا لم يطابق الرد `output` schema حتى بعد خطوة الإصلاح — راجع [Structured output](/ar/structured-output). أو `'budget-exceeded'` إذا ضربت ميزانية في `limits` مثل `maxTokens` أو `maxCostUsd`، و`result.budget` تحدد أيّ واحدة — راجع [الميزانيات](/ar/configuration#الميزانيات). أو `'guardrail'` إذا حجب guardrail إدخال أو إخراج أو أدوات الـrun، و`result.guardrail` تحدد أيّ واحد — راجع [guardrails الإدخال والإخراج](/ar/guardrails#input-و-output-guardrails).

`'max-steps'` تعني أن ميزانية `maxSteps` (الافتراضية 10) انتهت والـmodel كان ما زال يريد يكمل، فقد يكون الرد فارغًا أو جزئيًا. الـrun الذي ينتهي طبيعيًا ضمن الميزانية يحتفظ بـ`'stop'`. الخطوات التي تأتي من `initialSteps` أو من استئناف بعد approval تُحسب ضمن الميزانية، و`result.steps` هو عدد الخطوات التي تمت. السبب نفسه موجود في `run.done` ضمن [streaming](/ar/streaming)، وفي `finish` اللي هو مقابلها في `onEvent` الـdeprecated.

```ts
import { createAgent, createMockProvider } from '@lousho/build-ai-agent';
const agent = createAgent({ prompt: 'You are helpful.', provider: createMockProvider(), maxSteps: 3 });
const result = await agent.send('Research this thoroughly');
if (result.finishReason === 'max-steps') console.warn(`Gave up after ${result.steps} steps`);
```

## الإلغاء

مرّر `AbortSignal` لإيقاف الـrun: `agent.send(input, { signal })`، أو `AgentExecutor.execute({ ..., signal })`، أو `resumeAfterApproval(..., { signal })`.

```ts
import { createAgent, createMockProvider } from '@lousho/build-ai-agent';
const agent = createAgent({ prompt: 'You are helpful.', provider: createMockProvider() });
const controller = new AbortController();
setTimeout(() => controller.abort(), 5_000); // e.g. from a Stop button
const result = await agent.send('Write a long report', { signal: controller.signal });
console.log(result.finishReason); // 'aborted' if it was cancelled, else 'stop'
```

لمهلة زمنية استخدم `AbortSignal.timeout(ms)`:

```ts
import { createAgent, createMockProvider } from '@lousho/build-ai-agent';
const agent = createAgent({ prompt: 'You are helpful.', provider: createMockProvider() });
const result = await agent.send('Summarize this', { signal: AbortSignal.timeout(30_000) });
```

كيف يتصرف الإلغاء:

- الـ`signal` يُفحص قبل كل call للـmodel وقبل كل tool call. ويُمرَّر إلى الـprovider عبر `GenerateOptions.signal` (يُرسل إلى `ai` SDK باسم `abortSignal`) وإلى كل tool عبر `execute(args, { abortSignal })`، فالعمل الجاري يقدر يوقف مبكرًا. الـ`httpTool` الجاهزة تمرره إلى `fetch`، والـruns الفرعية المفوَّضة (أداة `task`) تُلغى مع الـrun الأب.
- الـrun الملغى **يرجع نتيجة** ولا يرمي rejection: `finishReason: 'aborted'` مع الرسائل والخطوات اللي تمت. الـrejection الناتج عن الإلغاء، مثل `AbortError`، لا يُعتبر فشلًا: أغلفة الـretry والـfallback الخاصة بالـprovider لا تعيد محاولته، ولا يُختصر إلى خطأ provider.
- أحداث الـrun تنتهي بـ`run.done` مع `finishReason: 'aborted'`.
- مع `sessionId` و`checkpointStore` تُحفظ الحالة في checkpoint. إذا استدعيت `execute()` ثانية بنفس الـ`sessionId` يكمل الـrun من حيث توقف، وأي `input` جديد ينضاف كرسالة مستخدم تالية (راجع [Durable execution](/ar/durable-execution)). الـtool calls التي لم يصلها الـrun تأخذ نتيجة `{ error }` تفيد بأنها أُلغيت، فتبقى المحادثة صالحة للـprovider.
- الـsignal الملغاة مسبقًا ترجع فورًا دون استدعاء الـprovider.

## Tool calls متوازية

عندما يطلب الـmodel عدة tools في دورة واحدة تعمل بالتوازي. `toolConcurrency` (في `createAgent()` و`AgentExecutor.execute()`) تحدد أكبر عدد يعمل في نفس الوقت: عدد صحيح موجب، أو `'unbounded'` (الافتراضي). استخدم `1` لتنفيذ متسلسل صارم، مثلًا عندما تتشارك الـtools حالة لا يُؤمَن لمسها بالتوازي.

```ts
import { createAgent, createMockProvider, defineTool } from '@lousho/build-ai-agent';
import { z } from 'zod';

const getWeather = defineTool({
  name: 'get_weather',
  description: 'Current weather for a city',
  input: z.object({ city: z.string() }),
  execute: async ({ city }) => ({ city, tempC: 21 }),
});

const agent = createAgent({
  prompt: 'You are a travel assistant.',
  provider: createMockProvider(),
  tools: [getWeather],
  toolConcurrency: 4, // at most 4 tool calls of a turn in flight
});
```

الضمانات، أيًّا كان الحد:

- **ترتيب السجل هو ترتيب الاستدعاء.** نتائج الـtools تنضاف بالترتيب اللي طلب فيه الـmodel الـcalls، لا بترتيب انتهائها، فيكون طلب الـprovider التالي deterministic.
- **الأحداث.** الـcalls تبدأ بترتيب الطلب. حدث `tool.start` للـcall و`onToolCall` وvalidation الوسائط وhooks الـ`preToolCall` وفحص `needsApproval` تعمل قبل بدايتها مباشرة، call واحدة كل مرة. حدث `tool.done` (أو `tool.error`) يُطلق عند انتهائها، فالنتائج تصل بترتيب الانتهاء. مع `toolConcurrency: 1` تتعاقب أحداث البدء والتسوية تمامًا كما كانت.
- **الموافقات.** أول call تحتاج approval توقف الدفعة: الـcalls اللي قبلها تعمل (بالتوازي) وتُسجَّل نتائجها، ثم يتوقف الـrun على هذه الـcall (`finishReason: 'awaiting-approval'`). الـcalls اللي بعدها لا تبدأ في هذا الـrun. `resumeAfterApproval()` تسجّل نتيجة الـcall المتوقفة (أو رفضها) ثم تشغّل الـcalls اللاحقة بنفس الطريقة، فكل call في الدورة تحصل على نتيجة واحدة بالضبط — راجع [Durable execution](/ar/durable-execution#approval-في-منتصف-batch-من-tool-calls).
- **الإخفاقات معزولة.** الـtool التي ترمي خطأ تأخذ نتيجة خطأ خاصة بها، وأخواتها تكمل. الخطأ المنتشر (`PropagatingToolError`، مثل حاجز عمق التفويض أو hook يرمي) يمنع بدء calls جديدة، وينتظر الجارية حتى تستقر، ثم يرفض الـrun. لا تبقى أي tool تعمل منفصلة.
- **الإلغاء.** إلغاء أثناء تشغيل دفعة ينهي الـrun بـ`finishReason: 'aborted'`. الـcalls التي انتهت تحتفظ بنتائجها، والباقي تأخذ نتيجة تفيد بأنها أُلغيت. الـtools الجارية ترى الإلغاء عبر `abortSignal` الخاص بها.
- **Checkpoints.** مع `sessionId` و`checkpointStore` تُحفظ دورة الـmodel في checkpoint قبل أن تبدأ أي call، ثم تُحفظ من جديد كلما زاد طول سلسلة الـcalls المنتهية بالترتيب (ومع `1`، بعد كل call). الـrun المستأنف لا يعيد تشغيل call مسجَّلة، ولا يسأل الـmodel ثانية عن دورة سبق حفظها.
