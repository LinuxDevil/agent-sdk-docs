موديلات الـ reasoning تفكّر قبل أن ترد. خيار `reasoning` يحدد مقدار التفكير.
والـ run يُرجع لك ما فكّر فيه الموديل منفصلًا عن الجواب: كأحداث `reasoning.*`
في `agent.stream()`، وكـ `result.reasoning`. بادئة `vendor/` في اسم الموديل
هي التي تختار الـ provider. ومع OpenRouter استخدم
`openrouter/<vendor>/<model>` (مثال `openrouter/anthropic/claude-sonnet-4.5`).

```ts
import { createAgent } from 'lousho';

const agent = createAgent({
  model: 'anthropic/claude-sonnet-4-5',
  instructions: 'You solve puzzles.',
  reasoning: 'medium',
});

for await (const event of agent.stream('Which weighs more, a kilo of feathers or a kilo of lead?')) {
  if (event.type === 'reasoning.delta') process.stdout.write(`\x1b[2m${event.text}\x1b[22m`);
  if (event.type === 'reasoning.done') console.log(`\n(${event.tokens ?? '?'} reasoning tokens)`);
  if (event.type === 'text.delta') process.stdout.write(event.text);
}

// One call can think harder; the object form takes a budget and a summary request.
const result = await agent.send('Prove it.', { reasoning: { effort: 'high', budgetTokens: 16_000 } });
console.log(result.reasoning, result.usage.reasoningTokens);
```

## الخيار

`reasoning` إما مستوى effort، `'none' | 'minimal' | 'low' | 'medium' | 'high'`،
أو object:

| الحقل | المعنى |
| --- | --- |
| `effort` | القيم نفسها المذكورة أعلاه. الافتراضي `'medium'`. |
| `budgetTokens` | ميزانية tokens، للـ providers التي تقبلها (Anthropic و OpenRouter). البقية تستخدم `effort`. |
| `summary` | `'auto'` يطلب من الـ Responses API لدى OpenAI ملخصًا للـ reasoning (وهذا هو ما تبثّه OpenAI على أنه reasoning). |
| `force` | أرسل الخيارات حتى لو لم يكن الموديل من عائلات الـ reasoning المعروفة (انظر أدناه). |

حدده في `createAgent({ reasoning })` لكل run، أو لكل call عن طريق
`send(input, { reasoning })` / `stream(input, { reasoning })`. الـ sub-agent
يستخدم `reasoning` الخاص به، لا الخاص بالأب. `AgentExecutor.execute()`
يأخذه كـ `ExecuteOptions.reasoning`، والـ provider المخصص يستلمه كـ
`GenerateOptions.reasoning`.

`'none'` لا يرسل شيئًا: يعمل الموديل بالإعداد الافتراضي لدى الـ provider (موديلات الـ
reasoning من OpenAI تبقى تفكّر بمستوى الـ effort الافتراضي لديها).

## ما يصل لكل provider

| الـ provider | يُرسل في صورة | مقابل الـ effort |
| --- | --- | --- |
| OpenAI | `providerOptions.openai.reasoningEffort` (و`reasoningSummary: 'auto'` مع `summary: 'auto'`) | الـ effort كما هو (`'minimal'` لموديلات GPT-5). |
| Anthropic | `providerOptions.anthropic.thinking: { type: 'enabled', budgetTokens }` | `minimal` = 1024، `low` = 2048، `medium` = 8192، `high` = 24576 token؛ و`budgetTokens` يتقدّم عليها (1024 على الأقل، وهو الحد الأدنى عند Anthropic). |
| OpenRouter | حقل `reasoning` الموحّد في جسم الطلب | `{ max_tokens: budgetTokens }` إذا وُجدت ميزانية، وإلا `{ effort }`. |
| Ollama | `providerOptions.ollama.think: true` (`ollama-ai-provider-v2`، `ai` 6/7) | تشغيل أو إيقاف فقط. مع `ai` 4 (`ollama-ai-provider`) يُتجاهل الخيار، مع تحذير واحد. |

هناك قيود تطبّقها حزم الـ providers نيابة عنك: `@ai-sdk/anthropic` يضيف
ميزانية التفكير فوق `max_tokens` (فتبقى الميزانية دائمًا أقل منه)
ويحذف `temperature` و`topP`، لأن Anthropic لا تسمح بهما مع التفكير؛
و`@ai-sdk/openai` يحذف `temperature` لموديلات الـ reasoning. وكل حزمة
تسجّل تحذيرًا عندما تحذف إعدادًا.

### أي الموديلات توصلها الخيارات

تُرسل الخيارات فقط لعائلات الموديلات المعروف أنها تقبلها. أي أن الموديل الذي
لا يدعم reasoning لن يتلقى خطأ «خيار غير معروف» أبدًا:

| الـ provider | معرّفات الموديلات |
| --- | --- |
| OpenAI | `o1` وإصدارات o-series التي تليه (عدا `o1-mini` / `o1-preview`)، و`gpt-5` وما بعده (عدا موديلات `-chat`) |
| Anthropic | `claude-3-7-*` و`claude-sonnet-4*` و`claude-opus-4*` و`claude-haiku-4*` و`claude-fable-*` وما بعدها |
| OpenRouter | `*/o1`...، `*/gpt-5`...، Claude 3.7 / 4+ (ومنها Fable)، `deepseek-r1`، `deepseek-v3.1`+، `gpt-oss`، `gemini-2.5`+، `grok-3`+، `qwen3`، ومتغيرات `:thinking` |
| Ollama | `deepseek-r1`، `qwen3`، `gpt-oss`، `magistral` |

لأي model id آخر (fine-tune أو عائلة جديدة) مرّر `{ effort, force: true }`.
وإذا كان `reasoning` مضبوطًا والموديل لا تصله الخيارات، يُسجَّل تحذير مرة واحدة لكل provider وموديل.

## الأحداث والنتائج

`agent.stream()` يصدر `reasoning.start`، ثم `reasoning.delta` (مع `text`)
بينما يفكّر الموديل، ثم `reasoning.done` (`text`: النص كاملًا؛ و`tokens` إذا
كان الـ provider قد أبلغ عن عدد الـ reasoning tokens حينها). تأتي الأحداث
داخل الـ step، قبل أول `text.delta` أو `tool.start` فيها. والـ provider الذي
لا يستطيع إجراء streaming يُبلغ عن reasoning الخطوة كـ start/delta/done واحدة
قبل نصها.

`result.reasoning` هو نص الـ reasoning لخطوات الـ run، ويُفصل بين كل خطوة
والتي تليها بسطر فارغ. و`result.usage.reasoningTokens` (وكل عنصر في `stepUsage`)
يعدّ الـ reasoning tokens عندما يُبلغ الـ provider عنها؛ والـ span الخاص بـ
`chat` يحملها في `lousho.usage.reasoning_tokens`.

المستهلِكون يعرضونه أيضًا: `reduceAgentEvents()` تحتفظ به كـ `reasoning`
في رسالة الـ assistant، و`toUIMessageStream()` تصدر أجزاء `reasoning-start` /
`reasoning-delta` / `reasoning-end` لـ `useChat`، و`lousho acp` يرسل
تحديثات `agent_thought_chunk`، و`lousho chat` يطبعه بلون باهت.

## ما يُحفظ في الـ transcript

لا يُكتب الـ reasoning أبدًا في الـ transcript كنص، ولا يُعاد إرساله إلى الـ model
كمحتوى. هناك استثناء واحد يفرضه الـ provider: تحتاج Anthropic الـ thinking
blocks الخاصة بالـ turn، دون تعديل ومع توقيعاتها، عندما تكمل بعد الـ tool
calls في الـ turn نفسها. وبالتالي:

- رسالة الـ assistant التي نفّذت tool calls تحتفظ بالـ thinking blocks
  الموقَّعة (أو المحجوبة) في `message.reasoning`؛ والـ provider الخاص بـ
  Anthropic يعيد إرسالها أولًا في تلك الـ turn. وتبقى موجودة بعد الـ
  step التالية، والـ checkpoint، والاستئناف بعد crash، وتوقّف الـ approval
  (الموافقة)، لأنها جزء من الرسائل المحفوظة.
- الـ reasoning غير الموقَّع (OpenAI و Ollama و OpenRouter) وreasoning
  الرد النهائي لا يُحفظان في `messages`. وعناصر الـ reasoning المشفّرة عند
  OpenAI لا تنتقل بين الخطوات.
- باقي الـ providers تتجاهل `message.reasoning`.
