موديلات الـ reasoning تفكّر قبل ما ترد. خيار `reasoning` يحدد مقدار التفكير.
والـ run يرجّع لك اللي الموديل فكّر فيه منفصلًا عن الجواب: كأحداث `reasoning.*`
في `agent.stream()`، وكـ `result.reasoning`. بادئة `vendor/` في اسم الموديل
هي اللي تختار الـ provider. ومع OpenRouter استخدم
`openrouter/<vendor>/<model>` (مثال `openrouter/anthropic/claude-sonnet-4.5`).

```ts
import { createAgent } from '@lousho/build-ai-agent';

const agent = createAgent({
  model: 'anthropic/claude-sonnet-4-5',
  instructions: 'You solve puzzles.',
  reasoning: 'medium',
});

for await (const event of agent.stream('Which weighs more, a kilo of feathers or a kilo of lead?')) {
  if (event.type === 'reasoning.delta') process.stdout.write(`\x1b[2m${event.text}\x1b[22m`);
  if (event.type === 'reasoning.done') console.log(`\n(${event.tokens ?? '?'} reasoning tokens)`);
  if (event.type === 'text.delta') process.stdout.write(event.text);
}

// One call can think harder; the object form takes a budget and a summary request.
const result = await agent.send('Prove it.', { reasoning: { effort: 'high', budgetTokens: 16_000 } });
console.log(result.reasoning, result.usage.reasoningTokens);
```

## الخيار

`reasoning` إما مستوى effort، `'none' | 'minimal' | 'low' | 'medium' | 'high'`،
أو object:

| الحقل | المعنى |
| --- | --- |
| `effort` | نفس القيم اللي فوق. الافتراضي `'medium'`. |
| `budgetTokens` | ميزانية tokens، للـ providers اللي تقبلها (Anthropic و OpenRouter). الباقي يستخدم `effort`. |
| `summary` | `'auto'` يطلب من الـ Responses API عند OpenAI ملخصًا للـ reasoning (هذا هو اللي OpenAI تبثّه على أنه reasoning). |
| `force` | ابعت الخيارات حتى لو الموديل ما كان من عائلات الـ reasoning المعروفة (شوف تحت). |

حدده في `createAgent({ reasoning })` لكل run، أو لكل call عن طريق
`send(input, { reasoning })` / `stream(input, { reasoning })`. الـ sub-agent
يستخدم `reasoning` الخاص فيه، مو الخاص بالأب. `AgentExecutor.execute()`
ياخذه كـ `ExecuteOptions.reasoning`، والـ provider المخصص يستلمه كـ
`GenerateOptions.reasoning`.

`'none'` ما يبعت شي: الموديل يشتغل بالافتراضي عند الـ provider (موديلات الـ
reasoning من OpenAI تفضل تفكّر بمستوى الـ effort الافتراضي عندها).

## ما يصل لكل provider

| الـ provider | يُرسل في صورة | مقابل الـ effort |
| --- | --- | --- |
| OpenAI | `providerOptions.openai.reasoningEffort` (و`reasoningSummary: 'auto'` مع `summary: 'auto'`) | الـ effort كما هو (`'minimal'` لموديلات GPT-5). |
| Anthropic | `providerOptions.anthropic.thinking: { type: 'enabled', budgetTokens }` | `minimal` = 1024، `low` = 2048، `medium` = 8192، `high` = 24576 token؛ و`budgetTokens` يغلّب عليها (1024 على الأقل، وهو الحد الأدنى عند Anthropic). |
| OpenRouter | حقل `reasoning` الموحّد في جسم الطلب | `{ max_tokens: budgetTokens }` لو في ميزانية، وإلا `{ effort }`. |
| Ollama | `providerOptions.ollama.think: true` (`ollama-ai-provider-v2`، `ai` 6/7) | تشغيل أو إيقاف فقط. مع `ai` 4 (`ollama-ai-provider`) الخيار يتجاهل، مع تحذير واحد. |

في قيود تطبّقها حزم الـ providers عنك: `@ai-sdk/anthropic` يضيف
ميزانية التفكير فوق `max_tokens` (فالميزانية تبقى دائمًا أقل منه)
ويشيل `temperature` و`topP`، لأن Anthropic ما يسمح بهم مع التفكير؛
و`@ai-sdk/openai` يشيل `temperature` لموديلات الـ reasoning. وكل حزمة
تسجّل تحذير لما تشيل إعداد.

### أي الموديلات توصلها الخيارات

الخيارات تتبعت فقط لعائلات الموديلات المعروف إنها تقبلها. يعني موديل
ما يدعم reasoning لن ياخد خطأ «خيار غير معروف» أبدًا:

| الـ provider | معرّفات الموديلات |
| --- | --- |
| OpenAI | `o1` وإصدارات o-series اللي بعده (عدا `o1-mini` / `o1-preview`)، و`gpt-5` وما بعده (عدا موديلات `-chat`) |
| Anthropic | `claude-3-7-*` و`claude-sonnet-4*` و`claude-opus-4*` و`claude-haiku-4*` وما بعدها |
| OpenRouter | `*/o1`...، `*/gpt-5`...، Claude 3.7 / 4+، `deepseek-r1`، `gemini-2.5`+، `grok-3`+، `qwen3`، ومتغيرات `:thinking` |
| Ollama | `deepseek-r1`، `qwen3`، `gpt-oss`، `magistral` |

لأي model id آخر (fine-tune أو عائلة جديدة) مرّر `{ effort, force: true }`.

## الأحداث والنتائج

`agent.stream()` يصدر `reasoning.start`، ثم `reasoning.delta` (مع `text`)
بينما الموديل يفكّر، ثم `reasoning.done` (`text`: النص كله؛ و`tokens` لو
الـ provider كان بلّغ عن عدد الـ reasoning tokens وقتها). الأحداث تجي
داخل الـ step، قبل أول `text.delta` أو `tool.start` فيها. والـ provider اللي
ما يقدر يعمل streaming يبلّغ عن reasoning الخطوة كـ start/delta/done واحدة
قبل نصها.

`result.reasoning` هو نص الـ reasoning لخطوات الـ run، مفصول بين كل خطوة
والتالية بسطر فارغ. و`result.usage.reasoningTokens` (وكل عنصر في `stepUsage`)
يعدّ الـ reasoning tokens لما الـ provider يبلّغ عنها؛ والـ span الخاص بـ
`chat` يحملها في `lousho.usage.reasoning_tokens`.

المستهلِكون يعرضوه هم كمان: `reduceAgentEvents()` تحتفظ به كـ `reasoning`
في رسالة الـ assistant، و`toUIMessageStream()` تصدر أجزاء `reasoning-start` /
`reasoning-delta` / `reasoning-end` لـ `useChat`، و`lousho acp` يبعت
تحديثات `agent_thought_chunk`، و`lousho chat` يطبعه باهت.

## ما يُحفظ في الـ transcript

الـ reasoning ما يتكتب أبدًا في الـ transcript كنص، وما يرجع يتبعت للـ model
كمحتوى. في استثناء واحد يفرضه الـ provider: Anthropic تحتاج الـ thinking
blocks الخاصة بالـ turn، بدون تعديل ومع توقيعاتها، لما تكمل بعد الـ tool
calls في نفس الـ turn. وبالتالي:

- رسالة الـ assistant اللي نفّذت tool calls تحتفظ بالـ thinking blocks
  الموقَّعة (أو المحجوبة) في `message.reasoning`؛ و provider الخاص بـ
  Anthropic يرجع يبعتها أول حاجة في الـ turn ده. وهي تفضل موجودة بعد الـ
  step التالية، والـ checkpoint، والاستئناف بعد crash، وتوقّف الـ approval
  (الموافقة)، لأنها جزء من الرسائل المحفوظة.
- الـ reasoning غير الموقَّع (OpenAI و Ollama و OpenRouter) وreasoning
  الرد النهائي لا يُحفظان في `messages`. وعناصر الـ reasoning المشفّرة عند
  OpenAI لا تنتقل بين الخطوات.
- باقي الـ providers تتجاهل `message.reasoning`.
