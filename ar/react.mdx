`useLoushoAgent()` يحط agent وراء واجهة محادثة. يشغّل turn، يقرأ الـ [typed event stream](/ar/streaming) أول ما يوصل، ويحوّله إلى state جاهز للـ render: رسائل بنصها وtool calls، و`status` لحقل كتابة الرسالة، والـ tool call الواقف على approval إذا فيه واحد.

موجود على الـ subpath `@lousho/build-ai-agent/react`. و`react` (18 أو 19) peer dependency اختيارية: ثبّتها في التطبيق اللي يستخدم الـ hook.

```tsx
import { useLoushoAgent } from '@lousho/build-ai-agent/react';

export function Chat() {
  const agent = useLoushoAgent({ url: '/api/agent' });

  return (
    <form
      onSubmit={(event) => {
        event.preventDefault();
        const input = new FormData(event.currentTarget).get('message');
        if (typeof input === 'string' && input.trim()) void agent.send(input);
        event.currentTarget.reset();
      }}
    >
      {agent.messages.map((message) => (
        <article key={message.id}>
          <header>{message.role}</header>
          <p>{message.text}</p>
          {message.toolCalls.map((call) => (
            <code key={call.id}>{call.name}: {call.status}</code>
          ))}
        </article>
      ))}
      {agent.pendingApproval && (
        <p>
          Run {agent.pendingApproval.toolName}?
          <button type="button" onClick={() => void agent.approve()}>Approve</button>
          <button type="button" onClick={() => void agent.reject('Not now')}>Reject</button>
        </p>
      )}
      <input name="message" disabled={agent.status === 'streaming'} />
      {agent.status === 'streaming' && <button type="button" onClick={agent.stop}>Stop</button>}
    </form>
  );
}
```

## المصادر

أول argument يحدد مكان تشغيل الـ agent.

| المصدر | ما يفعله الـ hook |
| ------ | ------------------ |
| `{ url, headers?, fetch? }` | **Remote.** `send(input)` ترسل `{ "input": "..." }` بـ POST كـ JSON إلى `url` وتقرا الـ response body كـ event stream: SSE (أسطر `data: {...}`) أو JSON مفصول بأسطر، حدث واحد كل سطر. السيرفر اللي تحت يكتب نفس الشيء بالضبط. |
| `{ agent }` | **داخل الـ process.** `send(input)` تنادي `agent.stream(input)`. كل turn هو run جديد بدون history، مثل `agent.send()`. |
| `{ agent, sessionId }` | **داخل الـ process، multi-turn.** الـ hook ينشئ `agent.session({ id: sessionId })` مرة واحدة ويعمل stream لكل turn بـ `session.stream()`، فكل turn يشوف المحادثة اللي قبله. |

وضع داخل الـ process لكود React اللي يشتغل في مكان يقدر الـ agent يشتغل فيه (Electron، React Native، الاختبارات). في المتصفح استخدم الـ remote mode: مفاتيح API للـ models مكانها السيرفر.

## الـ state المُرجَعة

| الحقل | ما هو |
| ----- | ---------- |
| `messages` | `UIMessage[]`: `{ id, role: 'user' \| 'assistant', text, toolCalls, reasoning? }`. كل `send()` يضيف رسالة user ورسالة assistant تمتلي مع وصول `text.delta` وأحداث الـ tools. و`reasoning` يجمع نص `reasoning.delta` اللي يبثه الـ model إذا بث شيء. |
| `toolCalls[i]` | `{ id, name, args, status, result?, error?, partial? }`، و`status` وحدة من `'running'`، `'awaiting-approval'`، `'done'`، `'error'`، `'rejected'`. `partial` هو آخر snapshot `tool.partial` لـ [streaming tool](/ar/tools#streaming-للنتائج-الجزئية) شغالة، وينحذف لما الـ call يستقر أو يتوقف مؤقتًا. |
| `status` | `'idle'`، `'streaming'`، `'awaiting-approval'` أو `'error'`. |
| `pendingApproval` | `{ id, toolCallId, toolName, args }` للـ tool call اللي توقف عنده الـ run، وإلا `null`. لـ call من نوع `ask_question` فيه كمان `kind: 'question'` و`question: { text, options?, allowFreeText? }`. والـ tool اللي مستنية تسجيل دخول OAuth فيها `kind: 'sign-in'` و`signIn: { provider, displayName?, url }` (شوف [ما يراه المستخدم](/ar/oauth#ما-يراه-المستخدم)). |
| `error` | `{ name, message }` لآخر حدث `error` أو لطلب فشل، وإلا `null`. |
| `usage` | استهلاك الـ tokens في آخر run خلص (من `run.done`)، وإلا `null`. |
| `todos` | قائمة الـ todos للـ agent (`{ id, content, status }[]`)، يضبطها كل حدث `todo.updated` من [todo tools](/ar/tools#todo-tools). `[]` لحد ما يوصل أول حدث. تبقى معك عبر الـ turns؛ شوف [Todos](#todos). |
| `lastEvent` | آخر حدث وصل، لأي شي الـ projection ما يغطيه. |
| `send(input)` | يبدأ turn. إذا فيه turn شغالة لسه، تنلغي أولًا. `input` تكون string أو content parts أو `Message[]` (يعني `AgentInput`). فقاعة الـ user تعرض النص مع علامة `[image]` / `[file]` لكل جزء ثاني، والـ remote mode يرسلها بـ POST كـ `{ "input": ... }`. |
| `stop()` | يلغي الـ turn الجارية عن طريق `AbortSignal`، و`status` ترجع `'idle'`. |
| `approve(note?)`, `reject(note?)` | يحسما الـ `pendingApproval` (شوف تحت). |
| `answer(text)` | يجاوب على سؤال (`pendingApproval.kind === 'question'`). نفس `approve(text)`. `reject()` يرفض السؤال. |

إلغاء تركيب المكوّن (unmount) يلغي الـ turn الجارية. أحداث run تبع [sub-agent](/ar/sub-agents) (اللي تحمل `subagent`) ما تغيّر `messages` — إلا `approval.requested` من sub-agent، هو يحدّث `messages` و`pendingApproval` و`status` (التوقف قرار المستخدم). إذا أردت تعرض باقي أحداث الـ sub-agent اقرأها من `lastEvent`.

## Approvals

لما يتنادى tool عليه `needsApproval`، الـ run يتوقف بـ `approval.requested`. `status` تصير `'awaiting-approval'` و`pendingApproval` يمسك الـ call. بعدها:

- **داخل الـ process**، `approve(note?)` و`reject(note?)` ينادوا `agent.approvals.streamResolve({ id, approved, note }, { signal })` (شوف [Approvals](/ar/approvals)). أحداث الـ run المكمّل توصل live، فالنص يلحق برسالة الـ assistant أول بأول و`status` ترجع `'idle'`، أو `'awaiting-approval'` إذا الـ run توقف مرة ثانية.
- **Remote**، مرّر `{ approvalsUrl }` كـ argument ثاني. الـ hook يرسل `{ "approved": true, "note": "..." }` بـ POST إلى `${approvalsUrl}/${approvalId}` ويعرض التكملة live من الـ SSE stream اللي يرد فيه الـ session API (نفس أحداث أي turn محادثة؛ توقف ثاني يوصل كـ `approval.requested`). سيرفر يرد بدلها بـ JSON من نوع `ApprovalOutcome` (زي اللي تحت) يظل شغال.
- **Remote بدون `approvalsUrl`**، `approve()` و`reject()` ما يسووا شيء. اعرض `pendingApproval` واحسمه عبر الـ API الخاص بك، بعدين ابعث الـ turn التالية بـ `send()`.

إذا أنشأت الـ agent بـ `askQuestion: true` يقدر يسأل المستخدم سؤال (شوف [سؤال المستخدم](/ar/approvals#سؤال-المستخدم)). التوقف يوصل بنفس الطريقة، مع `pendingApproval.kind === 'question'`: اعرض `pendingApproval.question.text` والـ `options` تبعه، ونادي `answer(text)`.

## جهة السيرفر

نقطة نهاية Node للـ remote mode، مع route الموافقات (بادئة `vendor/` في اسم الـ model هي اللي تختار الـ provider؛ مع OpenRouter استخدم `openrouter/<vendor>/<model>`، مثل `openrouter/openai/gpt-4o-mini`):

```ts
import { createServer, type IncomingMessage } from 'node:http';
import { createAgent } from '@lousho/build-ai-agent';
import type { ApprovalOutcome } from '@lousho/build-ai-agent/react';

const agent = createAgent({ model: 'openai/gpt-4o-mini' });

async function readJson(req: IncomingMessage): Promise<Record<string, unknown>> {
  let body = '';
  for await (const chunk of req) body += chunk;
  return body ? JSON.parse(body) : {};
}

createServer(async (req, res) => {
  const body = await readJson(req);
  const approval = /^\/api\/approvals\/(.+)$/.exec(req.url ?? '');

  if (approval) {
    const id = decodeURIComponent(approval[1]);
    const note = typeof body.note === 'string' ? body.note : undefined;
    const result = await agent.approvals.resolve({ id, approved: body.approved === true, note });
    const next = (await agent.approvals.list()).find((pending) => pending.id === result.approvalId);
    const outcome: ApprovalOutcome = { text: result.text, finishReason: result.finishReason, usage: result.usage, approval: next };
    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify(outcome));
    return;
  }

  const controller = new AbortController();
  res.on('close', () => controller.abort()); // the hook's stop() or unmount closes the request
  res.writeHead(200, { 'Content-Type': 'text/event-stream', 'Cache-Control': 'no-cache' });
  for await (const event of agent.stream(String(body.input), { signal: controller.signal })) {
    res.write(`data: ${JSON.stringify(event)}\n\n`);
  }
  res.end();
}).listen(3000);
```

الـ client بعدها يستخدم `useLoushoAgent({ url: '/api/agent' }, { approvalsUrl: '/api/approvals' })`. لمحادثة multi-turn، احتفظ بـ `agent.session({ id })` لكل محادثة على السيرفر واستدعِ `session.stream()` بدل `agent.stream()`. أعطِ الـ agent `store` (`createAgent({ store: memoryStore() })` أو store من نوع durable) لما الـ sessions تنفتح مع كل request: بدون store، كل `agent.session({ id })` يحصل على transcript جديد في الذاكرة، والـ turn التالية تنسى الأولى (شوف [اختيار الـ store](/ar/sessions#choosing-a-store)).

## داخل الـ process

الـ hook يستقبل الـ agent نفسه كمان. مثال على استدعائه من hook مخصّص:

```ts
import { createAgent } from '@lousho/build-ai-agent';
import { useLoushoAgent } from '@lousho/build-ai-agent/react';

const agent = createAgent({ model: 'openai/gpt-4o-mini' });

export function useSupportChat() {
  const chat = useLoushoAgent({ agent, sessionId: 'support' });
  const lastReply = chat.messages.filter((m) => m.role === 'assistant').at(-1)?.text ?? '';
  return { ...chat, lastReply, busy: chat.status === 'streaming' };
}
```

## بدون React

الـ hook مجرد wrapper رقيق. منطق الـ state هو `reduceAgentEvents(state, event)`، reducer نقي يشتغل على `AgentEvent` وشوية actions محلية (`ui.send`، `ui.decide`، `ui.resumed`، `ui.stopped`، `ui.reset`، `ui.error`). و`parseEventStream(response)` يقرأ الأحداث من response تبع fetch. الاتنين مُصدَّرين من نفس الـ subpath، عشان binding مخصّص أو client بدون React:

```ts
import { initialAgentUIState, parseEventStream, reduceAgentEvents } from '@lousho/build-ai-agent/react';

let state = reduceAgentEvents(initialAgentUIState, { type: 'ui.send', input: 'Weather in Paris?' });
const response = await fetch('http://localhost:3000/api/agent', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ input: 'Weather in Paris?' }),
});
for await (const event of parseEventStream(response)) {
  state = reduceAgentEvents(state, event);
}
console.log(state.status, state.messages.at(-1)?.text, state.usage?.totalTokens);
```

`parseEventStream()` يتخطى الأسطر الفاضية وتعليقات SSE وحقول `event:`/`id:` وأي سطر ليس حدثًا معروفًا، لذلك يقرأ صيغتَي التأطير الاثنتين. الخروج من حلقته يلغي الـ response body.

## Todos

الـ agent اللي عنده [todo tools](/ar/tools#todo-tools) يطلق حدث `todo.updated` مع كل `todo_write`. الـ hook يخزن أحدث قائمة في `todos`، و`useTodos(agent)` يحوّلها إلى view فيه العدّادات والبند الجاري والتقدم. يستقبل ناتج الـ hook، فـ stream واحد يغذي المحادثة والخطة. القائمة تبقى عبر الـ turns وما يمسحها شيء غير hook جديد — ولا تُستعاد لما الصفحة ترجع تتصل بـ session موجودة.

```tsx
import { useLoushoAgent, useTodos } from '@lousho/build-ai-agent/react';

export function Plan() {
  const agent = useLoushoAgent({ url: '/api/agent' });
  const { todos, counts, current, progress } = useTodos(agent);

  return (
    <aside>
      <p>
        {counts.completed} of {counts.total} done ({Math.round(progress * 100)}%)
        {current && <> - now: {current.content}</>}
      </p>
      <ul>
        {todos.map((todo) => (
          <li key={todo.id}>
            {todo.status === 'completed' ? '[x]' : todo.status === 'in_progress' ? '[>]' : '[ ]'} {todo.content}
          </li>
        ))}
      </ul>
      <button onClick={() => agent.send('Migrate the repo to ESM')}>Start</button>
    </aside>
  );
}
```

`current` هو البند `in_progress`، وإذا ما فيه فهو أول بند `pending`، و`undefined` لما ما يبقى شيء. `progress` هو `completed / total` (0 لقائمة فاضية). الـ view مُخزَّن memoized على `agent.todos`. و`todoView(todos)` يحسب نفس الـ view خارج React.
