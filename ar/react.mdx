`useLoushoAgent()` يضع agent خلف واجهة محادثة. يشغّل turn، ويقرأ الـ [typed event stream](/ar/streaming) فور وصوله، ويحوّله إلى state جاهزة للـ render: رسائل بنصها وtool calls، و`status` لحقل كتابة الرسالة، والـ tool call المتوقف على approval إن وُجد.

موجود على الـ subpath `lousho/react`. و`react` (18 أو 19) peer dependency اختيارية: ثبّتها في التطبيق الذي يستخدم الـ hook.

```tsx
import { useLoushoAgent } from 'lousho/react';

export function Chat() {
  const agent = useLoushoAgent({ url: '/api/agent' });

  return (
    <form
      onSubmit={(event) => {
        event.preventDefault();
        const input = new FormData(event.currentTarget).get('message');
        if (typeof input === 'string' && input.trim()) void agent.send(input);
        event.currentTarget.reset();
      }}
    >
      {agent.messages.map((message) => (
        <article key={message.id}>
          <header>{message.role}</header>
          <p>{message.text}</p>
          {message.toolCalls.map((call) => (
            <code key={call.id}>{call.name}: {call.status}</code>
          ))}
        </article>
      ))}
      {agent.pendingApproval && (
        <p>
          Run {agent.pendingApproval.toolName}?
          <button type="button" onClick={() => void agent.approve()}>Approve</button>
          <button type="button" onClick={() => void agent.reject('Not now')}>Reject</button>
        </p>
      )}
      <input name="message" disabled={agent.status === 'streaming'} />
      {agent.status === 'streaming' && <button type="button" onClick={agent.stop}>Stop</button>}
    </form>
  );
}
```

## المصادر

الـ argument الأول يحدد مكان تشغيل الـ agent.

| المصدر | ما يفعله الـ hook |
| ------ | ------------------ |
| `{ url, sessionId?, headers?, fetch? }` | **Remote.** `send(input)` ترسل `{ "input": "...", "sessionId": "..." }` بـ POST كـ JSON إلى `url` وتقرأ الـ response body كـ event stream: SSE (أسطر `data: {...}`؛ وقد يمتد JSON الحدث الواحد على أكثر من سطر `data:`) أو JSON مفصول بأسطر، حدث واحد في كل سطر. الخادم أدناه يكتب الشيء نفسه بالضبط. يولّد الـ hook `sessionId` واحدًا لكل محادثة ويرسله مع كل turn، فيحفظ الخادم الذي يعرف الـ sessions (`createRouteHandler`) المحادثة؛ مرّر `sessionId` خاصًا بك لتستأنف session محفوظة. و`reset()` يبدأ محادثة بـ id جديد. |
| `{ agent }` | **داخل الـ process.** `send(input)` تستدعي `agent.stream(input)`. كل turn هو run جديد دون history، مثل `agent.send()`. |
| `{ agent, sessionId }` | **داخل الـ process، multi-turn.** ينشئ الـ hook `agent.session({ id: sessionId })` مرة واحدة ويُجري stream لكل turn بـ `session.stream()`، فيرى كل turn المحادثة التي سبقته. |

وضع داخل الـ process مخصص لكود React الذي يعمل في مكان يستطيع الـ agent أن يعمل فيه (Electron، React Native، الاختبارات). في المتصفح استخدم الـ remote mode: مكان مفاتيح API الخاصة بالـ models هو الخادم.

## الـ state المُرجَعة

| الحقل | ما هو |
| ----- | ---------- |
| `messages` | `UIMessage[]`: `{ id, role: 'user' \| 'assistant', text, toolCalls, reasoning?, finishReason?, object? }`. نص كل step من الـ model يبدأ فقرة جديدة (`\n\n`)؛ وفي run له `output` schema يكون هو الرد النهائي، و`object` يحتوي القيمة بعد التحقق منها. كل `send()` يضيف رسالة user ورسالة assistant تمتلئ مع وصول `text.delta` وأحداث الـ tools. و`reasoning` يجمع نص `reasoning.delta` الذي يبثه الـ model إذا بث شيئًا. |
| `toolCalls[i]` | `{ id, name, args, status, result?, error?, partial? }`، و`status` واحدة من `'running'`، `'awaiting-approval'`، `'done'`، `'error'`، `'rejected'`. `partial` هو آخر snapshot `tool.partial` لـ [streaming tool](/ar/tools#streaming-للنتائج-الجزئية) قيد التشغيل، ويُحذف عندما يستقر الـ call أو يتوقف مؤقتًا. |
| `status` | `'idle'`، `'streaming'`، `'awaiting-approval'` أو `'error'`. |
| `pendingApproval` | `{ id, toolCallId, toolName, args }` للـ tool call الذي توقف عنده الـ run، وإلا `null`. والـ call من نوع `ask_question` يحتوي أيضًا `kind: 'question'` و`question: { text, options?, allowFreeText? }`. والـ tool التي تنتظر تسجيل دخول OAuth تحتوي `kind: 'sign-in'` و`signIn: { provider, displayName?, url }` (انظر [ما يراه المستخدم](/ar/oauth#ما-يراه-المستخدم)). |
| `error` | `{ name, message }` لآخر حدث `error` أو لطلب فشل، وإلا `null`. إذا انتهى remote stream قبل `run.done` الخاص به (timeout في الـ proxy، أو إعادة تشغيل الخادم) تصبح `status: 'error'` مع error اسمه `StreamEndedError`، أو يبقى حدث `error` من الخادم إذا وصل قبله. |
| `usage` | استهلاك الـ tokens في آخر run انتهى (من `run.done`)، وإلا `null`. |
| `finishReason` | كيف انتهى آخر run (`run.done`): `'stop'`، `'max-steps'`، `'output-invalid'`، `'budget-exceeded'`، `'guardrail'`، ...؛ و`null` قبل أن ينتهي أول run. القيم الأربع التي تلي `stop` تضبط أيضًا `status: 'error'` و`error` اسمه `RunEndedError` (إلا إذا سبقها حدث `error` وضبطه)، لكي لا تبدو المحادثة كأنها انتهت بشكل طبيعي. |
| `todos` | قائمة الـ todos للـ agent (`{ id, content, status }[]`)، يضبطها كل حدث `todo.updated` من [todo tools](/ar/tools#todo-tools). `[]` إلى أن يصل أول حدث. تبقى معك عبر الـ turns؛ انظر [Todos](#todos). |
| `partialObject` | لـ agent لديه `output` schema: الرد المُحلَّل حتى الآن، من آخر حدث `object.delta` (أفضل محاولة، دون تحقق)، ثم الـ `object` المتحقق منه من `run.done`. يكون `null` حتى أول `object.delta` في الـ run، و`send()` يعيده إلى البداية. |
| `lastEvent` | آخر حدث وصل، لأي شيء لا يغطيه الـ projection. |
| `send(input)` | يبدأ turn. إذا كانت هناك turn لا تزال قيد التشغيل، تُلغى أولًا. `input` تكون string أو content parts أو `Message[]` (أي `AgentInput`). فقاعة الـ user تعرض النص مع علامة `[image]` / `[file]` لكل جزء آخر، والـ remote mode يرسلها بـ POST كـ `{ "input": ... }`. |
| `reset()` | يلغي الـ run، وينسى الـ session الموجودة داخل الـ process، ويمسح المحادثة (والـ remote mode يبدأ محادثة بـ id جديد)، مثل `reset()` في bindings الخاصة بـ Vue و Svelte. |
| `stop()` | يلغي الـ turn الجارية عبر `AbortSignal`، وتعود `status` إلى `'idle'`. |
| `approve(note?)`, `reject(note?)` | يحسمان الـ `pendingApproval` (انظر أدناه). |
| `answer(text)` | يجيب عن سؤال (`pendingApproval.kind === 'question'`). مثل `approve(text)`. `reject()` يرفض السؤال. |

إلغاء تركيب المكوّن (unmount) يلغي الـ turn الجارية. أحداث run الخاص بـ [sub-agent](/ar/sub-agents) (التي تحمل `subagent`) لا تغيّر `messages` — باستثناء `approval.requested` من sub-agent، فهو يحدّث `messages` و`pendingApproval` و`status` (التوقف قرار المستخدم). إذا أردت عرض بقية أحداث الـ sub-agent فاقرأها من `lastEvent`.

## Approvals

عندما يُستدعى tool عليه `needsApproval`، يتوقف الـ run بـ `approval.requested`. تصبح `status` هي `'awaiting-approval'` ويمسك `pendingApproval` الـ call. بعد ذلك:

- **داخل الـ process**، `approve(note?)` و`reject(note?)` يستدعيان `agent.approvals.streamResolve({ id, approved, note }, { signal })` (انظر [Approvals](/ar/approvals)). أحداث الـ run المكمَّل تصل live، فيُلحق النص برسالة الـ assistant أولًا بأول وتعود `status` إلى `'idle'`، أو `'awaiting-approval'` إذا توقف الـ run مرة أخرى.
- **Remote**، مرّر `{ approvalsUrl }` كـ argument ثانٍ. يرسل الـ hook `{ "approved": true, "note": "..." }` بـ POST إلى `${approvalsUrl}/${approvalId}` ويعرض التكملة live من الـ SSE stream الذي يرد به الـ session API (أحداث أي turn محادثة نفسها؛ والتوقف الثاني يصل كـ `approval.requested`). والخادم الذي يرد بدلًا من ذلك بـ JSON من نوع `ApprovalOutcome` (مثل الذي أدناه) يظل يعمل.
- **Remote دون `approvalsUrl`**، لا يفعل `approve()` و`reject()` شيئًا. اعرض `pendingApproval` واحسمه عبر الـ API الخاص بك، ثم أرسل الـ turn التالية بـ `send()`.

إذا أنشأت الـ agent بـ `askQuestion: true` يستطيع أن يطرح سؤالًا على المستخدم (انظر [سؤال المستخدم](/ar/approvals#سؤال-المستخدم)). يصل التوقف بالطريقة نفسها، مع `pendingApproval.kind === 'question'`: اعرض `pendingApproval.question.text` والـ `options` الخاصة به، واستدعِ `answer(text)`.

## جهة السيرفر

نقطة نهاية Node للـ remote mode، مع route الموافقات (بادئة `vendor/` في اسم الـ model هي التي تختار الـ provider؛ مع OpenRouter استخدم `openrouter/<vendor>/<model>`، مثل `openrouter/openai/gpt-4o-mini`):

```ts
import { createServer, type IncomingMessage } from 'node:http';
import { createAgent } from 'lousho';
import type { ApprovalOutcome } from 'lousho/react';

const agent = createAgent({ model: 'openai/gpt-4o-mini' });

async function readJson(req: IncomingMessage): Promise<Record<string, unknown>> {
  let body = '';
  for await (const chunk of req) body += chunk;
  return body ? JSON.parse(body) : {};
}

createServer(async (req, res) => {
  const body = await readJson(req);
  const approval = /^\/api\/approvals\/(.+)$/.exec(req.url ?? '');

  if (approval) {
    const id = decodeURIComponent(approval[1]);
    const note = typeof body.note === 'string' ? body.note : undefined;
    const result = await agent.approvals.resolve({ id, approved: body.approved === true, note });
    const next = (await agent.approvals.list()).find((pending) => pending.id === result.approvalId);
    const outcome: ApprovalOutcome = { text: result.text, finishReason: result.finishReason, usage: result.usage, approval: next };
    res.writeHead(200, { 'Content-Type': 'application/json' });
    res.end(JSON.stringify(outcome));
    return;
  }

  const controller = new AbortController();
  res.on('close', () => controller.abort()); // the hook's stop() or unmount closes the request
  res.writeHead(200, { 'Content-Type': 'text/event-stream', 'Cache-Control': 'no-cache' });
  for await (const event of agent.stream(String(body.input), { signal: controller.signal })) {
    res.write(`data: ${JSON.stringify(event)}\n\n`);
  }
  res.end();
}).listen(3000);
```

بعد ذلك يستخدم الـ client `useLoushoAgent({ url: '/api/agent' }, { approvalsUrl: '/api/approvals' })`. لمحادثة multi-turn، احتفظ بـ `agent.session({ id })` لكل محادثة على الخادم واستدعِ `session.stream()` بدلًا من `agent.stream()`. أعطِ الـ agent `store` (`createAgent({ store: memoryStore() })` أو store من نوع durable) عندما تُفتح الـ sessions مع كل request: دون store، يحصل كل `agent.session({ id })` على transcript جديد في الذاكرة، وتنسى الـ turn التالية الأولى (انظر [اختيار الـ store](/ar/sessions#choosing-a-store)).

## داخل الـ process

الـ hook يستقبل الـ agent نفسه أيضًا. مثال على استدعائه من hook مخصّص:

```ts
import { createAgent } from 'lousho';
import { useLoushoAgent } from 'lousho/react';

const agent = createAgent({ model: 'openai/gpt-4o-mini' });

export function useSupportChat() {
  const chat = useLoushoAgent({ agent, sessionId: 'support' });
  const lastReply = chat.messages.filter((m) => m.role === 'assistant').at(-1)?.text ?? '';
  return { ...chat, lastReply, busy: chat.status === 'streaming' };
}
```

## بدون React

الـ hook مجرد wrapper رقيق. منطق الـ state هو `reduceAgentEvents(state, event)`، reducer نقي يعمل على `AgentEvent` وعلى بضعة actions محلية (`ui.send`، `ui.decide`، `ui.resumed`، `ui.stopped`، `ui.reset`، `ui.error`). و`parseEventStream(response)` يقرأ الأحداث من response الخاص بـ fetch. كلاهما مُصدَّر من الـ subpath نفسه، لاستخدامهما في binding مخصّص أو client دون React:

```ts
import { initialAgentUIState, parseEventStream, reduceAgentEvents } from 'lousho/react';

let state = reduceAgentEvents(initialAgentUIState, { type: 'ui.send', input: 'Weather in Paris?' });
const response = await fetch('http://localhost:3000/api/agent', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ input: 'Weather in Paris?' }),
});
for await (const event of parseEventStream(response)) {
  state = reduceAgentEvents(state, event);
}
console.log(state.status, state.messages.at(-1)?.text, state.usage?.totalTokens);
```

`parseEventStream()` يتخطى الأسطر الفارغة وتعليقات SSE وحقول `event:`/`id:` وأي سطر ليس حدثًا معروفًا، لذلك يقرأ صيغتَي التأطير الاثنتين. الخروج من حلقته يلغي الـ response body.

## Todos

الـ agent الذي لديه [todo tools](/ar/tools#todo-tools) يطلق حدث `todo.updated` مع كل `todo_write`. يخزن الـ hook أحدث قائمة في `todos`، و`useTodos(agent)` يحوّلها إلى view فيه العدّادات والبند الجاري والتقدم. يستقبل ناتج الـ hook، فيغذي stream واحد المحادثة والخطة. تبقى القائمة عبر الـ turns ولا يمسحها شيء سوى hook جديد — ولا تُستعاد عندما تعيد الصفحة الاتصال بـ session موجودة.

```tsx
import { useLoushoAgent, useTodos } from 'lousho/react';

export function Plan() {
  const agent = useLoushoAgent({ url: '/api/agent' });
  const { todos, counts, current, progress } = useTodos(agent);

  return (
    <aside>
      <p>
        {counts.completed} of {counts.total} done ({Math.round(progress * 100)}%)
        {current && <> - now: {current.content}</>}
      </p>
      <ul>
        {todos.map((todo) => (
          <li key={todo.id}>
            {todo.status === 'completed' ? '[x]' : todo.status === 'in_progress' ? '[>]' : '[ ]'} {todo.content}
          </li>
        ))}
      </ul>
      <button onClick={() => agent.send('Migrate the repo to ESM')}>Start</button>
    </aside>
  );
}
```

`current` هو البند `in_progress`، وإن لم يوجد فهو أول بند `pending`، و`undefined` عندما لا يبقى شيء. `progress` هو `completed / total` (0 لقائمة فارغة). الـ view مُخزَّن memoized على `agent.todos`. و`todoView(todos)` يحسب الـ view نفسه خارج React.
