`createRouteHandler(agent, options?)` يشغّل الـ agent من ملف route في أي framework تستقبل الـ handlers فيه `Request` من Web API وترجع `Response`: الـ Next.js App Router، وSvelteKit، وRemix / React Router، وHono، وBun.serve. هو غلاف رفيع فوق نفس session API المستخدم في `lousho dev` وفي السيرفر المنشور ([النشر](/ar/deployment))، لذلك تشتغل الـ bindings الخاصة بـ React وVue وSvelte معه بدون أي تغيير. لا يستورد أي framework ولا أي module من `node:*`. بادئة `vendor/` في اسم الـ model هي التي تحدد الـ provider؛ ومع OpenRouter استخدم `openrouter/<vendor>/<model>` (مثل `openrouter/openai/gpt-4o-mini`).

## Next.js App Router

```ts
// app/api/agent/[[...path]]/route.ts
import { createAgent, createRouteHandler, memoryStore } from 'lousho';

// `store` is what lets a session survive across requests: without one every
// `agent.session({ id })` the handler opens gets a fresh in-memory transcript,
// so a second turn forgets the first and `GET /chat/:id` returns empty.
const agent = createAgent({
  model: 'openai/gpt-4o-mini',
  instructions: 'You are helpful.',
  store: memoryStore(), // lives in the server process; use a durable store on serverless
});

export const { GET, POST } = createRouteHandler(agent, {
  basePath: '/api/agent',
  auth: process.env.AGENT_TOKEN,
  uiMessageStream: true,
});
```

**الـ route بدون `auth` عام (public)**: أي شخص يصل إليه يقدر يشغّل الـ agent ويصرف ميزانية الـ model عندك. مرّر bearer token، أو دالة تتحقق من الـ session أو الـ cookie الخاصة بتطبيقك:

```ts
import { createAgent, createRouteHandler } from 'lousho';

declare function isSignedIn(request: Request): Promise<boolean>;

export const { GET, POST } = createRouteHandler(createAgent({ model: 'openai/gpt-4o-mini' }), {
  auth: (request) => isSignedIn(request),
});
```

## المسارات

كل المسارات تحت `basePath` (الافتراضي `/api/agent`؛ الشرطة المائلة في آخره مقبولة، وأي طلب خارج الـ base path يرجع 404).

| المسار | ما يفعله |
| --- | --- |
| `POST <basePath>` | `{ input, sessionId? }`: الـ turn يصل بالبث عبر SSE. هذا ما يرسله `useLoushoAgent({ url })`؛ وبدون `sessionId` كل turn يفتح session جديدة |
| `POST <basePath>/approvals/:id` | `{ approved, note? }` أو `{ answer }`: الاستكمال يصل بالبث (`approvalsUrl` في `useLoushoAgent`) |
| `POST <basePath>/chat` | `{ sessionId, input }`: نفس session API في السيرفر المنشور |
| `GET <basePath>/chat/:sessionId` | الـ transcript الخاص بالـ session والـ approvals (الموافقات) المعلّقة (الـ turn المتوقف على approval يكون في `pending`، وليس بعد في `messages`) |
| `POST <basePath>/chat/:sessionId/approvals/:id` | حسم approval داخل session |
| `POST <basePath>/ui` | مع `uiMessageStream: true`: الـ endpoint الذي يستخدمه `useChat` من AI SDK |
| `GET <basePath>/oauth/callback` | الـ redirect من الـ OAuth provider بعد تسجيل الدخول؛ لا يمر على `auth` أبدًا (يحميه `state` الذي يُستخدم مرة واحدة) |
| `GET <basePath>/health` | `ok`، ولا يمر على `auth` أبدًا |

الـ agent يحتفظ بالـ sessions عبر `store` الخاص به (`createAgent({ store })`)، فإذا كنت تستخدم sessions أعطِ الـ agent ‏store يعيش أطول من استدعاء serverless واحد. مع `auth`، يرتبط معرّف الـ session بأول principal يرسل إليه turn (قراءة المعرّف لا تحجزه)، وأي principal آخر يحصل على `403` (`LOUSHO_SESSION_FORBIDDEN`). هذا الربط محفوظ في الذاكرة، فالـ instance الجديدة على serverless تنساه، وعندها ترفض الـ session المخزّنة لكل المستخدمين، حتى لمالكها: في تطبيق فيه أكثر من مستخدم، مرّر `authorizeSession` أيضًا، مثلًا مع معرّفات مشتقة من المتصل (`${userId}-<suffix without '-'>`، كما في المثال أدناه). راجع [من يحق له استخدام session](/ar/auth#من-يقدر-يستخدم-الـ-session).

مسارات POST تقبل JSON فقط (`Content-Type: application/json`، وهو ما يرسله `useLoushoAgent` و`useChat`)، وترفض طلب متصفح من origin آخر إلا إذا أضفته إلى `allowedOrigins`: راجع [الطلبات عبر المواقع](/ar/auth#الطلبات-بين-المواقع).

**من يحق له الموافقة على استدعاء.** لا يوجد في `createRouteHandler` خيار `approvers`؛ الـ approvals تُحسم عبر `authorizeApproval({ principal, sessionId, approval })`. افتراضيًا (`callerOwnsApproval`) المستخدم الذي يشتغل الاستدعاء المحجوز (gated) لصالحه هو من يقدر يوافق عليه، ولا يقدر يحسم استدعاء مستخدم آخر، فالتطبيق ذو المستخدم الواحد الذي يسأل مستخدمه نفسه لا يحتاج أي شيء. وهذا يعني أيضًا أن المستخدم يقدر يوافق على استرداد مبلغ لنفسه. إذا لازم تأتي الموافقة من شخص آخر، مرّر `authorizeApproval`. هذه قاعدة الشخصين: المشرف هو من يحسم، وأبدًا ليس على استدعاء يشتغل لصالحه هو. ويحتاج المشرف أيضًا `authorizeSession` حتى يقرأ session العميل (`GET /chat/:id`، ليعرض ما يوافق عليه) ويحسم فيها؛ فافتراضيًا الـ session ملك العميل وحده:

```ts
import { createAgent, createRouteHandler, memoryStore } from 'lousho';
import { jwt } from 'lousho/auth';

const agent = createAgent({ model: 'openai/gpt-4o-mini', store: memoryStore() });
const isSupervisor = (principal?: { claims?: Readonly<Record<string, unknown>> }) => principal?.claims?.role === 'supervisor';
// Session ids are `<user id>-<suffix without '-'>`; the owner is everything before the last `-`
// (a prefix match would let `alice` reach `alice-x`'s sessions).
const ownerOf = (sessionId: string) => sessionId.slice(0, Math.max(sessionId.lastIndexOf('-'), 0));

export const { GET, POST } = createRouteHandler(agent, {
  auth: jwt({ secret: process.env.JWT_SECRET!, issuer: 'https://auth.example.com', audience: 'agent-api' }),
  // Customers use their own sessions; supervisors may read and decide in any session.
  authorizeSession: ({ principal, sessionId, action }) =>
    (principal !== undefined && ownerOf(sessionId) === principal.id) || (action !== 'chat' && isSupervisor(principal)),
  authorizeApproval: ({ principal, approval }) =>
    isSupervisor(principal) &&
    !(principal?.id === approval.principal?.id && principal?.issuer === approval.principal?.issuer),
});
```

الخطأ يصل إلى الـ client على شكل `name` و`code` مع رسالة عامة؛ و`exposeErrors: true` يرسل النص الأصلي. راجع [من يحق له حسم approval](/ar/auth#من-يقدر-يحسم-الـ-approval) لمعرفة الـ `403` الذي يرد به، ولصيغة المشرف في أي session.

إذا اختفى الـ client أثناء بث turn في session (تبويب أُغلق، اتصال انقطع)، يكمل الـ turn حتى نهايته على السيرفر ويُحفظ في الـ session، فالـ tool الذي اشتغل فعلًا (استرداد مبلغ، بريد إلكتروني) يكون في الـ transcript، والرسالة التالية من المستخدم تقدر تسأل عنه. لا يُكتب أي شيء بعد ذلك في الـ stream المغلق. على host من نوع serverless، مرّر `waitUntil` الخاص بالمنصة (مثلًا `waitUntil` من `@vercel/functions`) حتى تبقى الـ function حيّة إلى أن يُحفظ الـ turn. أما `onDisconnect: 'abort'` فيلغي الـ turn بدلًا من ذلك، كما كان سابقًا؛ ونتائج الـ tools التي حصل عليها تبقى محفوظة.

`auth` يقبل أيضًا قائمة مرتبة من `jwt()` و`oidc()` و`basic()` و`apiToken()`، والمتصل الذي تقبله يصل إلى الـ run باسم `principal`: راجع [auth المسارات والـ principals](/ar/auth).

## Client: `useLoushoAgent`

```tsx
'use client';
import { useLoushoAgent } from 'lousho/react';

export function Chat() {
  const agent = useLoushoAgent({ url: '/api/agent', headers: { Authorization: `Bearer ${token}` } }, { approvalsUrl: '/api/agent/approvals' });
  // agent.messages, agent.send(text), agent.approve() ...
}
```

## Client: `useChat`

مع `uiMessageStream: true`، وجّه `useChat` إلى الـ route ‏`ui`. الـ `id` الخاص بالمحادثة هو اسم الـ session، لذلك لا يصل إلى الـ agent إلا آخر رسالة من المستخدم ([AI SDK UI](/ar/ai-sdk-ui)).

```tsx
import { useChat } from '@ai-sdk/react';
import { DefaultChatTransport } from 'ai';

// ai 6/7 signature; on ai 4 (also a supported peer) use useChat({ api: '/api/agent/ui' })
const { messages, sendMessage } = useChat({ transport: new DefaultChatTransport({ api: '/api/agent/ui' }) });
```

## Frameworks أخرى

نفس الـ handler، مركّبًا في المكان الذي تتوقعه الـ framework:

```ts
import { createAgent, createRouteHandler } from 'lousho';

const { handler } = createRouteHandler(createAgent({ model: 'openai/gpt-4o-mini' }), { basePath: '/agent', auth: 'secret' });

// SvelteKit: src/routes/agent/[...path]/+server.ts
export const GET = ({ request }: { request: Request }) => handler(request);
export const POST = ({ request }: { request: Request }) => handler(request);

// Hono: app.all('/agent/*', (c) => handler(c.req.raw))
// Bun.serve: fetch: handler
```
