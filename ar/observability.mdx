`AgentExecutor.execute()` و`FlowExecutor.execute()` ينتجان spans عبر `TraceExporter`. أسماء الـ spans والـ attributes تتبع [GenAI semantic conventions في OpenTelemetry](https://opentelemetry.io/docs/specs/semconv/gen-ai/)، فالـ observability backends التي تفهم GenAI تتعرف عليها بدون mapping خاص.

> **الاستقرار.** اصطلاحات GenAI ما زالت بحالة `Development` (يعني غير مستقرة). أسماء الـ attributes تغيّرت بين إصدارات المواصفة من قبل — مثلا `gen_ai.system` صارت `gen_ai.provider.name` — وممكن تتغير مرة ثانية. الـ SDK تتبع المواصفة كما هي بتاريخ 2026-10-01 من [مستودع semantic-conventions-genai](https://github.com/open-telemetry/semantic-conventions-genai) (مكانها الحالي). إذا الـ dashboards عندك تعتمد على هذه الأسماء، ثبّت إصدار الـ SDK.

## البداية السريعة

مرّر `exporter` إلى `createAgent()`. بعدها كل run للـ agent يتسجّل له trace: `send()` و`stream()` وturns الـ session (الجلسة) و`resume()` والـ runs التي يكملها `agent.approvals.resolve()` — حتى الـ sub-agents. إذا تريد تحفظ الـ traces على القرص وتتصفحها بـ `npx lousho traces`، استخدم `fileTraceExporter()` (شوف [Local traces](#local-traces)). بادئة `vendor/` في اسم الـ model تختار الـ provider؛ مع OpenRouter استخدم `openrouter/<vendor>/<model>` (مثلا `openrouter/openai/gpt-4o-mini`).

```ts
import { createAgent } from '@lousho/build-ai-agent';
import { fileTraceExporter } from '@lousho/build-ai-agent/traces';

const agent = createAgent({
  model: 'openai/gpt-4o-mini',
  instructions: 'You are a helpful assistant.',
  exporter: fileTraceExporter(), // writes .lousho/traces/<day>/<traceId>.jsonl
});
```

أي object فيه `onSpanStart` و`onSpanEnd` يعتبر exporter.

#### متقدم: الـ executor API

مع الـ executor، مرّر الـ exporter إلى `AgentExecutor.execute()`:

```ts
import { AgentExecutor } from '@lousho/build-ai-agent/executor';
import { type TraceExporter } from '@lousho/build-ai-agent';

const exporter: TraceExporter = {
  onSpanStart: (span) => console.log('[start]', span.kind, span.name),
  onSpanEnd: (span) => console.log('[end]', span.name, span.status?.code ?? 'ok', span.attributes),
};

await AgentExecutor.execute({ agent, input, provider, toolRegistry, exporter });
```

إذا تريد spans حقيقية من OpenTelemetry، استورد `createOtelTraceExporter()` من `@lousho/build-ai-agent/otel`. تحتاج الـ peer dependency الاختيارية `@opentelemetry/api` و`TracerProvider` مسجّل. تنقل نوع الـ span وحالة الخطأ إلى OpenTelemetry. شوف `examples/tracing` (`npm run example:tracing:console`، و`npm run example:tracing:otel` الذي يطبع metrics أيضا).

## شجرة الـ spans

```
invoke_agent {agent name}          INTERNAL
  chat {model}                     CLIENT     one per provider.generate() call
  execute_tool {tool name}         INTERNAL   one per tool call
```

الـ run الذي يكمل بعد approval (موافقة) عبر `agent.approvals.resolve()` هو trace مستقل بذاته: الـ span `invoke_agent` فيه يحتوي span الـ `execute_tool` الخاص بالـ call الموافَق عليه أولا (لأن الـ call يشتغل قبل استدعاء الـ model مرة ثانية)، وبعدها spans الـ `chat` لبقية الـ run. الـ call المرفوض ما له span `execute_tool`.

run لـ flow (`FlowExecutor.execute`) ينتج:

```
invoke_workflow {flow name}        INTERNAL
  flow.node {node type}            INTERNAL   one per node execution, nested like the flow
    chat {model}                   CLIENT     inside an llmCall node
    execute_tool {tool name}       INTERNAL   inside a toolCall node
```

إذا تريد تحط flow تحت span تبع agent، مرّر id ذلك الـ span في `parentSpanId` (`withSpan` تسلّم الـ span للـ callback الخاص بها). بعدها span الـ flow يصير child له.

## السمات

ثوابت كل الأسماء موجودة في `src/execution/semconv.ts` (متصدَّرة بالأسماء `GenAiAttr`، `GenAiOperation`، `GenAiMetric`، `ErrorAttr`، `FlowAttr`، `SdkAttr`، `LegacyAttr`).

### Agent run: `invoke_agent {agent name}`

| السمة | القيمة |
| --- | --- |
| `gen_ai.operation.name` | `invoke_agent` |
| `gen_ai.agent.name` | قيمة `name` للـ agent |
| `gen_ai.agent.id` | قيمة `id` للـ agent، إذا كانت محددة |
| `gen_ai.provider.name` | قيمة `name` للـ provider |
| `gen_ai.conversation.id` | `sessionId`، إذا كان محددا |
| `lousho.cost_usd` | التكلفة التقديرية التراكمية للـ run بالدولار (كل call لـ model وكل child run مفوَّض)؛ غائبة إذا أي model مستخدم ما له سعر معروف |
| `lousho.usage.estimated` | `true` إذا أي من tokens الـ run كان مقدَّرا |

### Model call: `chat {model}` (CLIENT)

| السمة | القيمة |
| --- | --- |
| `gen_ai.operation.name` | `chat` |
| `gen_ai.provider.name` | قيمة `name` للـ provider |
| `gen_ai.request.model` | الـ model المطلوب |
| `gen_ai.request.temperature`, `gen_ai.request.max_tokens` | إذا كانت محددة |
| `gen_ai.response.model` | إذا بلّغ عنها الـ provider |
| `gen_ai.response.finish_reasons` | مثلا `["stop"]`، `["tool_call"]` |
| `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens` | استهلاك الـ tokens |
| `lousho.cost_usd` | التكلفة التقديرية لهذه الخطوة بالدولار، إذا جدول الأسعار المدمج (أو `registerModel`) يعرف الـ model؛ غائبة غير ذلك |
| `lousho.usage.estimated` | `true` إذا الـ provider ما بلّغ عن الاستهلاك وكانت الـ tokens مقدَّرة |

### Tool call: `execute_tool {tool}`

| السمة | القيمة |
| --- | --- |
| `gen_ai.operation.name` | `execute_tool` |
| `gen_ai.tool.name` | اسم الـ tool |
| `gen_ai.tool.call.id` | id الـ tool call عند الـ model (في runs الـ agents) |
| `gen_ai.tool.description` | وصف الـ tool، إذا كان لها وصف |
| `gen_ai.tool.type` | `function` |
| `gen_ai.agent.name`, `gen_ai.conversation.id` | الـ agent المستدعي / الـ session |
| `lousho.tool.parent_call_id` | في call عمله سكربت [code mode](/ar/code-mode): id الخاص بـ call الـ `run_code` (والـ span تبعه هو الأب) |

### Flows

مواصفة GenAI ما تعرّف أي convention لعقد الـ flows، فـ spans الـ nodes تستخدم الـ namespace `lousho.flow.*`. أما span الـ run فيستخدم convention الـ workflow الوارد في المواصفة.

| الـ span | الـ attribute | القيمة |
| --- | --- | --- |
| `invoke_workflow {name}` | `gen_ai.operation.name` | `invoke_workflow` |
| | `gen_ai.workflow.name` | قيمة `name` للـ flow |
| | `lousho.flow.code` | قيمة `code` للـ flow |
| | `lousho.flow.outcome` | `success` أو `error` |
| `flow.node {type}` | `lousho.flow.node.id` | id الخاص بالـ node |
| | `lousho.flow.node.type` | نوع الـ node (`sequence`، `llmCall`، ...) |
| | `lousho.flow.outcome` | `success` أو `error` |

### الأخطاء

الـ span الفاشل يحصل على `error.type` وعلى حالة خطأ للـ span (`ERROR` في OpenTelemetry، والرسالة = رسالة الخطأ). قيمة `error.type` هي `name` الخطأ المرمي (`_OTHER` إذا المرمي ليس `Error`). والـ tool call الذي يرجع خطأ للـ model (`isError`) يتوسّم بـ `error.type = tool_error`.

## Metrics

`createOtelTraceExporter()` يسجّل أيضا metrics عميل GenAI في OpenTelemetry عبر الـ metrics API في `@opentelemetry/api`، باستخدام الـ `MeterProvider` العام (`metrics.getMeter(...)`) أو الخيار `meter`:

| الـ metric | النوع والوحدة | متى تُسجَّل | الـ attributes |
| --- | --- | --- | --- |
| `gen_ai.client.token.usage` | Histogram، `{token}` | مرة لكل نوع token في كل call لـ model يبلّغ عن الاستهلاك (أو يقدّره) | `gen_ai.operation.name` (`chat`)، `gen_ai.provider.name`، `gen_ai.request.model`، `gen_ai.response.model` (إذا كان معروفا)، `gen_ai.token.type` (`input` أو `output`) |
| `gen_ai.client.operation.duration` | Histogram، `s` | كل call لـ model (`chat`) وكل tool call (`execute_tool`) | `gen_ai.operation.name`، و`gen_ai.provider.name` و`gen_ai.request.model` (calls الـ model)، و`gen_ai.response.model` (إذا كان معروفا)، و`error.type` (عند الفشل) |

كلاهما يستخدم حدود الـ buckets التي توصي بها المواصفة. ويتبعان صفحة `gen-ai-metrics` في semantic-conventions v1.40 (بدرجة استقرار `Development`): أحدث الاصطلاحات تقسّم الـ histogram الخاص بالـ tokens إلى counters لكل نوع، وهذه الـ SDK لم تصدّرها بعد. spans الـ agents والـ flows ما تدخل في metric المدة — فقط calls الـ model والـ tools داخلها.

```ts
import { metrics } from '@opentelemetry/api';
import { ConsoleMetricExporter, MeterProvider, PeriodicExportingMetricReader } from '@opentelemetry/sdk-metrics';
import { createOtelTraceExporter } from '@lousho/build-ai-agent/otel';

// Swap ConsoleMetricExporter for an OTLP exporter to reach any backend.
metrics.setGlobalMeterProvider(
  new MeterProvider({ readers: [new PeriodicExportingMetricReader({ exporter: new ConsoleMetricExporter() })] })
);

const exporter = createOtelTraceExporter(); // metrics on by default
// createOtelTraceExporter({ metrics: false })  // spans only
// createOtelTraceExporter({ meter })           // an already-obtained Meter
```

بدون `MeterProvider` مسجّل، الـ no-op meter في OpenTelemetry يرمي القياسات. الـ metrics API موجودة في `@opentelemetry/api`، فالـ SDK لن تسجّل شيئا (ولن تحمّل شيئا) إذا لم تكن تلك الـ peer dependency الاختيارية مثبتة. والتكلفة تقدير من جدول الأسعار (شوف `registerModel`)، ليست فاتورة.

## محتوى الرسائل والـ arguments هو opt-in

الـ prompts ومخرجات الـ model وarguments ونتائج الـ tools حساسة وكبيرة الحجم. لذلك سمات المحتوى `gen_ai.*` **لا تُسجَّل افتراضيا أبدا**. فعّلها لكل agent على حدة بـ `createAgent({ exporter, captureContent: true })`.

#### متقدم: الـ executor API

مع الـ executor، فعّلها لكل run على حدة:

```ts
import { AgentExecutor } from '@lousho/build-ai-agent/executor';
import { type TraceExporter } from '@lousho/build-ai-agent';

declare const exporter: TraceExporter;

await AgentExecutor.execute({ agent, input, provider, exporter, captureContent: true });
```

الـ flows تأخذ نفس الـ flag في سياقها (`captureContent`). إذا ما حدّدت `captureContent`، متغير البيئة `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=true` (وهو الاسم الذي تستخدمه المواصفة مثالا) يفعّله. والقيمة الصريحة `captureContent: false` تغلب دائما.

عند التفعيل، يسجّل الـ SDK المحتوى على هيئة JSON strings (وهو الـ fallback الذي تحدده المواصفة للـ spans) حسب message schema المواصفة:

| الـ attribute | في الـ span | المحتوى |
| --- | --- | --- |
| `gen_ai.input.messages` | `invoke_agent`, `chat` | `[{ role, parts: [{ type: 'text', content }, { type: 'tool_call', id, name, arguments }, { type: 'tool_call_response', id, response }] }]` |
| `gen_ai.system_instructions` | `chat` | `[{ type: 'text', content }]` |
| `gen_ai.output.messages` | `chat` | `[{ role: 'assistant', parts: [...] }]` |
| `gen_ai.tool.call.arguments` | `execute_tool` | الـ arguments بصيغة JSON |
| `gen_ai.tool.call.result` | `execute_tool` | النتيجة بصيغة JSON (لا تُضبط إذا فشلت الـ tool) |

## Deprecated attribute names

قبل اصطلاحات GenAI، كانت الـ spans تستخدم أسماء ارتجالية وأسماء spans مثل `agent.run` و`llm.generate` و`tool.call`. أسماء الـ attributes القديمة ما زالت تُصدَر جنب الجديدة لكي تظل الـ dashboards القائمة شغالة، لكنها **deprecated** وستُزال في major version قادم. أما أسماء الـ spans فتغيّرت (إلى ما تفرضه المواصفة)، فحدّث الـ queries التي كانت تطابقها.

| الـ deprecated | استخدم بدله |
| --- | --- |
| span الـ `agent.run` | span الـ `invoke_agent {name}`، `gen_ai.operation.name = invoke_agent` |
| span الـ `llm.generate` | span الـ `chat {model}`، `gen_ai.operation.name = chat` |
| span الـ `tool.call` | span الـ `execute_tool {tool}`، `gen_ai.operation.name = execute_tool` |
| `model` | `gen_ai.request.model` |
| `promptTokens` | `gen_ai.usage.input_tokens` |
| `completionTokens` | `gen_ai.usage.output_tokens` |
| `totalTokens` | (اجمع قيمتي الـ usage) |
| `finishReason` | `gen_ai.response.finish_reasons` (مصفوفة؛ `tool_calls` صارت `tool_call`) |
| `toolName` | `gen_ai.tool.name` |
| `error` (رسالة على خطأ مرمي؛ boolean على `execute_tool`) | `error.type` وحالة الـ span |
| `input`, `prompt`, `args`, `result` | `gen_ai.input.messages`, `gen_ai.tool.call.arguments`, `gen_ai.tool.call.result` (opt-in، شوف فوق) |

سمات المحتوى الـ deprecated (`input`، `prompt`، `args`، `result`) تحتفظ بسلوكها القديم: تُسجَّل ما دمت لم تضبط `redactContent: true`. اضبط `redactContent: true` إذا تريد ألا يظهر أي محتوى على الـ spans إلا إذا فعّلته بـ `captureContent`.

## Local traces

`fileTraceExporter()` من `@lousho/build-ai-agent/traces` تكتب كل run في ملف، و`lousho traces` يعرض الملفات في الـ terminal. لا backend لـ OpenTelemetry ولا حزمة إضافية.

```ts
import { createAgent, defineTool } from '@lousho/build-ai-agent';
import { fileTraceExporter } from '@lousho/build-ai-agent/traces';
import { z } from 'zod';

const getWeather = defineTool({
  name: 'get_weather',
  description: 'Current weather for a city',
  input: z.object({ city: z.string() }),
  execute: async ({ city }) => `Sunny in ${city}`,
});

const agent = createAgent({
  model: 'openai/gpt-4o-mini',
  tools: [getWeather],
  exporter: fileTraceExporter({ dir: '.lousho/traces' }), // the default dir
});
```

بعدها، من مجلد المشروع:

```bash
npx lousho traces                 # the 20 most recent runs, newest first
npx lousho traces --limit 50 --json
npx lousho traces 3f2a            # one run as a tree; a unique id prefix is enough
npx lousho traces 3f2a --content  # also the captured messages and tool arguments
```

```
TIME    AGENT    DURATION  MODEL  TOOLS  TOKENS IN/OUT  COST       STATUS  ID
2h ago  weather  1.65s     2      1      159/32         $0.000043  ok      3f2a9c1e-5b7d-4e8a-9c0f-1a2b3c4d5e6f

Trace 3f2a9c1e-5b7d-4e8a-9c0f-1a2b3c4d5e6f  4 spans, 1.65s
invoke_agent weather         |████████████████████████|     1.65s  $0.000043
├─ chat gpt-4o-mini          |█████████████           |     900ms  openai/gpt-4o-mini  in 62 out 18  $0.000020
├─ execute_tool get_weather  |             █          |      22ms  tool get_weather
└─ chat gpt-4o-mini          |             ██████████ |     705ms  openai/gpt-4o-mini  in 97 out 14  $0.000023
```

الخيارات: `--dir D` يقرأ مجلد ثاني (الافتراضي `.lousho/traces`)، `--limit N` يعرض N من الـ runs (الافتراضي 20)، `--json` يطبع الملخصات أو الـ spans بصيغة JSON. بادئة id تطابق أكثر من run تعرضها كلها ويخرج الأمر بالرمز 1. الألوان تتعطّل إذا `NO_COLOR` مضبوط أو إذا الـ output ليس terminal. أعداد الـ tokens مأخوذة من spans الـ `chat` في الـ run، بما فيها تبع الـ sub-agents؛ والتكلفة هي `lousho.cost_usd` المجمَّعة للـ run، وتبقى فاضية (`-`) إذا سعر أحد الـ models مجهول.

**الملفات.** ملف واحد لكل run في `<dir>/<YYYY-MM-DD>/<traceId>.jsonl` (تاريخ بداية الـ run بالتوقيت المحلي؛ الـ trace id هو id الـ span `invoke_agent` الخاص به)، فتقدر تحذف الـ traces القديمة يوم بيوم. كل سطر هو span واحد منتهي، يُكتب فور انتهائه:

```json
{"v":1,"traceId":"3f2a…","id":"a100…","parentId":"3f2a…","name":"chat gpt-4o-mini","kind":"client","startTime":1790848800005,"endTime":1790848800905,"attributes":{"gen_ai.usage.input_tokens":62,"…":"…"}}
```

`startTime` و`endTime` بالـ milliseconds منذ الـ epoch؛ `attributes` هي سمات الـ span المذكورة فوق، كاملة بدون اختصار. الـ span الذي لم ينتهِ أبدا (العملية ماتت) لا يوجد في الملف. إذا تعذّرت الكتابة في المجلد، الـ exporter يحذّر مرة واحدة والـ run يكمل. `listTraces({ dir, limit })` و`readTrace(idOrPrefix, { dir })` تقرأ الملفات من الكود.

الملفات تحمل ما تحمله الـ spans: الـ attributes الـ deprecated `input` و`prompt` و`args` و`result` تحمل محتوى الرسائل والـ tools (شوف [Deprecated attribute names](#deprecated-attribute-names))، و`captureContent: true` يضيف محتوى `gen_ai.*`. خلّي `.lousho/` خارج الـ version control؛ المشاريع التي ينشئها `lousho init` تتجاهله.

`lousho dev` و`lousho chat` يكتبان هذه الملفات لما تمرّر `--traces` (إلى `.lousho/traces`) أو `--traces=<dir>`، سواء لملف spec أو مجلد agent أو module. يعني agent مبني من ملف spec تقدر تتتبّعه بدون أي كود. وهي opt-in عن قصد: الملفات تحفظ محتوى الـ prompt والـ tools، و`captureContent: false` لا يزيله (فقط `redactContent: true` يفعل)، فلا يُكتب شيء على القرص إلا إذا طلبت. تنسيق ملف الـ spec ليس فيه إعداد للـ traces.

## Backends

أي backend يستقبل traces من OpenTelemetry (OTLP) يستقبل هذه الـ spans. الـ backends والأدوات التي تفهم GenAI semantic conventions تقدر تعرضها كـ calls لـ LLM وagents وtools مع استهلاك الـ tokens؛ وغيرها يعرضها spans عادية مع attributes. أي conventions يدعمها كل backend، وأي إصدار منها، يختلف من واحد لآخر — راجع توثيقه.
