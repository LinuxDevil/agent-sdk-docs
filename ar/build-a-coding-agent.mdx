هذه الصفحة تبني coding agent يعمل في الـ terminal على طريقة Claude Code: يقرأ ملفات مشروعك ويعدّلها، ويشغّل أوامر، ويسألك قبل أن يكتب ملفًا أو يشغّل شيئًا خطرًا، ويُبقي المحادثة مستمرة لأسئلة المتابعة. تحتاج إلى Node 22، ومفتاح API في متغيّر البيئة الذي يتوقعه الـ provider (`OPENAI_API_KEY` للـ model المستخدم هنا)، ومجلد مشروع تشغّله فيه. الملف الجاهز في آخر [الخطوة 5](#5-حافظ-على-استمرار-المحادثة)، وتشغّله هكذا `npx tsx coding.ts "Fix the failing test"`.

## 1. أعطِ الـ agent workspace

الـ workspace مجلد يعمل فيه الـ agent. `NodeWorkspace` هو نظام الملفات والـ shell لها، و`createFsTools()` و`createShellTool()` تحوّل الـ workspace إلى tools.

```ts
import { NodeWorkspace, createFsTools, createShellTool } from 'lousho';

const workspace = new NodeWorkspace({ root: process.cwd() });
const tools = [...createFsTools(workspace), createShellTool(workspace)];
```

`root` مهم: كل path يمرّره الـ model ينحصر داخله، و`..` والمسارات المطلقة وحروف الأقراص مرفوضة (راجع [نموذج الأمان](/ar/workspace-tools#نموذج-الأمان)). شغّل البرنامج من مجلد المشروع واستخدم `process.cwd()` كـ root، وبهذا لا تصل file tools إلى أي شيء خارج المشروع.

يرى الـ model سبع tools: `read_file` و`write_file` و`edit_file` و`list_dir` و`glob` و`grep` من `createFsTools()`، و`shell` من `createShellTool()`. وسيطاتها وخياراتها في [Workspace tools](/ar/workspace-tools#الأدوات).

## 2. حدّد ما يحتاج approval

أي tool عليها `needsApproval` توقف الـ run قبل التنفيذ، لكي يقرر إنسان. القراءة لا ضرر فيها، فاطلب approval (موافقة) على file tools التي تغيّر شيئًا فقط، بخريطة لكل tool. وللـ shell مرّر predicate (دالة تعيد true أو false) على نص الأمر، واطلب approval على الأوامر التي تعتبرها خطرة فقط.

```ts
import { NodeWorkspace, createFsTools, createShellTool } from 'lousho';

const DESTRUCTIVE = /\b(rm|mv|chmod|chown|git\s+(push|reset|clean|checkout))\b|>/;

const workspace = new NodeWorkspace({ root: process.cwd() });
const tools = [
  ...createFsTools(workspace, { needsApproval: { write_file: true, edit_file: true } }),
  createShellTool(workspace, { needsApproval: (command) => DESTRUCTIVE.test(command) }),
];
```

أداة الـ shell تطلب approval افتراضيًا (`needsApproval: true`)؛ الـ predicate أعلاه يجعل أي شيء آخر، مثل `npm test` أو `git status`، يعمل دون سؤال. الطريقة الأخرى لتخطّي السؤال هي قائمة `allow` بالأوامر التي تثق بها مع `needsApproval: false`، كما هو مكتوب في بداية [Workspace tools](/ar/workspace-tools). استخدم هناك قواعد دقيقة مثل `{ command: 'npm test' }`: النص العادي مثل `'npm test'` يسمح بالأمر مع أي arguments، بما فيها flags تكتب خارج الـ workspace. الـ regex تسهيل، وليس حدًا أمنيًا: أمر الـ shell يمكن كتابته بطرق كثيرة. لأي شيء لا تتحكم فيه، أبقِ الافتراضي ووافق على كل أمر، أو شغّل الـ shell داخل sandbox (راجع `SandboxShell` في [Workspace tools](/ar/workspace-tools#sandboxed-shell-sandboxshell)).

## 3. شغّله وتابع الـ stream

أنشئ الـ agent بالـ tools، ثم استدعِ `agent.stream()`. تعيد run تمرّ عليه بـ `for await` وتأخذ typed events: `text.delta` يحمل نص الـ model أولًا بأول أثناء كتابته، و`tool.start` يعلن عن كل tool call (راجع [Streaming](/ar/streaming)).

```ts
import { NodeWorkspace, createAgent, createFsTools, createShellTool } from 'lousho';

const workspace = new NodeWorkspace({ root: process.cwd() });
const agent = createAgent({
  model: 'openai/gpt-4o-mini',
  instructions: 'You are a careful coding agent. Read before you edit; run the tests after every change.',
  maxSteps: 30,
  tools: [
    ...createFsTools(workspace, { needsApproval: { write_file: true, edit_file: true } }),
    createShellTool(workspace),
  ],
});

const run = agent.stream('Fix the failing test');
for await (const event of run) {
  if (event.type === 'text.delta') process.stdout.write(event.text);
  if (event.type === 'tool.start') console.log(`\n> ${event.toolName} ${JSON.stringify(event.args)}`);
}
```

`maxSteps` يحدد عدد استدعاءات الـ model في run واحد، فلا يدور الـ agent المرتبك إلى ما لا نهاية. هذا البرنامج يتوقف عند أول call يحتاج approval: ينتهي الـ stream بحدث `approval.requested` وينتهي الـ run بالحالة `'awaiting-approval'`. الخطوة التالية تعالج هذا. بادئة `vendor/` في اسم الـ model تختار الـ provider؛ ومع OpenRouter استخدم `openrouter/<vendor>/<model>` (مثل `openrouter/openai/gpt-4o-mini`).

## 4. تعامل مع التوقف

عندما ينتهي الـ stream، يعطيك `await run.result` النتيجة النهائية. إذا توقف الـ run، يسمّي `result.approvalId` الـ call المعلّق. اسأل المستخدم، ثم تابع بـ `agent.approvals.streamResolve()` التي تعيد run جديدًا لبقية العمل. وقد يتوقف هذا الـ run مرة أخرى، فكرّر الحلقة حتى لا يبقى `approvalId`.

```ts
import { createInterface } from 'node:readline/promises';
import { createAgent, type AgentRun } from 'lousho';

const agent = createAgent({ model: 'openai/gpt-4o-mini', instructions: 'You are a coding agent.' });
const rl = createInterface({ input: process.stdin, output: process.stdout });

async function drain(first: AgentRun): Promise<void> {
  let run = first;
  for (;;) {
    for await (const event of run) {
      if (event.type === 'text.delta') process.stdout.write(event.text);
      if (event.type === 'tool.start') console.log(`\n> ${event.toolName} ${JSON.stringify(event.args)}`);
    }
    const { approvalId } = await run.result;
    if (!approvalId) return;
    const answer = await rl.question('\nApprove this call? [y/N] ');
    run = agent.approvals.streamResolve({ id: approvalId, approved: answer.trim().toLowerCase() === 'y' });
  }
}

try {
  await drain(agent.stream('Fix the failing test'));
} finally {
  rl.close();
}
```

تفصيلتان في الـ stream بعد الاستئناف. الـ call الذي وافقت عليه للتو يُستأنف بحدث `tool.resume` — فقد طُبع `tool.start` الخاص به في الـ run الذي توقف، فتطبع الحلقة كل call مرة واحدة (و`tool.resume` هو الحدث الذي تطابقه إذا أردت أن تعلّم الـ call بأنه عاد إلى العمل). والـ call المرفوض لا يُفشل الـ run: يأخذ الـ model نتيجة رفض بدلًا من output الـ tool ويتابع. ولإخباره بالسبب، مرّر `note`: `streamResolve({ id, approved: false, note: 'Do not touch the lockfile' })`. و`try` / `finally` تغلق واجهة `readline` حتى لو رُفض `run.result` لأن الـ run فشل.

حدث `approval.requested` يحمل أيضًا `toolName` و`args`، فتستطيع طباعة ما سينفذه الـ call قبل أن تسأل. راجع [Approvals](/ar/approvals) للـ API كامل.

## 5. حافظ على استمرار المحادثة

حتى الآن تبدأ كل مهمة من الصفر. `agent.session()` تنشئ session (جلسة) تحتفظ بالـ transcript (سجل المحادثة)، فترى متابعةٌ مثل "now add a test for the empty case" الـ turns السابقة. و`session.stream(input)` هي `agent.stream()` لكن لمحادثة، وتعيد نوع الـ run نفسه؛ والـ turn الذي يتوقف على call يحتاج approval يكتمل في الـ session نفسها عندما تحسمه عبر الـ agent نفسه (راجع [الـ streaming داخل session](/ar/sessions#streaming-a-session-turn)). حوّل الحلقة إلى REPL: `session.stream()` واحدة لكل سطر يكتبه المستخدم، مع معالجة التوقف نفسها.

```ts
// coding.ts
// Run: OPENAI_API_KEY=... npx tsx coding.ts "Fix the failing test"
import { createInterface } from 'node:readline/promises';
import { NodeWorkspace, createAgent, createFsTools, createShellTool, type AgentRun } from 'lousho';

const DESTRUCTIVE = /\b(rm|mv|chmod|chown|git\s+(push|reset|clean|checkout))\b|>/;

const workspace = new NodeWorkspace({ root: process.cwd() });
const agent = createAgent({
  model: 'openai/gpt-4o-mini',
  instructions: 'You are a careful coding agent. Read before you edit; run the tests after every change.',
  maxSteps: 30,
  tools: [
    ...createFsTools(workspace, { needsApproval: { write_file: true, edit_file: true } }),
    createShellTool(workspace, { needsApproval: (command) => DESTRUCTIVE.test(command) }),
  ],
});
const session = agent.session();
const rl = createInterface({ input: process.stdin, output: process.stdout });

async function drain(first: AgentRun): Promise<void> {
  let run = first;
  for (;;) {
    for await (const event of run) {
      if (event.type === 'text.delta') process.stdout.write(event.text);
      if (event.type === 'tool.start') console.log(`\n> ${event.toolName} ${JSON.stringify(event.args)}`);
    }
    const { approvalId } = await run.result;
    if (!approvalId) return;
    const answer = await rl.question('\nApprove this call? [y/N] ');
    run = agent.approvals.streamResolve({ id: approvalId, approved: answer.trim().toLowerCase() === 'y' });
  }
}

try {
  let line = process.argv[2] ?? (await rl.question('> '));
  while (line.trim() && line.trim() !== 'exit') {
    await drain(session.stream(line));
    process.stdout.write('\n');
    line = await rl.question('> ');
  }
} finally {
  rl.close();
}
```

تأتي المهمة الأولى من سطر الأوامر (أو من prompt إذا لم توجد مهمة)؛ وبعد كل رد يسأل البرنامج عن السطر التالي، والسطر الفارغ أو `exit` ينهي البرنامج. الـ session موجودة في الذاكرة، فتنتهي بانتهاء العملية؛ إذا أردت محادثة تبقى بين runs، أعطِ الـ agent store (مخزن) (راجع [اختيار store](/ar/sessions#choosing-a-store)).

### الـ turns الطويلة وإعادة التشغيل

- **السياق.** الـ turn في coding agent يقرأ ملفات ويشغّل اختبارات ويعدّل على مدى خطوات كثيرة؛ وكل نتيجة tool تبقى في الـ transcript، فقد يتجاوز turn من 40 خطوة نافذة سياق (context window) بحجم 128k token قبل أن ينتهي. مرّر `createAgent({ compaction: true })` (أو دالة تلخيص، راجع [ضغط السياق](/ar/compaction)): يضغط السياق قبل كل استدعاء للـ model، حتى بين خطوات الـ turn الواحد.
- **الانهيار.** مع store متين، يُكمل `session.send()` التالي أو `session.resume()` الـ turn الذي قُتل في منتصفه. والـ tool call الذي كان قيد التشغيل عندما توقفت العملية يعمل مرة أخرى ([at-least-once](/ar/durable-execution#at-least-once-tools-اجعل-الـ-side-effects-idempotent)). و`write_file` و`edit_file` المدمجتان آمنتان لإعادة التشغيل: `write_file` تكتب المحتوى نفسه مرة أخرى، و`edit_file` التي يوجد تعديلها أصلًا في الملف (`old_string` اختفى و`new_string` موجود) تنجح برسالة "the edit was already applied" بدلًا من أن تفشل. ومع [`WorkspaceCheckpoints`](/ar/workspace-tools#الأدوات)، تُحفظ نسخة احتياطية لكل تغيير قبل كتابة الملف، وتحتفظ إعادة التشغيل بالنسخة الأولى، فيعيد `rewind()` الأصل حتى بعد الانهيار.
- **عرض التقدّم أثناء الاستئناف.** `session.resume()` تعيد نتيجة، لا stream، و`session.stream()` لا تبث الـ turn المعلّق الذي تكمله قبل الرسالة الجديدة. لعرض التقدّم، سجّل `session.on((event) => ...)` قبل الاستدعاء، أو مرّر `createAgent({ onEvent })`: كلاهما يستلم `AgentEvent`s الخاصة بالـ turn المستأنف (`tool.start`، `text.delta`، ...، `run.done`) أولًا بأول.
- **الـ approvals بعد إعادة التشغيل.** `agent.approvals.streamResolve({ id, approved })` (أو `resolve()`) من process جديد، بالـ store المتين نفسه، يكمل الـ turn المتوقف في الـ session الخاصة به؛ دون أن تستدعي `session.resume()` قبل ذلك.

## 6. اختبره بدون model

الـ agent لا يحتاج إلى شبكة لكي تختبره. `MemoryWorkspace` يُبقي الملفات في الذاكرة ويأخذ `exec` مكتوبًا مسبقًا للـ shell، و`mockModel` يؤدي دور الـ model. تحقق من `workspace.snapshot()` و`workspace.commands`.

```ts
import { createAgent, createFsTools, createShellTool, MemoryWorkspace } from 'lousho';
import { mockModel } from 'lousho/testing';

const workspace = new MemoryWorkspace({
  files: { 'math.js': 'exports.add = (a, b) => a - b;\n' },
  exec: (command) => (command === 'node --test' ? { stdout: 'pass 1\n' } : { exitCode: 1, stderr: 'unknown command\n' }),
});
const agent = createAgent({
  instructions: 'Fix bugs. Run the tests after every change.',
  provider: mockModel([
    { toolCalls: [{ name: 'edit_file', args: { path: 'math.js', old_string: 'a - b', new_string: 'a + b' } }] },
    { toolCalls: [{ name: 'shell', args: { command: 'node --test' } }] },
    'Fixed add(); the tests pass.',
  ]),
  tools: [...createFsTools(workspace), createShellTool(workspace, { needsApproval: false })],
});

await agent.send('add() is broken');
console.log(workspace.snapshot()['math.js']); // 'exports.add = (a, b) => a + b;\n'
console.log(workspace.commands.map((c) => c.command)); // ['node --test']
```

لاختبار مسار الـ approval، اطلب approval على `write_file` كما يفعل الـ agent الحقيقي. `send()` تنتهي بـ `finishReason: 'awaiting-approval'` و`approvalId`، ويبقى الملف دون تغيير، و`agent.approvals.resolve()` تنفّذ الكتابة وتنهي الـ turn.

```ts
import { createAgent, createFsTools, MemoryWorkspace } from 'lousho';
import { mockModel } from 'lousho/testing';

const workspace = new MemoryWorkspace({ files: { 'notes.txt': 'old\n' } });
const agent = createAgent({
  instructions: 'Write notes.',
  provider: mockModel([
    { toolCalls: [{ name: 'write_file', args: { path: 'notes.txt', content: 'new\n' } }] },
    'Wrote the file.',
  ]),
  tools: createFsTools(workspace, { needsApproval: { write_file: true } }),
});

const paused = await agent.send('Update the notes');
console.log(paused.finishReason, workspace.snapshot()['notes.txt']); // 'awaiting-approval' 'old\n'

const done = await agent.approvals.resolve({ id: paused.approvalId!, approved: true });
console.log(done.text, workspace.snapshot()['notes.txt']); // 'Wrote the file.' 'new\n'
```

وللتحقق من الـ prompt الحقيقي والـ tool schemas على model مرة واحدة ثم إعادة تشغيل التسجيل بعدها، راجع [Record and replay](/ar/testing#record-و-replay).

## الخطوات التالية

- [Workspace tools](/ar/workspace-tools): المرجع الكامل للـ tools، ونموذج الأمان، و`SandboxShell` لتشغيل الأوامر في Docker.
- [التراجع عن تعديلات الـ agent على الملفات](/ar/workspace-tools#الأدوات): مرّر `WorkspaceCheckpoints` إلى `createFsTools(workspace, { checkpoints })`، ثم يعرض لك `checkpoints.rewind(turn, { sessionId: session.id, dryRun: true })` ما سيُستعاد إذا عدت إلى turn معيّن.
- [Approvals](/ar/approvals): الـ durable approval stores، ودوال `approve`، واتخاذ القرار من process آخر.
- [Streaming](/ar/streaming): كل أنواع الـ events، وإلغاء run، وصيغ الـ stream للويب.
- [Sessions](/ar/sessions): الـ stores والحدود والـ durable sessions.
- [Durable execution](/ar/durable-execution): يكتمل الـ run حتى لو تعطّلت العملية في منتصفه.
- [Configuration](/ar/configuration): `projectInstructions: true` يلحق ملف `AGENTS.md` أو `CLAUDE.md` بالـ instructions.
