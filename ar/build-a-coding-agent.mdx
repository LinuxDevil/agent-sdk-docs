هذه الصفحة تبني coding agent يشتغل في الـ terminal على طريقة Claude Code: يقرأ ملفات مشروعك ويعدّلها، يشغّل أوامر، يسألك قبل ما يكتب ملف أو يشغّل شي خطر، ويخلّي المحادثة مكملة لأسئلة المتابعة. تحتاج Node 22، ومفتاح API في متغيّر البيئة اللي يتوقعه الـ provider (`OPENAI_API_KEY` للـ model المستخدم هنا)، ومجلد مشروع تشغّله فيه. الملف الجاهز في آخر [الخطوة 5](#5-خلي-المحادثة-شغالة)، وتشغّله هكذا `npx tsx coding.ts "Fix the failing test"`.

## 1. أعطِ الـ agent workspace

الـ workspace مجلد يشتغل فيه الـ agent. `NodeWorkspace` هو نظام الملفات والـ shell لها، و`createFsTools()` و`createShellTool()` تحوّل الـ workspace إلى tools.

```ts
import { NodeWorkspace, createFsTools, createShellTool } from '@lousho/build-ai-agent';

const workspace = new NodeWorkspace({ root: process.cwd() });
const tools = [...createFsTools(workspace), createShellTool(workspace)];
```

`root` مهم: كل path يمرّره الـ model ينحصر داخله، و`..` والمسارات المطلقة وحروف الأقراص مرفوضة (راجع [نموذج الأمان](/ar/workspace-tools#نموذج-الأمان)). شغّل البرنامج من مجلد المشروع واستخدم `process.cwd()` كـ root، وهكذا ما توصل file tools لأي شي خارج المشروع.

الـ model يشوف سبع tools: `read_file` و`write_file` و`edit_file` و`list_dir` و`glob` و`grep` من `createFsTools()`، و`shell` من `createShellTool()`. وسيطاتها وخياراتها في [Workspace tools](/ar/workspace-tools#الأدوات).

## 2. حدّد ما يحتاج approval

أي tool عليها `needsApproval` توقف الـ run قبل التنفيذ، عشان إنسان يقرر. القراءة ما فيها ضرر، فاطلب approval (موافقة) على file tools اللي تغيّر شي فقط، بخريطة لكل tool. وللـ shell مرّر predicate (دالة ترجع true أو false) على نص الأمر، واطلب approval على الأوامر اللي تعتبرها خطرة فقط.

```ts
import { NodeWorkspace, createFsTools, createShellTool } from '@lousho/build-ai-agent';

const DESTRUCTIVE = /\b(rm|mv|chmod|chown|git\s+(push|reset|clean|checkout))\b|>/;

const workspace = new NodeWorkspace({ root: process.cwd() });
const tools = [
  ...createFsTools(workspace, { needsApproval: { write_file: true, edit_file: true } }),
  createShellTool(workspace, { needsApproval: (command) => DESTRUCTIVE.test(command) }),
];
```

أداة الـ shell تطلب approval افتراضيًا (`needsApproval: true`)؛ الـ predicate فوق يخلّي أي شي ثاني، مثل `npm test` أو `git status`، يشتغل بدون سؤال. الطريقة الثانية لتخطّي السؤال هي قائمة `allow` بالأوامر اللي تثق فيها مع `needsApproval: false`، مثل ما هو مكتوب في أول [Workspace tools](/ar/workspace-tools). الـ regex تسهيل، ما هو حد أمني: أمر الـ shell ينكتب بطرق كثيرة. لأي شي ما تتحكم فيه، خلي الافتراضي ووافق على كل أمر، أو شغّل الـ shell داخل sandbox (راجع `SandboxShell` في [Workspace tools](/ar/workspace-tools#sandboxed-shell-sandboxshell)).

## 3. شغّله وتابع الـ stream

أنشئ الـ agent بالـ tools، بعدين استدعِ `agent.stream()`. ترجع run تمرّ عليه بـ `for await` وتاخذ typed events: `text.delta` يحمل نص الـ model أول بأول وهو ينكتب، و`tool.start` يعلن عن كل tool call (راجع [Streaming](/ar/streaming)).

```ts
import { NodeWorkspace, createAgent, createFsTools, createShellTool } from '@lousho/build-ai-agent';

const workspace = new NodeWorkspace({ root: process.cwd() });
const agent = createAgent({
  model: 'openai/gpt-4o-mini',
  instructions: 'You are a careful coding agent. Read before you edit; run the tests after every change.',
  maxSteps: 30,
  tools: [
    ...createFsTools(workspace, { needsApproval: { write_file: true, edit_file: true } }),
    createShellTool(workspace),
  ],
});

const run = agent.stream('Fix the failing test');
for await (const event of run) {
  if (event.type === 'text.delta') process.stdout.write(event.text);
  if (event.type === 'tool.start') console.log(`\n> ${event.toolName} ${JSON.stringify(event.args)}`);
}
```

`maxSteps` يحدد عدد استدعاءات الـ model في run واحد، فالـ agent المرتبك ما يدور للأبد. البرنامج هذا يوقف عند أول call محتاج approval: الـ stream ينتهي بحدث `approval.requested` والـ run ينتهي بالحالة `'awaiting-approval'`. الخطوة التالية تعالج هذا. بادئة `vendor/` في اسم الـ model تختار الـ provider؛ ومع OpenRouter استخدم `openrouter/<vendor>/<model>` (مثل `openrouter/openai/gpt-4o-mini`).

## 4. تعامل مع التوقف

لما الـ stream يخلص، `await run.result` يعطيك النتيجة النهائية. إذا الـ run توقف، `result.approvalId` يسمّي الـ call المعلّق. اسأل المستخدم، بعدين كمّل بـ `agent.approvals.streamResolve()` اللي ترجع run جديد لباقي الشغل. وهذا الـ run ممكن يتوقف مرة ثانية، فكرّر اللوب حتى ما يبقى `approvalId`.

```ts
import { createInterface } from 'node:readline/promises';
import { createAgent, type AgentRun } from '@lousho/build-ai-agent';

const agent = createAgent({ model: 'openai/gpt-4o-mini', instructions: 'You are a coding agent.' });
const rl = createInterface({ input: process.stdin, output: process.stdout });

async function drain(first: AgentRun): Promise<void> {
  let run = first;
  for (;;) {
    for await (const event of run) {
      if (event.type === 'text.delta') process.stdout.write(event.text);
      if (event.type === 'tool.start') console.log(`\n> ${event.toolName} ${JSON.stringify(event.args)}`);
    }
    const { approvalId } = await run.result;
    if (!approvalId) return;
    const answer = await rl.question('\nApprove this call? [y/N] ');
    run = agent.approvals.streamResolve({ id: approvalId, approved: answer.trim().toLowerCase() === 'y' });
  }
}

try {
  await drain(agent.stream('Fix the failing test'));
} finally {
  rl.close();
}
```

تفصيلتين في الـ stream بعد الاستئناف. الـ call اللي وافقت عليه لسّه يستأنف بحدث `tool.resume` — `tool.start` حقه انطبع في الـ run اللي توقف، فاللوب يطبع كل call مرة واحدة (و`tool.resume` هو الحدث اللي تطابقه لو تريد تعلّم الـ call إنه رجع يشتغل). والـ call المرفوض ما يفشّل الـ run: الـ model ياخذ نتيجة رفض بدل output الـ tool ويكمّل. ولإخباره بالسبب، مرّر `note`: `streamResolve({ id, approved: false, note: 'Do not touch the lockfile' })`. و`try` / `finally` تقفل واجهة `readline` حتى لو `run.result` انرفض لأن الـ run فشل.

حدث `approval.requested` يحمل أيضًا `toolName` و`args`، فتقدر تطبع ما سينفذه الـ call قبل ما تسأل. راجع [Approvals](/ar/approvals) للـ API كامل.

## 5. خلي المحادثة شغالة

لحد الآن كل مهمة تبدأ من الصفر. `agent.session()` تنشئ session (جلسة) تحتفظ بالـ transcript (سجل المحادثة)، فمتابعة مثل "now add a test for the empty case" تشوف الـ turns السابقة. و`session.stream(input)` هي `agent.stream()` بس لمحادثة، وترجع نفس نوع الـ run؛ الـ turn اللي يتوقف على call محتاج approval يكمل في نفس الـ session لما تحسمه عن طريق نفس الـ agent (راجع [الـ streaming داخل session](/ar/sessions#streaming-a-session-turn)). حوّل اللوب إلى REPL: `session.stream()` واحدة لكل سطر يكتبه المستخدم، مع نفس معالجة التوقف.

```ts
// coding.ts
// Run: OPENAI_API_KEY=... npx tsx coding.ts "Fix the failing test"
import { createInterface } from 'node:readline/promises';
import { NodeWorkspace, createAgent, createFsTools, createShellTool, type AgentRun } from '@lousho/build-ai-agent';

const DESTRUCTIVE = /\b(rm|mv|chmod|chown|git\s+(push|reset|clean|checkout))\b|>/;

const workspace = new NodeWorkspace({ root: process.cwd() });
const agent = createAgent({
  model: 'openai/gpt-4o-mini',
  instructions: 'You are a careful coding agent. Read before you edit; run the tests after every change.',
  maxSteps: 30,
  tools: [
    ...createFsTools(workspace, { needsApproval: { write_file: true, edit_file: true } }),
    createShellTool(workspace, { needsApproval: (command) => DESTRUCTIVE.test(command) }),
  ],
});
const session = agent.session();
const rl = createInterface({ input: process.stdin, output: process.stdout });

async function drain(first: AgentRun): Promise<void> {
  let run = first;
  for (;;) {
    for await (const event of run) {
      if (event.type === 'text.delta') process.stdout.write(event.text);
      if (event.type === 'tool.start') console.log(`\n> ${event.toolName} ${JSON.stringify(event.args)}`);
    }
    const { approvalId } = await run.result;
    if (!approvalId) return;
    const answer = await rl.question('\nApprove this call? [y/N] ');
    run = agent.approvals.streamResolve({ id: approvalId, approved: answer.trim().toLowerCase() === 'y' });
  }
}

try {
  let line = process.argv[2] ?? (await rl.question('> '));
  while (line.trim() && line.trim() !== 'exit') {
    await drain(session.stream(line));
    process.stdout.write('\n');
    line = await rl.question('> ');
  }
} finally {
  rl.close();
}
```

أول مهمة تجي من سطر الأوامر (أو من prompt إذا ما فيه مهمة)؛ بعد كل رد البرنامج يسأل عن السطر التالي، وسطر فاضي أو `exit` ينهي البرنامج. الـ session تعيش في الذاكرة، فتنتهي مع انتهاء العملية؛ إذا تريد محادثة تبقى بين runs، أعطِ الـ agent store (مخزن) (راجع [اختيار store](/ar/sessions#choosing-a-store)).

## 6. اختبره بدون model

الـ agent ما يحتاج شبكة عشان تختبره. `MemoryWorkspace` يخلّي الملفات في الذاكرة وياخذ `exec` مكتوب مسبقًا للـ shell، و`mockModel` يلعب دور الـ model. تحقق من `workspace.snapshot()` و`workspace.commands`.

```ts
import { createAgent, createFsTools, createShellTool, MemoryWorkspace } from '@lousho/build-ai-agent';
import { mockModel } from '@lousho/build-ai-agent/testing';

const workspace = new MemoryWorkspace({
  files: { 'math.js': 'exports.add = (a, b) => a - b;\n' },
  exec: (command) => (command === 'node --test' ? { stdout: 'pass 1\n' } : { exitCode: 1, stderr: 'unknown command\n' }),
});
const agent = createAgent({
  instructions: 'Fix bugs. Run the tests after every change.',
  provider: mockModel([
    { toolCalls: [{ name: 'edit_file', args: { path: 'math.js', old_string: 'a - b', new_string: 'a + b' } }] },
    { toolCalls: [{ name: 'shell', args: { command: 'node --test' } }] },
    'Fixed add(); the tests pass.',
  ]),
  tools: [...createFsTools(workspace), createShellTool(workspace, { needsApproval: false })],
});

await agent.send('add() is broken');
console.log(workspace.snapshot()['math.js']); // 'exports.add = (a, b) => a + b;\n'
console.log(workspace.commands.map((c) => c.command)); // ['node --test']
```

لاختبار مسار الـ approval، اطلب approval على `write_file` كما يفعل الـ agent الحقيقي. `send()` تنتهي بـ `finishReason: 'awaiting-approval'` و`approvalId`، والملف يبقى بدون تغيير، و`agent.approvals.resolve()` تنفّذ الكتابة وتنهي الـ turn.

```ts
import { createAgent, createFsTools, MemoryWorkspace } from '@lousho/build-ai-agent';
import { mockModel } from '@lousho/build-ai-agent/testing';

const workspace = new MemoryWorkspace({ files: { 'notes.txt': 'old\n' } });
const agent = createAgent({
  instructions: 'Write notes.',
  provider: mockModel([
    { toolCalls: [{ name: 'write_file', args: { path: 'notes.txt', content: 'new\n' } }] },
    'Wrote the file.',
  ]),
  tools: createFsTools(workspace, { needsApproval: { write_file: true } }),
});

const paused = await agent.send('Update the notes');
console.log(paused.finishReason, workspace.snapshot()['notes.txt']); // 'awaiting-approval' 'old\n'

const done = await agent.approvals.resolve({ id: paused.approvalId!, approved: true });
console.log(done.text, workspace.snapshot()['notes.txt']); // 'Wrote the file.' 'new\n'
```

وللتحقق من الـ prompt الحقيقي والـ tool schemas على model مرة واحدة ثم إعادة تشغيل التسجيل بعدها، راجع [Record and replay](/ar/testing#record-و-replay).

## الخطوات التالية

- [Workspace tools](/ar/workspace-tools): المرجع الكامل للـ tools، ونموذج الأمان، و`SandboxShell` لتشغيل الأوامر في Docker.
- [التراجع عن تعديلات الـ agent على الملفات](/ar/workspace-tools#الأدوات): مرّر `WorkspaceCheckpoints` لـ `createFsTools(workspace, { checkpoints })`، بعدين `checkpoints.rewind(turn, { sessionId: session.id, dryRun: true })` يعرض لك ما سيُستعاد لو رجعت إلى turn معيّن.
- [Approvals](/ar/approvals): الـ durable approval stores، ودوال `approve`، واتخاذ القرار من process ثاني.
- [Streaming](/ar/streaming): كل أنواع الـ events، وإلغاء run، وصيغ الـ stream للويب.
- [Sessions](/ar/sessions): الـ stores والحدود والـ durable sessions.
- [Durable execution](/ar/durable-execution): الـ run يكمل حتى لو العملية وقعت في النص.
- [Configuration](/ar/configuration): `projectInstructions: true` يلحق ملف `AGENTS.md` أو `CLAUDE.md` بالـ instructions.
