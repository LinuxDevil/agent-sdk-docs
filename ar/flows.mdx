الـflow هو سير عمل ثابت من عدة خطوات، يشغّله agent واحد. تكتب الخطوات وترتيبها مسبقاً، بدل ما تترك القرار للـmodel. صف الـgraph بـ`FlowBuilder`، وشغّله بالدالة static `FlowExecutor.execute(flow, context, onEvent?)`.

```ts
import { FlowBuilder, FlowExecutor, type EditorStep } from '@lousho/build-ai-agent/flows';

// FlowBuilder is a metadata builder: setCode/setName/setInputs/setFlow(...).build().
// EditorStep covers every node type FlowExecutor runs ('sequence', 'llmCall',
// 'oneOf', 'setVariable', ...).
const steps: EditorStep = {
  type: 'sequence',
  steps: [
    { type: 'llmCall', prompt: 'Classify this message as billing, technical or sales: {{message}}', outputVariable: 'category' },
    { type: 'llmCall', prompt: 'Write a one-line reply for a {{category}} request: {{message}}' },
  ],
};

const flow = new FlowBuilder()
  .setCode('triage')
  .setName('Triage')
  .addInput({ name: 'message', type: 'shortText', required: true })
  .setFlow(steps)
  .build();

// FlowExecutor is a static API too: execute(flow, context, onEvent?)
const result = await FlowExecutor.execute(flow, { agent, provider, variables: { message: input } });
```

## أنواع العُقد

`FlowExecutor` يشغّل أنواع العُقد هذه:

| `type` | ما يفعله |
| ------ | ------------ |
| `sequence` | يشغّل خطوات `steps` واحدة تلو الأخرى. |
| `parallel` | يشغّل خطواته في نفس الوقت. |
| `llmCall` | يستدعي الـmodel بـ`prompt` فيه placeholders بصيغة `{{variable}}`، و`outputVariable` يخزّن الرد. |
| `toolCall` | يستدعي tool بالـ`arguments` (تتعوّض الـplaceholders فيها). |
| `setVariable` | يضبط `variable` على `value`. |
| `oneOf` | يأخذ أول فرع يتحقق شرطه. |
| `forEach` | يشغّل خطوة لكل عنصر في `items`، بالتتابع. |
| `evaluator` | يقيّم تعبيراً على متغيرات الـflow. |
| `return`، `end` | يرجّعان `value` الخاصة بالعقدة كنتيجة. |
| `throw` | يفشّل الـflow بالـ`message` الخاصة بالعقدة (تتعوّض فيها الـ`{{variable}}` placeholders؛ والافتراضي `'Flow error'`). |

شروط `oneOf` وتعبيرات `evaluator` تمر على لغة تعبيرات صغيرة وآمنة: لا `eval` ولا كود host. اللغة تربط الـ`{{name}}` placeholders كقيم، ولا تلصقها في نص التعبير. قواعدها النحوية وقواعد فشلها في [تعبيرات الـflow](#تعبيرات-الـflow).

## flow أم sub-agent أم skill؟

استخدم flow إذا كان الـpipeline معروفاً مسبقاً. استخدم [sub-agents](/ar/sub-agents) لما تريد الـmodel نفسه أن يقرر ما يفوّضه، و[skills](/ar/skills) لما يحتاج نفس الـagent تعليمات إضافية لبعض المهام فقط. راجع [sub-agent أم skill أم flow؟](/ar/sub-agents#sub-agent-ولا-skill-ولا-flow).

الـtracing يغطي الـflows مثل أي run للـagent (راجع [Tracing والـobservability](/ar/observability#flows)).

## تعبيرات الـflow

مقيّم تعبيرات صغير مدمج يقيّم شروط فروع `oneOf` (وشروط فروع عقدة الـrouter في Agent Forge) وتعبيرات عقدة `evaluator`. المقيّم لا يصرّف ولا يشغّل كود host إطلاقاً: لا يوجد `eval` ولا `new Function` ولا `vm` في `src/flows`. الـ`{{name}}` placeholders تُربَط كقيم ولا تُلصَق في نص التعبير: فـ`{{score}} >= 90` المجرّد يستخدم قيمة المتغير، وداخل string literal مثل `'{{classify}}' === 'refund'` يدخل نص القيمة في الـliteral بعد ما يتجزّأ التعبير إلى tokens. وإذا كانت قيمة المتغير فيها علامات اقتباس أو backslashes أو operators — مثل `x' === 'x' || 'a` — تبقى مجرد بيانات ولا تستطيع تغيير منطق الشرط. المتغير المفقود أو `null` يصبح string فاضياً داخل الـliteral؛ وإذا استُخدم مجرّداً لا يضيف شيئاً، فـ`{{missing}} >= 90` يعطي خطأ syntax ويعتبر الشرط غير متحقق. المقيّم يقيّم التعبير على متغيرات الـflow.

| الصيغة | أمثلة |
| --- | --- |
| literals | `'text'`, `"text"`, `42`, `1.5`, `true`, `false`, `null` |
| متغيرات ومسارات | `score`, `user.address.city`, `user['first-name']`, `items[0].id` |
| الطول | `name.length`, `items.length` (للسلاسل النصية والمصفوفات) |
| مقارنة | `==`, `===`, `!=`, `!==`, `<`, `<=`, `>`, `>=` |
| منطقية | `&&`, `\|\|`, `!` (تقييم short-circuit، يرجّع المعامل الذي حسم النتيجة) |
| حسابية | `+`, `-`, `*`, `/`, `%`, والأحادية `-` و`+` |
| تجميع | `( ... )` |
| methods مسموحة | `s.includes(x)` و`s.startsWith(x)` و`s.endsWith(x)` على السلاسل النصية؛ و`list.includes(x)` على المصفوفات (معامل واحد بالضبط) |

الأسبقية، من الأضعف إلى الأقوى: `||`، ثم `&&`، ثم المساواة، ثم العلاقات، ثم `+ -`، ثم `* / %`، ثم الأحادية، ثم member access.

كل ما عدا الصيغ أعلاه غير مدعوم، ويُرفض بـ`ExpressionError` يسمّي التعبير وموضع المحرف وقائمة الصيغ المدعومة: أي استدعاء دالة أو method آخر، والإسناد (`=` و`+=` و`++`)، والـternary، وtemplate strings، وliterals للكائنات والمصفوفات، والوصول إلى `constructor` أو `__proto__` أو `prototype`، والـglobals مثل `process` و`require` و`globalThis`. الوصول ممكن فقط لمتغيرات الـflow نفسه، ولخصائصها هي فقط.

سلوك الفشل لم يتغيّر: شرط `oneOf` الذي لا يمكن تقييمه يُحسب غير متحقق (`false`)، وتعبير `evaluator` الذي لا يمكن تقييمه يفشّل الـflow برسالة `Failed to evaluate expression: ...`، مع تفاصيل `ExpressionError`.
