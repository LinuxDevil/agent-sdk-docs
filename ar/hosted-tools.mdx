بعض الـ providers يشغّلون tools بنفسهم، داخل طلب الـ model نفسه. أشهرها عند OpenAI: web search وcode interpreter وfile search. ضعها في `tools` بجانب الـ tools التي تعرّفها أنت. الـ provider هو الذي يشغّلها، والـ run يبلّغ عن كل call في الـ events، ويحتفظ بها في الـ transcript (سجل الرسائل)، ويحسبها في الـ usage.

```ts
import { createAgent, webSearch, defineTool } from '@lousho/build-ai-agent';
import { z } from 'zod';

const saveNote = defineTool({
  name: 'save_note',
  description: 'Save a note',
  input: z.object({ text: z.string() }),
  execute: async ({ text }) => ({ saved: text.length }),
});

const agent = createAgent({
  model: 'openai/gpt-4o-mini',
  instructions: 'Answer with sources.',
  tools: [webSearch({ searchContextSize: 'low' }), saveNote],
});

const result = await agent.send('What changed in Node 24?');
console.log(result.text, result.usage.hostedToolCalls); // { web_search: 1 }
```

الـ SDK لا ينفّذ أي hosted tool أبدًا. يرسلها مع كل model call في الـ run ويبلّغ عمّا فعله الـ provider. بادئة `vendor/` في الـ model هي التي تختار الـ provider. مع OpenRouter استخدم `openrouter/<vendor>/<model>` (مثل `openrouter/openai/gpt-4o-mini`).

## الـ helpers

| Helper | الاسم | الخيارات |
| --- | --- | --- |
| `webSearch(options?)` | `web_search` | `searchContextSize` (`'low' \| 'medium' \| 'high'`)، `userLocation` (`{ country, city, region, timezone }`)، `allowedDomains`، `blockedDomains`، `maxUses` |
| `codeInterpreter(options?)` | `code_interpreter` | `container`: مُعرّف container موجود؛ بدونها الـ provider ينشئ واحدًا |
| `fileSearch({ vectorStoreIds, maxResults? })` | `file_search` | `vectorStoreIds` (واحد على الأقل؛ vector stores أنشأتها عند الـ provider)، `maxResults` |
| `hostedTool(name, aiSdkTool)` | `name` | أي tool object من حزمة الـ provider في AI SDK، يُمرَّر كما هو |

`isHostedTool(value)` تفرّق بين الـ hosted tool والـ tool المحلية. اسم كل helper هو نفس الاسم الذي يستخدمه الـ model والـ events و`usage.hostedToolCalls`. لو كتبت `tools` على شكل record، لازم مفتاح الـ hosted tool يكون اسمها (`tools: { web_search: webSearch(), lookup }`). hosted tool باسم tool أخرى يرمي الخطأ `LOUSHO_CONFIG_INVALID` عند إنشاء الـ agent.

كل provider يستخدم الخيارات التي يدعمها ويتجاهل الباقي مع `console.warn` واحدة. OpenAI يأخذ `searchContextSize` و`userLocation` و`allowedDomains` (بدون `maxUses` وبدون `blockedDomains`). Anthropic يأخذ `maxUses` و`allowedDomains` و`blockedDomains` و`userLocation` (بدون `searchContextSize`؛ والـ code execution عنده بلا `container`). OpenRouter يأخذ `maxUses` و`allowedDomains` و`blockedDomains` (يُرسلها باسم `excluded_domains` عنده) و`searchContextSize` (بدون `userLocation`).

## أي provider يشغّل أي tool

| Tool | OpenAI | Anthropic | OpenRouter | Ollama | `fromAiSdk()` / باقي providers في AI SDK |
| --- | --- | --- | --- | --- | --- |
| `webSearch()` | ✅ `ai` 6 + `@ai-sdk/openai` 3، `ai` 7 + `@ai-sdk/openai` 4 | ✅ `ai` 6 + `@ai-sdk/anthropic` 3، `ai` 7 + `@ai-sdk/anthropic` 4 | ✅ كل models بصيغة `openrouter/...`، مع أي `ai` | ❌ | ❌ (استخدم `hostedTool()`) |
| `codeInterpreter()` | ✅ نفس التوليفات | ✅ نفس التوليفات (code execution في Anthropic) | ❌ | ❌ | ❌ (استخدم `hostedTool()`) |
| `fileSearch()` | ✅ نفس التوليفات | ❌ (Anthropic ما يوفّر hosted file search) | ❌ | ❌ | ❌ (استخدم `hostedTool()`) |
| `hostedTool()` | ✅ `ai` 6 أو 7 | ✅ `ai` 6 أو 7 | ✅ `ai` 6 أو 7 | ✅ `ai` 6 أو 7 | ✅ `ai` 6 أو 7 |

الـ hosted tools تحتاج `ai` 6 أو 7. الاستثناء الوحيد: web search في OpenRouter يشتغل على `ai` 4 أيضًا. مع `ai` 4 (ومعه `@ai-sdk/openai` بإصدار 0.0.x أو 1.x) يُرفض كل hosted tool آخر. في OpenAI الـ model هو الـ Responses API model، وهو ما تعطيه `@ai-sdk/openai` من الإصدار 2 فصاعدًا.

في Anthropic تستخدم الـ helpers أحدث server tool مؤرَّخة تصدّرها نسخة `@ai-sdk/anthropic` المثبّتة عندك: `webSearch()` تأخذ أحدث `tools.webSearch_*()`، و`codeInterpreter()` تأخذ أحدث `tools.codeExecution_*()` (Anthropic يسمّيها `code_execution`؛ والـ SDK يبقي الاسم `code_interpreter` في الـ events وفي `usage.hostedToolCalls` على كل الـ providers). الحزمة التي ما فيها أي منها تُرفض مع ذكر التوليفة التي تشتغل. لأي server tool ثانية في Anthropic (مثل web fetch) استخدم `hostedTool('web_fetch', anthropic.tools.webFetch_20260318())`.

في OpenRouter، `webSearch()` تضيف الـ server tool الخاصة بـ OpenRouter، وهي `openrouter:web_search`، إلى الطلب. البحث يصير على جهة OpenRouter لأي model. OpenRouter هو من يختار محرك البحث: بحث الـ model نفسه إن كان عنده، وإلا Exa. ويحاسبك على كل بحث فوق الـ tokens بالأسعار الموجودة في [صفحة أسعار OpenRouter](https://openrouter.ai/pricing). راجع [دليل web search](https://openrouter.ai/docs/guides/features/server-tools/web-search) لتفاصيل المحركات. ولأن السيرفر ينفّذ البحث داخل الطلب، الـ model لا يبلّغ عن أي tool call. بدلها يبلّغ الـ SDK عن hosted call واحدة لكل model step بحث فيها، ويقرأها من ردّ OpenRouter: `name: 'web_search'`، و`args` فارغة، والروابط المستشهد بها من `url_citation` annotations تصير `sources`، و`result: { requests }` إذا بلّغ OpenRouter عن `usage.server_tool_use.web_search_requests` (وإلا `result` تكون `{}`؛ الاختبار الحي ما استلم عددًا). الاستعلام الذي بحث عنه الـ model لا يُبلَّغ عنه.

أي توليفة غير مدعومة ترفض الـ run قبل أول model call بخطأ [`LOUSHO_HOSTED_TOOL_UNSUPPORTED`](/ar/errors#lousho_hosted_tool_unsupported) يذكر الـ provider والـ tool وما الذي سيشتغل.

الـ `LLMProvider` المخصّص يعلن عمّا يقدر يرسله عبر `supportsHostedTool(type)` — قيمة `type` هي `'web_search'` أو `'code_interpreter'` أو `'file_search'` أو `'custom'` لـ `hostedTool()` — ويستلم الـ tools في `GenerateOptions.hostedTools`. الـ provider الذي لا يملك هذه الدالة ما يدعم أي hosted tool. و`withRetry()` و`withFallback()` تسألان الـ provider المغلَّف (الأول).

## أي provider tool من AI SDK: `hostedTool()`

`hostedTool(name, tool)` ترسل كائن الـ provider tool الذي بنيته بحزمة الـ provider كما هو، بدون تغيير، على `ai` 6 أو 7. تشتغل مع الـ providers المدمجين ومع أي model من AI SDK مغلَّف بـ [`fromAiSdk()`](/ar/providers#أي-model-من-ai-sdk-fromaisdk):

```ts
import { createAgent, fromAiSdk, hostedTool } from '@lousho/build-ai-agent';
import { openai } from '@ai-sdk/openai';

const agent = createAgent({
  provider: fromAiSdk(openai('gpt-4o-mini')),
  tools: [hostedTool('image_generation', openai.tools.imageGeneration())],
});
```

استخدم اسم الـ tool كما توثّقه حزمة الـ provider.

## الـ events

الـ hosted call يُبلَّغ عنها مثل tool call، مع `executedBy: 'provider'` في `tool.start` و`tool.done` و`tool.error`:

```ts
import { createAgent, webSearch } from '@lousho/build-ai-agent';

const agent = createAgent({ model: 'openai/gpt-4o-mini', tools: [webSearch()] });

for await (const event of agent.stream('Latest TypeScript release?')) {
  if (event.type === 'tool.start' && event.executedBy === 'provider') console.log('provider runs', event.toolName, event.args);
  if (event.type === 'tool.done' && event.executedBy === 'provider') console.log('provider result', event.result);
  if (event.type === 'text.delta') process.stdout.write(event.text);
}
```

لو كان الـ model call بـ streaming، توصل الـ events لحظة يبلّغ الـ provider عن الـ call. ولو كان بدون streaming، تصل بعد الـ call، بترتيب الـ calls، وقبل نصّه. `tool.done.result` محدودة بـ 20,000 حرف من JSON؛ النتيجة الأطول تصير نص JSON مقصوصًا ينتهي بـ `... [truncated N characters]`. وفي `tool.error` تكون `error.name` هي `'HostedToolError'` مع رسالة الـ provider. وبث واجهة AI SDK (`toUIMessageStream()`) يعلّم أجزاء الـ tool هذه بـ `providerExecuted: true`.

في الـ traces، الـ `chat` span الخاص بـ model call يحمل `lousho.hosted_tool_calls` (أسماء الـ tools التي شغّلها الـ provider فيه). لا يوجد `execute_tool` span لها، لأن الـ SDK ما نفّذ شيئًا.

## الـ transcript والـ replay

رسالة الـ assistant في الـ step تحصل على `metadata.hostedToolCalls`: لكل call قيم `id` و`name` و`args` و`result` (بنفس الحد أعلاه) و`isError` و`sources` للروابط التي استشهد بها الـ provider بعدها. تجدها في `result.messages`.

في الـ calls اللاحقة يُرجَع للـ model نص الـ assistant فقط، ولا تُرجَع كتل الـ tools الخاصة بالـ provider أبدًا. هذا يشتغل مع كل provider وكل model. الثمن: الـ citations من الدورات السابقة لا تُعاد للـ model.

## الـ usage والتكلفة

`result.usage.hostedToolCalls` (و`usage.hostedToolCalls` في `run.done`) تحسب الـ calls لكل اسم tool، مثل `{ web_search: 2 }`. الـ calls الخاصة بالـ sub-agent تُضاف إلى calls الـ lead. الـ tokens التي تضيفها الـ hosted tool (نتائج البحث التي يقرأها الـ model، ومخرجات الكود) داخلة في عدّادات الـ tokens التي يبلّغ عنها الـ provider.

`costUsd` يغطي الـ tokens فقط. رسوم كل call للـ hosted tools (بحث ويب أو session (جلسة) لـ code interpreter) يحاسب عليها الـ provider و**لا** تدخل فيها. راجع أسعار الـ provider واستخدم الأعداد أعلاه.

## الموافقات والصلاحيات

الـ SDK لا يقدر يضبط شيئًا لا ينفّذه. الـ hosted tool تشتغل داخل طلب الـ provider، فلا تراها أي قاعدة صلاحيات، ولا guardrail للـ tools، ولا `needsApproval`، ولا hook مثل `preToolCall` / `postToolCall` أو `onToolCall`. **ولا يمكن إيقاف hosted tool لطلب approval (موافقة)**. لو كان الـ run ممنوعًا يبحث أو ينفّذ كودًا بدون إنسان، اترك الـ tool خارج `tools`، أو اختر الـ tools لكل run بدالة:

```ts
import { createAgent, webSearch } from '@lousho/build-ai-agent';

const agent = createAgent({
  model: 'openai/gpt-4o-mini',
  tools: ({ metadata }) => (metadata?.allowSearch ? [webSearch()] : []),
});

await agent.send('Summarize this page.', { metadata: { allowSearch: true } });
```

[أوضاع الصلاحيات](/ar/permission-modes) أيضًا ما تقدر ترفض hosted call، لذلك دورها أنها تقرر أي hosted tools تُرسل مع كل model call:

| الوضع | `webSearch()` و`fileSearch()` | `codeInterpreter()` و`hostedTool()` |
| --- | --- | --- |
| `'default'` | تُرسل | تُرسل |
| `'plan'` | تُرسل (لأنها تقرأ فقط) | **لا تُرسل**: الـ model لا يراها |
| `'acceptEdits'` | تُرسل | تُرسل |
| `'dontAsk'` | تُرسل (الـ hosted call لا يسأل أبدًا) | تُرسل |

الـ code interpreter ينفّذ كودًا، و`hostedTool()` هي tool لا يعرف عنها الـ SDK شيئًا، لذلك وضع `plan` يتعامل مع الاثنين كـ tools لها side effects. الوضع يُقرأ قبل كل model call، فأي تبديل (`session.setPermissionMode()` أو وضع معطى كدالة) يسري من الـ call التالي. ولا يُكتب إدخال `permission.decision` لأي hosted tool استُبعدت: ما حصل أي call.

الـ sub-agents لا ترث الـ hosted tools الخاصة بالـ lead؛ أعطِ كل sub-agent أدواته في `tools`. الـ run الذي يُستأنف من checkpoint أو من approval يرسل نفس الـ hosted tools. والـ agent الذي يستأنف بمجموعة مختلفة يبلّغ عن [agent drift](/ar/durable-execution).

## الاختبار

`mockModel` يقبل hosted calls في الـ turn ويسجّل `hostedTools` في كل request، فيقدر agent عنده hosted tools يشتغل بدون اتصال:

```ts
import { createAgent, webSearch } from '@lousho/build-ai-agent';
import { mockModel } from '@lousho/build-ai-agent/testing';

const model = mockModel([
  {
    text: 'Node 24 ships npm 11.',
    hostedToolCalls: [{ name: 'web_search', args: { query: 'node 24' }, result: { hits: 3 }, sources: [{ url: 'https://nodejs.org' }] }],
  },
]);
const agent = createAgent({ provider: model, tools: [webSearch()] });
const result = await agent.send('What changed in Node 24?');

console.log(model.calls[0]?.hostedTools?.[0]?.name); // 'web_search'
console.log(result.usage.hostedToolCalls); // { web_search: 1 }
```

## غير مغطّى بعد

لا توجد helpers لـ image generation وcomputer use وhosted MCP وhosted shell؛ مرّر الـ tool من حزمة الـ provider عبر `hostedTool()` حيث تعمل. وإعادة إرسال كتل الـ tools الخاصة بالـ provider للإبقاء على الـ citations عبر الدورات غير مدعومة.
