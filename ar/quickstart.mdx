## ابدأ مشروع جديد

أسرع طريقة أمر واحد. ينشئ مشروع جاهز للتشغيل (agent، وtool كمثال، واختبار offline، وملف `.env.example` للـ provider)، ويثبّت الـ dependencies، ويشغّل `git init`:

```bash
npx lousho init my-agent
cd my-agent
cp .env.example .env     # put your API key in .env
npm run dev              # chat with your agent in the terminal
npm test                 # offline tests: no API key needed
```

`npm create lousho-agent my-agent` يعمل نفس الشيء، وكذلك `npx @lousho/build-ai-agent init my-agent` إذا لم يكن الـ SDK مثبّتًا بعد (`npx lousho` لوحده لا يجد أمر `lousho` إلا بعد وجود الـ SDK في `node_modules` لديك). بدون arguments، يسألك `init` عن المجلد والـ provider والقالب. و`lousho init --help` يعرض كل الـ flags.

تفضّل تضيف الـ SDK إلى مشروع موجود؟ ثبّته يدويًا (راجع [التثبيت](/ar/installation)):

```bash
npm install @lousho/build-ai-agent ai@^7.0.0 zod
npm install @ai-sdk/openai@^4.0.0 @ai-sdk/anthropic@^4.0.0
```

هذا هو الـ major version الحالي من `ai`. ومع Ollama استخدم `ai@^7.0.0` مع `ollama-ai-provider-v2@^4.0.0` وzod 4 (راجع [الأزواج](/ar/installation#حزم-الـ-providers)).

## 1. Hello world

`createAgent()` هي نقطة الدخول بدون أي إعداد. تعطيها string بصيغة `provider/model` وتعليمات، وترجع لك agent فيه `{ send }`. مفتاح الـ API يُقرأ من متغير البيئة المعتاد للـ provider (`OPENAI_API_KEY` هنا، و`ANTHROPIC_API_KEY` أو `OPENROUTER_API_KEY` أو `OLLAMA_BASE_URL` للـ providers الباقين). الـ prefix `vendor/` في الـ model هو الذي يحدد الـ provider. ومع OpenRouter استخدم `openrouter/<vendor>/<model>` (مثل `openrouter/openai/gpt-4o-mini`).

```ts
import { createAgent } from '@lousho/build-ai-agent';

const agent = createAgent({ model: 'openai/gpt-4o-mini', instructions: 'You are a helpful assistant.' });
const { text } = await agent.send('Hello!');
console.log(text);
```

احذف `model` وخُذ قرار البيئة بدلًا عنك: `LOUSHO_MODEL` (string بصيغة `provider/model`) إذا كان موجودًا، وإلا أول واحد موجود من `OPENAI_API_KEY` و`ANTHROPIC_API_KEY` و`OPENROUTER_API_KEY` و`OLLAMA_BASE_URL`. إذا نقص مفتاح أو كُتب الـ prefix خطأ، رسالة الخطأ تخبرك بالضبط ما تضبطه أو تصلحه. `instructions` اختيارية، و`prompt` مقبولة كـ alias لها.

## 2. أضف tool

عرّف الـ tool بـ `defineTool()`. وسائط `execute` و`needsApproval` تكون typed من الـ zod `input`، والـ tool يدخل مباشرة في `createAgent({ tools: [...] })`. الـ mock provider يحاكي tool call كلما ذكرت رسالة المستخدم اسم tool، فهذا المثال يمر بـ tool call حقيقي كامل بدون LLM.

```ts
import { createAgent, createMockProvider, defineTool } from '@lousho/build-ai-agent';
import { z } from 'zod';

const currentDate = defineTool({
  name: 'current_date',
  description: 'Get the current date',
  input: z.object({}),
  async execute() {
    return { date: new Date().toISOString().slice(0, 10) };
  },
});

const agent = createAgent({
  prompt: 'You are a scheduling assistant. Use tools when helpful.',
  provider: createMockProvider({ responses: ['Let me check.', 'Here is the date you asked for.'] }),
  tools: [currentDate],
});

const result = await agent.send('Please call current_date for me');
console.log(result.toolCalls.map((call) => call.function.name)); // [ 'current_date' ]
console.log(result.text);
```

الأسماء يجب أن تكون من 1 إلى 64 حرف: حروف أو أرقام أو `_` أو `-`. راجع [الأدوات](/ar/tools) للـ validation والأخطاء والـ tools المدمجة.

## 3. اعمل streaming للرد

`agent.stream()` يشغّل الـ agent مثل `send()` ويرجع `AgentRun`. مرّ عليه بـ loop لتحصل على events typed (نص الـ model أول ما يصل، tool calls، حدود الـ steps). و`await run.result` يعطيك نفس النتيجة التي ترجعها `send()`.

```ts
import { createAgent, createMockProvider } from '@lousho/build-ai-agent';

const agent = createAgent({
  prompt: 'You are a helpful assistant.',
  provider: createMockProvider({ responses: ['Streaming works word by word.'] }),
});

const run = agent.stream('Tell me something.');
for await (const event of run) {
  if (event.type === 'text.delta') process.stdout.write(event.text);
}
process.stdout.write('\n');

const result = await run.result;
console.log(result.finishReason); // "stop"
```

راجع [Streaming](/ar/streaming) لقائمة الـ events الكاملة، والإلغاء، وإرسال الـ events إلى المتصفح.

## 4. احتفظ بالمحادثة

`agent.send()` تبدأ من history فارغ في كل استدعاء. أما `agent.session()` فتحتفظ بالمحادثة وتمررها للـ model مع كل `send()`.

```ts
import { createAgent, createMockProvider } from '@lousho/build-ai-agent';

const agent = createAgent({
  prompt: 'You are a helpful assistant.',
  provider: createMockProvider({ responses: ['Nice to meet you, Ali.', 'Your name is Ali.'] }),
});

const session = agent.session();
await session.send('My name is Ali.');
const { text } = await session.send('What is my name?');

console.log(text);
console.log(session.messages.length); // 4: two user messages and two replies
```

مرّر store لتحفظ الـ sessions بين إعادات التشغيل. راجع [الجلسات](/ar/sessions).

## 5. اسأل قبل خطوة فيها مخاطرة

علّم الـ tool بـ `needsApproval` ويتوقف الـ run قبل استدعائها. `send()` تنتهي بـ `finishReason: 'awaiting-approval'` و`approvalId`. بعدها يوافق كودك (أو إنسان) على الـ call أو يرفضه، ويكمل الـ run. هنا `mockModel` من `@lousho/build-ai-agent/testing` يحدد turns الـ model بدقة، فالـ tool call مضمون.

```ts
import { createAgent, defineTool } from '@lousho/build-ai-agent';
import { mockModel } from '@lousho/build-ai-agent/testing';
import { z } from 'zod';

const sendEmail = defineTool({
  name: 'send_email',
  description: 'Send an email',
  input: z.object({ to: z.string() }),
  needsApproval: true,
  execute: async ({ to }) => `sent to ${to}`,
});

const agent = createAgent({
  instructions: 'You send emails.',
  provider: mockModel([
    { toolCalls: [{ name: 'send_email', args: { to: 'sam@example.com' } }] },
    { text: 'Sent.' },
  ]),
  tools: [sendEmail],
});

const paused = await agent.send('Email the report to sam@example.com');
console.log(paused.finishReason); // "awaiting-approval"

const result = await agent.approvals.resolve({ id: paused.approvalId!, approved: true });
console.log(result.text); // "Sent."
```

مرّر `approved: false` (مع `note`) لرفض الـ call بدل الموافقة. راجع [الموافقات](/ar/approvals) للـ predicates والـ stores والقرار من process آخر.

## 6. اختبره offline

الـ agent من الخطوة السابقة جاهز للاختبار أصلًا. `mockModel` يسجّل كل طلب أرسله الـ agent، فتقدر تتحقق مما أُرسل للـ model وكذلك من النتيجة. بدون شبكة وبدون مفتاح.

```ts
import { createAgent, defineTool } from '@lousho/build-ai-agent';
import { mockModel } from '@lousho/build-ai-agent/testing';
import { z } from 'zod';

let sent: string | undefined;
const sendEmail = defineTool({
  name: 'send_email',
  description: 'Send an email',
  input: z.object({ to: z.string() }),
  needsApproval: true,
  execute: async ({ to }) => {
    sent = to;
    return `sent to ${to}`;
  },
});

const model = mockModel([
  { toolCalls: [{ name: 'send_email', args: { to: 'sam@example.com' } }] },
  { text: 'Sent.' },
]);
const agent = createAgent({ instructions: 'You send emails.', provider: model, tools: [sendEmail] });

const paused = await agent.send('Email the report to sam@example.com');
const result = await agent.approvals.resolve({ id: paused.approvalId!, approved: true });

function check(ok: boolean, message: string): void {
  if (!ok) throw new Error(`Assertion failed: ${message}`);
}
check(result.text === 'Sent.', 'final answer');
check(sent === 'sam@example.com', 'the tool ran with the approved arguments');
check(model.calls.length === 2, 'the model was called twice');
model.assertExhausted(); // throws if a scripted turn was never used
console.log('ok');
```

في مشروع حقيقي، ضع نفس الـ assertions في اختبار vitest أو Jest. راجع [الاختبار](/ar/testing) لتدفقات الـ tool calls وturns الأخطاء و`recordReplay`.

## 7. Custom provider

`model: 'provider/model'` هو الطريق المختصر. مرّر `provider` بدلًا منه إذا كان عندك `LLMProvider` خاص بك أو تريد الـ mock للاختبارات. `resolveProvider('<provider>/<model>')` هي الدالة التي يستخدمها `model` من الداخل. هذا المثال يستخدم OpenAI إذا كان `OPENAI_API_KEY` موجودًا، ويرجع إلى الـ mock provider في غير ذلك. وهو نفس النمط الذي تستخدمه [الأمثلة](https://github.com/LinuxDevil/agent-sdk/blob/main/examples/README.md) الجاهزة للتشغيل.

```ts
import { createAgent, createMockProvider, resolveProvider } from '@lousho/build-ai-agent';

const provider = process.env.OPENAI_API_KEY
  ? resolveProvider('openai/gpt-4o-mini')
  : createMockProvider({ responses: ['Paris.'] });

const agent = createAgent({
  name: 'geography-bot',
  prompt: 'Answer geography questions in one word.',
  provider,
});

const result = await agent.send('What is the capital of France?');
console.log(result.text);
```

## 8. Declarative agents: ملفات spec

تقدر توصف الـ agent كبيانات عادية، أي `AgentSpec`، وتحوّله إلى agent شغّال بـ `specToAgent()`. ونفس الشكل يُكتب كملف YAML أو JSON ويُحمّل بـ `loadSpec()`.

```ts
import { specToAgent, agentSpecSchema } from '@lousho/build-ai-agent';

const spec = agentSpecSchema.parse({
  name: 'support-bot',
  prompt: 'You are a friendly support agent.',
  provider: { type: 'mock', model: 'mock-1' },
  tools: ['current-date'],
});

const agent = specToAgent(spec);
const result = await agent.send('Hello!');
console.log(result.text);
```

احفظه باسم `agent.yaml`:

```yaml
name: support-bot
prompt: You are a friendly support agent.
provider:
  type: mock
  model: mock-1
tools:
  - current-date
```

نفس الـ spec يشتغل في سيرفر التطوير المحلي (واجهة chat على `/`، و`POST /chat`، وhot reload عند الحفظ) ويُبنى كسيرفر جاهز للنشر:

```bash
npx lousho dev agent.yaml
npx lousho build --target=node-server --agent=agent.yaml
```

## متقدم: executor API

`createAgent()` هي نقطة الدخول الموصى بها. وهي مبنية فوق `AgentBuilder` والدالة `AgentExecutor.execute()`، وهذه تقبل خيارات أدنى مستوى لا تقبلها `createAgent()`، مثل `temperature` و`maxTokens`. راجع [executor API](/ar/executor-api).
