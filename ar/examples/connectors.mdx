يعمل هذا المثال **دون اتصال بالكامل**، فالملف `./mock-connectors-server.ts` خادم MCP حقيقي يعمل عبر stdio (مكتوب بالدالة `serveMcp` التي يوفّرها الـ SDK نفسه) ويعرض أدوات وهمية من نوع `docs_*` و`slack_*`. كود الـ agent مطابق لما يحتاجه موصِّل حقيقي، ولا يتغيّر إلا مُدخَل `mcpServers`.

## الموصِّلات الحقيقية

| الخدمة   | مُدخَل `mcpServers` |
| --------- | ------------------ |
| Google Docs/Drive | `{ url: '<google docs MCP endpoint>', oauth: { redirectUri: '<your callback>' } }` |
| Slack     | `{ url: 'https://mcp.slack.com/mcp', oauth: { redirectUri } }` |
| GitHub    | `{ url: 'https://api.githubcopilot.com/mcp/', headers: { Authorization: 'Bearer <PAT>' } }` أو خادم stdio المجتمعي عبر `command` |
| Notion    | `{ url: 'https://mcp.notion.com/mcp', oauth: { redirectUri } }` |
| أي موصِّل محلي | `{ command: 'npx', args: ['-y', '<their-mcp-server>'] }` |

يكون OAuth **مملوكًا للتطبيق**: يسجّل مشغّل واحد دخول الـ agent مرة واحدة لكل خادم عبر `agent.oauth.mcpSignInUrl('slack')`، ثم يعيد كل run استخدام هذا التفويض. راجع [docs/oauth.md](/ar/oauth) و[docs/connectors.md](/ar/connectors).

## أمان عمليات الكتابة

تحمل `slack_post_message` التوصيفين `destructiveHint` و`readOnlyHint`، ولا يضبط العرض التوضيحي `approval: 'never'` إلا ليعمل دون تفاعل. في بيئة الإنتاج أبقِ القيمة الافتراضية (`'always'`)، أو استخدم `'annotations'` مع خادم تثق به، أو دالة شرطية لـ `approval` أو قواعد صلاحيات، كي تتوقف *عمليات الكتابة* عبر الموصِّل بانتظار موافقة بشرية. راجع [docs/approvals.md](/ar/approvals).
