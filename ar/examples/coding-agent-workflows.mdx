يجيب القرار المُنمَّط (typed decision) عن سؤال احتمالي منظَّم، مثل التصنيف أو التوجيه أو التقييم أو التحقق، بدلًا من توليد نص. والصيغة التي يأخذها ذلك في Lousho هي `createAgent({ output: DECISION })`: يُرجع النموذج `{ route, confidence, reason }` بعد التحقق منه بمخطط zod (ويمكن قراءته عبر `result.object`)، ويتفرّع مسار العمل بحسب الحقول المُنمَّطة.

```text
request ──► TRIAGE { route, confidence, reason }   ◄── the typed decision
                │ 'fix'      ∧ confident ──► fix flow:      edit → verify
                │ 'refactor' ∧ confident ──► refactor flow: plan → edit → verify
                │ 'explain'  ∧ confident ──► explain flow:  read-only llmCall
                │ confidence < floor     ──► careful path (refactor), whatever
                                            the route said — calibrated abstention
```

خاصيتان تستحقان الاقتباس:

- **الامتناع المُعايَر.** يوجّه `confidenceFloor` (القيمة الافتراضية 0.7) القرارات منخفضة الثقة إلى مسار العمل الحذر، فالنموذج يصرّح بعدم يقينه، والـ harness يتراجع بسلاسة بدلًا من الوثوق بتوجيه مهزوز.
- **التراجع المُنمَّط.** إذا تعذّر تحليل ردّ الفرز أُرجع `confidence: 0`، فيُسلَك المسار الحذر. ولا يوجد مسار يتحوّل فيه قرار معيب بصمت إلى "أصلح الأشياء".

لتشغيله:

```bash
npm run example:coding-agent-workflows            # offline
OPENROUTER_API_KEY=… npx tsx examples/coding-agent-workflows/index.ts
```

تعيد مسارات العمل استخدام شكل [phase-pipeline](/ar/examples/phase-pipeline)، ويمكن تعميم القرار المُنمَّط على أي خطوة تصنيف أو توجيه أو تحقق. راجع [docs/prompting-techniques.md](/ar/prompting-techniques#قرارات-typed-بأسلوب-system-one).
