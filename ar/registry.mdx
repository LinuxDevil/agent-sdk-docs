`lousho add` يثبّت tool أو skill أو channel أو schedule أو خانة memory أو kit
داخل [agent directory](/ar/agent-directories) من registry. عنصر الـ`kit` هو
agent directory كامل: تثبيته يوزّع `agent.*` و`instructions.md` وtools وskills
وسub-agents، فيصبح الهدف (أو يتوسع ليصبح) agent directory بذاته. الـregistry
مجرد JSON ثابت: index إضافة إلى مستند لكل عنصر يحمل محتوى ملفاته. تُنسخ الملفات
إلى مشروعك كودًا مصدريًا تملكه وتستطيع تعديله. لا يوجد plugin loader في
الـruntime، ولا شيء من الـregistry يُنفَّذ أو يُستورد أثناء الإضافة.

`lousho add` يعمل دون أي إعداد: بدون `--registry` أو `LOUSHO_REGISTRY` يقرأ
الـregistry الافتراضي على `https://registry.lousho.com/index.json`، وهو مجلد
`registry/dist/` في مستودع الـSDK مُقدَّم كـJSON ثابت. إذا تعذّر الوصول لهذا
الـhost، يقرأ `lousho add` بدلًا منه من GitHub: من وسم الإصدار (release tag)
الخاص بنسخة الـSDK المثبّتة
(`https://raw.githubusercontent.com/LinuxDevil/lousho/<version>/registry/dist/index.json`)،
ثم من الوسم نفسه مع البادئة `v` (للإصدارات الأقدم)، ثم من `main`.
وإذا تعذّر الوصول إلى GitHub أيضًا (بدون اتصال، أو عطل، أو نسخة لم يُرفع وسمها
أبدًا)، يقرأ `lousho add` نسخة `registry/dist/` المرفقة داخل الحزمة المثبّتة،
ويطبع تنبيهًا من سطر واحد بأن هذا الـregistry المرفق قد يكون أقدم من النسخة
المتاحة على الإنترنت. الـregistry الافتراضي وحده يرجع إلى هذا البديل، أما الـregistry الذي تسمّيه بنفسك فلا. `--registry`
و`LOUSHO_REGISTRY` توجّهانه إلى registry آخر، والقيمة `none` (في أي منهما)
تعطّل الـregistry بالكامل — وحينها يفشل `lousho add` بـ`LOUSHO_CONFIG_INVALID`،
وهذا يناسب الاستخدام offline أو البيئات المغلقة.

الـregistry الافتراضي فيه حاليًا تسعة عناصر:

| الاسم | النوع | الصلاحيات التي يطلبها |
| ---- | ---- | ----------------------- |
| `changelog` | skill | لا شيء |
| `code-review` | skill | لا شيء |
| `coding-kit` | kit (الـcoding harness كاملًا كـagent directory) | `exec`, `fs-write` |
| `coding-pi` | kit (الـcoding harness على مزوّد Pi مع coding sub-agent من Pi) | `exec`, `fs-write`, `api.openrouter.ai`, `OPENROUTER_API_KEY` |
| `generic-webhook` | channel | `WEBHOOK_SECRET` |
| `github-issues` | tool (يسرد الـissues وينشئها؛ الإنشاء يطلب approval أي موافقة) | `api.github.com`, `GITHUB_TOKEN` |
| `inbox-triage` | kit (agent directory لفرز الرسائل: tools للـinbox والـoutbox، pipeline ردود محكوم بـapproval، channel للـwebhook، schedule للاستطلاع، وذاكرة لكل مرسل) | `fs-write`, `INBOX_TRIAGE_HOME`, `INBOUND_TOKEN`, `INBOX_TRIAGE_AUTO_APPROVE`, `OPENROUTER_API_KEY` |
| `incident-response` | kit (agent directory للاستجابة للحوادث بنمط SRE: webhook تنبيهات متحقق بـHMAC، approvals للمعالجة حسب مستوى الخطورة، وtimeline للتدقيق) | `fs-write`, `INCIDENT_WEBHOOK_SECRET`, `INCIDENT_TIMELINE_FILE` |
| `open-meteo-weather` | tool | `api.open-meteo.com`, `geocoding-api.open-meteo.com` |

الـcoding kits (`coding-kit` و`coding-pi`) تستخدم الـagent directory نفسه
كمساحة عمل المشروع. لذلك ترفض أدوات الملفات فيها تعديل ملفات الـagent نفسه:
`agent.*` و`approve.*` و`hooks.*` و`instructions*` و`lousho-registry.json`،
وأي شيء تحت `.lousho/` و`tools/` و`skills/` و`subagents/` و`.git/`
و`node_modules/`. والـshell فيها يشغّل فقط `node --test` (مسارات ملفات
اختبار، بلا flags) و`git status`. ومع ذلك تظل الـkits تشغّل الاختبارات التي
يكتب الـagent الكود لها، أي أن كود الـagent يعمل بصلاحيات مستخدمك. استخدم shell
داخل sandbox للعمل غير الموثوق (راجع [أدوات مساحة العمل](/ar/workspace-tools)).
والـsub-agent الخاص بالبرمجة من Pi في kit الـ`coding-pi` له أدواته الخاصة،
وهذه القواعد لا تغطيها.

```bash
lousho add --list                       # the default registry's items
lousho add open-meteo-weather --dir ./my-agent
lousho add web-search --registry https://example.com/registry/index.json --dir ./my-agent
LOUSHO_REGISTRY=./registry/index.json lousho add web-search --dry-run
lousho add --list --registry none       # fails: the registry is disabled
```

| الخيار | المعنى |
| ---- | ------- |
| `--registry <url-or-path>` | الـindex: رابط `http(s)` أو مسار محلي (`LOUSHO_REGISTRY` إذا لم يُعطَ، وإلا الـregistry الافتراضي). القيمة `none` تعطّل الـregistry. |
| `--dir <agent-dir>` | الـagent directory الذي يُكتب فيه (الافتراضي: المجلد الحالي). يجب أن يكون موجودًا، إلا مع `kit` فهو ينشئه. ومع أي عنصر آخر، المجلد الذي ليس فيه `agent.*` أو `instructions.md` يعطي تحذيرًا: فقط الـagent directory يحمّل `tools/` و`skills/` (مشروع `lousho init` يستورد الـtools في `src/agent.ts` بدلًا من ذلك). |
| `--yes`, `-y` | لا يسأل عن تأكيد. مطلوب عندما لا يكون stdin terminal. لا يمنح الصلاحيات المرتفعة بنفسه (راجع `--allow`). الخياران يُفحصان قبل طباعة أي شيء: التشغيل غير التفاعلي بدونهما يفشل بسطر واحد يسمّي الخيارات التي يحتاجها العنصر بالضبط، مثل `pass --yes --allow exec,fs-write`. |
| `--allow <list>` | مع `--yes`، الصلاحيات المرتفعة التي تمنحها، مفصولة بفواصل: `exec` و`fs-write` و`network` و`env`. العنصر الذي يطلب واحدة لم تسمّها يُرفض. |
| `--overwrite` | يستبدل الملفات الموجودة (بدونه الملف الموجود يعطي `LOUSHO_REGISTRY_FILE_EXISTS`). |
| `--dry-run` | يطبع الـmanifest والملفات، لا يكتب شيئًا، ويخرج 0. |
| `--list` | يطبع عناصر الـregistry ويخرج. |

قبل أن يكتب أي شيء، يطبع `lousho add` الـmanifest والملفات التي سيكتبها، ويفحص
كود العنصر مقابل الـmanifest، ثم يسأل `[y/N]`. بعد الكتابة يسجّل العنصر في
`lousho-registry.json`.

## الصيغة

الـindex هو `{ items: [{ name, type, description, url | path }] }`. قيمة `type`
واحدة من `tool` أو `skill` أو `channel` أو `schedule` أو `memory` أو `kit`.
و`url` / `path` يحددان مكان مستند العنصر؛ المسار النسبي يُحلّ بالنسبة لموقع
الـindex نفسه.

كل مستند عنصر بهذا الشكل:

```json
{
  "name": "web-search",
  "type": "tool",
  "description": "Search the web with the Example Search API",
  "files": [
    {
      "path": "tools/web-search.ts",
      "content": "import { defineTool } from 'lousho';\nimport { z } from 'zod';\n\nexport default defineTool({\n  name: 'web-search',\n  description: 'Search the web',\n  input: z.object({ query: z.string() }),\n  needsApproval: true,\n  execute: async ({ query }) => {\n    const response = await fetch(`https://api.example.com/search?q=${encodeURIComponent(query)}`, {\n      headers: { authorization: `Bearer ${process.env.SEARCH_KEY}` },\n    });\n    return response.json();\n  },\n});\n"
    }
  ],
  "permissions": {
    "network": ["api.example.com"],
    "env": ["SEARCH_KEY"],
    "filesystem": "none",
    "exec": false,
    "needsApproval": true
  },
  "dependencies": ["zod"]
}
```

ومدخله في `index.json`:

```json
{
  "items": [
    { "name": "web-search", "type": "tool", "description": "Search the web with the Example Search API", "path": "items/web-search.json" }
  ]
}
```

استضف الاثنين كملفات ثابتة في أي مكان: مجلد في repo، أو object store، أو web
server. يجب أن يطابق `name` و`type` في المستند مدخلهما في الـindex. يبدأ الاسم
بحرف أو رقم، ثم أحرف وأرقام و`.` و`_` و`-`. المستند الذي لا يطابق الصيغة
يُرجع `LOUSHO_REGISTRY_INVALID` مع ذكر الحقول.

لتساهم بعنصر في الـregistry الافتراضي، أضف مجلد `registry/<name>/` في مستودع
الـSDK: ملف `item.json` (فيه `name` و`type` و`description` و`permissions`
و`dependencies`) وملفات العنصر مرتبة كما يجب أن تصل في الـagent directory
(`tools/x.ts` و`skills/<name>/SKILL.md` و`channels/x.ts`؛ وملفات الـ`kit`
تكوّن agent directory كامل، مثل `agent.json` و`instructions.md` و`hooks.ts`
و`tools/` و`subagents/<name>/`). الأمر `npm run registry:build` يتحقق من كل
عنصر بالقواعد نفسها التي يفرضها `lousho add` (الـschema والمسارات وفحص الكود
مقابل الـmanifest) ويعيد بناء `registry/dist/`؛ أجرِ commit للنتيجة. الـCI
يشغّل `npm run registry:check` ويفشل إذا كانت `registry/dist/` قديمة.

## بيان الصلاحيات

`permissions` يصرّح بما يستطيع العنصر فعله، فتقرر قبل أن تثبّته. كله اختياري؛
وما يغيب يظهر كـ"none" / "no".

| الحقل | المعنى |
| ----- | ------- |
| `network` | الـhosts التي يستدعيها. |
| `env` | متغيرات البيئة التي يقرأها. |
| `filesystem` | `none` أو `read` أو `write`. |
| `exec` | `true` إذا كان يشغّل أوامر. |
| `needsApproval` | `true` إذا كانت أدواته تطلب [approval](/ar/approvals) قبل أن تعمل. |

ما يفرضه `lousho add` قبل أن يكتب أي شيء:

- **الكود يطابق الـmanifest.** كل ملف JavaScript وTypeScript في العنصر يُفحص،
  بعد حذف التعليقات، عما يصل إليه بشكل ظاهر:
  - `exec: true` عند import لـ`child_process` (بـ`node:` أو بدونها) أو `execa`
    أو `shelljs`، أو عند استخدام `createShellTool` أو `runShellCommand` أو
    `SubprocessSandbox` من الـSDK؛
  - `filesystem: "read"` (أو `"write"`) عند import لـ`fs` (بما فيها
    `fs/promises` وصيغ `node:`) أو `fs-extra` أو `graceful-fs`، أو
    `createFsTools` من الـSDK، و`"write"` عند استدعاء `writeFile` أو
    `appendFile` أو `createWriteStream` أو `mkdir` أو `mkdtemp` أو `rm` أو
    `rmdir` أو `unlink` أو `rename` أو `copyFile` أو `cp` (وصيغها الـ`Sync`)؛
  - `network` غير فارغ عند `fetch(` أو استخدام `createHttpTool` من الـSDK أو
    import لـ`http` أو `https` أو `http2` أو `net` أو `tls` أو `dgram` أو
    `undici` أو `axios` أو `node-fetch` أو `ws`، وكل host بصيغة `http(s)://`
    أو `ws(s)://` داخل string يجب أن يطابق أحد مدخلات `network` (الـhost الذي
    يُبنى وقت التشغيل، مثل `` `https://${host}/` ``، يحتاج `network` غير فارغ
    ويُطبع كملاحظة، لأنه لا يمكن فحصه)؛
  - كل `process.env.NAME` و`process.env['NAME']` يجب أن يكون مدرجًا في `env`.

  تُرفض دائمًا `eval(` و`new Function(` و`process.env[name]` المحسوب
  و`process.env` مستخدمة كاملة، وأي `import()` أو `require()` لغير string
  literal، و`require` مستخدمة كقيمة (`const r = require`). عدم المطابقة يُرجع
  `LOUSHO_REGISTRY_MANIFEST_MISMATCH` مع كل ملاحظة بالشكل `<file>:<line>:
  <what> (<fix>)`؛ و`--dry-run` يبلّغ عنها أيضًا. ملفات Markdown وغيرها مما
  ليس كود (مثل `SKILL.md` في الـskill) لا تُفحص. يجب أن تكون مدخلات `network`
  أسماء host أو wildcards تبدأ بـ`*.` (`api.example.com` و`*.example.com` —
  الـwildcard يطابق الـsubdomains فقط، لا الـhost المجرّد)، ومدخلات `env`
  أسماء متغيرات (`SEARCH_KEY`)؛ أي شيء آخر يُرجع `LOUSHO_REGISTRY_INVALID`.
- **الموافقة تغطي الصلاحيات المرتفعة.** `exec: true` و`filesystem: "write"`
  و`network` غير الفارغ و`env` غير الفارغ تُوسم `[elevated: ...]` في
  الـmanifest المطبوع. السؤال التفاعلي يسردها قبل `[y/N]`. ومع `--yes` يجب
  أن تسمّي كل واحدة في `--allow` (`--allow network,env` للمثال أعلاه)، لأن
  `--yes` هو الطريقة التي تشغّل بها السكربتات والـagents الأمر `lousho add`،
  ولا ينبغي أن يمنح تنفيذ أوامر بصمت.
- **إيصال بما ثُبِّت.** بعد الكتابة، `lousho add` يحدّث `lousho-registry.json`
  في جذر الـagent directory (بجانب `instructions.md`). مدخل كل عنصر فيه
  `type` و`registry` الذي جاء منه و`installedAt` و`permissions` و`path`
  و`sha256` لكل ملف، فتستطيع لاحقًا معرفة ما إذا عُدّل ملف. `--overwrite` يستبدل
  المدخل؛ `--dry-run` لا يكتب شيئًا. الإيصال غير الصالح كـJSON يوقف التثبيت
  قبل كتابة أي ملف. والإيصال هو ما يفرضه `loadAgentDir` عند التحميل ووقت
  التشغيل (أدناه).

وما يفرضه `loadAgentDir`، انطلاقًا من الإيصال، عندما يُحمَّل الـagent وتعمل أدوات
العنصر:

- **السلامة.** كل ملف يسرده الإيصال يُعاد حساب هاشه. الملف الذي عُدّل أو
  حُذف منذ ذلك الحين يجعل عنصره *unattested* (غير مُصدَّق): تحذير يذكر العنصر
  والملفات المتغيرة، و`resolveAgentDir()` يبلّغ عن الشيء نفسه في
  `manifest.registry` (`status: 'attested' | 'unattested'`، إضافة إلى مسارات
  `modified` و`missing`). التحميل لا يُرفض — الملفات ملكك تعدّلها — والإيصال
  الذي يتعذّر قراءته تحذير، لا خطأ.
- **الـapproval.** أدوات العنصر المصرِّح فيه بـ`exec: true` أو
  `needsApproval: true` — وأدوات أي عنصر unattested لم يعد إيصاله القديم
  يشهد للكود المعدَّل — تنتظر [approval](/ar/approvals) دائمًا؛ و`deny` من
  `needsApproval` الخاصة بالأداة نفسها يظل رافضًا. ولا شيء داخل الـagent
  directory يستطيع تجاوزها: [قاعدة صلاحيات](/ar/approvals#سياسات-الصلاحيات)
  من نوع `allow` و[وضع صلاحيات](/ar/permission-modes) (`acceptEdits`) لا يشغّلان الاستدعاء
  (قاعدة `deny` أو `plan` أو `dontAsk` تظل ترفضه)، وملف `approve` الخاص
  بالمجلد نفسه يؤجّله. الذي يقرر فقط هو شخص يحلّ التوقف
  (`agent.approvals.resolve()`) أو callback `approve` يمرّره كودك إلى
  `loadAgentDir(dir, { approve })`.
- **الـsub-agents.** مجلد الـsub-agent داخل العنصر المثبَّت (`subagents/<name>/`
  في الـkit) يخضع للإيصال نفسه: أدواته مقيّدة مثل باقي أدوات العنصر، وملف
  `approve` الخاص به يؤجّل استدعاءاتها المفروضة أيضًا. توقف الـsub-agent ليس
  له مقبض `approvals.resolve()`، فالذي يقرر فيها هو callback `approve` الذي
  يمرّره كودك إلى `loadAgentDir()`؛ وبدونه لا يعمل الاستدعاء المفوَّض، ويُبلَّغ
  الوكيل الرئيسي أن الـsub-agent توقف بانتظار approval.
- **الشبكة.** أثناء عمل أداة لعنصر له إيصال، `fetch` يقتصر على الـhosts التي
  يصرّح بها `network`: الـhost غير المدرج في الـmanifest يُرفض، والعنصر الذي
  لا يصرّح بأي `network` لا يستطيع إجراء fetch أصلًا.
- **البيئة.** وأثناء عملها، `process.env` يعرض للأداة فقط الأسماء التي يصرّح
  بها `env`.
- **أدوات الـsandbox.** الأداة التي تعلن `requiresSandbox` تحصل على adapter
  مضيَّق: `run()` يُرفض بدون `exec`، و`writeFile()` بدون
  `filesystem: "write"`، وبيئة الأمر هي الأساس المعتاد غير السري زائد
  المتغيرات المصرَّح بها فقط.

التقييد يظل بضيق الـmanifest الذي قُبل عند التثبيت على الأقل، سواء كان العنصر
مُصدَّقًا أم لا: تعديل ملف مثبَّت يوسمه ويطلب approval على استدعاءاته ولا
يوسّع شيئًا، إلى أن يثبّت `lousho add <name> --overwrite` الملفات الحالية
ويصدّقها من جديد.

ما لا يفعله: فحص وقت التثبيت يقرأ الكود كما هو مكتوب، وتقييد وقت التشغيل يغطي
فقط ما يستطيع الـSDK اعتراضه — استدعاءات `fetch` وقراءات `process.env` أثناء عمل
الأداة، والـadapter المسلَّم لأداة sandbox. الطلبات عبر `http`/`net`/`axios`،
والوصول للملفات، ومرجع محفوظ في module scope (`const f = fetch`)، والعمل
المنفَّذ عند استيراد الملف، وسياسة الشبكة الخاصة بالحاوية نفسها (`{ allow }`
في `SubprocessSandbox` خاصية للـsandbox لا للعنصر) — كل هذا خارجه. وكذلك
الكود الذي يخفي ما يفعله (string escapes وaliasing وحمولات مشفَّرة
وdependency تؤدي العمل) عن الفحص الساكن. اقرأ الملفات التي يسردها (يعرضها
`--dry-run`) كما تقرأ أي dependency قبل تشغيلها.

## قواعد الأمان

- يجب أن يكون كل `files[].path` نسبيًا وnormalized وبشرطات أمامية: لا `..`، لا
  مسار مطلق، لا حرف قرص (`C:`)، لا backslashes، لا مقاطع فارغة أو `.`. وبعد
  حل الـsymlinks يجب أن يظل داخل الـagent directory، ولا يُكتب أبدًا عبر symlink
  إلى هدفه.
- يجب أن يكون الملف داخل المجلد الذي يسمح به نوع عنصره: `tool` في `tools/`،
  و`skill` في `skills/<name>/`، و`channel` في `channels/`، و`schedule` في
  `schedules/`، و`memory` في `memory/`. الـ`kit` هو الاستثناء الوحيد: لأنه
  agent directory كامل، يمكن أن تقع ملفاته في أي مسار نسبي (تظل normalized
  وداخل الهدف حسب القاعدة أعلاه).
- الملفات الموجودة لا تُستبدل بدون `--overwrite`. كل الملفات تُفحص قبل كتابة
  أي منها، فالعنصر المعيب لا يكتب شيئًا. كل إخفاق من هذه هو
  `LOUSHO_REGISTRY_UNSAFE_PATH` أو `LOUSHO_REGISTRY_FILE_EXISTS`.
- الحد الأقصى للملف 256 KiB وللعنصر 1 MiB؛ ومستند الـregistry مليونا حرف كحد
  أقصى.
- تُقرأ فقط روابط `http(s)` والمسارات المحلية، بمهلة 15 ثانية لكل fetch (وإلا
  `LOUSHO_REGISTRY_UNREACHABLE`).
- `dependencies` تُطبع كسطر `npm install ...` لتشغّله أنت. الأمر لا يثبّت
  حزمًا أبدًا.

الأخطاء مسردة في [الأخطاء](/ar/errors#السجل). والـCLI كامل في [CLI](/ar/cli).
