يثبّت `lousho add` أداة أو مهارة أو قناة أو جدولًا زمنيًا أو خانة ذاكرة في [مجلد وكيل](/ar/agent-directories) من سجل. السجل مجرد JSON ثابت: فهرس ومستند لكل عنصر يحمل محتويات ملفاته. تُنسخ الملفات إلى مشروعك شيفرةً مصدرية تملكها وتستطيع تعديلها. لا يوجد محمِّل إضافات في وقت التشغيل، ولا يُنفَّذ أو يُستورد أي شيء من السجل أثناء الإضافة.

يعمل `lousho add` دون إعداد: فمن دون `--registry` أو `LOUSHO_REGISTRY` يقرأ السجل الافتراضي في `https://registry.lousho.com/index.json`، وهو مجلد `registry/dist/` في مستودع الـSDK مقدَّمًا ملفات JSON ثابتة. وتوجّه `--registry` و`LOUSHO_REGISTRY` الأمر إلى سجل آخر، والقيمة `none` (في أيٍّ منهما) تعطّل السجل كليًا — فيفشل `lousho add` حينها بالخطأ `LOUSHO_CONFIG_INVALID`، وهو ما يناسب الاستخدام دون اتصال أو البيئات المقيَّدة.

يحمل السجل الافتراضي حاليًا خمسة عناصر:

| الاسم | النوع | الصلاحيات التي يطلبها |
| ---- | ---- | ----------------------- |
| `changelog` | مهارة | لا شيء |
| `code-review` | مهارة | لا شيء |
| `generic-webhook` | قناة | `WEBHOOK_SECRET` |
| `github-issues` | أداة (سرد المشكلات وإنشاؤها؛ والإنشاء يطلب موافقة) | `api.github.com` و`GITHUB_TOKEN` |
| `open-meteo-weather` | أداة | `api.open-meteo.com` و`geocoding-api.open-meteo.com` |

```bash
lousho add --list                       # the default registry's items
lousho add open-meteo-weather --dir ./my-agent
lousho add web-search --registry https://example.com/registry/index.json --dir ./my-agent
LOUSHO_REGISTRY=./registry/index.json lousho add web-search --dry-run
lousho add --list --registry none       # fails: the registry is disabled
```

| الخيار | المعنى |
| ---- | ------- |
| `--registry <url-or-path>` | الفهرس: عنوان `http(s)` أو مسار محلي (ويُستخدم `LOUSHO_REGISTRY` عند غيابه، وإلا السجل الافتراضي). والقيمة `none` تعطّل السجل. |
| `--dir <agent-dir>` | مجلد الوكيل الذي يُكتب فيه (الافتراضي: المجلد الحالي؛ ويجب أن يكون موجودًا). |
| `--yes`، `-y` | لا تطلب تأكيدًا. مطلوب حين لا يكون stdin طرفية. لا يمنح الصلاحيات المرتفعة بمفرده (انظر `--allow`). |
| `--allow <list>` | مع `--yes`، الصلاحيات المرتفعة التي تمنحها، مفصولة بفواصل: `exec` و`fs-write` و`network` و`env`. يُرفض العنصر الذي يطلب صلاحية لم تسمّها. |
| `--overwrite` | استبدل الملفات الموجودة (ودونه يكون الملف الموجود خطأ `LOUSHO_REGISTRY_FILE_EXISTS`). |
| `--dry-run` | اطبع بيان الصلاحيات والملفات، ولا تكتب شيئًا، واخرج بالرمز 0. |
| `--list` | اطبع عناصر السجل ثم اخرج. |

قبل أن يكتب أي شيء، يطبع `lousho add` بيان الصلاحيات (manifest) والملفات التي سيكتبها، ويفحص شيفرة العنصر مقابل البيان، ثم يسأل `[y/N]`. وبعد الكتابة يسجّل العنصر في `lousho-registry.json`.

## الصيغة

الفهرس هو `{ items: [{ name, type, description, url | path }] }`. و`type` أحد القيم `tool` أو `skill` أو `channel` أو `schedule` أو `memory`. يحدّد `url` / `path` موقع مستند العنصر؛ والمسار النسبي يُحلّ نسبةً إلى موقع الفهرس نفسه.

كل مستند عنصر يكون بهذا الشكل:

```json
{
  "name": "web-search",
  "type": "tool",
  "description": "Search the web with the Example Search API",
  "files": [
    {
      "path": "tools/web-search.ts",
      "content": "import { defineTool } from '@lousho/build-ai-agent';\nimport { z } from 'zod';\n\nexport default defineTool({\n  name: 'web-search',\n  description: 'Search the web',\n  input: z.object({ query: z.string() }),\n  needsApproval: true,\n  execute: async ({ query }) => {\n    const response = await fetch(`https://api.example.com/search?q=${encodeURIComponent(query)}`, {\n      headers: { authorization: `Bearer ${process.env.SEARCH_KEY}` },\n    });\n    return response.json();\n  },\n});\n"
    }
  ],
  "permissions": {
    "network": ["api.example.com"],
    "env": ["SEARCH_KEY"],
    "filesystem": "none",
    "exec": false,
    "needsApproval": true
  },
  "dependencies": ["zod"]
}
```

ومدخله في `index.json`:

```json
{
  "items": [
    { "name": "web-search", "type": "tool", "description": "Search the web with the Example Search API", "path": "items/web-search.json" }
  ]
}
```

استضف الاثنين ملفات ثابتة في أي مكان (مجلد في مستودع، أو مخزن كائنات، أو خادم ويب). يجب أن يطابق `name` و`type` في المستند مدخله في الفهرس، ويبدأ الاسم بحرف أو رقم، تتبعه أحرف وأرقام و`.` و`_` و`-`. المستند الذي لا يطابق الصيغة يُعطي الخطأ `LOUSHO_REGISTRY_INVALID`، مع ذكر الحقول المعنية.

وللمساهمة بعنصر في السجل الافتراضي، أضف مجلد `registry/<name>/` إلى مستودع الـSDK: ملف `item.json` (فيه `name` و`type` و`description` و`permissions` و`dependencies`) وملفات العنصر مرتَّبة كما ينبغي أن تصل إلى مجلد الوكيل (`tools/x.ts` و`skills/<name>/SKILL.md` و`channels/x.ts`). ويتحقق `npm run registry:build` من كل عنصر مقابل القواعد نفسها التي يفرضها `lousho add` (المخطط والمسارات وفحص الشيفرة/البيان) ويعيد بناء `registry/dist/`؛ فأدرج النتيجة في الالتزام. ويشغّل CI الأمر `npm run registry:check` الذي يفشل حين تكون `registry/dist/` قديمة.

## بيان الصلاحيات

يصرّح `permissions` بما يستطيع العنصر فعله، لتقرر قبل تثبيته. كله اختياري؛ وما يغيب يُعرض بالقيمة "none" / "no".

| الحقل | المعنى |
| ----- | ------- |
| `network` | الخوادم (hosts) التي يتصل بها. |
| `env` | متغيرات البيئة التي يقرؤها. |
| `filesystem` | `none` أو `read` أو `write`. |
| `exec` | `true` حين ينفّذ أوامر. |
| `needsApproval` | `true` حين تطلب أدواته [موافقة](/ar/approvals) قبل أن تعمل. |

ما يفرضه `lousho add` قبل أن يكتب أي شيء:

- **الشيفرة تطابق البيان.** يُفحص كل ملف JavaScript وTypeScript في العنصر، بعد حذف التعليقات، بحثًا عمّا يلجأ إليه ظاهريًا:
  - `exec: true` عند استيراد `child_process` (بـ`node:` أو دونها) أو `execa` أو `shelljs`، أو عند استخدام `createShellTool` أو `runShellCommand` أو `SubprocessSandbox` من SDK؛
  - `filesystem: "read"` (أو `"write"`) عند استيراد `fs` (بما فيها `fs/promises` وصيغ `node:`) أو `fs-extra` أو `graceful-fs`، أو `createFsTools` من SDK، و`"write"` عند استدعاء `writeFile` أو `appendFile` أو `createWriteStream` أو `mkdir` أو `mkdtemp` أو `rm` أو `rmdir` أو `unlink` أو `rename` أو `copyFile` أو `cp` (وصيغها `Sync`)؛
  - `network` غير فارغ عند `fetch(` أو استخدام `createHttpTool` من SDK أو استيراد `http` أو `https` أو `http2` أو `net` أو `tls` أو `dgram` أو `undici` أو `axios` أو `node-fetch` أو `ws`، ويجب أن يطابق كل مضيف `http(s)://` أو `ws(s)://` في أي سلسلة نصية أحد مدخلات `network` (أما المضيف الذي يُبنى وقت التشغيل، مثل `` `https://${host}/` ``، فيحتاج إلى `network` غير فارغ ويُطبع ملاحظةً لأنه لا يمكن فحصه)؛
  - يجب إدراج كل `process.env.NAME` و`process.env['NAME']` في `env`.

  وتُرفض دائمًا `eval(` و`new Function(` و`process.env[name]` المحسوب و`process.env` المستخدم كاملًا، وأي `import()` أو `require()` لما ليس سلسلة نصية حرفية، و`require` المستخدم قيمةً (`const r = require`). وعدم المطابقة يعطي `LOUSHO_REGISTRY_MANIFEST_MISMATCH` مع كل ملاحظة بالشكل `<file>:<line>: <what> (<fix>)`؛ ويبلّغ عنه `--dry-run` أيضًا. أما ملفات Markdown وغيرها مما ليس شيفرة (مثل `SKILL.md` في المهارة) فلا تُفحص. ويجب أن تكون مدخلات `network` أسماء مضيفين أو أنماطًا بديلة تبدأ بـ`*.` (`api.example.com` و`*.example.com` — والنمط البديل يطابق النطاقات الفرعية فقط لا المضيف المجرّد)، ومدخلات `env` أسماء متغيرات (`SEARCH_KEY`)؛ وغير ذلك يعطي `LOUSHO_REGISTRY_INVALID`.
- **الموافقة تغطي الصلاحيات المرتفعة.** يوسَم كل من `exec: true` و`filesystem: "write"` و`network` غير الفارغ و`env` غير الفارغ بالعلامة `[elevated: ...]` في البيان المطبوع. ويسردها السؤال التفاعلي قبل `[y/N]`. ومع `--yes` يجب تسمية كل منها في `--allow` (`--allow network,env` للمثال أعلاه)، لأن `--yes` هو الطريقة التي تشغّل بها السكربتات والوكلاء الأمر `lousho add` ولا ينبغي أن يمنح تنفيذ الأوامر بصمت.
- **إيصال بما ثُبِّت.** بعد الكتابة يحدّث `lousho add` الملف `lousho-registry.json` في جذر مجلد الوكيل (بجانب `instructions.md`). يحتوي مدخل كل عنصر على `type` و`registry` الذي جاء منه و`installedAt` و`permissions` و`path` و`sha256` لكل ملف، لتعرف لاحقًا هل عُدّل ملف ما. ويستبدل `--overwrite` المدخل؛ ولا يكتب `--dry-run` شيئًا. والإيصال الذي ليس JSON صالحًا يوقف التثبيت قبل كتابة أي ملف. والإيصال هو ما يفرضه `loadAgentDir` عند التحميل ووقت التشغيل (أدناه).

ما يفرضه `loadAgentDir`، انطلاقًا من الإيصال، حين يُحمَّل الوكيل وتعمل أدوات العنصر:

- **السلامة.** يُعاد حساب بصمة كل ملف يسرده الإيصال. والملف الذي عُدّل أو حُذف منذئذ يجعل عنصره *غير مُصدَّق* (unattested): يذكر تحذيرٌ العنصرَ والملفات المتغيرة، ويبلّغ `resolveAgentDir()` عن ذلك نفسه في `manifest.registry` (`status: 'attested' | 'unattested'`، إضافةً إلى مسارات `modified` و`missing`). ولا يُرفَض التحميل — فالملفات ملكك تعدّلها — والإيصال الذي يتعذّر قراءته تحذير لا خطأ.
- **الموافقة.** أدوات العنصر المصرَّح فيه `exec: true` أو `needsApproval: true` — وأدوات أي عنصر غير مُصدَّق لم يعد إيصاله القديم يشهد للشيفرة المعدَّلة — تنتظر [الموافقة](/ar/approvals) دائمًا؛ ويبقى `deny` الصادر من `needsApproval` الخاصة بالأداة رافضًا.
- **الشبكة.** أثناء عمل أداة لعنصر له إيصال، يقتصر `fetch` على الخوادم التي يصرّح بها `network`: فيُرفض المضيف الذي لا يدرجه البيان، والعنصر الذي لا يصرّح بأي `network` لا يستطيع الجلب أصلًا.
- **البيئة.** وأثناء عملها لا يعرض `process.env` للأداة إلا الأسماء التي يصرّح بها `env`.
- **الأدوات المعزولة.** تحصل الأداة التي تعلن `requiresSandbox` على محوّل مضيَّق: يُرفض `run()` دون `exec`، و`writeFile()` دون `filesystem: "write"`، وبيئة الأمر هي الأساس المعتاد غير السري مضافًا إليه المتغيرات المصرَّح بها فقط.

يبقى التقييد على الأقل بضيق البيان الذي قُبل عند التثبيت، مُصدَّقًا كان الإيصال أم لا: فتعديل ملف مثبَّت يوسمه، ويطلب موافقة على استدعاءاته، ولا يوسّع شيئًا، إلى أن يثبّت `lousho add <name> --overwrite` الملفات الحالية ويصدّقها من جديد.

ما لا يفعله: فحص وقت التثبيت يقرأ الشيفرة كما هي مكتوبة، والتقييد وقت التشغيل لا يغطي إلا ما يستطيع الـSDK اعتراضه — استدعاءات `fetch` وقراءات `process.env` التي تتم أثناء عمل الأداة، والمحوّل المسلَّم إلى أداة معزولة. أما الطلبات عبر `http`/`net`/`axios`، والوصول إلى الملفات، والمرجع المحفوظ في نطاق الوحدة (`const f = fetch`)، والعمل المنفَّذ عند استيراد الملف، وسياسة الشبكة الخاصة بالحاوية نفسها (`{ allow }` في `SubprocessSandbox` خاصية للبيئة المعزولة لا للعنصر)، فكلها خارجه؛ وكذلك الشيفرة التي تُخفي ما تفعله (محارف الهروب في السلاسل، والأسماء المستعارة، والحمولات المشفَّرة، واعتمادية تؤدي العمل) عن الفحص الساكن. اقرأ الملفات التي يسردها (يعرضها `--dry-run`) كما تقرأ أي اعتمادية قبل تشغيلها.

## قواعد الأمان

- كل `files[].path` يجب أن يكون نسبيًا ومطبَّعًا (normalized) وبشرطات مائلة أمامية: لا `..`، ولا مسار مطلق، ولا حرف قرص (`C:`)، ولا شرطات مائلة عكسية، ولا مقاطع فارغة أو `.`. وبعد حلّ الروابط الرمزية (symlinks) يجب أن يبقى داخل مجلد الوكيل، ولا يُكتب أبدًا عبر رابط رمزي إلى هدفه.
- يجب أن يكون الملف داخل المجلد الذي يسمح به نوع عنصره: `tool` في `tools/`، و`skill` في `skills/<name>/`، و`channel` في `channels/`، و`schedule` في `schedules/`، و`memory` في `memory/`.
- لا تُستبدل الملفات الموجودة دون `--overwrite`. تُفحص كل الملفات قبل كتابة أي منها، فالعنصر المعيب لا يكتب شيئًا. وكل إخفاق من هذه يكون `LOUSHO_REGISTRY_UNSAFE_PATH` أو `LOUSHO_REGISTRY_FILE_EXISTS`.
- الحد الأقصى للملف 256 KiB وللعنصر 1 MiB؛ ولمستند السجل مليونا حرف.
- لا تُقرأ إلا عناوين `http(s)` والمسارات المحلية، بمهلة 15 ثانية لكل عملية جلب (وإلا `LOUSHO_REGISTRY_UNREACHABLE`).
- تُطبع `dependencies` في صورة سطر `npm install ...` لتنفّذه أنت. الأمر لا يثبّت حزمًا أبدًا.

الأخطاء مسرودة في [الأخطاء](/ar/errors#السجل). وواجهة سطر الأوامر كلها في [CLI](/ar/cli).
