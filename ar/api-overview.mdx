## بناء الـ agents وتشغيلها

| Export                        | الوصف                                                                 |
| ----------------------------- | --------------------------------------------------------------------------- |
| `createAgent(config)`         | agent بدون إعدادات بواجهة `{ send(message) }`، من string في `model` أو من provider (مع instructions وtools). |
| `AgentBuilder` (من `@lousho/build-ai-agent/executor`) | builder بأسلوب fluent لـ `AgentConfig` (`AgentBuilder.create().setName(...)...build()`). متقدم: راجع [واجهة الـ executor](/ar/executor-api). |
| `AgentExecutor.execute(opts)` (من `@lousho/build-ai-agent/executor`) | executor ساكن (static): يشغّل agent (LLM + حلقة tool calls) ويرجّع `ExecutionResult`. متقدم: راجع [واجهة الـ executor](/ar/executor-api). |
| `resumeAfterApproval()` (من `@lousho/build-ai-agent/executor`) | استئناف execution متوقف على approval (موافقة) بشري. متقدم: راجع [واجهة الـ executor](/ar/executor-api). |
| `InMemoryApprovalStore`       | `ApprovalStore` محلي داخل الـ process؛ هو الـ store الافتراضي للـ agents التي تُنشأ بـ `createAgent()`. |
| `StorageServiceApprovalStore`, `LocalStorageCheckpointStore` (من `/utils`) | stores للـ approvals والـ checkpoints مبنية على ملفات فوق `StorageService` (راجع [Approvals](/ar/approvals) و[Durable execution](/ar/durable-execution)). |
| `SqliteStore` (من `/sqlite`) | sessions وcheckpoints وapprovals في ملف SQLite واحد (راجع [Sessions](/ar/sessions#choosing-a-store)). |
| `fileStore(dir)`              | sessions وcheckpoints وapprovals كملفات JSON عادية تحت `dir` (راجع [Sessions](/ar/sessions#choosing-a-store)). |
| `KVStore`, `KVCheckpointStore` (من `/kv`) | stores على binding من Cloudflare Workers KV، لـ Worker تكتبه بنفسك (راجع [النشر](/ar/deployment)). |
| `AgentStore`, `memoryStore()` | خيار `createAgent({ store })`: `{ sessions?, checkpoints?, approvals?, tokens? }`، وواحد يشتغل في الذاكرة (راجع [Sessions](/ar/sessions#choosing-a-store)؛ `tokens` فيه tokens الـ OAuth، راجع [OAuth](/ar/oauth)). |
| `SessionAwaitingApprovalError` | يرميه `execute()` إذا الـ `sessionId` الممرّر متوقف على approval (راجع [Durable execution](/ar/durable-execution)). |
| `SDKError`, `ERROR_CODES`    | الكلاس الأساس لأخطاء الـ SDK: `code` ثابت و`hint` ورابط `docs` (راجع [الأخطاء](/ar/errors)). |

### Dynamic config

`model` و`instructions` (أو `prompt`) و`tools` في `createAgent()` كل خيار فيهم
يقبل القيمة الثابتة أو دالة على الـ run: `(ctx) => value | Promise<value>`
(النوع `PerRun<T>`). الـ `ctx` هو `{ sessionId?, input, metadata?, principal? }` (النوع
`RunConfigContext`): فيه الـ `sessionId` الممرّر لـ `send()` / `stream()` أو معرّف
`agent.session()`، وإدخال المستخدم في الـ run، وخيار الاستدعاء `metadata` في
`send()` و`stream()` و`session.send()` و`session.stream()`، والمتصل اللي قبلته
مصادقة الـ run (`principal`، يغيب إذا الاستدعاء ما مرّر متصل). الدوال تنفّذ
مرة وحدة لما يبدأ الـ run، قبل أول model call، ومرة ثانية في كل turn في الـ
session. وكل شيء ثاني ينطبق على اللي ترجعه: `fallbackModels` و`retry` و
`projectInstructions` والـ memory والـ skills والـ sub-agents وtools الـ MCP
والصلاحيات والـ approvals والـ guardrails. وإذا استخدمت agent ديناميكي كـ
sub-agent، الـ `input` يكون هو task prompt.

```ts
import { createAgent, defineTool } from '@lousho/build-ai-agent';
import { mockModel } from '@lousho/build-ai-agent/testing';
import { z } from 'zod';

const refund = defineTool({ name: 'refund', description: 'Refunds an order', input: z.object({ orderId: z.string() }), execute: async () => 'ok' });

const agent = createAgent({
  provider: mockModel(['Hello!']),
  // A cheaper model for short inputs, tenant instructions, tools by role.
  model: ({ input }) => (typeof input === 'string' && input.length < 200 ? 'small-model' : 'large-model'),
  instructions: ({ metadata }) => `You are the support agent of ${String(metadata?.tenant ?? 'Acme')}.`,
  tools: ({ metadata }) => (metadata?.role === 'admin' ? [refund] : []),
});

await agent.send('Hi', { metadata: { tenant: 'Globex', role: 'admin' } });
```

الدالة إذا رمت خطأ، الـ run يفشل بـ `LOUSHO_CONFIG_RESOLVER_FAILED`
(`error.field` يسمّي الخيار، و`error.cause` هو الخطأ المرمي): `send()` يرفض،
و`stream()` ينتهي بحدث `error`، والـ session تحتفظ بالـ transcript مثل ما كان.
الـ run المتوقف على approval أو سؤال يحتفظ بالـ `ctx` وبالـ model اللي حسمه في
snapshot التوقف: استئنافه، حتى من process ثانية، يستخدم ذلك الـ model (ما
يتبدّل أبدًا في منتصف الـ turn) ويستدعي دالة `tools` مرة ثانية بنفس الـ `ctx`.
أما الـ run المستأنف من checkpoint بعد crash (`agent.resume(id)`) فينحسب من
جديد مع `input: []` وبدون `metadata`. وإذا كل القيم ثابتة، ما يتغير شيء: الـ
agent يتبنّى مرة وحدة لما تنشئه.

### UI bindings

`@lousho/build-ai-agent/react` يصدّر `useLoushoAgent(source, options?)`، وهو
React hook يشغّل agent داخل نفس الـ process (`{ agent, sessionId? }`) أو عبر HTTP
(`{ url }`)، ويرجّع `messages` و`status` و`pendingApproval` و
`send()` و`stop()` و`approve()` و`reject()`. أجزاؤه المحايدة عن الـ framework —
`reduceAgentEvents()` و`parseEventStream()` — مُصدّرة أيضًا. راجع
[React](/ar/react). `@lousho/build-ai-agent/vue` يصدّر نفس `useLoushoAgent()`
كـ composable لـ Vue 3، والحالة فيه refs. راجع [Vue](/ar/vue). و
`@lousho/build-ai-agent/svelte` يصدّر `loushoAgent()`، نفس الحالة والأفعال كـ
Svelte store (`$agent`). راجع [Svelte](/ar/svelte).

### Sub-agents

مرّر `subagents: { researcher, writer }` (agents من `createAgent()` لكل واحد فيهم
`description`، أو catalog بصيغة `{ list, resolve }`) إلى `createAgent()` أو
`AgentExecutor.execute()`. الـ agent الرئيسي يحصل على tool باسم `task` للتفويض،
وعلى tools المهام الخلفية الثلاث `agent_status` و`agent_await` و`agent_cancel`،
وعلى قائمة بالـ sub-agents في الـ prompt. كل sub-agent يشتغل على task prompt
لوحده، ويرث من run الـ agent الرئيسي: الـ signal والـ hooks (`ctx.subagent`)
والـ tracing وstore الـ approvals وevent listeners (`event.subagent`).
`maxSubagentDepth` (الافتراضي 1) يحدّ عمق التداخل. راجع
[Sub-agents](/ar/sub-agents).

### Approvals

الـ agent اللي تبنيه بـ `createAgent()` يوقف مؤقتًا عند tool عليها `needsApproval`
بدل ما يفشل: `send()` (و`session.send()`) يرجّع `finishReason: 'awaiting-approval'`
مع `approvalId`. `agent.approvals.list()` يرجّع الاستدعاءات المعلّقة، و
`agent.approvals.resolve({ id, approved, note? })` ينفّذ الاستدعاء أو يرفضه
ويرجّع نتيجة الـ run بعد ما كمّل (يكمّل نفس الـ session اللي وقف فيها).
التوقفات تنحفظ في `InMemoryApprovalStore` خاص بكل agent إلا إذا مرّرت
`approvalStore` (مثل `SqliteStore.approvals`) أو `store`. والخيار
`approve: (request: PendingApproval) => boolean | string | Promise<boolean | string>`
يحسم كل استدعاء من الكود بدون توقف (`stream()` يظل ينتهي عند التوقف) —
`request` يحمل الاستدعاء مع `kind` و`principal`. ومع `askQuestion: true` يقدر
الـ agent يسأل المستخدم (`kind: 'question'`)، وتجاوب بـ
`agent.approvals.answer({ id, answer })`. راجع [Approvals](/ar/approvals).

### Structured output

مرّر `output: zodSchema` إلى `createAgent()` (أو `AgentExecutor.execute()` /
`stream()`): الرد الأخير لازم يكون كائن JSON يطابق الـ schema، و
`send()` / `run.result` يرجّعه بعد الـ validation كـ `result.object` بالنوع
`z.output<typeof schema>` (`result.text` يحتفظ بـ JSON الخام). الـ tools
تشتغل أول مثل العادة. كل model call يحمل hint باسم
`responseFormat: { type: 'json', schema }`، وproviders الـ `ai` SDK يحوّلونه
إلى JSON mode. الرد غير الصالح يحصل على خطوة repair وحدة تسرد المشاكل (تنحسب
من `maxSteps`)؛ إذا ظل غير صالح، الـ run ينتهي بـ
`finishReason: 'output-invalid'` و`outputError: { message, issues }`. راجع
[Structured output](/ar/structured-output).

### Skills

مرّر `skills: [defineSkill({ name, description, content }), ...(await loadSkills(dir))]`
إلى `createAgent()` أو `AgentExecutor.execute()`: بس الأسماء والأوصاف تدخل الـ
system prompt، والـ model يحمّل محتوى كل skill عبر tool باسم `load_skill`
تتسجّل تلقائيًا. راجع [Skills](/ar/skills).

### الذاكرة

مرّر `memory: [defineMemory({ name, scope, provider })]` إلى `createAgent()`
عشان تحتفظ بعناصر عبر المحادثات: كل run يستحضر أحدث عناصر كل slot في الـ
system prompt عند أول model call، والـ model يحصل على tools باسم
`remember_<name>` / `recall_<name>`. الـ `scope` إما `'global'` أو `'session'`
أو دالة على `{ sessionId, metadata }`. `inMemoryMemory()` و
`fileMemory({ dir })` هما الـ providers المدمجة. راجع [الذاكرة](/ar/memory).

### Durable execution

مع `sessionId` + `checkpointStore` يصير الـ run آمن من الـ crash والـ session
متعددة الـ turns: الـ run ينحط له checkpoint بعد كل رد من الـ model وكل نتيجة
tool وكل توقف مؤقت، واستدعاء `execute()` مرة ثانية بنفس الـ `sessionId` يكمّل
run ما خلص (بدون ما يعيد الـ model call لـ turn صار عنده)، أو يواصل محادثة
منتهية بالإدخال الجديد، أو يرمي `SessionAwaitingApprovalError` ما دام في
approval معلّق. الـ tools تنفّذ at-least-once عبر الـ crash، و`execute`
يستقبل `toolCallId` الخاص بالاستدعاء لتستخدمه كـ idempotency key. راجع
[Durable execution](/ar/durable-execution) للضمانات بالضبط.

كيف ينتهي الـ run (أسباب الإنهاء)، وكيف تلغي واحد، وكيف تنفّذ الـ tool calls
بالتوازي: راجع [Runs](/ar/runs).

راجع [Tools](/ar/tools) لدليل تعريف الـ tools وتسجيلها.

```ts
import { defineTool } from '@lousho/build-ai-agent';
import { z } from 'zod';

const sendEmail = defineTool({
  name: 'send_email', // 1-64 chars: letters, digits, _ and -
  description: 'Send an email',
  input: z.object({ to: z.string().email(), subject: z.string() }),
  needsApproval: ({ to }) => !to.endsWith('@mycompany.com'), // `to` is typed
  async execute({ to, subject }) {
    return { messageId: `${to}:${subject}` };
  },
});
```

الحقول الاختيارية: `displayName` و`needsApproval` (boolean أو predicate)
و`requiresSandbox` و`sandboxExecute`. تعريف الـ tool يتحقق فورًا من اسمها
ووصفها والـ `input` بـ zod، وتسجيل tool بنفس الاسم مرتين يرمي خطأ يذكر موضع
التعارض.

الـ tool المعرّفة تحمل الـ schema في `inputSchema` (نفس الـ zod schema في
`input`) ودالة `execute` مباشرة. هذان الحقلان هما المعتمدان في
`ToolDescriptor`. أما كائن `.tool` (`{ description, parameters, execute }` بصيغة
`ai` v4) فهو legacy: يُبنى للتوافق فقط، ويُستخدم بس مع descriptors التي ما
تحدد `inputSchema` / `execute`.

```ts
import { loadMcpTools } from '@lousho/build-ai-agent/mcp';

const tools = await loadMcpTools(mcpClient, 'my-server');
```

**دعم الـ schema.** `inputSchema` (بصيغة JSON Schema) لكل tool يتحوّل إلى zod
schema، ووسائط الـ model تُفحَص مقابله قبل استدعاء السيرفر. المحوّل يعالج
`type` (منها المصفوفات مثل `["string", "null"]`)، و`enum` بأنواع مختلطة، و`const`،
و`anyOf` / `oneOf` (union؛ `anyOf: [X, { type: "null" }]` تصير `X.nullable()`)،
و`allOf` (دمج / intersection)، و`$ref` المحلي داخل `$defs` / `definitions`،
و`properties` / `required`، و`additionalProperties` (boolean أو schema)، و`items`،
و`default`، والقيود `minimum` و`maximum` و`exclusiveMinimum`
و`exclusiveMaximum` و`minLength` و`maxLength` و`pattern` و`minItems` و
`maxItems`. ولما يكون JSON Schema ملتبس، يكون التحويل متساهل: الكلمات المفتاحية
غير المعروفة والـ schemas الفارغة و`items` بصيغة tuple والـ refs التي ما تنحلّ
تصير `z.any()`، والـ `$ref` التعاودي يتوسّع مرة وحدة ويُستخدم `z.any()` للموضع
الداخلي، وregex غير صالح في `pattern` يتخطّى، والكائنات تحتفظ بخصائص إضافية
إلا إذا `additionalProperties` كان `false`. المحوّل ما يرمي خطأ أبدًا بسبب
محتوى الـ schema.

**الـ tools المتخطّاة.** إذا tool وحدة ما قدرت تتحوّل، هي بس اللي تتخطّى؛ باقي
tools السيرفر تتحمّل. مرّر `logger` عشان يوصلك تحذير يذكر السيرفر والـ tool
والسبب، و`onSkip` عشان تجمع اللي انترك:

```ts
import { loadMcpTools, type SkippedMcpTool } from '@lousho/build-ai-agent/mcp';

const skipped: SkippedMcpTool[] = [];
const tools = await loadMcpTools(mcpClient, 'my-server', {
  logger: console,
  onSkip: (tool) => skipped.push(tool), // { name, reason }
});
```

**النتائج.** نتيجة MCP التي فيها `isError: true` هي فشل tool عادي: الـ model
يستقبل `{ "error": "McpToolError", "toolName": "...", "message": "..." }` و
`message` فيه المحتوى النصي اللي رجّعه السيرفر. النتائج الناجحة قابلة للتسلسل
كـ JSON: إذا السيرفر رجّع `structuredContent`، هو كائن النتيجة؛ وإلا النتيجة
`{ text, content }`، بحيث `text` يجمع كل الأجزاء النصية و`content` يحتفظ بكل
جزء بترتيبه (`text`، `image`، `audio`، `resource`، `resource_link`؛ والجزء
اللي نوعه غير معروف ينحتفظ به كـ `{ type: 'unknown', raw }`). وإذا وصل
`structuredContent` مع أجزاء غير نصية، تصير النتيجة
`{ structuredContent, text, content }` و`content` فيه بس الأجزاء غير النصية،

## Flows وevals وobservability والأمان

- `FlowBuilder` / `FlowExecutor` (`@lousho/build-ai-agent/flows`) - graphs
  لمسارات شغل متعددة الخطوات؛ راجع [Flows](/ar/flows).
- `WebhookTriggerAdapter` و`SlackTriggerAdapter` و`CronTriggerAdapter` و
  `TriggerRegistry` (`@lousho/build-ai-agent/triggers`) - توقظ الـ agent من
  webhook أو رسالة Slack أو جدول زمني؛ راجع [Triggers](/ar/triggers).
- `jwt()` و`oidc()` و`basic()` و`apiToken()` و`anonymous()` و`routeAuth()`
  (`@lousho/build-ai-agent/auth`) - auth على الـ routes كقائمة مرتبة؛ المتصل
  اللي تقبله يوصل الـ run كـ `principal`؛ راجع
  [Route auth and principals](/ar/auth).
- `defineEval()`، وscorers مثل `exactMatch` و`toolCallOrder` و`budget`، وفحوص
  مثل `includes` و`atLeast`، و`llmJudge()` - evals للـ agents تشتغل تحت vitest
  أو `lousho eval`؛ راجع [Evals](/ar/evals).
- `withSpan()` و`TraceExporter` - tracing لـ `AgentExecutor.execute()`.
  `TraceExporter` واجهة BYO: الحزمة ما تشحن مع أي exporter افتراضي. ولـ spans
  حقيقية في OpenTelemetry، استورد `createOtelTraceExporter()` من الـ subpath
  `@lousho/build-ai-agent/otel` (يحتاج الـ peer dependency الاختيارية
  `@opentelemetry/api`) بدل ما تكتب جسر OTel بنفسك - راجع
  `examples/tracing/run-otel.ts`. الـ spans تتبع الـ GenAI semantic conventions
  الخاصة بـ OpenTelemetry (والـ flows تتتبّع أيضًا)؛ راجع
  [observability](/ar/observability).
- `NoopSandbox` / `SubprocessSandbox` - sandbox للـ tools التي تختاره عبر
  `requiresSandbox`؛ و`runPatchChecks()` وفحوص الـ patch مثل
  `createCommandCheck()` و`createDiffSizeCheck()` و
  `secretScanCheck`. راجع [Guardrails وsandboxing](/ar/guardrails).
- `HookRegistry` و`AgentHook` و`HookContext` و`ToolCallHookContext` و
  `GenerateHookContext` - hooks تراقب الـ tool calls والـ model calls أو ترفضها
  أو تعيد كتابتها أو تحجب أجزاء منها. راجع [Hooks](/ar/hooks).
- `EncryptionUtils` و`sha256` و`StorageService`
  (`@lousho/build-ai-agent/utils`) - أدوات مساعدة داعمة؛ راجع
  [Utilities](/ar/utilities).
