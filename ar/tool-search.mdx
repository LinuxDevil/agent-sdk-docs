agent عنده tools كثيرة (عدة سيرفرات MCP أو toolkit داخلية كبيرة) يرسل
تعريف كل tool مع كل استدعاء للـ model. هذا يكلّف input tokens، وبعد
حوالي 30 tool يصير الـ model أسوأ في اختيار الصح. مع tool search،
الـ tools المعلَّمة بـ `deferLoading` تُترَك خارج الطلب. الـ model
يحصل على tool مدمجة واحدة هي `tool_search`، يلاقي الذي يحتاجه بكلمات
قليلة، والـ tools التي وجدها تُرسَل من خطوته التالية.

البحث يشتغل داخل الـ SDK، فيعمل مع كل provider.

## متى تستخدمه

- الـ agent متصل بسيرفرات MCP فيها tools كثيرة، أو عنده tool set
  كبيرة، ومعظم الـ runs تستخدم منها القليل فقط.
- تعريفات الـ tools تأخذ حصة واضحة من الـ context window.

مع عدد قليل من الـ tools لا شيء تكسبه: افتراضيًا لا يُطبَّق التأجيل إلا
حين تبلغ التعريفات المؤجلة 10% من الـ context window (انظر
[العتبة](#العتبة)).

## علّم الـ tools أو السيرفرات بـ `deferLoading`

علّم tool بعينها بـ `defineTool({ deferLoading: true })`. بادئة الـ model
`vendor/` تختار الـ provider؛ ومع OpenRouter استخدم
`openrouter/<vendor>/<model>` (مثل `openrouter/openai/gpt-4o-mini`).

```ts
import { createAgent, defineTool } from '@lousho/build-ai-agent';
import { z } from 'zod';

const convertCurrency = defineTool({
  name: 'convert_currency',
  description: 'Convert an amount of money from one currency to another',
  input: z.object({ amount: z.number(), from: z.string(), to: z.string() }),
  deferLoading: true,
  execute: async ({ amount, to }) => ({ amount: amount * 0.92, currency: to }),
});

const lookupStock = defineTool({
  name: 'lookup_stock',
  description: 'Look up the latest price of a stock ticker',
  input: z.object({ ticker: z.string() }),
  deferLoading: true,
  execute: async ({ ticker }) => ({ ticker, price: 123.45 }),
});

const agent = createAgent({
  model: 'openai/gpt-4o-mini',
  instructions: 'You are a helpful assistant.',
  tools: [convertCurrency, lookupStock],
  toolSearch: { thresholdPercent: 0 }, // defer even this small set (see below)
});
```

أو علّم سيرفر MCP كامل: كل tool يسردها تُؤجَّل.

```ts
import { createAgent } from '@lousho/build-ai-agent';

const agent = createAgent({
  model: 'openai/gpt-4o-mini',
  mcpServers: {
    github: { url: 'https://example.com/github/mcp', deferLoading: true },
    files: { command: 'npx', args: ['-y', '@modelcontextprotocol/server-filesystem', '.'] },
  },
});
```

`deferLoading` يعمل بنفس الطريقة في ملفات spec ومجلدات الـ agent
(`mcpServers.<name>.deferLoading: true`)، ومع `connectMcp()`: الـ
descriptors التي يرجعها تحمل `deferLoading`، فتمرير `mcp.tools` إلى
`createAgent({ tools })` يحافظ على التأجيل.

لا تُؤجَّل أبدًا مهما عُلِّمت: `load_skill` ([skills](/ar/skills))، وأدوات
الذاكرة، و`task` وأدوات مهام الخلفية ([sub-agents](/ar/sub-agents))،
و`ask_question`، وأدوات `transfer_to_<name>` الخاصة بـ
[handoffs](/ar/handoffs)، و`tool_search` نفسها. أما الـ tools المستضافة
لدى الـ provider فتُرسَل دائمًا.

## ما يراه الـ model

حين ينطبق التأجيل، يحتوي أول طلب في الـ run على الـ tools غير المؤجلة
مع `tool_search`، ويأخذ الـ system prompt فقرة واحدة: كم tool لم
تُحمَّل، ومن أي سيرفرات MCP جاءت (مع العدد)، وأن عليه استدعاء
`tool_search` بكلمات قليلة تصف القدرة المطلوبة.

`tool_search` تأخذ `{ query: string }` وترجع JSON:

```json
{ "loaded": [{ "name": "convert_currency", "description": "Convert an amount of money from one currency to another" }], "more": 38 }
```

`loaded` يسرد الـ tools التي وجدها هذا البحث (بحد أقصى `maxResults`)،
و`more` يعدّ الـ tools المؤجلة التي لم تُحمَّل بعد. من الخطوة التالية
يتضمن الطلب هذه الـ tools. وحين تُحمَّل كل الـ tools المؤجلة لا تعود
`tool_search` معروضة.

الـ tool المؤجلة التي يستدعيها الـ model باسمها قبل تحميلها تشتغل مثل أي
tool أخرى (الـ approvals والصلاحيات والـ guardrails تنطبق كالمعتاد).
و`stream()` يبلّغ عن `tool_search` كزوج عادي `tool.start` / `tool.done`.

الترتيب الافتراضي يقارن كلمات الاستعلام باسم كل tool مؤجلة (مقسَّمًا عند
`_` و`-` و`__` وحدود camelCase) ووصفها، بلا حساسية لحالة الأحرف. الكلمة
في الاسم تُحسب ثلاثة أضعاف الكلمة في الوصف، والتعادل يُرتَّب بالاسم.
نفس الدالة مُصدَّرة باسم `rankToolsByKeywords(query, tools)`.

## خيارات `toolSearch`

`createAgent({ toolSearch })` و`AgentExecutor.execute({ toolSearch })`
يضبطان البحث. التأجيل نفسه يُفعَّل بتعليم الـ tools أو السيرفرات بـ
`deferLoading`؛ و`toolSearch: false` يحمّل كل الـ tools مسبقًا.

| الخيار | القيمة الافتراضية | الوصف |
| ------ | ------- | ----------- |
| `thresholdPercent` | `0.1` | التأجيل فقط حين تبلغ التعريفات المؤجلة هذه الحصة من الـ context window. القيمة `0` تؤجّل دائمًا. |
| `maxResults` | `5` | عدد الـ tools التي تُحمَّل في كل بحث. |
| `contextWindow` | من الـ model registry، وإلا 128,000 | الـ context window الخاص بالـ model، لحساب العتبة. |
| `search(query, tools)` | الترتيب بالكلمات المفتاحية | ترتيبك الخاص (مثلًا embeddings): أرجِع أسماء الـ tools، الأفضل أولًا. الأسماء غير المعروفة والمكررة تُسقَط. وإذا رمت الدالة خطأً، يصير الاستدعاء tool error ولا يُحمَّل شيء. |

```ts
import { createAgent } from '@lousho/build-ai-agent';

const agent = createAgent({
  model: 'openai/gpt-4o-mini',
  mcpServers: { github: { url: 'https://example.com/github/mcp', deferLoading: true } },
  toolSearch: {
    maxResults: 3,
    search: (query, tools) => tools.filter((tool) => tool.description.toLowerCase().includes(query.toLowerCase())).map((tool) => tool.name),
  },
});
```

القيمة غير الصالحة ترمي `LOUSHO_CONFIG_INVALID` عند إنشاء الـ agent.
وtool من عندك اسمها `tool_search` ترمي `LOUSHO_CONFIG_INVALID` حين يبدأ
run والتأجيل فعّال: غيّر اسمها أو اضبط `toolSearch: false`.

## العتبة

عند بدء الـ run يقدّر الـ SDK عدد الـ tokens في التعريفات المؤجلة
(الاسم والوصف والـ JSON Schema لكل tool، عبر `estimateTokens()` للـ
model الخاص بالـ run). تحت `thresholdPercent` من الـ context window
تُرسَل كل الـ tools مسبقًا ولا تُضاف `tool_search`: التعريفات رخيصة،
وخطوة بحث ستكلّف أكثر مما توفّر. هذه نفس قاعدة وضع `auto` في
Claude Agent SDK.

الاختبار الحي لهذه الميزة (40 tool من سطر واحد على `gpt-4o-mini`) قاس
157 input token في الاستدعاء الأول مع التأجيل، و892 بدونه.

## كيف يبقى التحميل

الـ tools المحمَّلة لا تُخزَّن في أي مكان: تُقرأ من الـ transcript عند كل
استدعاء للـ model. الـ tool تُعتبر محمَّلة إذا سمّتها نتيجة
`tool_search` ناجحة في رسائل الـ run. لذلك:

- الاستئناف بعد crash من checkpoint، وتوقف الـ approval واستئنافه،
  والـ fork، والدورة التالية في الـ session، كلها تبقي الـ tools
  المحمَّلة.
- الاستئناف لا يبلّغ عن
  [agent drift](/ar/durable-execution#استئناف-run-بعد-ما-يتغير-الـ-agent) بسبب
  التحميل: الـ fingerprint يشمل كل tool، مؤجلة أو لا.
- [compaction](/ar/compaction) يقتطع نتيجة `tool_search` يلغي تحميل
  أدواتها من استدعاء الـ model التالي؛ والـ model يبحث من جديد حين
  يحتاجها.
- هدف الـ [handoff](/ar/handoffs) يبدأ بلا أي tool محمَّلة، حتى لو كان
  عنده نفس الـ tools المؤجلة: لا تُحسب إلا نتائج `tool_search` بعد آخر
  handoff، وتنطبق أدوات `deferLoading` وإعداد `toolSearch` الخاصة
  بالهدف. أما الـ [sub-agent](/ar/sub-agents) فيشغّل قائمة الـ tools
  الخاصة به على الـ transcript الخاص به، فلا يرث أبدًا ما حمّله الـ
  lead.

## سيرفرات MCP التي تحتاج تسجيل دخول

سرد tools السيرفر يحتاج اتصالًا، لذا سيرفر معلَّم بـ `deferLoading`
ويستخدم [OAuth](/ar/oauth#خوادم-mcp-مع-oauth) ولم يُسجَّل الدخول إليه
يُفشِل الـ run بـ `LOUSHO_MCP_AUTH_REQUIRED` مثل أي سيرفر آخر. حين
يسجّل المشغّل الدخول تُؤجَّل أدواته كالمعتاد. وأي صلاحية تُسحَب لاحقًا
تحوّل استدعاء tool محمَّلة إلى خطأ `LOUSHO_MCP_AUTH_REQUIRED`، كما لو
بلا تأجيل.

## Prompt caching

قائمة الـ tools تتغير حين تُحمَّل الـ tools. الـ providers الذين يخزنون
مؤقتًا بادئة الطلب (Anthropic prompt caching والتخزين التلقائي في
OpenAI) يضعون تعريفات الـ tools في أولها، فالخطوة التي تحمّل tools قد
تفوت الـ cache من تلك النقطة. التحميل يحدث بضع مرات في الـ run الواحد
على الأكثر؛ وإذا كانت الـ runs عندك تعيد استخدام بادئة مخزَّنة طويلة
عبر استدعاءات كثيرة، قارن التكلفة مع `toolSearch: false`.
