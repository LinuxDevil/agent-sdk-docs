تبدأ معظم شيفرات الوكلاء حلقةً تدور حول استدعاء نموذج، ثم تأتي بيئة الإنتاج بمطالب أخرى: لا بدّ أن يوافق إنسان على استرداد المبلغ قبل إرساله، والعملية يُعاد تشغيلها والوكيل في منتصف عمله، والمحادثة يجب أن تُستكمل غدًا من خادم آخر، وهناك من يريد اختبارًا يفشل حين يتوقف الوكيل عن استدعاء الأداة الصحيحة.

`@lousho/build-ai-agent` هي تلك الحلقة وقد بُنيت فيها هذه الإجابات. إنها مكتبة، بلا إطار ويب وبلا بيئة تشغيل مستضافة: حلقة استدعاء أدوات محدَّدة الأنواع، معها الموافقات والجلسات والبث والوكلاء الفرعيون والمهارات و MCP وواجهة سطر أوامر (CLI). والوكيل نفسه يعمل في سكربت، أو خادم Node، أو حاوية Docker، أو Cloudflare Worker.

```mermaid
flowchart LR
    A["شيفرتك<br/>send() أو stream()"] --> B["تشغيل الوكيل<br/>خطوة نموذج، استدعاءات أدوات، ثم التكرار"]
    B --> C{"هل تحتاج الأداة<br/>إلى موافقة؟"}
    C -- "لا" --> B
    C -- "نعم" --> D["يتوقف التشغيل مؤقتًا<br/>وتُحفظ الحالة في مخزن"]
    D -- "تمت الموافقة، من أي عملية" --> B
    B --> E["النتيجة<br/>نص، كائن محدَّد النوع،<br/>الاستهلاك والتكلفة"]
```

```ts
import { createAgent } from '@lousho/build-ai-agent';

const agent = createAgent({ model: 'openai/gpt-4o-mini', instructions: 'You are a helpful assistant.' });
const { text } = await agent.send('Hello!');
console.log(text);
```

## اللبنات الأساسية

كل لبنة هي دالة واحدة أو خيار واحد في `createAgent()`. استخدم ما تحتاج إليه منها؛ فلا تتوقف أي لبنة على غيرها.

| اللبنة | ما تكتبه | ما تحصل عليه |
| ----- | -------------- | ------------ |
| [الأدوات](/ar/tools) | `defineTool()` مع `input` من zod | معاملات محدَّدة الأنواع ومُتحقَّق منها، واستدعاءات تُنفَّذ بالتوازي |
| [الموافقات](/ar/approvals) | `needsApproval`، أو قواعد `permissions` | تشغيل يتوقف مؤقتًا بانتظار إنسان، ثم يُكمل عبر `agent.approvals.resolve()` |
| [الجلسات](/ar/sessions) | `agent.session({ id })` | محادثة متعددة الدورات تُحفظ في الذاكرة أو الملفات أو SQLite |
| [الذاكرة](/ar/memory) | خانات `defineMemory()` | حقائق تُستحضر إلى الموجّه عبر الجلسات، لكل مستخدم أو على المستوى العام |
| [المخرجات المنظَّمة](/ar/structured-output) | `output: zodSchema` | `result.object` محدَّد النوع ومُتحقَّق منه، مع خطوة إصلاح واحدة |
| [البث](/ar/streaming) | `agent.stream()` | أحداث JSON محدَّدة الأنواع وذات إصدارات، جاهزة لـ SSE |
| [الوكلاء الفرعيون](/ar/sub-agents) | `subagents: { researcher, writer }` | أداة `task` واحدة للوكيل الرئيسي؛ ويعمل الوكلاء الفرعيون بالتوازي، محليًا أو عن بُعد |
| [المهارات](/ar/skills) | `loadSkills()` | تعليمات لا يحمّلها الوكيل إلا حين تحتاج إليها المهمة |
| [المزوّدون](/ar/providers) | سلسلة نصية بصيغة `provider/model` | OpenAI أو Anthropic أو OpenRouter أو Ollama أو مزوّد وهمي، مع إعادة المحاولة والبديل الاحتياطي |

## أين يمكن أن يعمل الوكيل

الوكيل هو الكائن نفسه في كل مكان. ما يتغير هو الواجهة التي تقف أمامه.

تقع `@lousho/build-ai-agent` في طبقة فوق استدعاء النموذج مباشرةً: فهي، مثل LangGraph أو Mastra أو OpenAI Agents SDK، تُشغّل حلقة وكيل كاملة، لكن كمكتبة لا تتطلب منصة ولا إطار ويب ولا بيئة تشغيل مستضافة — وعلى خلاف AI SDK الخام، فهي تأتي بمكوّنات الإنتاج (المتانة والموافقات والجلسات) بدل أن تترك بناءها لك.

| القدرة | `@lousho/build-ai-agent` | Vercel AI SDK | LangChain / LangGraph | Mastra | OpenAI Agents SDK |
| ---------- | ---------------------- | ------------- | --------------------- | ------ | ----------------- |
| بث أحداث محدَّد الأنواع | نعم — يصدر `agent.stream()` أحداث JSON مُرقَّمة ومتسلسلة وذات إصدارات للتشغيلات والخطوات والرموز واستدعاءات الأدوات، جاهزة لـ SSE | جزئي — أجزاء `streamText` محدَّدة الأنواع؛ أما حلقة التشغيل فعليك بناؤها | نعم — أحداث العقد والمخطط عبر `streamEvents` | نعم — بثّ للوكلاء ولمسارات العمل | نعم — أحداث تشغيل مبثوثة |
| التنفيذ المتين ونقاط الحفظ | نعم — نقاط حفظ في مخازن قابلة للتبديل (الذاكرة، الملفات، SQLite، Cloudflare KV)؛ والتشغيل المتعطّل أو المتوقف مؤقتًا يُستأنف في عملية أخرى | لا — تبقى الحالة في الذاكرة؛ وحفظها مسؤوليتك | نعم — يحفظ مُسجِّل نقاط الحفظ (checkpointer) حالة المسار (thread) | نعم — لقطات إيقاف/استئناف لمسارات العمل | جزئي — الجلسات تحفظ السجل؛ أما الاستئناف في منتصف التشغيل عبر العمليات فغير مدمج |
| الموافقات (إشراك الإنسان) | نعم — يوقف `needsApproval` التشغيل مؤقتًا؛ ويكمله `agent.approvals.resolve()` من أي عملية | تبنيها بنفسك — أنت من يتحكم في استدعاء الأداة | نعم — `interrupt()` وعقد بشرية | نعم — خطوات بشرية في مسارات العمل | جزئي — توجد موافقات للأدوات المستضافة؛ أما التحكم في أدوات عشوائية فيدوي |
| القنوات | نعم — يقدّم `mountChannels()` واجهات HTTP و webhook و Slack و Discord، مع إعادة الموافقات إلى القناة | لا | لا — محوّلات مجتمعية فقط | جزئي — بعض تكاملات النشر والمحادثة | لا |
| أهداف النشر | `lousho build` ينتج خادم Node أو صورة Docker أو Cloudflare Worker من ملف مواصفات واحد | وفّرها بنفسك — يعمل أينما يعمل تطبيقك | وفّرها بنفسك، أو LangGraph Platform (مستضافة) | `mastra build` يستهدف Node و Vercel و Netlify و Workers | وفّرها بنفسك — تعمل الحلقة داخل عمليتك |
| الجلسات | نعم — `agent.session({ id })` فوق مخازن الذاكرة أو الملفات أو SQLite | لا — أنت تحتفظ بمصفوفة الرسائل | نعم — مسارات (threads) ومساعدات لسجل المحادثة | نعم — مسارات وذاكرة | نعم — كائنات الجلسة تحفظ سجل المحادثة |
| MCP | عميل (`mcpServers`) وخادم (`serveMcp`) | عميل فقط (`experimental_createMCPClient`) | عميل عبر محوّلات مجتمعية | نعم — عميل MCP وخادم | نعم — خوادم MCP كمصادر للأدوات |
| حواجز الحماية | نعم — حواجز حماية للمدخلات والمخرجات ومعاملات الأدوات، وفحوصات حقن الموجّهات والإشراف، وأدوات في بيئة معزولة | لا — ركّب ما يناسبك بنفسك | جزئي — حواجز حماية مجتمعية ومقيّمات LangSmith | نعم — معالجات للمدخلات والمخرجات | نعم — حواجز حماية للمدخلات والمخرجات |

متى يكون خيار آخر أنسب: إن كان كل ما تحتاجه هو بثّ نص النموذج في مسار Next.js، فإن AI SDK وحده أخفّ؛ وإن كان فريقك يعمل بـ Python أو يشغّل LangGraph Platform أصلًا، فالبقاء في تلك المنظومة يجنّبك إضافة حزمة تقنية ثانية. أما `@lousho/build-ai-agent` فموجّه لفرق TypeScript التي تريد حلقة وكيل متينة تدعم الموافقات وتعمل داخل عمليتها الخاصة دون تبنّي منصة.
