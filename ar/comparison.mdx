## ما يفعله lousho بشكل مختلف حتى الآن

كل بند يمكن التحقق منه في هذا المستودع.

- **cassettes للتسجيل وإعادة التشغيل وانحراف مسار التنفيذ في CLI واحد.** `lousho eval --record`
  يشغّل كل حالة مرة واحدة على الـ provider الحقيقي ويكتب cassette،
  و`--replay` يشغّلها في CI بدون شبكة ولا مفتاح API، و`--drift`
  يعيد التسجيل في مجلد مؤقت ويوضّح كيف تغيّر مسار استدعاءات الـ tools
  في كل حالة ([Evals](/ar/evals#record-replay-and-drift)،
  [Testing](/ar/testing#record-و-replay)).
- **approvals متينة على Cloudflare Workers KV** إلى جانب الذاكرة والملفات و
  SQLite، بنفس كود `needsApproval` / `resumeAfterApproval()` على كل منها
  ([التنفيذ المتين](/ar/durable-execution)، [Cloudflare Workers](/ar/cloudflare-workers)).
- **واجهات المحررات و MCP من نفس الـ agent.** `lousho acp` يقدّم أي agent
  لـ Zed وغيره من محررات Agent Client Protocol ([ACP](/ar/acp))؛ و`serveMcp`
  يعرضه كسيرفر MCP لـ Claude Code و Cursor وعملاء آخرين ([MCP](/ar/mcp-integration)).
- **مستضاف عندك، حزمة واحدة، بدون حساب على منصة.** يشتغل داخل عملية Node عندك
  أو في Worker؛ لا شيء يتصل بالخارج، ولا توجد control plane مستضافة تحتاج التسجيل فيها.
- **يدعم عدة إصدارات رئيسية من AI SDK.** الـ peer dependency `ai` تقبل `^4.3.19` و`^6` و
  `^7`، فيقدر تطبيق موجود يتبنّى lousho بدون أن يرقّي AI SDK أولًا
  ([Installation](/ar/installation)).

## أين lousho أضعف

- **إصدار alpha ومطوّر واحد.** خط 1.0 ما زال `1.0.0-alpha.*`. توقّع تغيّرات في الـ API، ومجتمعًا صغيرًا، وتكاملات قليلة من أطراف ثالثة.
- **لا يوجد store لـ Postgres.** stores الـ checkpoints والـ approvals متوفرة للذاكرة والملفات و SQLite و Cloudflare KV. أما Mastra و LangGraph فيوفران Postgres؛ وهنا تطبّق بنفسك الواجهتين الصغيرتين `CheckpointStore` / `ApprovalStore`.
- **providers أصلية أقل.** OpenAI و Anthropic و OpenRouter و Ollama وكتالوج Pi مدمجة؛ وأي شيء آخر يمر عبر `fromAiSdk()` ([Providers](/ar/providers)).
- **لا توجد لوحة مستضافة.** الـ traces عبارة عن spans وفق OpenTelemetry ترسلها إلى backend خاص بك ([Observability](/ar/observability))؛ ولا يوجد مقابل لـ LangSmith أو VoltOps أو playground الخاص بـ Mastra.
- **نقطة الدخول الجذرية ليست آمنة للـ edge.** Cloudflare Workers تستخدم build المخصص `worker` والمسارات الفرعية ([Cloudflare Workers](/ar/cloudflare-workers)).
- **الـ runs الحية يدوية.** الـ CI يشغّل اختبارات offline وإعادة تشغيل الـ cassettes؛ أما فحوص الـ providers الحية فتُشغَّل يدويًا.

## كيف تختار

إذا كنت تحتاج فقط استدعاءات model مع واجهة streaming، فـ Vercel AI SDK وحده هو
الخيار الأبسط. وإذا كنت تريد coding agent جاهزًا، فابدأ من Claude
Agent SDK أو من harness مبني على AI SDK. وإذا كنت تريد framework متكاملًا مع واجهة
تطوير و Postgres، فانظر إلى Mastra؛ وإذا كان التحكم في التدفق عندك graph، فـ LangGraph.js؛
وإذا كنت تنشر على Vercel، فـ eve. اختر lousho عندما تريد evals تعمل offline
بالتسجيل وإعادة التشغيل، و approvals تصمد بعد إعادة التشغيل على stores خاصة بك
(بما فيها Workers KV)، وحزمة واحدة مستضافة عندك تقدر أيضًا تقدّمها عبر ACP
و MCP.
