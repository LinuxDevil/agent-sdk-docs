أي coding agent يكتب كود Lousho أحسن لما يقرأ التوثيق الحالي بدل التخمين من بيانات التدريب. الـ SDK يأتي بتوثيقه في ملفين machine-readable، وهذا الموقع يقدّم كل صفحة بصيغة Markdown.

## التوثيق كملفات

حزمة npm تحتوي الملفين، بجانب `README.md` الخاص بها:

| الملف | ما هو |
| ---- | ---------- |
| `node_modules/@lousho/build-ai-agent/llms.txt` | فهرس [llmstxt.org](https://llmstxt.org): سطر واحد لكل صفحة توثيق، مع ملخص ورابط |
| `node_modules/@lousho/build-ai-agent/llms-full.txt` | الـ README وكل صفحات التوثيق في ملف واحد، بروابط مطلقة |

الملفان مولّدان من نفس توثيق هذا الموقع، والـ CI الخاص بالـ SDK يتحقق منهما. يعني يطابقان النسخة المثبتة عندك. أخبر الـ coding agent بمكانهما، مثلًا في `AGENTS.md` أو `CLAUDE.md` في مشروعك:

```markdown
## Lousho SDK

This project uses @lousho/build-ai-agent. Before writing or changing agent code,
read node_modules/@lousho/build-ai-agent/llms-full.txt. It documents the installed version.
Tests must run offline: use mockModel from @lousho/build-ai-agent/testing.
```

## التوثيق من هذا الموقع

في أعلى كل صفحة هنا زر **Copy page**، ينسخ الصفحة بصيغة Markdown لتلصقها في محادثة. ومن نفس القائمة تقدر تفتح الصفحة في ChatGPT أو Claude.

## دع الـ coding agent يتحقق من عمله

جزءان في الـ SDK يسهّلان التحقق من عمل الـ agent بدون مفتاح API:

- [Testing](/ar/testing): `mockModel` يحدد ردود الـ model مسبقًا، فيقدر الاختبار يتحقق من الـ tool calls ومن النص النهائي ويشتغل offline في CI.
- [Evals](/ar/evals): `defineEval()` يتحقق من مسار التنفيذ (أي tools، بأي ترتيب، وبأي معاملات)، و`lousho eval` يطلع النتيجة بصيغة JUnit.

الأمر `npx lousho doctor` يفحص نسخة Node والـ peer dependencies ومفاتيح API، ويطبع طريقة إصلاح أي نقص. وهو أول أمر مفيد يشغّله الـ coding agent في checkout جديد.

## الـ agent الذي تبنيه بـ Lousho كـ coding agent

الاتجاه المعاكس متغطى أيضًا. الـ agent الذي تبنيه بالـ SDK يقدر هو نفسه يشتغل على الكود:

- [Build a coding agent](/ar/build-a-coding-agent): شرح خطوة بخطوة لـ coding agent يشتغل في الطرفية، مع tools للملفات والـ shell، وapprovals وأسئلة متابعة.
- [Registry kits](/ar/registry): `lousho add coding-kit` (أو `coding-pi`، نفس الـ harness على الـ Pi provider مع Pi coding sub-agent) يثبّت coding agent ببنية production — checkpoints وقواعد صلاحيات وloop guard وسقف تكلفة — كمجلد واحد.
- [Pi coding sub-agents](/ar/sub-agents#pi-coding-agent-sub-agents-piagent): `piAgent()` يفوّض مهام implementation محددة النطاق لـ Pi coding agent. له قواعد صلاحيات خاصة به، ويوقّف الـ approval ويستأنفه بشكل durable.
- [Workspace tools](/ar/workspace-tools): tools لنظام الملفات والـ shell محصورة في مجلد جذر، والـ shell يتطلب approval.
- [Editors (ACP)](/ar/acp): `lousho acp ./my-agent` يقدّم الـ agent لـ Zed وباقي محررات Agent Client Protocol.
- [Project instructions](/ar/configuration#تعليمات-المشروع): `projectInstructions` يلحق ملف `AGENTS.md` الموجود في مستودعك بتعليمات الـ agent.
