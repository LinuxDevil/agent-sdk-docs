يكتب وكيل البرمجة شيفرة Lousho أفضل حين يقرأ التوثيق الحالي بدل أن يخمّن اعتمادًا على بيانات تدريبه. تأتي حزمة الـ SDK بتوثيقها في ملفين قابلين للقراءة الآلية، وهذا الموقع يقدّم كل صفحة بصيغة Markdown.

## التوثيق في صورة ملفات

تحتوي حزمة npm على الملفين كليهما، بجوار ملف `README.md` الخاص بها:

| الملف | ما هو |
| ---- | ---------- |
| `node_modules/@lousho/build-ai-agent/llms.txt` | فهرس وفق [llmstxt.org](https://llmstxt.org): سطر واحد لكل صفحة من التوثيق، مع ملخص ورابط |
| `node_modules/@lousho/build-ai-agent/llms-full.txt` | ملف README وكل صفحات التوثيق في ملف واحد، بروابط مطلقة |

يُولَّد الملفان من التوثيق نفسه الذي يُبنى منه هذا الموقع، ويُتحقَّق منهما في نظام التكامل المستمر (CI) الخاص بالـ SDK، ولذلك يطابقان الإصدار المثبَّت لديك. أخبر وكيل البرمجة بمكانهما، مثلًا في ملف `AGENTS.md` أو `CLAUDE.md` في مشروعك:

```markdown
## Lousho SDK

This project uses @lousho/build-ai-agent. Before writing or changing agent code,
read node_modules/@lousho/build-ai-agent/llms-full.txt. It documents the installed version.
Tests must run offline: use mockModel from @lousho/build-ai-agent/testing.
```

## التوثيق من هذا الموقع

في أعلى كل صفحة هنا زر **نسخ الصفحة (Copy page)**، ينسخ الصفحة بصيغة Markdown لتلصقها في محادثة. ومن القائمة نفسها يمكنك فتح الصفحة في ChatGPT أو Claude.

## دع وكيل البرمجة يتحقق من عمله

في الـ SDK جزءان يسهّلان التحقق من عمل الوكيل دون مفتاح API:

- [الاختبار](/ar/testing): `mockModel` يحدّد ردود النموذج سلفًا، فيستطيع الاختبار أن يتحقق من استدعاءات الأدوات ومن النص النهائي وأن يعمل دون اتصال في CI.
- [التقييمات](/ar/evals): `defineEval()` يتحقق من مسار التنفيذ (أي الأدوات استُدعيت، وبأي ترتيب، وبأي معاملات)، و`lousho eval` يُخرج النتيجة بصيغة JUnit.

يفحص الأمر `npx lousho doctor` إصدار Node والاعتماديات النظيرة ومفاتيح API، ويطبع طريقة إصلاح كل ما ينقص. وهو أمر مفيد يبدأ به وكيل البرمجة في نسخة جديدة من المستودع.

## وكيل Lousho الذي تبنيه وكيلَ برمجة

الاتجاه المعاكس مدعوم أيضًا. فالوكيل الذي تبنيه بالـ SDK يستطيع هو نفسه أن يعمل على الشيفرة:

- [بناء وكيل برمجة](/ar/build-a-coding-agent): شرح خطوة بخطوة لوكيل برمجة يعمل في الطرفية، بأدوات للملفات والصدفة (shell) وموافقات وأسئلة متابعة.
- [أدوات مساحة العمل](/ar/workspace-tools): أدوات لنظام الملفات والصدفة (shell) محصورة في مجلد جذر، مع إخضاع الصدفة للموافقة.
- [المحررات (ACP)](/ar/acp): الأمر `lousho acp ./my-agent` يقدّم وكيلك إلى Zed وغيره من المحررات التي تدعم Agent Client Protocol.
- [تعليمات المشروع](/ar/configuration#تعليمات-المشروع): الخيار `projectInstructions` يُلحق ملف `AGENTS.md` في مستودعك بتعليمات الوكيل.
