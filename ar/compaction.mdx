run طويل لـagent يملأ الـcontext window غالبًا بنتائج الـtools: محتويات ملفات، نتائج بحث، ردود API قرأها الـmodel مرة وما عاد يحتاجها كاملة. الـcompaction (ضغط سياق المحادثة) يبقي run كهذا تحت حد الـmodel على مرحلتين: أولاً يبدل نتائج الـtools القديمة بعلامة قصيرة، وإذا هذا ما كفى يبدل أقدم الدورات بملخص يكتبه model (أرخص).

## تفعيل الـcompaction على agent

مع `createAgent()`، فعّل الـcompaction بخيار `compaction`. القيمة `true` تثبّت الـhook بإعداداته الافتراضية: تقليم نتائج الـtools القديمة فوق 90% من window الـmodel. ولو مررت object تضبطه بنفسك، وفيه `summarizer` يختار `twoPhaseStrategy()` مع الـmodel اللي تعطيه — سلسلة `"provider/model"` أو `LLMProvider`. بادئة `vendor/` في اسم الـmodel هي اللي تحدد الـprovider. مع OpenRouter استخدم `openrouter/<vendor>/<model>` (مثلاً `openrouter/openai/gpt-4o-mini`).

```ts
import { createAgent } from '@lousho/build-ai-agent';

const simple = createAgent({ model: 'openai/gpt-4o', compaction: true });

const agent = createAgent({
  model: 'openai/gpt-4o',
  compaction: {
    thresholdPercent: 0.8, // compact above 80% of the context window (default 0.9)
    protectedTokens: 20_000, // never change the newest 20K tokens (default 40_000)
    summarizer: 'openai/gpt-4o-mini', // prune, then summarize if still too big
  },
});

for await (const event of agent.stream('Audit the repository.')) {
  if (event.type === 'compaction.done') console.log(`${event.tokensBefore} -> ${event.tokensAfter} tokens`);
}
```

الـobject يقبل `strategy` و`thresholdPercent` و`contextWindow` و`protectedTokens` (مثل الجدول تحت) و`summarizer`. الجمع بين `summarizer` و`strategy` خطأ في الإعداد — مرّر `twoPhaseStrategy({ model })` كقيمة لـ`strategy` بدلها. `createAgent({ hooks })` يقبل أي `AgentHook` ثانية، وهي تشتغل قبل hook الـcompaction، فالـcompaction يشوف اللي أضافته. الـhooks والـcompaction ينطبقان على `send()` و`stream()` والـsessions.

### أحداث الـstream

`agent.stream()` و`session.stream()` و`AgentExecutor.stream()` يبلّغون عن كل عملية compaction بحدثين، داخل الخطوة وقبل استدعاء الـmodel اللي أثارها (شوف [Streaming](/ar/stream-events#event-schema-version-1)):

| `type` | الحقول |
| --- | --- |
| `compaction.start` | `strategy`, `tokensBefore`, `contextWindow`, `thresholdTokens`, `trigger?: 'manual'` |
| `compaction.done` | `strategy`, `tokensBefore`, `tokensAfter`, `prunedToolCallIds`, `summary?: boolean`, `error?: { message }`, `trigger?: 'manual'` |

كل `compaction.start` يتبعه `compaction.done` واحد بالضبط. إذا الاستراتيجية ما قدرت تصغّر شيء، `tokensAfter` يساوي `tokensBefore`. وإذا فشلت (أو فشل الـsummarizer فرجع الـhook للتقليم)، `error` ينضبط والـrun يكمل. الملخص اللي ما ينزّل المحادثة تحت العتبة — أو اللي يكبّرها — مرفوض بنفس الطريقة: `error` ينضبط، الـrun يحتفظ بالنتيجة المقلّمة بدل الملخص، والـhook يكتفي بتقليم الـtranscript هذا لباقي الـrun. فالـhook ما يرجع يستدعي summarizer ما يقدر يساعد، خطوة ورا خطوة. `summary` تكون `true` لما الدورات القديمة تبدلت بملخص (النص نفسه لا يُرسَل؛ استخدم `onCompaction` له). `send()` بدون listener ما يطلق أحداث. الـhooks تضيف أحداثها بـ `ctx.emit?.(...)` على سياق `preGenerate`، وهو موجود لما يكون للـrun listeners (`createAgent({ onEvent })` أو `onAgentEvent`) أو لما يكون ماشي بـstream.

## الـcompaction على run

`createCompactionHook()` يرجع `AgentHook` اسمه `compaction`. مرّره في `createAgent({ hooks })`. الإعداد الموصى به: استراتيجية المرحلتين مع model تلخيص رخيص:

```ts
import { createAgent, createCompactionHook, twoPhaseStrategy } from '@lousho/build-ai-agent';

const agent = createAgent({
  provider,
  hooks: [
    createCompactionHook({
      strategy: twoPhaseStrategy({ model: 'openai/gpt-4o-mini' }), // prune, then summarize if still too big
      thresholdPercent: 0.9, // compact above 90% of the context window (the default)
      protectedTokens: 40_000, // never change the newest 40K tokens (the default)
      onCompaction: ({ tokensBefore, tokensAfter, prunedToolCallIds, summary, error }) => {
        console.log(`compacted ${tokensBefore} -> ${tokensAfter} tokens (${prunedToolCallIds.length} results pruned)`);
        if (summary) console.log('summary:', summary);
        if (error) console.warn('summarizer failed, kept the pruned conversation:', error.message);
      },
    }),
  ],
});
```

قبل كل استدعاء للـmodel، الـhook يقدّر حجم الطلب بـ `estimateTokens` (شوف [Models, tokens and cost](/ar/models-and-cost#الـ-models-وجدول-الأسعار)). إذا الحجم فوق `thresholdPercent` من الـcontext window، الـhook يشغّل استراتيجيته (وينتظرها إذا كانت async) ويستدعي `onCompaction` مع أعداد الـtokens، والـ`toolCallId`s اللي اتقلّمت، والملخص إن وجد، واسم الاستراتيجية.

| الخيار | الافتراضي | المعنى |
| --- | --- | --- |
| `thresholdPercent` | `0.9` | نفّذ الـcompaction لما الطلب المقدَّر يتجاوز هذه النسبة من الـcontext window. لازم تكون القيمة في (0, 1]. |
| `contextWindow` | من الـregistry، وإلا `128_000` | الـcontext window بالـtokens. افتراضيًا تُجلب لـ `request.model` بـ `getModelInfo()`؛ سجّل الـmodels الخاصة بك بـ `registerModel()`. |
| `protectedTokens` | `40_000` | أحدث الرسائل اللي تسعها هذه الكمية من الـtokens ما تتغير أبدًا. |
| `strategy` | `pruneToolResultsStrategy()` | طريقة الـcompaction (شوف تحت). `twoPhaseStrategy()` هي الموصى بها؛ لكنها تحتاج model تلخيص، فهي ليست الافتراضية. |
| `onCompaction` | لا شيء | تُستدعى بعد كل compaction غيّر المحادثة أو أبلغ عن `error`. |

الـcompaction ما يفشل الـrun أبدًا. إذا الاستراتيجية رمت استثناء، أو فشل استدعاء الـsummarizer، الـrun يكمل (بالمحادثة المقلّمة، أو بدون تغيير) و`onCompaction` تستلم الـ`error`.

الـhook يعيد كتابة transcript الـrun نفسه، مش نسخة منه: مصفوفة `messages` في الطلب هي قائمة رسائل الـrun، والـhook يغيّرها في مكانها. فالنتيجة المقلّمة أو الملخص تبقى في الخطوات اللاحقة، وفي الـcheckpoints (الـsession المستأنفة ما ترجع السجل الكامل) وفي `result.messages`، وما تنضغط مرة ثانية في الخطوة التالية. الـcompaction يضيّع معلومات: إذا الـmodel احتاج نتيجة مقلّمة مرة ثانية، لازم يستدعي الـtool من جديد.

#### متقدم: executor API

تسجيل الـhook في `HookRegistry` للكود اللي يستدعي الـexecutor مباشرة (شوف [executor API](/ar/executor-api)):

```ts
import { AgentExecutor } from '@lousho/build-ai-agent/executor';
import { HookRegistry, createCompactionHook, twoPhaseStrategy } from '@lousho/build-ai-agent';

const hooks = new HookRegistry();
hooks.register(
  createCompactionHook({
    strategy: twoPhaseStrategy({ model: 'openai/gpt-4o-mini' }),
    thresholdPercent: 0.9,
    protectedTokens: 40_000,
  })
);

const result = await AgentExecutor.execute({ agent, input, provider, toolRegistry, hooks });
```

## الاستراتيجيات

| الاستراتيجية | وظيفتها |
| --- | --- |
| `pruneToolResultsStrategy()` | تبدل نتائج الـtools القديمة بعلامة. بدون استدعاء model. |
| `summarizeStrategy({ model, ... })` | تبدل الدورات القديمة برسالة ملخص واحدة يكتبها `model`. |
| `twoPhaseStrategy({ model, ... })` | تقلّم أولاً؛ وتلخّص بس إذا بقيت المحادثة فوق العتبة. موصى بها. |

### تقليم نتائج الـtools

`pruneToolResultsStrategy()` تبدل `content` كل نتيجة tool أقدم من الذيل المحمي بعلامة مثل `[pruned: search result, 18234 chars]`. وما تغيّر أبدًا:

- رسائل system، ولا رسائل user (ومنها الأولى)، ولا دورات assistant — فكل tool call يحتفظ برسالة نتيجته، والـtranscript يبقى صالح لكل provider؛
- نتائج آخر دورة assistant، اللي الـmodel ما قرأها بعد، حتى لو كانت أكبر من `protectedTokens`؛
- النتائج المثبتة، ولا النتائج اللي هي أصلاً علامة، ولا النتائج الأقصر من العلامة.

### تلخيص الدورات القديمة

`summarizeStrategy()` ترسل الرسائل اللي قبل الذيل المحمي للـsummarizer مع تعليمة مركّزة، وتبدلها برسالة `user` واحدة:

```text
[Conversation summary]
<the summary>
```

| الخيار | الافتراضي | المعنى |
| --- | --- | --- |
| `model` | مطلوب | الـsummarizer: `LLMProvider`، أو spec بصيغة `"provider/model"` ينحل بـ `resolveProvider()`. model صغير ورخيص عادة يكفي. |
| `protectedTokens` | قيمة الـhook | الـtokens الحديثة اللي تبقى كما هي. |
| `prompt` | `DEFAULT_SUMMARY_PROMPT` | التعليمة اللي تنرسل كرسالة system للـsummarizer. المحادثة اللي تتلخّص هي رسالة الـuser. |
| `maxSummaryTokens` | افتراضي الـprovider | قيمة `maxTokens` لاستدعاء التلخيص. |

الملخص يبقي الـtranscript صالح لكل provider:

- رسائل system والرسائل المثبتة تبقى في أماكنها، والملخص يحل محل أول رسالة مُلخّصة؛
- دورة assistant تتلخّص أو تبقى مع كل نتائج الـtools الخاصة بها معًا، فما في tool call يفقد نتيجته (ولا نتيجة تفقد الـcall الخاص بها)؛
- الرسالة الأخيرة ونتائج آخر دورة assistant تبقى دائمًا.

إذا فشل استدعاء التلخيص (أو رجع فاضي)، الاستراتيجية ترجع للتقليم وتردّ الفشل في `error`.

### المرحلتان

`twoPhaseStrategy()` تأخذ نفس الخيارات. تقلّم نتائج الـtools أولاً — وهذا مجاني — وما تستدعي الـsummarizer إلا إذا المحادثة المقلّمة ما زالت فوق `thresholdPercent` من الـcontext window. وقتها الـsummarizer يقرأ المحادثة المقلّمة. وإذا فشل، المحادثة المقلّمة تبقى ويُبلَّغ عن `error`.

## تثبيت الرسائل

`pinMessage(message)` ترجع نسخة من الرسالة موسومة بأنها مثبتة (تضبط `metadata.pinned: true`؛ و`Message.metadata` بيانات للتطبيق ما تنرسل للـmodel أبدًا). الاستراتيجيات المدمجة ما تقلّم ولا تلخّص رسالة مثبتة أبدًا؛ ونتيجة tool مثبتة تحفظ دورة الـassistant التابعة لها كاملة. ثبّت اللي لازم الـagent يشوفه كامل دائمًا، مثل نص المهمة أو مستند أساسي:

```ts
import { pinMessage, isPinned, type Message } from '@lousho/build-ai-agent';

const messages: Message[] = [
  { role: 'system', content: 'You are a research assistant.' },
  pinMessage({ role: 'user', content: 'Goal: compare the three vendors on price and support.' }),
];
console.log(isPinned(messages[1])); // true
```

الاستراتيجيات المخصصة لازم تراعي `isPinned()` أيضًا.

## الـcompaction يدويًا

`compactMessages(messages, options)` تشغّل استراتيجية مرة واحدة، مهما كان حجم المحادثة، وترجع promise نتيجته مصفوفة جديدة (المدخل ما يتعدل). استخدمها لتصغير transcript مخزّن قبل ما تكمله:

```ts
import { compactMessages, summarizeStrategy, type Message } from '@lousho/build-ai-agent';

declare const history: Message[];

const { messages, tokensBefore, tokensAfter, prunedToolCallIds } = await compactMessages(history, {
  protectedTokens: 8_000,
  model: 'gpt-4o-mini', // for the context-window lookup and the token estimator
});
console.log(`${tokensBefore} -> ${tokensAfter} tokens, pruned ${prunedToolCallIds.length} results`);

const summarized = await compactMessages(history, {
  protectedTokens: 8_000,
  strategy: summarizeStrategy({ model: 'openai/gpt-4o-mini' }),
});
console.log(summarized.summary ?? summarized.error?.message);
```

## الـcompaction على session

`session.compact(options?)` تعمل compaction لسجل [session](/ar/sessions) فورًا، مهما كان حجمه، وتحفظه في الـstore الخاص بالـsession (الذاكرة أو ملف أو SQLite أو KV) وترجع `{ messagesBefore, messagesAfter, tokensBefore, tokensAfter, strategy, error? }`. تشغّل `options.strategy` إن وُجدت، وإلا استراتيجية `agent.session({ compaction })` — وهي نفس القيمة اللي ياخذها `createAgent({ compaction })`، و`compaction` الخاص بالـagent إذا الـsession ما ضبطت واحدة — وإلا تقلّم نتائج الـtools القديمة. الرسائل المثبتة تبقى. والـsession اللي ما فيها رسائل تنتهي بدون ما تعمل شيء. الاستدعاء يرفض بـ `LOUSHO_SESSION_BUSY` إذا في turn شغالة، وبـ `LOUSHO_SESSION_TURN_PENDING` / `LOUSHO_SESSION_AWAITING_APPROVAL` إذا في durable turn ما خلصت. الـlisteners اللي اتضافت بـ `session.on()` تستلم `compaction.start` و`compaction.done` مع `trigger: 'manual'`. أما `session.clear()` فتفرّغ الـtranscript وتطلق `context.cleared`.

```ts
import { createAgent, twoPhaseStrategy } from '@lousho/build-ai-agent';
import { mockModel } from '@lousho/build-ai-agent/testing';

const agent = createAgent({ provider: mockModel(['ok']) });
const session = agent.session({ compaction: { strategy: twoPhaseStrategy({ model: 'openai/gpt-4o-mini' }) } });
session.on((event) => {
  if (event.type === 'compaction.done') console.log(event.trigger, event.tokensBefore, '->', event.tokensAfter);
});
await session.send('hello');
const { tokensBefore, tokensAfter } = await session.compact({ protectedTokens: 2_000 });
console.log(`${tokensBefore} -> ${tokensAfter} tokens`);
await session.clear();
console.log(session.messages.length); // 0
```

## كتابة strategy

الاستراتيجية اسم ودالة `compact()`، وممكن تكون async. تستلم الرسائل، وعدّاد tokens لـmodel الطلب، والـcontext window، و`protectedTokens`، و`thresholdTokens` (الحجم اللي لازم تنزل تحته)، و`signal` الإلغاء الخاصة بالـrun، وترجع الرسائل الجديدة مع عدد الـtokens قبل وبعد (واختياريًا `summary` أو `error`). رجّع مصفوفة الإدخال بدون تغيير لما ما يكون في شيء تفعله: الـhook وقتها يترك الـrun على حاله وما يستدعي `onCompaction`.

```ts
import { createCompactionHook, isPinned, type CompactionStrategy } from '@lousho/build-ai-agent';

// Keep the system prompt, pinned messages and the last 20 messages.
const keepRecent: CompactionStrategy = {
  name: 'keep-recent',
  compact({ messages, estimateTokens }) {
    const tokensBefore = estimateTokens(messages);
    if (messages.length <= 22) return { messages, tokensBefore, tokensAfter: tokensBefore, prunedToolCallIds: [] };
    // A real strategy must not split a tool call from its result.
    const older = messages.slice(0, -20).filter((m) => m.role === 'system' || isPinned(m));
    const kept = [...older, ...messages.slice(-20)];
    return { messages: kept, tokensBefore, tokensAfter: estimateTokens(kept), prunedToolCallIds: [] };
  },
};

const hook = createCompactionHook({ strategy: keepRecent });
```

الاستراتيجية المخصصة تستلم نفس الحدثين `compaction.start` و`compaction.done` مثل الاستراتيجيات المدمجة. و`onCompaction` (على `createCompactionHook()`) تظل تستلم نص الملخص وكائن `Error`.
