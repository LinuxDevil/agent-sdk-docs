`agent.stream()` تشغّل الـ agent بطريقة `agent.send()` نفسها بالضبط، وتُرجع لك
الـ run كـ stream من أحداث typed: نص الـ model حالما يصل، وكل tool call،
وحدود الخطوات، وطلبات الـ approval (الموافقة)، وفي النهاية `run.done`. كل event
كائن JSON عادي، فيمكنك تمريره إلى المتصفح عبر Server-Sent Events أو WebSocket
دون أي تحويل. بادئة `vendor/` في اسم الـ model هي التي تختار الـ provider؛
ومع OpenRouter استخدم `openrouter/<vendor>/<model>` (مثال
`openrouter/openai/gpt-4o-mini`).

> المقتطفات في هذه الصفحة تترك لك بعض الأسماء: `provider` هو أي `LLMProvider` (بدون اتصال: `createMockProvider()`)؛ و`agent` هو ناتج `createAgent()`؛ و`input` هو نص المستخدم، من نوع `string`؛ و`approvalStore` هو `ApprovalStore`؛ و`toolRegistry` هو `ToolRegistry`.

```ts
import { createAgent } from 'lousho';

const agent = createAgent({ model: 'openai/gpt-4o-mini' });

for await (const event of agent.stream('Weather in Paris?')) {
  if (event.type === 'text.delta') process.stdout.write(event.text);
}
```

الدالة نفسها موجودة في الـ API الكامل: `AgentExecutor.stream(options)` تأخذ
خيارات `AgentExecutor.execute()` نفسها (الـ approval store، والـ checkpoints،
والـ hooks، والـ tracing، و`toolConcurrency`، ...).

هذه الأحداث، أي الـ union `AgentEvent`، هي نظام الأحداث الوحيد في الـ SDK:
الـ stream، و[خيارات الـ listener](#الاستماع-بدون-iterating)، و`session.on()`،
والـ UI hooks، وroutes السيرفر، وACP والقنوات — كلها تنقل الأحداث نفسها.

## الـ `AgentRun`

`stream()` تُرجع `AgentRun`:

```ts
interface AgentRun extends AsyncIterable<AgentEvent> {
  readonly runId: string;                   // the runId on every event
  readonly result: Promise<ExecutionResult>; // what send() / execute() would return
  enqueue(input: AgentInput): EnqueueResult; // add user input to the running run
  steer(input: AgentInput): SteerResult;     // redirect the running run to new input
}
```

- **الـ run يبدأ فورًا.** لا تحتاج إلى إجراء iterate عليه: `await run.result`
  وحده يوصل الـ run إلى نهايته.
- **`result`** يعود بـ `ExecutionResult` نفسها التي تُرجعها `send()`، ويرفض بالخطأ
  نفسه الذي كانت `send()` سترفضه. الـ run الملغى يُرجع
  `finishReason: 'aborted'`؛ والـ run الموقوف بانتظار approval يُرجع
  `finishReason: 'awaiting-approval'` مع `approvalId`. ترك `result` دون
  `await` لن يسبّب أبدًا unhandled rejection.
- **الـ run الفاشل يرمي الخطأ من الحلقة.** عندما يفشل الـ run، تُخرج `for await`
  حدثَي `error` و`run.done { finishReason: 'error' }`، ثم ترمي من جديد الخطأ
  الذي يرفض به `run.result` (الخطأ نفسه الذي كانت `send()` سترميه)، فـ `try`
  حول الحلقة يلتقطه. مرّر `{ throwOnError: false }` إلى `stream()` لتنتهي
  الحلقة بشكل عادي وتقرأ الفشل من الأحداث أو من `run.result`. الإلغاء، والخروج
  المبكر بـ `break`، والتوقف بانتظار approval لا ترمي خطأ أبدًا. أما streams
  الـ session و`approvals.streamResolve()` فما زالت تنتهي بشكل عادي.
- **إذا خرجت من حلقة `for await` مبكرًا، يُلغى الـ run** (عبر مسار
  `signal` نفسه، راجع [الإلغاء](#الإلغاء)). وعندها `result` يُرجع
  `finishReason: 'aborted'`.
- **لا backpressure ولا يضيع شيء.** الـ run لا ينتظر المستهلك أبدًا. تتراكم
  الأحداث في buffer حتى تقرأها، فيرى المستهلك البطيء كل حدث وبالترتيب. وحتى
  لو أجريت iterate بعد نهاية الـ run، تصلك أحداثه كلها.
- **`enqueue(input)`** تضيف input من المستخدم إلى الـ run أثناء عمله: يدخل سجل
  المحادثة قبل الـ model call التالي. راجع
  [الـ input المنتظر](/ar/queue-and-steer#queued-input).
- **`steer(input)`** تعيد توجيه الـ run: الـ model call التي لم تُنتج شيئًا
  بعد تُلغى وتتكرر مع الـ input الجديد. راجع
  [الـ steering](/ar/queue-and-steer#steering).
- **مستهلك واحد.** لا يمكنك إجراء iterate على `AgentRun` إلا مرة واحدة؛
  و`for await` ثانية ترمي خطأ. لتوزيع الأحداث على أكثر من جهة، اجمعها بنفسك.
- الخيارات غير الصالحة — غياب `provider` أو `agent` أو `input`، أو
  `toolConcurrency` خاطئ — تجعل `stream()` يرمي الخطأ بشكل متزامن.

```ts
import { createAgent } from 'lousho';

const agent = createAgent({ model: 'openai/gpt-4o-mini' });

const run = agent.stream('Summarize the report', { signal: AbortSignal.timeout(30_000) });
const result = await run.result; // no iteration needed
console.log(result.finishReason, result.text);
```

## الاستماع بدون iterating

الـ listener الذي يرمي خطأ لا يُفشل الـ run (فقد تكون أدواته أحدثت آثارًا جانبية بالفعل): الخطأ يُسجَّل مرة واحدة لكل run عبر `console.warn` ويكمل الـ run.

لمراقبة كل run دون إجراء iterate على stream، أعطِ الـ agent listener:
`createAgent({ onEvent })`، أو `onAgentEvent` في خيارات
`AgentExecutor.execute()` / `stream()` / `resumeAfterApproval()`. يصل إلى الـ listener
كل `AgentEvent` لحظة حدوثه وبشكل متزامن، في `send()` كما في `stream()`،
وفي turns الـ session وفي الـ runs التي تُستأنف بعد approval. وتصله الأحداث نفسها
وبالترتيب نفسه الذي كنت ستراه لو أجريت iterate على الـ stream: مع وجود
listener، حتى `send()` و`execute()` تُجري stream لكل model call، فيصلك نص الخطوة
على عدة أحداث `text.delta` (إذا كان الـ provider لا يستطيع إجراء stream، يصل
`text.delta` واحد لكل خطوة). اجمعها معًا، أو استخدم `text.done` للنص
الكامل لكل خطوة؛ و`AgentExecutor.execute({ streamModelCalls: false })` تولّد
خطوات كاملة. الـ output guardrails تفحص فقط الرد النهائي لـ `send()`، كما هو
الحال بدون listener. وأحداث الـ sub-agents تصل موسومة بـ `subagent`.

```ts
import { createAgent } from 'lousho';

const agent = createAgent({
  model: 'openai/gpt-4o-mini',
  onEvent: (event) => {
    if (event.type === 'tool.start') console.log('calling', event.toolName, event.args);
    if (event.type === 'run.done') console.log('done:', event.finishReason, event.usage?.totalTokens);
  },
});

await agent.send('Weather in Paris?');
```

### الانتقال من `onEvent` / `ExecutionEvent`

`ExecuteOptions.onEvent` ونوعه `ExecutionEvent` حُذفا في هذا الإصدار (كانا
deprecated منذ إصدار سابق). مرّر بدلها `onAgentEvent` إلى
`AgentExecutor.execute()` / `stream()` / `resumeAfterApproval()` — أما
`createAgent({ onEvent })` فتستقبل أحداث `AgentEvent` أصلًا ولم تتغير.
الجدول أدناه يربط أسماء الأحداث القديمة بأحداث `AgentEvent` التي يستقبلها الـ
listener الآن:

| `ExecutionEvent` (`onEvent`) | `AgentEvent` (`onAgentEvent`) |
| --- | --- |
| `start` (`agentId`, `agentName`) | `run.start` (`agentId`, `agentName`) |
| `text-delta` (لم يكن يصدر أبدًا) | `text.delta` (`text`) |
| `text-complete` (`text`, `stepUsage`) | `text.done` (`text`)؛ استهلاك الخطوة على `step.done` (`usage`) |
| `tool-call` (`toolCall`) | `tool.start` (`toolCallId`, `toolName`، و`args` بعد تحليلها؛ و`rawArgs` عندما يكون نص الـ model غير JSON صالح كما أُرسل) |
| `tool-result` (`toolResult`) | `tool.done` (`result`, `durationMs`, `replacedByHook`)، أو `tool.error` (`error.name`, `error.message`) |
| `error` (`error: Error`) | `error` (`error: { name, message }`) |
| `abort` (`abortReason`, `usage`) | `run.done` مع `finishReason: 'aborted'` (والسبب هو `reason` في الـ signal) |
| `finish` (`finishReason`, `usage: RunUsage`) | `run.done` (`finishReason`, `text`, `usage`, `object`)؛ الـ `RunUsage` الكامل على `result.usage` |
| `start` / `finish` لـ sub-agent (مع `subagent`) | `tool.start` / `tool.done` للـ lead الخاصة بالـ call التي بدأته |
| (لا شيء: كان الـ run يمثل agent واحد) | `handoff` (`from`، `to`، `toolCallId`): الـ run سلّم المحادثة لـ agent آخر ([Handoffs](/ar/handoffs)) |
| `timestamp: Date` | `timestamp`: string بصيغة ISO-8601؛ زيادةً على `runId` و`seq` و`v` |

`AgentEvent` يبلغك أيضًا عن أشياء لم يكن `ExecutionEvent` يوصلها أبدًا: حدود
الخطوات، طلبات الـ approval، قرارات الصلاحيات، الـ budgets، الـ guardrails،
الـ input المنتظر والموجَّه (queued وsteered)، الـ compaction، الـ reasoning،
retries الـ provider، الـ agent drift، والـ handoffs (راجع
[الـ schema](/ar/stream-events#event-schema-version-1)).

## الـ streaming لـ turn في session

`session.stream(input, { signal })` تعمل stream لـ turn واحد من
[session](/ar/sessions) (جلسة) متعددة الـ turns وتُرجع `AgentRun` نفسه. يرى الـ run
المحادثة حتى تلك اللحظة، وعندما ينتهي يُحفظ الـ turn في store الـ session،
تمامًا كما تحفظه `session.send()`. و`run.done` يصل بعد الحفظ، فيكون سجل
المحادثة كاملًا عندما تنتهي الحلقة. أما الـ run الملغى أو الفاشل، أو الذي توقفت
عن قراءته مبكرًا، فلا يُحفظ.

```ts
import { createAgent } from 'lousho';

const agent = createAgent({ model: 'openai/gpt-4o-mini' });
const session = agent.session({ id: 'user-42' });

for await (const event of session.stream('My name is Ali.')) {
  if (event.type === 'text.delta') process.stdout.write(event.text);
}
const again = session.stream('What is my name?'); // streams with the first turn in its history
console.log((await again.result).text);
```

## الـ streaming بعد الـ approval

الـ run الذي توقف بانتظار [approval](/ar/approvals) يستطيع أن يكمل كـ stream
أيضًا. `agent.approvals.streamResolve()` (أو `streamAnswer()`) تُرجع
`AgentRun` يكون الـ `result` فيه هو نفسه ما تُرجعه `agent.approvals.resolve()`.
أحداثه: `run.start`، ثم `tool.resume` و`tool.done` للـ call التي حُسم أمرها
(`tool.error` في حالة الرفض — `tool.resume` وليس `tool.start` ثانية، لأن الـ
run الموقوف كان قد أبلغ عن بداية تلك الـ call)، ثم أحداث الاستكمال نفسها كما
في run جديد، حتى `run.done`. وإذا حدث توقف آخر، ينتهي الـ stream بـ
`approval.requested` (مع `kind: 'sign-in'` ورابط `signIn` عندما تنتظر أداة
[تسجيل دخول OAuth](/ar/oauth#ما-يراه-المستخدم)). الإلغاء و`enqueue()`
و`steer()` تعمل بالطريقة نفسها، والـ approval يمكن أن تأتي من process أخرى،
لأن كل شيء يُقرأ من الـ approval store. وإذا كان الـ model يُختار لكل run
(`model` دالة)، فالمستخدم هو نفسه الذي استخدمه الـ run الموقوف.

```ts
import { createAgent } from 'lousho';

const agent = createAgent({ provider /* , a tool with needsApproval */ });
const paused = await agent.send('Delete the old reports.');
// paused.finishReason === 'awaiting-approval'
const run = agent.approvals.streamResolve({ id: paused.approvalId!, approved: true });
for await (const event of run) {
  if (event.type === 'tool.done') console.log(`${event.toolName} ran`);
  if (event.type === 'text.delta') process.stdout.write(event.text);
}
```

#### متقدّم: executor API

مع الـ executor مباشرة، `streamResumeAfterApproval()` تأخذ وسائط
`resumeAfterApproval()` نفسها (راجع [الـ executor API](/ar/executor-api))
وتُرجع `AgentRun` نفسه.

```ts
import { AgentExecutor, streamResumeAfterApproval } from 'lousho/executor';

const paused = await AgentExecutor.execute({ agent, input, provider, toolRegistry, approvalStore });
const run = streamResumeAfterApproval({ id: paused.approvalId!, approved: true }, approvalStore, toolRegistry, provider);
for await (const event of run) {
  if (event.type === 'tool.done') console.log(`${event.toolName} ran`);
  if (event.type === 'text.delta') process.stdout.write(event.text);
}
```

كل event فيه `type` و`runId` و`seq` و`timestamp` و`v`. القائمة الكاملة لأنواع
الأحداث وضمانات الترتيب ومساعدات TypeScript وقواعد الإصدارات موجودة في
[Stream events](/ar/stream-events).

## Sub-agents

عندما يفوّض الـ agent العمل عن طريق أداة `task`
(راجع [Sub-agents](/ar/sub-agents))، يصل run الـ sub-agent داخل الـ
stream نفسه: خطواته وأحداث `text.delta` و`text.done` وأحداث الـ tool والأخطاء تظهر
بين `tool.start` و`tool.done` (أو `tool.error`) للـ lead في تلك الـ call،
وكلها تحمل حقل `subagent`:

```json
{ "name": "researcher", "depth": 1, "toolCallId": "call_1", "description": "find sources" }
```

`toolCallId` هو الـ tool call لدى الـ lead الذي بدأ الـ sub-agent؛ والـ
sub-agent التابع لـ sub-agent آخر يحمل `depth: 2` والذي يحتويه في `parent`.
الأحداث التي لا تحتوي `subagent` تخص الـ run في المستوى الأعلى: ضمانات الترتيب
المذكورة أعلاه تسري عليها، وتسري بشكل مستقل على خطوات كل sub-agent (وعدة
sub-agents يعملون بالتوازي تتداخل أحداثهم). `run.start` و`run.done` يخصّان
الـ run في المستوى الأعلى فقط، فيظهران مرة واحدة بالضبط. والـ sub-agent الذي
يتوقف بانتظار approval يُبلَغ عنه مرة واحدة، عبر `approval.requested` في
المستوى الأعلى (وهي تحمل الـ call الخاصة بالـ sub-agent).

```ts
import { createAgent } from 'lousho';

const researcher = createAgent({ provider, instructions: 'You research.', description: 'Finds sources' });
const lead = createAgent({ provider, instructions: 'You coordinate.', subagents: { researcher } });

for await (const event of lead.stream('Write about bicycles')) {
  const who = event.subagent ? `[${event.subagent.name}] ` : '';
  if (event.type === 'text.delta') process.stdout.write(who + event.text);
}
```

## Token streaming والـ providers

عندما ينفّذ الـ provider `stream()` (كل الـ providers المدمجة تنفذها،
و`mockModel` كذلك)، تخرج كل خطوة model كـ stream وتصل أحداث `text.delta` مع
إنتاج الـ model للنص. والـ tool calls تتجمّع من الـ stream. وإذا لم يكن لدى الـ provider
`stream()`، أو كانت `supportsStreaming(model)` تُرجع `false`، تعود الخطوة
إلى `generate()` ويصل نصها في `text.delta` واحد يتبعه `text.done`.

الـ streaming يغيّر فقط طريقة الحصول على خطوة model واحدة. الـ hooks،
والتحقق من الـ arguments، والـ approvals، والـ tool calls المتوازية، والـ
checkpoints، والإلغاء، والـ tracing spans، وباقي callbacks في `execute()` —
كلها تتصرف تمامًا كما في `send()`. و`send()` و`execute()` تُجري stream بالطريقة
نفسها عندما يكون لديها listener (`onEvent` / `onAgentEvent`)؛ وبدونه
تستخدم `generate()`.

يجب أن تُخرج `stream()` في الـ provider المخصص chunks من نوع `text-delta`
وchunk أخيرًا `finish` فيه `finishReason` و`usage`. يمكنك إخراج الـ tool calls
كـ chunks من نوع `tool-call`، أو تُنجزها على الـ promise `toolCalls` في
`StreamResult`. وchunk من نوع `error` يفشّل الخطوة.

## الإلغاء

مرّر `signal` لإيقاف run من الخارج، أو اخرج من الحلقة. كلاهما ينهي الـ run
بطريقة `send()` الملغاة نفسها: يُفحص الـ signal بين chunks الـ stream، وقبل كل
model call وكل tool call، ويصل إلى الـ provider والـ tools. ينتهي الـ stream بـ
`step.done` (`'aborted'` إذا كانت هناك خطوة تعمل) ثم `run.done`
(`'aborted'`)، و`result` يُرجع `finishReason: 'aborted'`.

```ts
import { createAgent } from 'lousho';

const agent = createAgent({ model: 'openai/gpt-4o-mini' });
const run = agent.stream('Write a long story');

let chars = 0;
for await (const event of run) {
  if (event.type === 'text.delta') chars += event.text.length;
  if (chars > 500) break; // aborts the run
}
console.log((await run.result).finishReason); // 'aborted'
```

لإضافة input إلى run ما زال يعمل، أو لإعادة توجيهه، راجع [الـ queued input
والـ steering](/ar/queue-and-steer): `run.enqueue(input)` تنتظر النقطة
الآمنة التالية، و`run.steer(input)` تقاطع الـ model call الحالي.

## مثال: terminal

```ts
import { createAgent, defineTool } from 'lousho';
import { z } from 'zod';

const getWeather = defineTool({
  name: 'get_weather',
  description: 'Current weather for a city',
  input: z.object({ city: z.string() }),
  execute: async ({ city }) => ({ city, tempC: 21 }),
});

const agent = createAgent({ model: 'openai/gpt-4o-mini', tools: [getWeather] });

for await (const event of agent.stream('Weather in Paris?')) {
  switch (event.type) {
    case 'text.delta':
      process.stdout.write(event.text);
      break;
    case 'tool.start':
      console.log(`\n→ ${event.toolName}(${JSON.stringify(event.args)})`);
      break;
    case 'tool.done':
      console.log(`← ${event.toolName} in ${event.durationMs}ms`);
      break;
    case 'run.done':
      console.log(`\n[${event.finishReason}, ${event.usage?.totalTokens ?? 0} tokens]`);
      break;
  }
}
```

## مثال: Server-Sent Events

كل event serializable كـ JSON، فنقطة نهاية SSE ليست إلا `res.write` واحدًا
لكل event. ألغِ الـ run عندما ينقطع اتصال العميل. أما مع turns الـ session، فإن
`createRouteHandler()` يفعل العكس افتراضيًا: يكتمل الـ turn ويُحفظ حتى لو
غادر العميل (راجع [Next.js](/ar/nextjs#المسارات)).

```ts
import { createServer } from 'node:http';
import { createAgent } from 'lousho';

const agent = createAgent({ model: 'openai/gpt-4o-mini' });

createServer(async (req, res) => {
  const question = new URL(req.url ?? '/', 'http://localhost').searchParams.get('q') ?? 'Hello!';
  const controller = new AbortController();
  res.on('close', () => controller.abort());

  res.writeHead(200, { 'Content-Type': 'text/event-stream', 'Cache-Control': 'no-cache' });
  for await (const event of agent.stream(question, { signal: controller.signal })) {
    res.write(`data: ${JSON.stringify(event)}\n\n`);
  }
  res.end();
}).listen(3000);
```

في المتصفح:

```ts
const source = new EventSource('/chat?q=Weather%20in%20Paris%3F');
source.onmessage = (message) => {
  const event = JSON.parse(message.data);
  if (event.type === 'text.delta') output.textContent += event.text;
  if (event.type === 'run.done') source.close();
};
```

لواجهة chat بـ React فوق endpoint من هذا النوع، راجع [React](/ar/react):
`useLoushoAgent()` يرسل الـ input بـ POST ويقرأ أسطر `data:` نفسها.

`lousho dev` يقدّم الصيغة نفسها بـ session لكل تبويب في المتصفح: `POST /chat`
مع `{ sessionId, input }` يُجري stream لـ `agent.session({ id }).stream(input)`
كأسطر `data:` تنتهي بـ `event: done`، والـ approvals تُحسم عبر
`POST /chat/:sessionId/approvals/:id` (راجع [CLI](/ar/cli#lousho-dev)).

## متقدّم: executor API

`AgentExecutor.stream()` تقبل كل خيارات `execute()` (راجع
[الـ executor API](/ar/executor-api)). هنا tool يحتاج approval ينهي الـ
stream بـ `approval.requested`:

```ts
import { AgentExecutor } from 'lousho/executor';

const run = AgentExecutor.stream({ agent, input, provider, toolRegistry, approvalStore });
for await (const event of run) {
  if (event.type === 'approval.requested') {
    console.log(`Approve ${event.toolName}(${JSON.stringify(event.args)})? id=${event.approvalId}`);
  }
}
const paused = await run.result; // paused.finishReason === 'awaiting-approval'
```
