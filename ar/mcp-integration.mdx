MCP يشتغل في الاتجاهين. الـ agent يستطيع مناداة tools موجودة في سيرفرات MCP،
أو يكون هو نفسه سيرفر MCP يناديه Claude Code وCursor وغيرهما من MCP clients.
الاتجاهان موجودان في الـ subpath `@lousho/build-ai-agent/mcp`، وحزمة
`@modelcontextprotocol/sdk` هي peer dependency اختيارية: ثبّتها لاستخدام أي اتجاه منهما.

```sh
npm install @modelcontextprotocol/sdk
```

`connectMcp` و`loadMcpTools` و`serveMcp` مُصدَّرة من
`@lousho/build-ai-agent/mcp`؛ وجذر الحزمة و`@lousho/build-ai-agent/tools`
يصدّرانها أيضًا. أما `createAgent({ mcpServers })` فلا يحتاج أي import من الـ subpath.

## استخدام سيرفرات MCP داخل agent

`createAgent({ mcpServers })` يأخذ نفس الـ map. السيرفرات تتصل عند
`await agent.ready()`، أو تلقائيًا عند أول `send()` / `stream()`.
tools كل سيرفر تنضاف باسم `<server>__<tool>` (مثل `docs__search`).
إذا سيرفر فشل في الاتصال، النداء يفشل، والنداء التالي يحاول من جديد.
`agent.close()` يقطع الاتصال بها (ويوقف عمليات stdio)؛ وأي tool call بعده
يعيد الاتصال. بدون `mcpServers` لا تفعل `ready()` و`close()` شيئًا.
بادئة `vendor/` في الـ model تحدد الـ provider؛ ومع OpenRouter استخدم
`openrouter/<vendor>/<model>` (مثل `openrouter/openai/gpt-4o-mini`).

```ts
import { createAgent } from '@lousho/build-ai-agent';

const agent = createAgent({
  model: 'openai/gpt-4o-mini',
  mcpServers: {
    files: { command: 'npx', args: ['-y', '@modelcontextprotocol/server-filesystem', '.'] },
    docs: { url: 'https://example.com/mcp', headers: { Authorization: 'Bearer <token>' } },
  },
});
const { text } = await agent.send('List the files here.');
await agent.close();
```

مدخلات stdio تنطلق بـ`command` و`args`؛ و`env` تنضاف إلى
البيئة الافتراضية (`PATH` وما شابه) وليست بديلًا عنها. مدخلات HTTP
تستخدم streamable HTTP transport وترسل الـ `headers` الثابتة مع كل
طلب. ويمكن لمدخل HTTP أيضًا تسجيل الدخول عبر OAuth كما يصفه MCP
authorization spec: أضف `oauth: { redirectUri }` فيسجّل operator دخول
الـ agent مرة واحدة؛ انظر [سيرفرات MCP مع OAuth](/ar/oauth#خوادم-mcp-مع-oauth).

الـ map هو نفسه الذي يعرّفه ملف spec؛ انظر
[الإعدادات](/ar/configuration) (قسم `mcpServers`) لصيغة YAML.

### مشاركة السيرفرات عبر `connectMcp()`

لمشاركة السيرفرات بين أكثر من agent، أو لتختار كيف تُعالَج الأعطال، استدعِ
`connectMcp(servers, options?)` ومرّر `tools` الناتجة عنها بنفسك. هي تتصل
بكل سيرفر وتسرد tools قبل أن تُكمِل، فتكون الـ tools معروفة من البداية.
الخيارات:

- `onError`: القيمة `'throw'` (الافتراضية) ترفض الـ promise إذا سيرفر فشل
  في الاتصال، بعد إغلاق الباقي؛ والقيمة `'skip'` تتجاوز ذلك السيرفر وتحذّر عبر `logger`.
- `lazy` (الافتراضية `true`): بعد `close()` أو انقطاع الاتصال، الـ tool call
  التالي يعيد الاتصال. مع `false` النداء يفشل بدل ذلك. سرد الـ tools
  يحتاج اتصالًا، لذلك `lazy` لا تؤجّل أول اتصال أبدًا.
- `logger`: يستقبل تحذيرات السيرفرات والـ tools المتخطّاة (الافتراضي: لا شيء).
- `tokens`: الـ token store (`AgentStore.tokens`) للسيرفرات التي فيها `oauth`؛
  مطلوب إذا كان أي سيرفر عنده `oauth`.

ترجع `{ tools, close(), status() }`؛ و`status()` تعطي لكل سيرفر واحدة من القيم
`'idle'` أو `'connected'` أو `'failed'` أو `'needs-auth'` (سيرفر `oauth`
لم يسجّل التطبيق دخوله إليه).

`tools` هي `Record<string, ToolDescriptor>` بمفتاح `<server>__<tool>` —
يعني record، وليست الـ array التي تنتجها `defineTool()`. و`createAgent({ tools })`
يقبل الشكلين ويجمعهما: `tools: [myTool, mcp.tools]` تسجّل عناصر الـ array
بأسمائها وعناصر الـ record بمفاتيحها، فتجتمع الـ tools الخاصة بك وtools MCP
في قائمة واحدة. (النشر داخل record واحد، `tools: { ...mcp.tools, my_tool: myTool }`،
يشتغل أيضًا.)

```ts
import { createAgent } from '@lousho/build-ai-agent';
import { connectMcp } from '@lousho/build-ai-agent/mcp';

const mcp = await connectMcp(
  { files: { command: 'npx', args: ['-y', '@modelcontextprotocol/server-filesystem', '.'] } },
  { onError: 'skip', logger: console }
);
console.log(mcp.status()); // { files: 'connected' }
const agent = createAgent({ model: 'openai/gpt-4o-mini', tools: mcp.tools });
await agent.send('List the files here.');
await mcp.close();
```

`mcp.tools` record، و`tools` يقبل array أيضًا، فالشكلان يندمجان:
`tools: [mcp.tools, weatherTool]` أو
`tools: [...createFsTools(workspace), ...Object.values(mcp.tools)]` (كل
descriptor من MCP يحمل اسم `<server>__<tool>` الخاص به، فيشتغل `Object.values` أيضًا).

### الـ approval على tools MCP

سيرفرات MCP تصف كل tool بـ annotations: `readOnlyHint` و
`destructiveHint` و`idempotentHint` و`openWorldHint` و`title`. هي مجرد
hints، لكن الـ SDK يستخدمها إعدادًا افتراضيًا لـ[الـ approvals](/ar/approvals)
(الموافقات): الـ tool مع `readOnlyHint: true` يشتغل مباشرة. والـ tool مع
`destructiveHint: true`، أو الذي لا يرسل `destructiveHint` أصلًا (الافتراضي في
spec MCP أنه destructive)، يوقف الـ run حتى إنسان يوافق. و`destructiveHint: false`
يشتغل. يعني الـ tool بدون annotations يسأل دائمًا. الـ annotations الخام
تبقى في `descriptor.metadata.mcp.annotations`، و`title` يصبح `displayName`.

اضبط `approval` في مدخل السيرفر (`mcpServers` أو `createAgent` أو `connectMcp()`) أو
في `loadMcpTools(client, name, { approval })`:

- `'annotations'` (الافتراضية): كما في الأعلى.
- `'always'` / `'never'`: اسأل عن كل tool / لا تسأل عن أي منها.
- دالة `({ name, annotations }) => boolean` تقرر لكل tool (`name` هو
  اسم الـ tool المجرّد؛ و`annotations` هي `{}` إذا السيرفر لم يرسل شيئًا).
  في الكود فقط؛ أما ملف spec فيأخذ السلاسل الثلاث.

[قواعد الصلاحيات](/ar/approvals#سياسات-الصلاحيات) تشتغل أولًا، ولا يزال بإمكانها
`allow` أو `deny` أو `ask`.

```ts
import { createAgent } from '@lousho/build-ai-agent';

const agent = createAgent({
  model: 'openai/gpt-4o-mini',
  mcpServers: {
    files: { command: 'npx', args: ['-y', '@modelcontextprotocol/server-filesystem', '.'] },
    // Ask before anything except tools whose name starts with `search`.
    docs: { url: 'https://example.com/mcp', approval: ({ name }) => !name.startsWith('search') },
    // A server you trust: never ask.
    scratch: { command: 'node', args: ['./scratch-server.js'], approval: 'never' },
  },
});
```

### tools من client اتصلت به بنفسك

اتصل بـ`Client` من `@modelcontextprotocol/sdk` بنفسك، وحمّل
tools بـ`loadMcpTools()`، ثم مرّر النتيجة إلى `createAgent()` (أو
سجّلها في `ToolRegistry`):

```ts
import { createAgent } from '@lousho/build-ai-agent';
import { loadMcpTools } from '@lousho/build-ai-agent/mcp';

const tools = await loadMcpTools(mcpClient, 'my-server');
const agent = createAgent({ prompt: '...', provider, tools });
```

`loadMcpTools` متوفرة أيضًا من جذر الحزمة ومن
`@lousho/build-ai-agent/tools`.

## تشغيل agent كسيرفر MCP

`serveMcp()` عكس `loadMcpTools()`: تعرض الـ agent (واختياريًا بعض
tools) كسيرفر MCP، فيستطيع Claude Code وCursor وغيرهما من MCP clients
مناداته.

```ts
import { createAgent, defineTool } from '@lousho/build-ai-agent';
import { serveMcp } from '@lousho/build-ai-agent/mcp';
import { z } from 'zod';

const searchDocs = defineTool({
  name: 'search_docs',
  description: 'Search the docs',
  input: z.object({ query: z.string() }),
  execute: ({ query }) => `results for ${query}`,
});

const supportAgent = createAgent({ prompt: 'You answer support questions.', provider, tools: [searchDocs] });

const server = await serveMcp({
  agent: supportAgent,            // exposed as ONE tool taking { message: string }
  name: 'support-bot',            // server name; the tool name defaults to a sanitized version
  description: 'Ask the support agent a question',
  tools: [searchDocs],            // optional: also expose these tools directly
  transport: { type: 'http', port: 3920, host: '127.0.0.1', path: '/mcp' }, // default: 'stdio'
});
await server.close();
```

- **Stateless.** كل نداء لـ tool الـ agent محادثة جديدة.
- **الإلغاء.** إلغاء طلب MCP يوقف الـ run
  (`agent.send(message, { signal })`).
- **الأخطاء.** فشل الـ agent يرجع نتيجة MCP فيها `isError: true`.
- **الـ approvals.** الـ tools المشروطة بـ approval لا يمكن الموافقة عليها عبر
  MCP. الـ run الذي يتوقف بانتظار approval يرجع `isError: true` مع رسالة
  توضّح ذلك. والـ tools المعلَّمة `needsApproval` لا تُعرض مباشرة إلا إذا
  مرّرت `allowApprovalTools: true`؛ وإذا فعلت، الـ clients يشغّلونها **بدون أي
  موافقة بشرية**.
- **stdio.** لا يُكتب على stdout شيء غير بروتوكول MCP؛ التحذيرات تذهب إلى stderr.
- **HTTP.** يربط `127.0.0.1` افتراضيًا. أضف `auth: { type: 'bearer', token }`
  لاشتراط ترويسة `Authorization: Bearer`. والربط بـ host غير loopback
  بدون `auth` يسجّل تحذيرًا.

### Annotations

`tools/list` تحمل annotations MCP حتى يعرف الـ clients ماذا يفعل كل tool.
الـ tool الذي يحتاج approval يُعلَن بـ`readOnlyHint: false, destructiveHint: true`؛
وحدّد الـ hints بنفسك عبر `annotations` (تُرسَل كما هي). الـ tool بلا hints
لا يرسل شيئًا، فيظل agent من Lousho يستهلك هذا السيرفر يسأل قبل تشغيله (انظر
`approval` في `connectMcp()`)؛ أما `readOnlyHint: true` فيشتغل بدون سؤال.
الـ tool الذي يحتاج approval لا يُعلَن أبدًا read-only. الـ tools المدمجة
`read_file` و`list_dir` و`glob` و`grep` و`todo_read` و`current_date` و
`day_name` كلها read-only.

```ts
import { defineTool } from '@lousho/build-ai-agent';
import { z } from 'zod';

const lookupOrder = defineTool({
  name: 'lookup_order',
  description: 'Look up an order',
  input: z.object({ id: z.string() }),
  annotations: { readOnlyHint: true, destructiveHint: false, title: 'Look up order' },
  execute: ({ id }) => ({ id, status: 'shipped' }),
});
```

### من الـ CLI

`lousho mcp` يقدّم ملف spec لـ agent (عبر stdio افتراضيًا):

```sh
npx lousho mcp agent.yaml
npx lousho mcp agent.yaml --http --port 3920 --host 127.0.0.1
```

لاستخدامه من MCP client، أضفه إلى إعدادات MCP عند العميل (مثل
`.mcp.json` في Claude Code):

```json
{
  "mcpServers": {
    "support-bot": { "command": "npx", "args": ["lousho", "mcp", "agent.yaml"] }
  }
}
```

## القيود

- الـ tools المشروطة بـ approval لا يمكن الموافقة عليها عبر MCP عندما تقدّم agent: الـ run الذي يتوقف لـ approval يرجع `isError: true`، والـ tools المعلَّمة `needsApproval` لا تُعرض إلا إذا ضُبطت `allowApprovalTools`.
- الـ clients عبر HTTP يرسلون الـ `headers` الثابتة مع كل طلب. أما OAuth (`oauth`) فملك التطبيق: grant واحدة لكل سيرفر للـ agent كله، يسجّل دخولها operator؛ ولا توجد grants لكل مستخدم حتى الآن.
- نداءات `serveMcp()` stateless: كل نداء لـ tool الـ agent محادثة جديدة، وHTTP transport يقبل `POST` فقط.
