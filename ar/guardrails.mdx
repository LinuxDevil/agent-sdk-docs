أدوات تشغّل الـ agents بأمان: **input و output guardrails** تفحص ما يدخل أي run وما يخرج منه (ومعاملات الـ tool calls)، و**patch checks** فحوص fail-closed على تغيير مقترح قبل أن تتصرّف بناءً عليه، و**sandboxed tools** تعمل داخل container معزولة بدلًا من عملية الـ host. للقرارات البشرية على كل call انظر [Approvals](/ar/approvals)؛ وللـ hooks التي تفحص كل tool call أو ترفضه انظر [Hooks](/ar/hooks).

## Input و output guardrails

`createAgent({ guardrails })` (أو `ExecuteOptions.guardrails`) يفحص الـ run في ثلاث نقاط، وكل قائمة تعمل بالترتيب:

| القائمة | تفحص | متى |
| ---- | ------- | ---- |
| `input` | كل رسالة مستخدم جديدة (رسائل المستخدم التي تنهي سجل المحادثة) | قبل أول model call. إذا حُجب، لا يحدث model call أصلاً. أما input guardrail الذي عليه `runInParallel` فيعمل بينما أول model call قيد التشغيل (انظر أدناه). |
| `output` | نص الـ assistant النهائي؛ وفي run من نوع `stream()` (الذي تمرّ عليه بـ loop)، نص كل step. `send()` مع listener يفحص النص النهائي فقط. | قبل أن يخرج: قبل `text.done` الخاص به، وقبل `run.done`. |
| `tools` | معاملات الـ tool call (`text` هي المعاملات بصيغة JSON، و`args` الكائن) | بعد [قواعد الصلاحيات](/ar/approvals#سياسات-الصلاحيات) (يُتخطّى الفحص إذا رفضت قاعدة الـ call) وقبل `needsApproval`. |

**الـ input guardrails المتوازية.** فحص input بطيء (فحص يستدعي model، مثل `moderationGuardrail({ model })`) يضيف زمن الاستجابة الخاص به كاملًا قبل أن يبدأ الـ agent بالرد. علّمه بـ `runInParallel: true` (على `IoGuardrail` الخاص بك، أو كخيار في `promptInjectionGuardrail` و`moderationGuardrail`) فيعمل بينما أول model call قيد التشغيل: الـ input guardrails الحاجبة (الوضع الافتراضي) تعمل أولًا، بما فيها الـ rewrites، ثم تبدأ الفحوص المتوازية معًا على الـ input نفسه ويبدأ الـ model call فورًا. إلى أن تجتاز كل الفحوص المتوازية، لا يخرج أي شيء أنتجه الـ call: أحداث `text.delta` و`reasoning.*` وأحداث الـ tools التي ينفّذها الـ provider تُحتجز بالترتيب (`step.start` لا يُحتجز)، ولا تُنفَّذ الـ tool calls؛ والرد الذي يصل مبكرًا ينتظر الفحوص. إذا اجتازت، تخرج الأحداث المحتجزة ويستمر الـ run تمامًا كما في وضع الـ guardrails الحاجبة. وإذا حجب أحدها، يُلغى الـ model call، وتُرمى الأحداث المحتجزة، ولا يصل شيء من الـ call إلى سجل المحادثة أو checkpoint أو `onLLMResponse`، وينتهي الـ run بـ `finishReason: 'guardrail'` و`guardrail.tripped` (أو `GuardrailError` مع `onTripped: 'throw'`) مثل أي حظر عادي. الفحص المتوازي لا يستطيع إجراء rewrite، لأن الـ input وصل إلى الـ model بالفعل: نتيجة `rewrite` تحجب، ويبدأ السبب بـ `runInParallel guardrails cannot rewrite: `. الثمن هو التكلفة: قد يكون الـ call المحجوب قد استهلك tokens قبل الحظر. تُحسب في `result.usage` إذا أبلغ عنها الـ provider (call انتهى قبل الـ trip)؛ أما الـ stream الملغى فلا يُبلغ عنها عادةً، ولا نقدّرها بأنفسنا. أول model call في الـ run فقط هو الذي يتسابق، والـ run الذي يُستأنف بعد approval (موافقة) لا يعيد فحص الـ input. وفي guardrails من نوع `output` و`tools`، يُتجاهَل `runInParallel`. نص `model` في الـ guardrail هو spec بصيغة `provider/model`: بادئة `vendor/` تختار الـ provider؛ ومع OpenRouter استخدم `openrouter/<vendor>/<model>` (مثال `openrouter/openai/gpt-4o-mini`).

```ts
import { createAgent, moderationGuardrail, piiGuardrail } from 'lousho';

const agent = createAgent({
  provider,
  guardrails: {
    // The PII check is instant and may rewrite, so it blocks; the moderation call runs alongside the agent's.
    input: [piiGuardrail({ action: 'rewrite' }), moderationGuardrail({ model: 'openai/gpt-4o-mini', runInParallel: true })],
  },
});
```

الـ guardrail هو `{ name, check(ctx) }`. في `ctx`: `kind` (`'input'` أو `'output'` أو `'tool'`)، و`text`، و`messages` الخاصة بالـ run، و`toolName` و`args` عندما يكون tool call، و`signal` الخاصة بالـ run. تعيد `check` (مباشرة أو عبر promise) `{ ok: true }` أو `{ ok: false, reason, action?, replacement?, info? }`:

- `action: 'block'` (الافتراضي) ينهي الـ run بـ `finishReason: 'guardrail'` و`result.guardrail` (`{ name, kind, reason, toolName?, info? }`). تكون `result.text` هي `''` ولا يُضاف الرد المحجوب إلى سجل المحادثة؛ ولا يُنفَّذ الـ tool call المحجوب (ولا الذي يليه في الدورة نفسها) ويأخذ نتيجة "cancelled"، لكي يبقى سجل المحادثة صالحًا. `stream()` يطلق `guardrail.tripped` قبل `run.done`.
- `action: 'rewrite'` يضع `replacement` مكان النص (وفي معاملات tool call: `replacement` هي المعاملات الجديدة بصيغة JSON)، ويرى الـ guardrail التالي النص الجديد، و`stream()` يطلق `guardrail.rewrote`.

مع `onTripped: 'throw'` يُرفض الحظر بـ `GuardrailError` (`LOUSHO_GUARDRAIL_TRIPPED`، ومعه الـ `guardrail` نفسه) بدلًا من أن ينتهي بشكل عادي. وإذا رمت `check` خطأً، يفشل الـ run. الـ sub-agents تشغّل guardrails الأب أولًا، ثم guardrails الخاصة بها. ملفات spec الخاصة بالـ agent تسمّي الـ guardrails المدمجة في `policy.guardrails` (انظر [الإعداد](/ar/configuration#السياسة-policy)).

```ts
import {
  createAgent,
  denyTopicsGuardrail,
  GuardrailError,
  llmJudgeGuardrail,
  maxLengthGuardrail,
  regexGuardrail,
  type IoGuardrail,
} from 'lousho';

const noProdWrites: IoGuardrail = {
  name: 'no-prod-writes',
  check: ({ toolName, args }) =>
    toolName === 'run_sql' && String(args?.db) === 'prod' ? { ok: false, reason: 'prod is read-only' } : { ok: true },
};

const agent = createAgent({
  provider,
  guardrails: {
    input: [maxLengthGuardrail({ maxChars: 4_000 }), denyTopicsGuardrail({ topics: ['medical advice'] })],
    output: [
      regexGuardrail({ name: 'secrets', action: 'rewrite' }),
      llmJudgeGuardrail({ model: 'openai/gpt-4o-mini', instruction: 'Replies must stay on the topic of cooking.' }),
    ],
    tools: [noProdWrites],
  },
});

const result = await agent.send('What should I cook tonight?');
if (result.finishReason === 'guardrail') {
  console.warn(`Blocked by ${result.guardrail?.name} (${result.guardrail?.kind}): ${result.guardrail?.reason}`);
}

try {
  await createAgent({ provider, guardrails: { input: [maxLengthGuardrail({ maxChars: 10 })], onTripped: 'throw' } }).send('A long question');
} catch (error) {
  if (error instanceof GuardrailError) console.error(error.guardrail);
}
```

| المدمج | يفشل عندما |
| -------- | ---------- |
| `maxLengthGuardrail({ maxChars })` | يكون النص أطول من `maxChars` حرفًا. |
| `regexGuardrail({ name, pattern?, action?, replacement? })` | يطابق النص `pattern` (`RegExp` أو قائمة؛ الافتراضي: أنماط `secretScanCheck`). مع `action: 'rewrite'` يصبح كل تطابق `replacement` (الافتراضي `'[redacted]'`). |
| `denyTopicsGuardrail({ topics })` | يحتوي النص أحد `topics` (كلمات مفتاحية، دون اعتبار لحالة الأحرف). |
| `llmJudgeGuardrail({ model, instruction, name? })` | `model` (`LLMProvider` أو `"provider/model"`)، يُسأل مرة لكل فحص هل يلتزم النص بـ `instruction`، ولا يرد بـ `PASS`؛ ردّه `FAIL: <reason>` هو السبب. |
| `piiGuardrail({ types?, action?, name? })` | يحتوي النص بيانات شخصية من أحد `types` (الافتراضي الكل): `email`، `phone` (من 9 إلى 15 رقمًا، مع رمز دولة `+` وفواصل اختيارية)، `credit-card` (يجب أن يجتاز فحص Luhn)، `iban` (يجب أن يجتاز فحص mod-97)، `us-ssn` (صيغة `123-45-6789`)، `ip-address` (IPv4). يحجب افتراضيًا؛ `action: 'rewrite'` يستبدل بكل تطابق `[<type>]`، مثل `[email]`. فحص heuristic، دون model call. |
| `secretsGuardrail({ action?, extraPatterns?, name? })` | يحتوي النص private key، أو مفتاح Anthropic (`sk-ant-`) أو OpenRouter (`sk-or-v1-`) أو OpenAI (`sk-proj-`، `sk-`) أو AWS (`AKIA`) أو GitHub (`ghp_` وباقي بادئات `gh?_`، و`github_pat_`) أو Slack (`xoxb-` ونحوه) أو Google (`AIza`) أو مفتاح Stripe live (`sk_live_`، `rk_live_`)، أو JWT، أو `Authorization: Bearer` token، أو تطابق مع `extraPatterns`. يستبدل بكل تطابق `[secret]` افتراضيًا؛ `action: 'block'` يحجب. heuristic، دون model call. |
| `promptInjectionGuardrail({ model?, name?, runInParallel? })` | يحتوي النص إشارة prompt injection: "ignore (all) previous instructions" ونحوها، أو "you are now"، أو طلب الـ system prompt، أو علامة دور من chat template (`<\|im_start\|>`، `### System:`، `[INST]`)، أو عبارة jailbreak معروفة، أو أحرف Unicode tag الخفية (من U+E0000 إلى U+E007F). مع `model`، يُرسل النص الذي يجتاز الأنماط بعد ذلك إلى الـ model، ويجب أن يرد بـ `SAFE` أو `INJECTION: <reason>`. يحجب فقط. |
| `moderationGuardrail({ model, categories?, name?, runInParallel? })` | `model`، يُسأل مرة لكل فحص بـ prompt ثابت، يعدّ إحدى `categories` منطبقة (الافتراضي الكل: `hate`، `harassment`، `self-harm`، `sexual`، `sexual-minors`، `violence`، `illicit`)؛ يرد بـ `NONE` أو بالفئات. prompt عادي وليس moderation endpoint خاصًا بـ vendor، لذا يعمل مع أي provider. يحجب فقط. ومع `runInParallel: true` (موجودة أيضًا في `promptInjectionGuardrail`) يعمل فحص الـ input بجانب أول model call. |

الأربعة الأخيرة starter set للفحوص التي تحتاجها أغلب الـ agents في الإنتاج:

```ts
import { createAgent, piiGuardrail, promptInjectionGuardrail, secretsGuardrail } from 'lousho';

const agent = createAgent({
  provider,
  guardrails: {
    input: [promptInjectionGuardrail(), piiGuardrail({ action: 'rewrite' })],
    output: [secretsGuardrail()],
  },
});

const result = await agent.send('My card is 4111 1111 1111 1111, can you check my order?');
// The model sees "My card is [credit-card], can you check my order?"
if (result.guardrail?.info?.category === 'prompt-injection') console.warn(result.guardrail.info.signals);
```

**أي guardrail تفعّل، دون النص.** أي حظر (`result.guardrail`، `guardrail.tripped`، `guardrail.rewrote`، `GuardrailError.guardrail`) يحمل `info` — `GuardrailTripInfo` إذا وفّره الـ guardrail، والـ starter set توفّره دائمًا: `{ category: 'pii', matches: [{ type, start, end }] }` أو `{ category: 'secret', matches: [{ label, start, end }] }` أو `{ category: 'prompt-injection', source: 'heuristic' | 'model', signals }` أو `{ category: 'moderation', categories }`. تشير الإزاحات إلى مواضع في النص المفحوص (`ctx.text`). لا يحتوي `info` النص المطابق أبدًا، ولا `reason` في فحصَي PII والأسرار (أنواع وتسميات فقط)، فلا تنسخ الأحداث والـ traces والـ logs البيانات الشخصية ولا السر. ويستطيع الـ guardrail الخاص بك أن يعيد `info: { category: 'custom', ...anything }`.

**الحدود.** فحوص PII والأسرار وprompt injection فحوص أنماط heuristic: تلتقط الصيغ الشائعة المذكورة أعلاه وتفوّت غيرها (بيانات شخصية بصيغ أو لغات أخرى، سر ببادئة غير معروفة، injection أُعيدت صياغته أو تُرجم أو رُمّز)، وتعلّم أيضًا بعض النصوص البريئة (رقم طلب يشبه رقم هاتف، نسخة تشبه IP address، مستخدم يسأل عن "system prompts"). عاملها كـ filter أول، لا كحد أمني؛ وأبقِ صلاحيات الـ tools والـ approvals مفعّلة لأي شيء يهمك. الفحوص التي تعتمد على model موثوقيتها بقدر موثوقية الـ model، وتكلّف call واحدًا لكل نص مفحوص، وتفشل fail-closed: الرد الذي لا يأتي بأي من الصيغتين يُحجب، مع سبب يذكر أن الرد لم يُقرأ. نتائج الـ tools (مثل صفحة ويب مجلوبة فيها injection غير مباشر) لا يفحصها أي guardrail حتى الآن.

## Patch checks

`runPatchChecks(patch, checks)` يشغّل كل الفحوص بالتوازي على patch مقترح ويجمع النتائج في verdict واحد. [مثال ops-pipeline](https://github.com/LinuxDevil/lousho/blob/main/examples/ops-pipeline) يستخدمه كبوابة على patch من agent إصلاح قبل أن يُفتح pull request:

```ts
import { runPatchChecks, secretScanCheck, createDiffSizeCheck, createCommandCheck } from 'lousho';

const verdict = await runPatchChecks(
  { diff: patch },
  [
    secretScanCheck,
    createDiffSizeCheck(500),
    createCommandCheck('test-run', repoPath, 'npm', ['test']),
  ],
);

if (!verdict.pass) {
  console.log(verdict.failures); // [{ name, reason }, ...] — never call the write-side tool
}
```

| فحص الـ patch | يفشل عندما |
| --------- | ---------- |
| `secretScanCheck` | يحتوي الـ diff على header لمفتاح خاص، أو مفتاح API بأسلوب OpenAI، أو AWS access key. |
| `createDiffSizeCheck(maxLines)` | يحتوي الـ diff على أكثر من `maxLines` سطرًا. |
| `createCommandCheck(name, cwd, command, args, { timeoutMs? })` | يخرج الأمر بكود خروج غير صفري. إذا لم يكن الـ diff فارغًا يُطبَّق أولًا (`git apply`) على نسخة مؤقتة من `cwd`، ويفشل الفحص إذا لم يُطبَّق بشكل سليم. |
| `createTestRunCheck(repoPath)`، `createLintCheck(repoPath)` | يفشل `npm test` / `npm run lint` (اختصارات لفحص الأمر). |

**Fail-closed.** الفحص الذي يرمي خطأً، أو يُرفض، أو لا ينتهي خلال مهلة الـ timeout (30 ثانية افتراضيًا)، أو يعيد أي شيء غير `pass: true` يُحسب فاشلًا: `runPatchCheckSafely(check, patch)` تغلّف كل واحد منها. فحص الأمر يقتل العملية عندما تنقضي المهلة (على Windows، شجرة العمليات كلها). اكتب فحصك بالشكل `{ name, check(patch) }` الذي يعيد `{ pass, reason? }`.

## Sandboxed tools

الـ tool تشترك بـ `requiresSandbox: true` ودالة `sandboxExecute(args, sandbox)`. بعد ذلك يستدعي الـ executor `sandboxExecute` مع `SandboxAdapter` الخاص بالـ run بدلًا من أن يستدعي `execute`. `createAgent()` لا تأخذ `sandbox` حتى الآن، لذا يمر ذلك عبر الـ executor.

#### متقدم: الـ executor API

```ts
import { AgentExecutor } from 'lousho/executor';
import { SubprocessSandbox } from 'lousho';

// Route a flagged tool (requiresSandbox + sandboxExecute) through a real,
// Docker-backed sandbox instead of the in-process NoopSandbox default
await AgentExecutor.execute({ agent, input, provider, toolRegistry, sandbox: new SubprocessSandbox() });
```

- `NoopSandbox` (الافتراضي) يعمل على الـ host. مجرد بديل شكلي، لا عزل فيه.
- `SubprocessSandbox` ينفّذ كل أمر في Docker container جديدة، معزولة عن الشبكة وتُحذف تلقائيًا، ولا يُوصَل بها أي مجلد من الـ host إلا `cwd` الذي تمرّره. يحتاج Docker daemon قيد التشغيل والـ peer dependency الاختيارية `dockerode` (`npm install dockerode@^5.0.1`؛ تُحمَّل عند أول استخدام). وإذا أُلغي الـ run (أُلغيت الـ `signal` الخاصة به) أو انتهت مهلة الأمر، تُقتل الـ container وتُحذف. كل container تعمل بمستخدم غير root (`user`، الافتراضي `'1000:1000'`؛ وعلى host لينكس يجب أن يستطيع الكتابة في الـ `cwd` الموصول)، مع إسقاط كل Linux capabilities، و`no-new-privileges`، و`limits` افتراضيًا 512 MiB ذاكرة و256 عملية و1 CPU. `writeFile(path)` يكتب على الـ host فقط تحت `root` (الافتراضي: مجلد العمل الحالي)؛ وأي مسار خارجه، حتى لو كان عبر symlink، يُرفض بـ `LOUSHO_SANDBOX_PATH_DENIED`.
- نفّذ `SandboxAdapter` (`name`، `run(cmd, args, opts)`، `writeFile(path, content)`) لـ backend آخر.

إذا كنت تبني coding agent، فإن `SandboxShell` يضع أداة الـ shell الخاصة بالـ workspace خلف الـ adapter نفسه؛ انظر [أدوات مساحة العمل](/ar/workspace-tools#sandboxed-shell-sandboxshell).
