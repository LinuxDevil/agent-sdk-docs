أدوات تشغّل الـ agents بأمان: **input و output guardrails** تفحص اللي يدخل أي run واللي يطلع منه (ومعاملات الـ tool calls)، و**patch checks** فحوص fail-closed على تغيير مقترح قبل ما تتصرّف عليه، و**sandboxed tools** تشتغل داخل container معزولة بدل عملية الـ host. للقرارات البشرية على كل call شوف [Approvals](/ar/approvals)؛ وللـ hooks اللي تفحص أو ترفض كل tool call شوف [Hooks](/ar/hooks).

## Input و output guardrails

`createAgent({ guardrails })` (أو `ExecuteOptions.guardrails`) يفحص الـ run في ثلاث نقاط، وكل قائمة تشتغل بالترتيب:

| القائمة | تفحص | متى |
| ---- | ------- | ---- |
| `input` | كل رسالة مستخدم جديدة (رسائل المستخدم اللي تنهي سجل المحادثة) | قبل أول model call. لو انحجب، ما يصير model call أصلاً. أما input guardrail عليه `runInParallel` فيشتغل وأول model call شغّال (شوف تحت). |
| `output` | نص الـ assistant النهائي؛ وفي run من نوع `stream()` (اللي تلفّ عليه بـ loop)، نص كل step. `send()` مع listener يفحص النص النهائي فقط. | قبل ما يطلع: قبل `text.done` حقّه، وقبل `run.done`. |
| `tools` | معاملات الـ tool call (`text` هي المعاملات بصيغة JSON، و`args` الكائن) | بعد [قواعد الصلاحيات](/ar/approvals#سياسات-الصلاحيات) (يتخطّى الفحص لو قاعدة رفضت الـ call) وقبل `needsApproval`. |

**الـ input guardrails المتوازية.** فحص input بطيء (واحد يستدعي model، مثل `moderationGuardrail({ model })`) يضيف كل زمن الاستجابة حقّه قبل ما الـ agent يبدأ يرد. علّمه بـ `runInParallel: true` (على `IoGuardrail` تبعك، أو كخيار في `promptInjectionGuardrail` و`moderationGuardrail`) فيشتغل وأول model call شغّال: الـ input guardrails الحاجبة (الوضع الافتراضي) تشتغل أول، بما فيها الـ rewrites، بعدين الفحوص المتوازية تبدأ مع بعض على نفس الـ input والـ model call يبدأ فورًا. إلى ما تعدّي كل الفحوص المتوازية، ما يطلع أي شي أنتجه الـ call: أحداث `text.delta` و`reasoning.*` وأحداث الـ tools اللي ينفّذها الـ provider تنحجز بالترتيب (`step.start` ما ينحجز)، والـ tool calls ما تنفّذ؛ وردّ وصل بدري ينتظر الفحوص. لو عدّت، الأحداث المحجوزة تطلع والـ run يكمل تمامًا مثل وضع الـ guardrails الحاجبة. لو واحد منها حجب، يُلغى الـ model call، الأحداث المحجوزة تُرمى، ولا شي من الـ call يوصل لسجل المحادثة أو checkpoint أو `onLLMResponse`، والـ run ينتهي بـ `finishReason: 'guardrail'` و`guardrail.tripped` (أو `GuardrailError` مع `onTripped: 'throw'`) مثل أي حظر عادي. الفحص المتوازي ما يقدر يعمل rewrite، لأن الـ model وصله الـ input خلاص: نتيجة `rewrite` تحجب، والسبب يبدأ بـ `runInParallel guardrails cannot rewrite: `. الثمن هو التكلفة: call محجوب ممكن يكون صرف tokens قبل الحظر. تنحسب في `result.usage` لو الـ provider بلّغ عنها (call خلّص قبل الـ trip)؛ أما stream ملغي فعادة ما يبلّغ عنها، وما نقدّرها بأنفسنا. بس أول model call في الـ run هو اللي يتسابق، والـ run اللي يستأنف بعد approval (موافقة) ما يعيد فحص الـ input. وفي guardrails من نوع `output` و`tools`، `runInParallel` يتجاهَل. نص `model` في الـ guardrail هو spec بصيغة `provider/model`: بادئة `vendor/` تختار الـ provider؛ ومع OpenRouter استخدم `openrouter/<vendor>/<model>` (مثال `openrouter/openai/gpt-4o-mini`).

```ts
import { createAgent, moderationGuardrail, piiGuardrail } from '@lousho/build-ai-agent';

const agent = createAgent({
  provider,
  guardrails: {
    // The PII check is instant and may rewrite, so it blocks; the moderation call runs alongside the agent's.
    input: [piiGuardrail({ action: 'rewrite' }), moderationGuardrail({ model: 'openai/gpt-4o-mini', runInParallel: true })],
  },
});
```

الـ guardrail هو `{ name, check(ctx) }`. في `ctx`: `kind` (`'input'` أو `'output'` أو `'tool'`)، و`text`، و`messages` حق الـ run، و`toolName` و`args` لما يكون tool call، و`signal` حق الـ run. ترجع `check` (مباشرة أو عبر promise) `{ ok: true }` أو `{ ok: false, reason, action?, replacement?, info? }`:

- `action: 'block'` (الافتراضي) ينهي الـ run بـ `finishReason: 'guardrail'` و`result.guardrail` (`{ name, kind, reason, toolName?, info? }`). `result.text` تكون `''` والرد المحجوب ما ينضاف لسجل المحادثة؛ والـ tool call المحجوب ما ينفّذ (ولا اللي بعده في نفس الدورة) وياخد نتيجة "cancelled"، عشان سجل المحادثة يبقى صالح. `stream()` يطلق `guardrail.tripped` قبل `run.done`.
- `action: 'rewrite'` يحط `replacement` مكان النص (وفي معاملات tool call: `replacement` هي المعاملات الجديدة بصيغة JSON)، والـ guardrail اللي بعده يشوف النص الجديد، و`stream()` يطلق `guardrail.rewrote`.

مع `onTripped: 'throw'` الحظر يرفض بـ `GuardrailError` (`LOUSHO_GUARDRAIL_TRIPPED`، ومعه نفس الـ `guardrail`) بدل ما ينتهي عادي. ولو `check` رمت، الـ run يفشل. الـ sub-agents تشغّل guardrails الأب أول، بعدين guardrails هم. ملفات spec حق الـ agent تسمّي الـ guardrails المدمجة في `policy.guardrails` (شوف [الإعداد](/ar/configuration#السياسة-policy)).

```ts
import {
  createAgent,
  denyTopicsGuardrail,
  GuardrailError,
  llmJudgeGuardrail,
  maxLengthGuardrail,
  regexGuardrail,
  type IoGuardrail,
} from '@lousho/build-ai-agent';

const noProdWrites: IoGuardrail = {
  name: 'no-prod-writes',
  check: ({ toolName, args }) =>
    toolName === 'run_sql' && String(args?.db) === 'prod' ? { ok: false, reason: 'prod is read-only' } : { ok: true },
};

const agent = createAgent({
  provider,
  guardrails: {
    input: [maxLengthGuardrail({ maxChars: 4_000 }), denyTopicsGuardrail({ topics: ['medical advice'] })],
    output: [
      regexGuardrail({ name: 'secrets', action: 'rewrite' }),
      llmJudgeGuardrail({ model: 'openai/gpt-4o-mini', instruction: 'Replies must stay on the topic of cooking.' }),
    ],
    tools: [noProdWrites],
  },
});

const result = await agent.send('What should I cook tonight?');
if (result.finishReason === 'guardrail') {
  console.warn(`Blocked by ${result.guardrail?.name} (${result.guardrail?.kind}): ${result.guardrail?.reason}`);
}

try {
  await createAgent({ provider, guardrails: { input: [maxLengthGuardrail({ maxChars: 10 })], onTripped: 'throw' } }).send('A long question');
} catch (error) {
  if (error instanceof GuardrailError) console.error(error.guardrail);
}
```

| المدمج | يفشل لما |
| -------- | ---------- |
| `maxLengthGuardrail({ maxChars })` | النص أطول من `maxChars` حرف. |
| `regexGuardrail({ name, pattern?, action?, replacement? })` | النص يطابق `pattern` (`RegExp` أو قائمة؛ الافتراضي: أنماط `secretScanCheck`). مع `action: 'rewrite'` كل تطابق يصير `replacement` (الافتراضي `'[redacted]'`). |
| `denyTopicsGuardrail({ topics })` | النص فيه واحد من `topics` (كلمات مفتاحية، ما يهم حالة الأحرف). |
| `llmJudgeGuardrail({ model, instruction, name? })` | `model` (`LLMProvider` أو `"provider/model"`)، يُسأل مرة لكل فحص إذا النص يلتزم بـ `instruction`، وما يرد `PASS`؛ ردّه `FAIL: <reason>` هو السبب. |
| `piiGuardrail({ types?, action?, name? })` | النص فيه بيانات شخصية من أحد `types` (الافتراضي الكل): `email`، `phone` (من 9 إلى 15 رقم، رمز دولة `+` وفواصل اختيارية)، `credit-card` (لازم يعدّي فحص Luhn)، `iban` (لازم يعدّي فحص mod-97)، `us-ssn` (صيغة `123-45-6789`)، `ip-address` (IPv4). يحجب افتراضي؛ `action: 'rewrite'` يستبدل كل تطابق بـ `[<type>]`، مثل `[email]`. فحص heuristic، بدون model call. |
| `secretsGuardrail({ action?, extraPatterns?, name? })` | النص فيه private key، أو مفتاح Anthropic (`sk-ant-`) أو OpenRouter (`sk-or-v1-`) أو OpenAI (`sk-proj-`، `sk-`) أو AWS (`AKIA`) أو GitHub (`ghp_` وباقي بادئات `gh?_`، و`github_pat_`) أو Slack (`xoxb-` ونحوه) أو Google (`AIza`) أو مفتاح Stripe live (`sk_live_`، `rk_live_`)، أو JWT، أو `Authorization: Bearer` token، أو تطابق مع `extraPatterns`. يستبدل كل تطابق بـ `[secret]` افتراضي؛ `action: 'block'` يحجب. heuristic، بدون model call. |
| `promptInjectionGuardrail({ model?, name?, runInParallel? })` | في النص إشارة prompt injection: "ignore (all) previous instructions" ونحوها، أو "you are now"، أو طلب الـ system prompt، أو علامة دور من chat template (`<\|im_start\|>`، `### System:`، `[INST]`)، أو عبارة jailbreak معروفة، أو أحرف Unicode tag الخفية (من U+E0000 إلى U+E007F). مع `model`، النص اللي يعدّي الأنماط يروح بعد للـ model، ولازم يرد `SAFE` أو `INJECTION: <reason>`. يحجب فقط. |
| `moderationGuardrail({ model, categories?, name?, runInParallel? })` | `model`، يُسأل مرة لكل فحص بـ prompt ثابت، يعدّ واحدة من `categories` منطبقة (الافتراضي الكل: `hate`، `harassment`، `self-harm`، `sexual`، `sexual-minors`، `violence`، `illicit`)؛ يرد `NONE` أو الفئات. prompt عادي مو moderation endpoint تبع vendor، فبيشتغل مع أي provider. يحجب فقط. ومع `runInParallel: true` (موجودة كمان في `promptInjectionGuardrail`) فحص الـ input يشتغل جنب أول model call. |

الأربعة الأخيرة starter set للفحوص اللي أغلب الـ agents في الإنتاج يحتاجونها:

```ts
import { createAgent, piiGuardrail, promptInjectionGuardrail, secretsGuardrail } from '@lousho/build-ai-agent';

const agent = createAgent({
  provider,
  guardrails: {
    input: [promptInjectionGuardrail(), piiGuardrail({ action: 'rewrite' })],
    output: [secretsGuardrail()],
  },
});

const result = await agent.send('My card is 4111 1111 1111 1111, can you check my order?');
// The model sees "My card is [credit-card], can you check my order?"
if (result.guardrail?.info?.category === 'prompt-injection') console.warn(result.guardrail.info.signals);
```

**أي guardrail تفعّل، بدون النص.** أي حظر (`result.guardrail`، `guardrail.tripped`، `guardrail.rewrote`، `GuardrailError.guardrail`) يحمل `info` — `GuardrailTripInfo` لو الـ guardrail وفّره، والـ starter set توفّره دائمًا: `{ category: 'pii', matches: [{ type, start, end }] }` أو `{ category: 'secret', matches: [{ label, start, end }] }` أو `{ category: 'prompt-injection', source: 'heuristic' | 'model', signals }` أو `{ category: 'moderation', categories }`. الإزاحات تشير لمواضع في النص المفحوص (`ctx.text`). `info` ما يحوي النص المطابق أبد، ولا `reason` في فحصَي PII والأسرار (أنواع وتسميات فقط)، فالأحداث والـ traces والـ logs ما تنسخ البيانات الشخصية ولا السر. والـ guardrail تبعك يقدر يرجّع `info: { category: 'custom', ...anything }`.

**الحدود.** فحوص PII والأسرار وprompt injection فحوص أنماط heuristic: تلقط الصيغ الشائعة اللي فوق وتفوّت غيرها (بيانات شخصية بصيغ أو لغات ثانية، سر ببادئة غير معروفة، injection معاد صياغته أو مترجم أو مرمّز)، وتعلّم بعض النصوص البريئة كمان (رقم طلب شكله رقم هاتف، نسخة شكلها IP address، مستخدم يسأل عن "system prompts"). عاملها filter أول، مو حد أمني؛ خلّي صلاحيات الـ tools والـ approvals شغّالة لأي شي يهمك. الفحوص اللي تعتمد على model موثوقيتها بقدر موثوقية الـ model، وتكلّف call واحد لكل نص مفحوص، وتفشل fail-closed: رد ما هو بأي صيغة من الصيغتين ينحجب، مع سبب يقول إن الرد ما انقرأ. نتائج الـ tools (مثل صفحة ويب منجلبة فيها injection غير مباشر) ما يفحصها أي guardrail لحد الآن.

## Patch checks

`runPatchChecks(patch, checks)` يشغّل كل الفحوص بالتوازي على patch مقترح ويجمع النتائج في verdict واحد. [مثال ops-pipeline](https://github.com/LinuxDevil/agent-sdk/blob/main/examples/ops-pipeline) يستخدمه كبوابة على patch من agent إصلاح قبل ما ينفتح pull request:

```ts
import { runPatchChecks, secretScanCheck, createDiffSizeCheck, createCommandCheck } from '@lousho/build-ai-agent';

const verdict = await runPatchChecks(
  { diff: patch },
  [
    secretScanCheck,
    createDiffSizeCheck(500),
    createCommandCheck('test-run', repoPath, 'npm', ['test']),
  ],
);

if (!verdict.pass) {
  console.log(verdict.failures); // [{ name, reason }, ...] — never call the write-side tool
}
```

| فحص الـ patch | يفشل لما |
| --------- | ---------- |
| `secretScanCheck` | الـ diff فيه header لمفتاح خاص، أو مفتاح API بأسلوب OpenAI، أو AWS access key. |
| `createDiffSizeCheck(maxLines)` | الـ diff فيه أكثر من `maxLines` سطر. |
| `createCommandCheck(name, cwd, command, args, { timeoutMs? })` | الأمر يطلع بكود خروج غير صفري. لو الـ diff غير فارغ يتطبّق أول (`git apply`) على نسخة مؤقتة من `cwd`، والفحص يفشل لو ما انطبق بشكل سليم. |
| `createTestRunCheck(repoPath)`، `createLintCheck(repoPath)` | `npm test` / `npm run lint` يفشل (اختصارات لفحص الأمر). |

**Fail-closed.** فحص يرمي، أو ينرفض، أو ما يخلّص خلال مهلة الـ timeout (30 ثانية افتراضي)، أو يرجّع أي شي غير `pass: true` يُحسب فاشل: `runPatchCheckSafely(check, patch)` تغلّف كل واحد فيهم. فحص الأمر يقتل العملية لما تنطلق المهلة (على Windows، شجرة العمليات كلها). اكتب فحصك بشكل `{ name, check(patch) }` يرجّع `{ pass, reason? }`.

## Sandboxed tools

الـ tool تدخل بـ `requiresSandbox: true` ودالة `sandboxExecute(args, sandbox)`. بعدها الـ executor يستدعي `sandboxExecute` مع `SandboxAdapter` حق الـ run بدل ما يستدعي `execute`. `createAgent()` ما تاخذ `sandbox` لحد الآن، فالموضوع يمر عن طريق الـ executor.

#### متقدم: الـ executor API

```ts
import { AgentExecutor } from '@lousho/build-ai-agent/executor';
import { SubprocessSandbox } from '@lousho/build-ai-agent';

// Route a flagged tool (requiresSandbox + sandboxExecute) through a real,
// Docker-backed sandbox instead of the in-process NoopSandbox default
await AgentExecutor.execute({ agent, input, provider, toolRegistry, sandbox: new SubprocessSandbox() });
```

- `NoopSandbox` (الافتراضي) يشتغل على الـ host. مجرد بديل شكلي، ما فيه عزل.
- `SubprocessSandbox` ينفّذ كل أمر في Docker container جديدة، معزولة عن الشبكة وتنحذف تلقائي، وما يوصل فيها أي مجلد من الـ host إلا `cwd` اللي تمرّره. يحتاج Docker daemon شغّال والـ peer dependency الاختيارية `dockerode` (`npm install dockerode@^5.0.1`؛ تتحمّل أول استخدام). ولو الـ run انلغى (`run.abort()` أو `signal`) أو الأمر خلصت مهلته، الـ container تُقتل وتنحذف.
- نفّذ `SandboxAdapter` (`name`، `run(cmd, args, opts)`، `writeFile(path, content)`) لـ backend ثاني.

لو بتبني coding agent، `SandboxShell` يحط أداة الـ shell حق الـ workspace ورا نفس الـ adapter؛ شوف [أدوات مساحة العمل](/ar/workspace-tools#sandboxed-shell-sandboxshell).
