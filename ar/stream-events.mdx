الأحداث التي يُصدرها `agent.stream()`، وترتيبها وإصداراتها. لمعرفة كيفية استهلاك البث، راجع [البث](/ar/streaming).

## مخطط الأحداث (الإصدار 1)

لكل حدث هذه الحقول:

| الحقل       | النوع     | المعنى |
| ----------- | -------- | ------- |
| `type`      | string   | نوع الحدث (الجدول أدناه). استعمله لتضييق النوع في TypeScript. |
| `runId`     | string   | يعرّف التشغيل. وهو نفسه في كل أحداث استدعاء `stream()` واحد. |
| `seq`       | number   | `0` للحدث الأول، ثم `+1` لكل حدث، دون فجوات. |
| `timestamp` | string   | وقت إصدار الحدث بصيغة ISO 8601 (`2026-10-01T09:30:00.000Z`). |
| `v`         | `1`      | إصدار المخطط، ويُصدَّر باسم `AGENT_EVENT_SCHEMA_VERSION`. |
| `subagent`  | كائن، اختياري | يظهر فقط في أحداث تشغيل وكيل فرعي - راجع [الوكلاء الفرعيون](/ar/streaming#الوكلاء-الفرعيون). |

أنواع الأحداث وحقولها الإضافية:

| `type`               | حقول إضافية | متى يصدر |
| -------------------- | ------------ | ------- |
| `run.start`          | `agentName: string`, `agentId?: string` | أول حدث في كل تشغيل. |
| `step.start`         | `step: number` | تبدأ خطوة نموذج: استدعاء نموذج واحد مع استدعاءات الأدوات التي يطلبها. يبدأ عدّ `step` من 1 (والتشغيل المستأنف من نقطة حفظ يواصل العدّ). |

| `text.done`          | `text: string` | النص الكامل للخطوة: ناتج ضمّ أحداث `text.delta` الخاصة بها. فقط للخطوات التي فيها نص. |
| `reasoning.start`    | (لا شيء) | يبدأ النموذج الاستدلال في هذه الخطوة. فقط مع [الخيار `reasoning`](/ar/reasoning) (أو مع نموذج يستدل دائمًا). تتبعه أحداث `reasoning.delta` ثم `reasoning.done`، قبل أول `text.delta` أو `tool.start` في الخطوة. |
| `reasoning.delta`    | `text: string` | جزء من نص الاستدلال (أو من ملخّصه). لا يدخل أبدًا في `text.delta` ولا في `text` الخاص بـ `run.done`. |

| `tool.resume`        | `toolCallId`, `toolName`, `args: Record<string, unknown>` | يُنفَّذ الاستدعاء الذي بُتّ فيه ضمن [استكمال بعد موافقة](/ar/streaming#البث-بعد-الموافقة). صدر `tool.start` الخاص به عن التشغيل الذي توقف؛ فعامِله مثل `tool.start` عندما تتتبّع الاستدعاءات. |
| `tool.partial` | `toolCallId`, `toolName`, `output: unknown`, `index: number` | لقطة من مخرجات أداة قيد التشغيل: الأداة التي `execute` فيها دالة `async function*` تُبلغ بلقطة واحدة عند كل `yield` (انظر [بث النتائج الجزئية](/ar/tools#بث-النتائج-الجزئية)). كل لقطة كاملة وتحلّ محل السابقة؛ و`index` يعدّ لقطات الاستدعاء ابتداءً من 0. وآخر لقطة هي أيضًا `result` في `tool.done` للاستدعاء. وتُرمَّز `output` بصيغة JSON مثل `result`. ولا تصل اللقطات أبدًا إلى النموذج أو سجل المحادثة أو نقاط الحفظ أو التتبّعات. ولقطة الوكيل الفرعي تحمل `subagent`. |
| `tool.done`          | `toolCallId`, `toolName`, `result: unknown`, `durationMs: number`, `replacedByHook?: string`, `executedBy?: 'provider'` | عاد استدعاء أداة. `result` هي القيمة كما ستُرمَّز بصيغة JSON (`undefined` تصبح `null`، و`Date` تصبح سلسلة نصية). ويُحسب `durationMs` من `tool.start` / `tool.resume` الخاص به. ويسمّي `replacedByHook` [الخطّاف](/ar/hooks) الذي حلّت نتيجته `{ result }` محلّ نتيجة الأداة (أو قامت مقامها). واستدعاء [أداة مستضافة](/ar/hosted-tools) يحمل `executedBy: 'provider'` ولا تتجاوز `result` فيه 20,000 محرفًا من JSON. |
| `todo.updated`       | `todos: Todo[]`, `counts: { pending, in_progress, completed, total }`, `toolCallId: string` | استدعاء `todo_write` ناجح من [أدوات قائمة المهام](/ar/tools#أدوات-قائمة-المهام) استبدل القائمة، مباشرة بعد `tool.done` لذلك الاستدعاء. `todos` هي القائمة الجديدة كاملة (`{ id, content, status }`)، و`toolCallId` هو استدعاء `todo_write`. وحدث الوكيل الفرعي يحمل `subagent`. وتحتفظ [روابط واجهات المستخدم](/ar/react#المهام) بالقائمة وتعرضها مباشرة. |

### ضمانات الترتيب

- `run.start` هو الأول و`run.done` هو الأخير، كل منهما مرة واحدة بالضبط.
- يتبع كل `step.start` حدث `step.done` واحد بالضبط له `step` نفسها، قبل `step.start` التالي. وكل ما تفعله الخطوة يقع بينهما. غير أن بعض الأحداث لا يقع داخل خطوة: فـ `agent.drift`، و`guardrail.tripped` الخاص بحاجز المدخلات، وأحداث الاستدعاء الذي بُتّ فيه ضمن استكمال موافقة مبثوث (أدناه)، كلها تأتي قبل أول `step.start` أو بين اثنين منها، و`context.cleared` يذهب إلى `session.on()` لا إلى تشغيل.
- داخل الخطوة: `compaction.start` / `compaction.done` (إذا ضُغط الطلب، قبل استدعاء النموذج)، ثم أحداث `provider.retry` / `provider.fallback` (إذا فشل استدعاء النموذج)، ثم أحداث `text.delta`، ثم `text.done`، ثم أحداث الأدوات.
- تعمل استدعاءات الأدوات في الخطوة الواحدة بالتوازي (راجع `toolConcurrency`): تأتي أحداث `tool.start` بترتيب استدعاءات النموذج، وأحداث `tool.done` / `tool.error` بترتيب الاكتمال. طابِقها بـ `toolCallId`.
- استدعاءات `run_code` الداخلية ([وضع الشيفرة](/ar/code-mode)) تبدأ وتنتهي بين `tool.start` الخاص بها و`tool.done` / `tool.error` الخاص بها.
- أحداث `tool.partial` للاستدعاء تأتي بين `tool.start` و`tool.done` / `tool.error` الخاصين به، مع `index` يساوي 0 ثم 1 ثم 2 ...؛ وتتداخل أحداث الاستدعاءات المتوازية. والاستدعاء الذي يتوقف بانتظار تسجيل دخول أو موافقة لا يكون له `tool.done`؛ بل يُنفَّذ من جديد من البداية حين يُبتّ فيه، ويُبلَّغ عنه بـ `tool.resume` (لا `tool.start` ثانيًا) و`index` يبدأ من 0.
- يأتي `input.queued` عند استدعاء `run.enqueue()` (بعد `run.start`، حتى للمُدخَل الذي وُضع في قائمة الانتظار قبل أن ينطلق التشغيل)، فقد يقع داخل خطوة. ويأتي `input.applied` الخاص به بين `step.done` للخطوة التي كانت جارية و`step.start` التالي، الذي يحمل الخطوة `step` التي سمّاها.
- يأتي `input.steered` عند استدعاء `run.steer()`. ومع `mode: 'immediate'` تنتهي الخطوة الجارية بعده بـ `step.done` (`'steered'`، دون أحداث نص من استدعائها الملغى)، ثم `input.applied` و`step.start` التالي.
- حين يحتاج استدعاء إلى موافقة، تُنفَّذ الاستدعاءات التي قبله وتُبلَّغ نتائجها، ثم يأتي `approval.requested` و`step.done` (`'awaiting-approval'`) و`run.done` (`'awaiting-approval'`). والاستدعاءات التي بعده لا تبدأ أبدًا. والتشغيل الذي يُستكمَل بثًّا (`agent.approvals.streamResolve()` / `streamAnswer()`، راجع [البث بعد موافقة](/ar/streaming#البث-بعد-الموافقة)) بثٌّ جديد: يُبلغ عن `run.start` الخاص به، ثم `agent.drift` عندما يكون الوكيل قد تغيّر، ثم `tool.resume` و`tool.done` للاستدعاء الذي بُتّ فيه (و`tool.error` عند الرفض) قبل أول `step.start` له — فيرى المستهلِك الذي يتابع البثّين `tool.start` لذلك الاستدعاء مرة واحدة، في التشغيل الذي توقف.
- حين يمنع حاجز حماية، يأتي `guardrail.tripped` قبل النهاية مباشرة: في حاجز المدخلات بعد `run.start` مباشرة (ولا تبدأ أي خطوة)؛ وفي حاجز المخرجات أو الأدوات داخل الخطوة، ويتبعه `step.done` و`run.done` (`'guardrail'`). والمخرجات الممنوعة لا يكون لها `text.done`؛ والاستدعاءات التي بعد استدعاء أداة ممنوع لا تبدأ أبدًا.

تشغيل نصي فقط:

```
run.start → step.start → text.delta × n → text.done → step.done → run.done
```

تشغيل فيه استدعاء أداة واحد:

```
run.start
step.start(1) → tool.start → tool.done → step.done(1, 'tool_calls')
step.start(2) → text.delta × n → text.done → step.done(2, 'stop')
run.done('stop')
```

### TypeScript

`AgentEvent` اتحاد مميَّز (discriminated union): وتضييق النوع بـ `event.type` يعطيك الحمولة. وكل نوع حدث مُصدَّر أيضًا (`TextDeltaEvent` و`ToolDoneEvent` و`RunDoneEvent` ...)، ويختار `AgentEventOf<'tool.done'>` واحدًا منها بالاسم.

```ts
import { isAgentEvent, isToolEvent, type AgentEvent } from '@lousho/build-ai-agent';

function render(event: AgentEvent): string {
  switch (event.type) {
    case 'text.delta':
      return event.text;
    case 'tool.start':
      return `\n[${event.toolName}] ${JSON.stringify(event.args)}\n`;
    case 'tool.error':
      return `\n[${event.toolName} failed: ${event.error.message}]\n`;
    case 'run.done':
      return `\n(${event.finishReason})\n`;
    default:
      return '';
  }
}

// isToolEvent / isTextEvent / isStepEvent narrow to an event family:
const toolNames = (events: AgentEvent[]) => events.filter(isToolEvent).map((e) => e.toolName);

// isAgentEvent validates an event received over the wire:
const received: unknown = JSON.parse('{"type":"run.start","runId":"r","seq":0,"timestamp":"","v":1,"agentName":"a"}');
if (isAgentEvent(received)) console.log(render(received), toolNames([received]));
```

### الإصدارات

لا يتغير `v` إلا عندما يتغير حدث قائم تغييرًا غير متوافق (حقل أُزيل أو أُعيدت تسميته أو تغيّر نوعه). ويمكن إضافة أنواع أحداث جديدة وحقول اختيارية جديدة دون تغيير `v`، فتجاهل أنواع الأحداث التي لا تعرفها.
