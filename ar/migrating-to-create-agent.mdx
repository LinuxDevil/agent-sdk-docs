هذه الصفحة للكود الذي يستخدم `AgentBuilder` و`AgentExecutor` و`ToolRegistry` و`resumeAfterApproval()`: الـ API الأدنى مستوى الذي بدأ به الـ SDK. هذه الـ exports انتقلت إلى `@lousho/build-ai-agent/executor` ولن تُحذف. إذا بقيت عليها، راجع [واجهة الـ executor](/ar/executor-api). سبب الانتقال أن استدعاء `createAgent()` واحد يربط الـ tools والـ stores والـ approvals (موافقات) والـ sessions (جلسات) والـ retries (إعادة المحاولة) والـ compaction (ضغط سياق المحادثة)، بينما الـ executor يجعلك تجمع كل واحد منها بنفسك وتمرره في كل استدعاء.

ما يزال `createAgent()` لا يقبل كل الخيارات التي يقبلها الـ executor. راجع [ما لا يقبله createAgent() حتى الآن](#ما-لا-يقبله-createagent-حتى-الآن) قبل أن تبدأ.

## قبل وبعد

agent واحد مع tool يتطلب approval: أولًا بـ executor API، ثم بـ `createAgent()`. كلاهما يستخدم model بردود جاهزة مسبقًا، فيعملان دون اتصال وينتهيان بنفس النص `Sent the report to Sam.` بعد نفس التوقف.

```ts
import {
  AgentBuilder,
  AgentExecutor,
  ToolRegistry,
  resumeAfterApproval,
} from '@lousho/build-ai-agent/executor';
import { InMemoryApprovalStore, defineTool } from '@lousho/build-ai-agent';
import { mockModel } from '@lousho/build-ai-agent/testing';
import { z } from 'zod';

const sendEmail = defineTool({
  name: 'send_email',
  description: 'Send an email',
  input: z.object({ to: z.string() }),
  needsApproval: true,
  execute: async ({ to }) => `sent to ${to}`,
});

const provider = mockModel([
  { toolCalls: [{ name: 'send_email', args: { to: 'sam@example.com' } }] },
  'Sent the report to Sam.',
]);

// Before: the agent, the tool registry, the approval store and the provider are
// separate objects, and the resume call needs all of them again.
const agent = AgentBuilder.create().setName('Mailer').setPrompt('You send emails.').addTool(sendEmail).build();
const toolRegistry = new ToolRegistry();
toolRegistry.register(sendEmail);
const approvalStore = new InMemoryApprovalStore();

const paused = await AgentExecutor.execute({
  agent,
  input: 'Email the report to Sam',
  provider,
  toolRegistry,
  approvalStore,
});
console.log(paused.finishReason); // 'awaiting-approval'

const result = await resumeAfterApproval(
  { id: paused.approvalId!, approved: true },
  approvalStore,
  toolRegistry,
  provider,
);
console.log(result.text); // 'Sent the report to Sam.'
```

```ts
import { createAgent, defineTool } from '@lousho/build-ai-agent';
import { mockModel } from '@lousho/build-ai-agent/testing';
import { z } from 'zod';

const sendEmail = defineTool({
  name: 'send_email',
  description: 'Send an email',
  input: z.object({ to: z.string() }),
  needsApproval: true,
  execute: async ({ to }) => `sent to ${to}`,
});

// After: the same scripted model gives the same result as the snippet above.
const mailer = createAgent({
  provider: mockModel([
    { toolCalls: [{ name: 'send_email', args: { to: 'sam@example.com' } }] },
    'Sent the report to Sam.',
  ]),
  instructions: 'You send emails.',
  tools: [sendEmail],
});

const paused = await mailer.send('Email the report to Sam');
console.log(paused.finishReason); // 'awaiting-approval'

const result = await mailer.approvals.resolve({ id: paused.approvalId!, approved: true });
console.log(result.text); // 'Sent the report to Sam.'
```

الـ tool هو ناتج `defineTool()` نفسه في الحالتين. الـ agent يحتفظ بالـ registry والـ approval store والـ provider الخاصة به، فيكفي معرّف الـ approval لاستكمال التوقف.

## Mapping

| القديم | `createAgent()` |
| ------ | --------------- |
| `AgentBuilder.create().setName(n).setPrompt(p).build()` | `createAgent({ name, instructions })` (`prompt` اسم بديل لـ`instructions`). |
| `addTool(key, config)` في الـ builder، مع `ToolRegistry.register(tool)` | `tools: [defineTool(...)]`. لا يوجد registry تبنيه؛ راجع [Tools](/ar/tools). |
| `AgentExecutor.execute({ agent, input, provider })` | `agent.send(message)`. الـ model تحدده بـ`model` (سلسلة بصيغة `provider/model`) أو `provider`. |
| `AgentExecutor.stream(...)` | `agent.stream(message)`؛ راجع [Streaming](/ar/streaming). |
| `onAgentEvent` | `onEvent` في `createAgent()`؛ و`stream()` يعطي نفس الأحداث. |
| `onEvent` مع `ExecutionEvent` (deprecated) | `AgentEvent` listeners؛ راجع [الانتقال من `onEvent` / `ExecutionEvent`](/ar/streaming#الانتقال-من-onevent-executionevent). |
| `sessionId` + `checkpointStore` | `store` في `createAgent()` و`agent.send(message, { sessionId })`؛ واستأنف run انقطع بـ`agent.resume(sessionId)`. راجع [Durable execution](/ar/durable-execution). |
| `approvalStore` | `approvalStore`، أو `store` مع `approvals`. وبدون أي منهما، `InMemoryApprovalStore` خاص بكل agent. |
| `resumeAfterApproval(decision, store, registry, provider)` | `agent.approvals.resolve({ id, approved, note? })`؛ و`agent.approvals.answer()` للرد على سؤال. راجع [Approvals](/ar/approvals). |
| `streamResumeAfterApproval(...)` | `agent.approvals.streamResolve(...)` و`streamAnswer(...)`. |
| `AgentExecutor.fork(...)` | `agent.fork(sessionId, { fromStep, patch })`. |
| `hooks: HookRegistry` | `hooks: AgentHook[]`. |
| `signal` | `agent.send(message, { signal })`. |
| `maxSteps` و`limits` و`guardrails` و`toolConcurrency` و`onAgentDrift` و`reasoning` و`output` | نفس الأسماء في `createAgent()`؛ ويمكن تعيين `reasoning` لكل `send()` أيضًا. |
| `exporter` و`captureContent` و`redactContent` | نفس الأسماء في `createAgent()`. |
| `skills` و`subagents` | نفس الأسماء في `createAgent()`، الذي يقبل أيضًا `mcpServers` و`memory`. |
| `inputQueue` | `run.enqueue()` في run مع streaming، أو `agent.session({ turnPolicy })`؛ راجع [Queued input](/ar/queue-and-steer#queued-input). |
| `sessionBudget` | `agent.session({ id, limits })`؛ راجع [Sessions](/ar/sessions). |

## ما لا يقبله createAgent() حتى الآن

هذه خيارات `ExecuteOptions` ليس لها خيار مقابل في `createAgent()`. إذا وُجد بديل مدعوم فهو مذكور؛ وإلا فأبقِ ذلك الاستدعاء على `AgentExecutor.execute()`.

| خيار الـ executor | البديل |
| --------------- | ----------- |
| `temperature` و`maxTokens` | لا يوجد: ابقَ على الـ executor. (`limits.maxTokens` ميزانية للـ run، وليس إعداد توليد.) |
| `sandbox` | لا يوجد: ابقَ على الـ executor. |
| `onLLMRequest` و`onLLMResponse` | `preGenerate` / `postGenerate` hook في `hooks`، أو `onEvent` listener. |
| `onToolCall` و`onToolResult` | `preToolCall` / `postToolCall` hook في `hooks`، أو `onEvent` listener. |
| `onRunEnd` | `onEvent` listener لحدث `run.done`، أو نتيجة `send()`. |
| `businessState` | لا يوجد: ابقَ على الـ executor. |

الـ run الواحد يستخدم إحدى الواجهتين فقط: agent يحتاج خيارًا من صفوف «لا يوجد» يترك ذلك الاستدعاء على الـ executor، ويستخدم `createAgent()` في باقي الكود.

## اختلافات السلوك

- `send()` هو turn واحد. المحادثة كائن مستقل هو `agent.session()`، يحتفظ بالـ transcript ويرسله مع كل turn؛ راجع [Sessions](/ar/sessions). الكود الذي كان يبني سجل الرسائل يدويًا ينتقل إلى session.
- الـ run الموقوف يرجع نتيجة، لا يعلق. الـ `send()` الذي يصل إلى tool عليه `needsApproval` يرجع بـ`finishReason: 'awaiting-approval'` ومعه `approvalId`، ولا يرمي خطأ. التوقف يبقى عند الـ agent، فيعرضه `agent.approvals.list()` ويكمله `resolve()` دون registry أو provider.
- الـ approval store الافتراضي خاص بكل agent ويعيش في الذاكرة. التوقف لا ينجو من restart إلا مع `store` أو `approvalStore` من نوع durable؛ راجع [اختيار الـ store](/ar/sessions#choosing-a-store).
- الـ retries مفعّلة افتراضيًا مع سلسلة `model`: محاولتان إضافيتان لاستدعاء model فاشل. الـ `provider` الذي تمرره لا يُغلَّف إلا إذا عيّنت `retry`. راجع [Provider retries and fallback](/ar/configuration#الـ-retry-والـ-fallback-عند-الـ-provider).

## الانتقال خطوة بخطوة

1. الـ tools أولًا. أبقِ الـ tools المعرفة بـ`defineTool()`، واحذف `ToolRegistry` وأي استدعاء `addTool(key, config)`، وعدّد الـ tools في `tools`.
2. استبدل `AgentBuilder` بـ`createAgent({ name, instructions, tools })`، ومرّر `model` أو الـ `provider` نفسه الذي كنت تمرره إلى `execute()`.
3. استبدل كل `AgentExecutor.execute()` بـ`agent.send()` وكل `stream()` بـ`agent.stream()`. انقل `maxSteps` و`limits` وبقية الخيارات المشتركة إلى `createAgent()`. إذا احتاج استدعاء إلى خيار من قائمة «حتى الآن» فاتركه على الـ executor.
4. استبدل `resumeAfterApproval()` بـ`agent.approvals.resolve()`. إذا كان يجب أن تبقى الـ approvals بعد انتهاء العملية، مرّر الـ store الذي استخدمته كـ`approvalStore`.
5. انقل `checkpointStore` و`sessionId` الخاص به إلى `store`، ومرّر `sessionId` إلى `send()`. واستخدم `agent.session()` بدل سجل الرسائل الذي كنت تحتفظ به بنفسك.
6. استبدل `onEvent` مع `ExecutionEvent` بـ`AgentEvent` listener، ثم انقل الـ hooks الموجودة في `HookRegistry` إلى `hooks`.
