الـtrigger adapter يحوّل آلية تنبيه واحدة إلى run للـagent: webhook وارد، ساعة، أو حدث من Slack. **`WebhookTriggerAdapter` و`SlackTriggerAdapter` و`CronTriggerAdapter` صارت deprecated** وستُحذف في إصدار major قادم: استخدم بدلها `webhookChannel()` و`slackChannel()` و`defineSchedule()` (كل قسم أدناه فيه مقتطف migration). أما `TriggerAdapter` و`TriggerRegistry` فهما نقطة التوسعة وليسا deprecated. استوردها من الـsubpath `@lousho/build-ai-agent/triggers`: `WebhookTriggerAdapter` و`SlackTriggerAdapter` و`CronTriggerAdapter` و`TriggerRegistry`. اربط أيًّا منها بـ`listen(agent, onEvent)`، حيث `onEvent` هي التي تشغّل الـagent، واستدعِ `stop()` على الـhandle الذي يرجعه `listen` لإيقاف الـadapter.

```ts
import { createAgent, createMockProvider } from '@lousho/build-ai-agent';
import { CronTriggerAdapter } from '@lousho/build-ai-agent/triggers';

const agent = createAgent({ prompt: 'You are helpful.', provider: createMockProvider() });

const cron = new CronTriggerAdapter({
  intervalMs: 60_000,
  input: 'Check the queue',
  onResult: (result, error) => console.log(error ?? result?.text),
});
const handle = cron.listen(agent, (input) => agent.send(input));

// Later, on shutdown: clear the timer (a webhook adapter closes its HTTP listener).
await handle.stop();
```

## الاختيار بين triggers وchannels وschedules

| | استخدمها من أجل | نقاط الدخول |
|---|---|---|
| Triggers | نقطة التوسعة لآلية التنبيه الخاصة بك. الـadapters الثلاثة الجاهزة deprecated. | `TriggerAdapter` و`TriggerRegistry` (deprecated: `WebhookTriggerAdapter` و`SlackTriggerAdapter` و`CronTriggerAdapter`) |
| [Channels](/ar/channels) | واجهة يتكلم معها الناس. كل محادثة ترتبط بـsession (جلسة)، والـapprovals (الموافقات) والأسئلة التي يتوقف عندها الـagent ترجع إلى الواجهة. | `defineChannel()` و`mountChannels()` و`httpChannel()` و`webhookChannel()` |
| [Schedules](/ar/schedules) | cron لمجلدات الـagents ولـnode server، مع دعم في الـdeployment targets. | `defineSchedule()` و`startSchedules()` |

كل adapter deprecated له بديل مربوط بالـsessions والـapprovals ومجلدات الـagents و`lousho build`: بديل Slack هو `slackChannel()`، وبديل webhooks هو `webhookChannel()` (وكلاهما تركّبه بـ`mountChannels()`)، وبديل cron هو `defineSchedule()` مع `startSchedules()`. الـadapters الـdeprecated تظل تعمل إلى أن تُحذف.

## واجهة TriggerAdapter

```text
interface TriggerAdapter<TChannel = unknown> {
  type: string;
  listen(
    agent: RunnableAgent, // { send(message: string): Promise<ExecutionResult> }
    onEvent: (input: string, context: TriggerContext) => Promise<ExecutionResult>
  ): TriggerHandle; // { stop(): Promise<void> | void }
  reply?(channel: TChannel, message: string): Promise<void>;
}
```

`listen` تأخذ `agent` و`onEvent` معًا بقصد. الـ`agent` هو الواجهة البسيطة: prompt يدخل ونص يطلع. والـ`onEvent` هي نقطة الدخول التي يناديها الـadapter عندما ينطلق الـtrigger: الـcaller البسيط يمرّر `(input) => agent.send(input)`، والـcaller الذي عنده checkpointing أو approval gates أو تحكم بالإلغاء يمرّر `onEvent` تغلّف هذا كله.

دلالات الرد تختلف بين adapter وآخر. الـwebhook يكتب النتيجة التي ترجعها كرد HTTP، فلا يحتاج `reply()`. والـcron لا ينتظره مستدعٍ، فيسلّم النتيجة إلى خيار `onResult`. أما Slack فينشر الجواب عبر `reply()`.

اكتب adapter خاص بك بإرجاع handle من `listen`:

```ts
import { createAgent, createMockProvider } from '@lousho/build-ai-agent';
import type { TriggerAdapter } from '@lousho/build-ai-agent/triggers';

const agent = createAgent({ prompt: 'You are helpful.', provider: createMockProvider() });

const everyTenSeconds: TriggerAdapter = {
  type: 'ten-seconds',
  listen(_agent, onEvent) {
    const timer = setInterval(() => void onEvent('tick', { firedAt: new Date() }), 10_000);
    return { stop: () => clearInterval(timer) };
  },
};

const handle = everyTenSeconds.listen(agent, (input) => agent.send(input));
handle.stop();
```

يحفظ `TriggerRegistry` الـadapters بالاسم: `register(name, adapter)` و`registerMany()` و`get()` و`has()` و`list()` و`getAll()` و`unregister()` و`clear()` و`size()`. و`globalTriggerRegistry` هو instance مشترك.

## Webhook

### مصادقة webhook

**Deprecated.** بدل `WebhookTriggerAdapter` صار `webhookChannel()` المُركَّب بـ`mountChannels()` (راجع [Channels](/ar/channels))، ويأخذ نفس خيار `auth` ويضيف sessions وapprovals. تبقى أشكال `WebhookAuth` أدناه وهي مرجع `webhookChannel({ auth })`.

```ts
import { createAgent, createMockProvider, mountChannels, webhookChannel } from '@lousho/build-ai-agent';

const agent = createAgent({ instructions: 'You are helpful.', provider: createMockProvider() });

// POST /webhook, authenticated with an HMAC of the raw body; serve it from any node server.
const handler = mountChannels(agent, [
  webhookChannel({ auth: { type: 'hmac', secret: process.env.WEBHOOK_SECRET ?? '' } }),
]);
```

`WebhookTriggerAdapter` يشغّل خادم HTTP. **اضبط `auth` دائمًا لأي webhook يمكن الوصول إليه من خارج جهازك**: بدونه، أي شخص يصل إلى الـport يستطيع تشغيل الـagent الخاص بك (وإنفاق الـtokens الخاصة بك). وإذا استمعت على host غير loopback بدون `auth`، يسجّل الـadapter تحذيرًا مرة واحدة عبر `options.logger`.

```ts
import { createAgent, createMockProvider } from '@lousho/build-ai-agent';
import { WebhookTriggerAdapter } from '@lousho/build-ai-agent/triggers';

const agent = createAgent({ prompt: 'You are helpful.', provider: createMockProvider() });

// HMAC of the RAW request body (GitHub / Shopify style): header `x-signature-256: sha256=<hex>`.
new WebhookTriggerAdapter({
  port: 8787,
  auth: { type: 'hmac', secret: process.env.WEBHOOK_SECRET ?? '' },
}).listen(agent, (input) => agent.send(input));

// Replay protection: the signed payload becomes `${timestamp}.${body}` and
// requests more than `toleranceSeconds` (default 300) old are rejected.
new WebhookTriggerAdapter({
  auth: {
    type: 'hmac',
    secret: process.env.WEBHOOK_SECRET ?? '',
    header: 'x-signature',
    timestampHeader: 'x-timestamp',
    toleranceSeconds: 120,
  },
});

// A shared bearer token (`Authorization: Bearer <token>`).
new WebhookTriggerAdapter({ auth: { type: 'bearer', token: process.env.WEBHOOK_TOKEN ?? '' } });

// Anything else: return true to accept. `rawBody` is a Buffer of the exact bytes received.
new WebhookTriggerAdapter({
  auth: { type: 'custom', verify: (req) => req.headers['x-api-key'] === process.env.API_KEY },
});
```

خيارات HMAC: `header` (الافتراضي `x-signature-256`)، `algorithm` (`sha256` أو `sha1`، الافتراضي `sha256`)، `prefix` (الافتراضي `sha256=`؛ `''` لـdigest مجرّد)، `timestampHeader` و`toleranceSeconds`. التواقيع وbearer tokens تُقارَن في زمن ثابت. والطلب الذي تفشل مصادقته يأخذ ردًّا عامًّا `401 {"error":"Unauthorized"}` — الرد لا يذكر أي فحص فشل — والسبب، دون أي سر أو توقيع، يُسجَّل بمستوى `warn`. قدّم الـwebhooks عبر HTTPS (أنهِ TLS أمام الـadapter) حتى لا تُرسَل الـtokens والـpayloads نصًّا صريحًا.

## Slack

### تواقيع طلبات Slack

**Deprecated.** بدل `SlackTriggerAdapter` صار `slackChannel()` المُركَّب بـ`mountChannels()` (راجع [Slack في Channels](/ar/channels#slack)): session واحدة لكل Slack thread، وأزرار approval، وفحص التوقيع مدمج. تبقى `verifySlackSignature()` وهي ليست deprecated.

```ts
import { createAgent, createMockProvider, mountChannels, slackChannel } from '@lousho/build-ai-agent';

const agent = createAgent({ instructions: 'You are helpful.', provider: createMockProvider() });

const handler = mountChannels(agent, [
  slackChannel({
    signingSecret: process.env.SLACK_SIGNING_SECRET ?? '',
    botToken: process.env.SLACK_BOT_TOKEN ?? '',
  }),
]);
```

`SlackTriggerAdapter.handleRequest({ headers, rawBody })` تعالج طلب Slack Events API خامًّا وترجع `{ status, body }` التي ترسلها جوابًا. **اضبط `signingSecret` لأي endpoint يمكن الوصول إليه من خارج جهازك**: بدونه، أي شخص يصل إلى الـendpoint يستطيع تشغيل الـagent الخاص بك، و`listen()` تسجّل تحذيرًا مرة واحدة عبر `options.logger`. ومعه، يُتحقَّق من كل طلب [كما يوثّقه Slack](https://docs.slack.dev/authentication/verifying-requests-from-slack) قبل تحليل الـbody: HMAC-SHA256 على `v0:{X-Slack-Request-Timestamp}:{raw body}`، يُقارَن في زمن ثابت مع `X-Slack-Signature` (`v0=<hex>`)، والطلبات الأقدم من خمس دقائق تُرفَض. حالات الفشل تأخذ `401 {"error":"Unauthorized"}` عامًّا؛ والسبب، دون أي سر أو توقيع، يُسجَّل بمستوى `warn`. ومصافحة `url_verification` الموقَّعة تُجاب بعد التحقق.

```ts
import { createAgent, createMockProvider } from '@lousho/build-ai-agent';
import { SlackTriggerAdapter, verifySlackSignature } from '@lousho/build-ai-agent/triggers';
import * as http from 'node:http';

const agent = createAgent({ prompt: 'You are helpful.', provider: createMockProvider() });
const slack = new SlackTriggerAdapter({ signingSecret: process.env.SLACK_SIGNING_SECRET });
slack.listen(agent, (input) => agent.send(input));

http
  .createServer((req, res) => {
    const chunks: Buffer[] = [];
    req.on('data', (chunk: Buffer) => chunks.push(chunk));
    req.on('end', async () => {
      const { status, body } = await slack.handleRequest({ headers: req.headers, rawBody: Buffer.concat(chunks) });
      res.writeHead(status, { 'Content-Type': 'application/json' }).end(JSON.stringify(body));
    });
  })
  .listen(3000);

// Your own handler (slash commands, interactivity)? Verify the RAW body yourself:
const authentic = verifySlackSignature({
  signingSecret: process.env.SLACK_SIGNING_SECRET ?? '',
  timestamp: '1700000000', // the X-Slack-Request-Timestamp header
  signature: 'v0=...', // the X-Slack-Signature header
  rawBody: '{"type":"url_verification"}',
});
```

`handleRequest` ترد على Slack بعد انتهاء الـagent؛ وSlack تتوقع ردًّا خلال ثلاث ثوانٍ، فإذا كان الـagent بطيئًا فأرسل acknowledge أولًا وشغّل الـagent في الخلفية.

## Cron

### جداول cron

**Deprecated.** بدل `CronTriggerAdapter` صار `defineSchedule()` مع `startSchedules()` (راجع [Schedules](/ar/schedules))، ويعمل أيضًا من `schedules/` في مجلد الـagent ومن الـcron triggers في ملف الـspec. ويبقى `parseCronExpression()` و`CronExpressionError`. الـschedules ليس فيها `intervalMs`: اكتب تعبير cron المكافئ (`*/5 * * * *` لكل خمس دقائق)، أو أبقِ `setInterval` تنادي `agent.send()`.

```ts
import { createAgent, createMockProvider, defineSchedule, startSchedules } from '@lousho/build-ai-agent';

const agent = createAgent({ instructions: 'You are helpful.', provider: createMockProvider() });

const queue = defineSchedule({
  cron: '*/15 9-17 * * MON-FRI',
  timezone: 'Europe/Paris',
  prompt: 'Check the support queue',
});
const running = startSchedules(agent, [queue]);
// later, on shutdown:
running.stop();
```

تأخذ `CronTriggerAdapter` إما `intervalMs` ثابتة أو تعبير cron حقيقيًّا:

```ts
import { createAgent, createMockProvider } from '@lousho/build-ai-agent';
import { CronTriggerAdapter } from '@lousho/build-ai-agent/triggers';

const agent = createAgent({ prompt: 'You are helpful.', provider: createMockProvider() });

new CronTriggerAdapter({
  cron: '*/15 9-17 * * MON-FRI', // minute hour day-of-month month day-of-week
  timezone: 'Europe/Paris', // IANA name; defaults to the machine's local zone
  input: 'Check the support queue',
  onResult: (result, error) => console.log(error ?? result?.text),
}).listen(agent, (input) => agent.send(input));
```

الصياغة المدعومة: `*`، القوائم (`1,15`)، النطاقات (`1-5`)، الخطوات (`*/15` و`10-40/10`)، أسماء الأشهر (`JAN`) وأسماء أيام الأسبوع (`MON`)، و`0` و`7` كلاهما يعني الأحد. وفيها أيضًا اختصارات `@hourly` و`@daily` (أو `@midnight`) و`@weekly` و`@monthly` و`@yearly` (أو `@annually`). وكما في cron الكلاسيكي، إذا قيّدت يوم الشهر ويوم الأسبوع معًا فاليوم يطابق إن طابق أحدهما. التعبير غير الصالح يرمي `CronExpressionError` يذكر الحقل ويعرض مثالًا صالحًا. و`parseCronExpression(expr, timezone).nextRun(after)` مُصدَّرة إذا احتجت وقت الإطلاق التالي.

حول تغيّر التوقيت الصيفي، الوقت الذي لا يوجد (عند تقديم الساعة) يُتخطّى في ذلك اليوم، والوقت الذي يحدث مرتين (عند إرجاع الساعة) يُطلَق مرة واحدة؛ والجدول الذي يعمل كل ساعة يستمر يُطلَق كل ساعة. والـtimer يُعاد ضبطه بعد كل run انطلاقًا من الوقت المجدول (بلا drift وبلا إطلاق مزدوج)، و`stop()` تمسحه.
