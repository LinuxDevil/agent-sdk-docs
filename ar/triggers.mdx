الـtrigger adapter يحوّل آلية تنبيه واحدة إلى run للـagent. الـsubpath `lousho/triggers` هو نقطة التوسعة لآليتك الخاصة (`TriggerAdapter` و`TriggerRegistry`)، ومعه بعض الأدوات المساعدة المشتركة مع الـchannels والـschedules: أشكال `WebhookAuth` و`verifySlackSignature()` و`parseCronExpression()`. أما الـadapters الجاهزة للـwebhook وSlack وcron فقد حُذفت؛ راجع [الانتقال من triggers](/ar/upgrading#الانتقال-من-الـ-triggers).

## الاختيار بين triggers وchannels وschedules

| | استخدمها من أجل | نقاط الدخول |
|---|---|---|
| Triggers | نقطة التوسعة لآلية التنبيه الخاصة بك. | `TriggerAdapter` و`TriggerRegistry` |
| [Channels](/ar/channels) | واجهة يتكلم معها الناس. كل محادثة ترتبط بـsession (جلسة)، والـapprovals (الموافقات) والأسئلة التي يتوقف عندها الـagent ترجع إلى الواجهة. | `defineChannel()` و`mountChannels()` و`httpChannel()` و`webhookChannel()` و`slackChannel()` |
| [Schedules](/ar/schedules) | cron لمجلدات الـagents ولـnode server، مع دعم في الـdeployment targets. | `defineSchedule()` و`startSchedules()` |

## واجهة TriggerAdapter

```text
interface TriggerAdapter<TChannel = unknown> {
  type: string;
  listen(
    agent: RunnableAgent, // { send(message: string): Promise<ExecutionResult> }
    onEvent: (input: string, context: TriggerContext) => Promise<ExecutionResult>
  ): TriggerHandle; // { stop(): Promise<void> | void }
  reply?(channel: TChannel, message: string): Promise<void>;
}
```

`listen` تأخذ `agent` و`onEvent` معًا بقصد. الـ`agent` هو الواجهة البسيطة: prompt يدخل ونص يطلع. والـ`onEvent` هي نقطة الدخول التي يناديها الـadapter عندما ينطلق الـtrigger: الـcaller البسيط يمرّر `(input) => agent.send(input)`، والـcaller الذي عنده checkpointing أو approval gates أو تحكم بالإلغاء يمرّر `onEvent` تغلّف هذا كله. استدعِ `stop()` على الـhandle الذي ترجعه لإيقاف الـadapter.

دلالات الرد تختلف بين adapter وآخر. الـadapter الذي يكون ردّه هو الطلب المفتوح نفسه (webhook) ليس فيه `reply()`، والذي لا ينتظره مستدعٍ (ساعة) يسلّم النتيجة إلى مكان آخر، والذي عنده قناة رد منفصلة عن الطلب (chat) يطبّق `reply()`.

اكتب adapter خاص بك بإرجاع handle من `listen`:

```ts
import { createAgent, createMockProvider } from 'lousho';
import type { TriggerAdapter } from 'lousho/triggers';

const agent = createAgent({ instructions: 'You are helpful.', provider: createMockProvider() });

const everyTenSeconds: TriggerAdapter = {
  type: 'ten-seconds',
  listen(_agent, onEvent) {
    const timer = setInterval(() => void onEvent('tick', { firedAt: new Date() }), 10_000);
    return { stop: () => clearInterval(timer) };
  },
};

const handle = everyTenSeconds.listen(agent, (input) => agent.send(input));
handle.stop();
```

يحفظ `TriggerRegistry` الـadapters بالاسم: `register(name, adapter)` و`registerMany()` و`get()` و`has()` و`list()` و`getAll()` و`unregister()` و`clear()` و`size()`. و`globalTriggerRegistry` هو instance مشترك.

## مصادقة webhook

أشكال `WebhookAuth` هي مرجع `webhookChannel({ auth })` (راجع [Channels](/ar/channels)). و`checkWebhookAuth()` و`assertValidWebhookAuth()` مُصدَّرتان لتستخدمهما في الـhandler الخاص بك.

```ts
import { createAgent, createMockProvider, mountChannels, webhookChannel } from 'lousho';

const agent = createAgent({ instructions: 'You are helpful.', provider: createMockProvider() });

// HMAC of the RAW request body (GitHub / Shopify style): header `x-signature-256: sha256=<hex>`.
const handler = mountChannels(agent, [
  webhookChannel({ auth: { type: 'hmac', secret: process.env.WEBHOOK_SECRET ?? '' } }),
]);

// Replay protection: the signed payload becomes `${timestamp}.${body}` and
// requests more than `toleranceSeconds` (default 300) old are rejected.
webhookChannel({
  auth: {
    type: 'hmac',
    secret: process.env.WEBHOOK_SECRET ?? '',
    header: 'x-signature',
    timestampHeader: 'x-timestamp',
    toleranceSeconds: 120,
  },
});

// A shared bearer token (`Authorization: Bearer <token>`).
webhookChannel({ auth: { type: 'bearer', token: process.env.WEBHOOK_TOKEN ?? '' } });

// Anything else: return true to accept. `rawBody` is a Buffer of the exact bytes received.
webhookChannel({
  auth: { type: 'custom', verify: (req) => req.headers['x-api-key'] === process.env.API_KEY },
});
```

خيارات HMAC: `header` (الافتراضي `x-signature-256`)، `algorithm` (`sha256` أو `sha1`، الافتراضي `sha256`)، `prefix` (الافتراضي `sha256=`؛ `''` لـdigest مجرّد)، `timestampHeader` و`toleranceSeconds` (ويُسمح أيضًا للـtimestamp أن يسبق الوقت المحلي بدقيقة على الأكثر). التواقيع وbearer tokens تُقارَن في زمن ثابت. والطلب الذي تفشل مصادقته يأخذ ردًّا عامًّا `401 {"error":"Unauthorized"}` — الرد لا يذكر أي فحص فشل. والـ`auth` غير الصالح يرمي `LOUSHO_TRIGGER_INVALID`. قدّم الـwebhooks عبر HTTPS (أنهِ TLS أمام الخادم) حتى لا تُرسَل الـtokens والـpayloads نصًّا صريحًا.

## تواقيع طلبات Slack

`slackChannel()` يتحقق من كل طلب نيابةً عنك (راجع [Slack في Channels](/ar/channels#slack)). أما في الـhandler الخاص بك (slash commands والتفاعلات)، فتحقّق من الـbody الخام بـ`verifySlackSignature()`: HMAC-SHA256 على `v0:{X-Slack-Request-Timestamp}:{raw body}`، يُقارَن في زمن ثابت مع `X-Slack-Signature` (`v0=<hex>`). الطلبات الأقدم من خمس دقائق، أو التي تسبق الوقت المحلي بأكثر من دقيقة، تُرفَض (الـtimestamp بالثواني، كما ترسله Slack). راجع [توثيق Slack](https://docs.slack.dev/authentication/verifying-requests-from-slack).

```ts
import { verifySlackSignature } from 'lousho/triggers';

const authentic = verifySlackSignature({
  signingSecret: process.env.SLACK_SIGNING_SECRET ?? '',
  timestamp: '1700000000', // the X-Slack-Request-Timestamp header
  signature: 'v0=...', // the X-Slack-Signature header
  rawBody: '{"type":"url_verification"}',
});
```

## تعابير cron

`defineSchedule()` مع `startSchedules()` هو الذي يشغّل cron (راجع [Schedules](/ar/schedules)). و`parseCronExpression(expr, timezone)` و`CronExpressionError` مُصدَّرتان إذا احتجت أن تتحقق من صحة تعبير أو تحسب وقت الإطلاق التالي بـ`.nextRun(after)`.

الصياغة المدعومة: `*`، القوائم (`1,15`)، النطاقات (`1-5`)، الخطوات (`*/15` و`10-40/10`)، أسماء الأشهر (`JAN`) وأسماء أيام الأسبوع (`MON`)، و`0` و`7` كلاهما يعني الأحد. وفيها أيضًا اختصارات `@hourly` و`@daily` (أو `@midnight`) و`@weekly` و`@monthly` و`@yearly` (أو `@annually`). وكما في cron الكلاسيكي، إذا قيّدت يوم الشهر ويوم الأسبوع معًا فاليوم يطابق إن طابق أحدهما. التعبير غير الصالح يرمي `CronExpressionError` يذكر الحقل ويعرض مثالًا صالحًا.

حول تغيّر التوقيت الصيفي، الـjob ذو الساعة الثابتة الذي لا يوجد وقته (عند تقديم الساعة، مثلًا `30 2 * * *`) يعمل مرة واحدة في أول لحظة بعد الفجوة (03:00) بدل أن يُتخطّى في ذلك اليوم، والوقت الذي يحدث مرتين (عند إرجاع الساعة) يُطلَق مرة واحدة؛ والجدول الذي يعمل كل ساعة يستمر يُطلَق كل ساعة.
