إذا كان الـ front end عندك يستخدم أصلًا الـ UI hooks في Vercel AI SDK (`useChat` من `@ai-sdk/react` ومثيلاتها في Vue وSvelte وAngular)، تقدر تخليها على حالها وتشغّل Lousho agent خلف الـ route. ثلاث دوال مُصدَّرة من جذر الحزمة تتولى التحويل. ما تستورد شيء من `ai`، وما تستخدم أي `node:*` module، وتشتغل على Node وWorkers وأي runtime مبني على Fetch.

| الدالة | الاتجاه | ماذا تفعل |
| --- | --- | --- |
| `toUIMessageStream(run)` | out | تطلّع أحداث الـ run كـ `ReadableStream` من UI message chunks |
| `toUIMessageStreamResponse(run, init?)` | out | ترجع `Response`: SSE مع `data: [DONE]` في النهاية والهيدر `x-vercel-ai-ui-message-stream: v1` |
| `fromUIMessages(messages, { lastUserOnly? })` | in | تحوّل الـ `UIMessage[]` اللي يبعتها `useChat` إلى `AgentInput` |

## Route handler

بادئة الـ model `vendor/` هي اللي تختار الـ provider؛ ومع OpenRouter استخدم `openrouter/<vendor>/<model>` (مثلا `openrouter/openai/gpt-4o-mini`).

```ts
import { createAgent, fromUIMessages, memoryStore, toUIMessageStreamResponse, type UIMessageLike } from '@lousho/build-ai-agent';

// The store must outlive the request: without one, every `agent.session({ id })`
// gets a fresh in-memory transcript and the next turn would start empty.
// `memoryStore()` keeps it for the process's life; for a serverless deployment
// or to survive a restart use `fileStore()`, a `SqliteStore` or `KVStore`
// (see [Sessions](sessions.md#choosing-a-store)).
const agent = createAgent({ model: 'openai/gpt-4o-mini', instructions: 'You are helpful.', store: memoryStore() });

// app/api/chat/route.ts
export async function POST(request: Request): Promise<Response> {
  const { id, messages } = (await request.json()) as { id: string; messages: UIMessageLike[] };
  // The session (keyed on the chat id) keeps the transcript, so only the new user message is the input.
  const session = agent.session({ id });
  return toUIMessageStreamResponse(session.stream(fromUIMessages(messages, { lastUserOnly: true })));
}
```

بدون session (جلسة)، مرّر كل الرسائل بدلها:
`toUIMessageStreamResponse(agent.stream(fromUIMessages(messages)))`.

## Client

```tsx
import { useChat } from '@ai-sdk/react';
import { DefaultChatTransport } from 'ai';

export function Chat() {
  const { messages, sendMessage } = useChat({
    transport: new DefaultChatTransport({ api: '/api/chat' }),
  });
  return (
    <>
      {messages.map((message) =>
        message.parts.map((part, i) =>
          part.type === 'text' ? <p key={i}>{part.text}</p> : null
        )
      )}
      <button onClick={() => sendMessage({ text: 'Weather in Paris?' })}>Ask</button>
    </>
  );
}
```

المقتطف هذا يستهدف `ai` 6 و7 (`useChat` يأخذ `transport`، و`sendMessage` يرسل الرسالة). على `ai` 4 — وهو peer مدعوم أيضًا — `useChat({ api: '/api/chat' })` يأخذ الـ endpoint مباشرة ويرجع `input` و`handleInputChange` و`handleSubmit` بدل `sendMessage`؛ أما `ai` 5 فليس ضمن الـ peer range.

## Event mapping

| حدث Lousho | UI message chunk |
| --- | --- |
| `run.start` | `start` (الـ `messageId` هو الـ run id) |
| `step.start` / `step.done` | `start-step` / `finish-step` |
| `text.delta`، `text.done` | `text-start` (مرة واحدة لكل text part)، `text-delta`، `text-end` |
| `reasoning.start`، `reasoning.delta`، `reasoning.done` | `reasoning-start`، `reasoning-delta`، `reasoning-end` (راجع [Reasoning](/ar/reasoning)) |
| `tool.start` / `tool.resume` | `tool-input-start`، ثم `tool-input-available` مع الـ arguments |
| `tool.partial` | `tool-output-available` مع `preliminary: true` (AI SDK 5 فما فوق): snapshot من [streaming tool](/ar/tools#streaming-للنتائج-الجزئية) |
| `tool.done` / `tool.error` | `tool-output-available` / `tool-output-error` |
| `approval.requested` | `data-lousho-approval` (أدناه) |
| `todo.updated` | `data-lousho-todos`: data part بالشكل `{ todos, counts }` فيه قائمة الـ todos كاملة، بنفس الـ id `todos` فكل تحديث يستبدل اللي قبله (راجع [Todo tools](/ar/tools#todo-tools)) |
| `error` | `error` |
| `run.done` | `finish` |

الـ snapshots اللي تجي من streaming tool توصل كـ preliminary outputs، و`useChat` يعرضها كـ `output` للـ tool part مع `preliminary: true`. أما الـ `tool.done` اللي بعدها فبدون `preliminary`، وهو الـ output النهائي.

الأحداث اللي ما لها مقابل في الـ UI — retries وcompaction وقرارات الصلاحيات وguardrails وغيرها — وأحداث الـ sub-agents ما توصل. و`finishReason` في الـ `finish` chunk هو الخاص بـ AI SDK (`stop`، `length`، `content-filter`، `tool-calls`، `error`؛ وأي قيمة أخرى مثل `awaiting-approval` أو `max-steps` تتحوّل إلى `other`).

## Usage والتكلفة

الـ usage يروح في `messageMetadata` الخاصة بالـ `finish` chunk، فتجده في `message.metadata` على رسالة الـ assistant المكتملة:

```json
{ "runId": "run_1", "loushoFinishReason": "stop", "usage": { "totalTokens": 120, "costUsd": 0.0004 } }
```

`usage` هو الـ `AgentEventUsage` للـ run (يغيب إذا فشل الـ run)؛ و`loushoFinishReason` هو الـ finish reason الخاص بالـ run نفسه، بدون mapping.

## Approvals و`ask_question`

الـ tool اللي يحتاج approval (موافقة)، أو استدعاء `ask_question`، يوقّف الـ run: الـ stream ينتهي بـ `finish` مع `loushoFinishReason: "awaiting-approval"`، بعد data part مخصص يعرضه `useChat` كـ part من النوع `data-lousho-approval`:

```json
{
  "type": "data-lousho-approval",
  "id": "appr_1",
  "data": {
    "approvalId": "appr_1",
    "toolCallId": "call_1",
    "toolName": "deploy",
    "input": { "env": "prod" },
    "kind": "question",
    "question": { "text": "Which environment?", "options": ["staging", "prod"] }
  }
}
```

`kind` و`question` موجودين بس في حالة `ask_question`؛ أما الـ tool اللي ينتظر [تسجيل دخول OAuth](/ar/oauth#ما-يراه-المستخدم) فيحمل بدلها `kind: 'sign-in'` و`signIn: { provider, displayName?, url }` — اعرض الرابط، ولما الـ provider يرجّع المستخدم، اعتمده («سجّلت الدخول»). ارسم الـ part بأزرارك وأجب عليه عبر الـ approvals route في الـ session API (`POST /chat/:sessionId/approvals/:approvalId`، راجع [Sessions](/ar/sessions) و[Approvals](/ar/approvals)): `{ "approved": true }` أو `{ "approved": false, "note": "..." }` للـ tool، و`{ "answer": "prod" }` للسؤال. الاستجابة هي تكملة الـ run كـ event stream: تقدر تقرأه بالـ parser اللي توفره الـ UI bindings، أو تتجاهله وتستدعي `sendMessage` من `useChat` من جديد؛ أو في الـ route عندك، استدعِ `agent.approvals.streamResolve()` / `streamAnswer()` وأرجع `toUIMessageStreamResponse()` للنتيجة، فتظهر التكملة في نفس المحادثة.

## تحويل الرسائل الواردة

`fromUIMessages()` تحوّل الـ text parts إلى نص، والـ file parts من نوع `image/*` إلى image parts، وباقي الـ file parts إلى file parts — والـ `url` الخاص بالـ part (عنوان `data:` أو `http(s)`) يصير هو البيانات. أجزاء الـ tool وreasoning وdata وsource وأي جزء غير معروف تتجاهلها، والرسائل اللي تطلع فاضية تحذفها.

ممكن ينضاف لاحقًا subpath مخصص `@lousho/build-ai-agent/ai-sdk-ui`؛ حاليًا الدوال تجي من جذر الحزمة.
