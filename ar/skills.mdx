الـ skill هي مجموعة تعليمات لها اسم (مستند markdown) يحمّلها الـ model **فقط عندما يحتاجها**. هذه هي فكرة progressive disclosure: بدلًا من لصق كل playbook في الـ system prompt، تسرد الـ skills بالاسم مع وصف من سطر واحد، ويجلب الـ model النص الكامل عند الطلب.

كيف تجري الأمور عندما يملك الـ agent skills:

1. يُضاف إلى الـ system prompt قسم صغير بعنوان **Available skills**: سطر لكل skill (`- name: description`)، وجملة واحدة تطلب من الـ model استدعاء `load_skill` قبل أي مهمة تغطيها skill.
2. تُسجَّل تلقائيًا tool باسم `load_skill` (مدخلها `{ name }`). تُرجع المحتوى الكامل للـ skill كنتيجة للـ tool.
3. نصوص الـ skills **ليست** في الـ prompt قبل تحميلها. الـ agent الذي يملك عشرين skill طويلة يدفع تقريبًا سطرًا واحدًا لكل skill في كل طلب، ولا تُدفع تكلفة النص الكامل إلا في الـ runs التي تستخدمه.

إذا كان الاسم غير معروف، تُرجع الـ tool خطأ يسرد أسماء الـ skills الصالحة، فيستطيع الـ model تصحيح نفسه.

## Skills في الكود

```ts
import { createAgent, defineSkill } from 'lousho';

const agent = createAgent({
  instructions: 'You are a release engineer.',
  provider,
  skills: [
    defineSkill({
      name: 'changelog',
      description: 'How to write a changelog entry',
      content: '# Changelog entries\n\nUse the imperative mood and link the PR.',
    }),
  ],
});
```

`defineSkill({ name, description, content })` تتحقق من مدخلاتها. يجب أن يطابق `name` النمط `^[a-z0-9][a-z0-9-_]{0,63}$`، ويجب ألا يكون `description` و`content` فارغين. توضّح الأخطاء موضع المشكلة وكيفية إصلاحها.

`AgentExecutor.execute()` يأخذ خيار `skills` نفسه؛ راجع [الـ executor API](/ar/executor-api).

إذا كانت لديك tool مسجّلة مسبقًا باسم `load_skill`، فإن تمرير `skills` يرمي خطأ: غيّر اسم الـ tool أو احذف الخيار.

## Skills من القرص

`loadSkills(dir)` يقرأ ملفات الـ skills، فيستطيع غير المطورين تعديلها دون المساس بالكود. هناك تنسيقان مدعومان ويمكنك الجمع بينهما في مجلد واحد:

```
skills/
  changelog/SKILL.md      # <name>/SKILL.md  (Anthropic / open-harness convention)
  code-review.md          # <name>.md        (eve convention)
```

كل ملف يبدأ بـ YAML frontmatter، والباقي هو محتوى الـ skill:

```markdown
---
description: How to write a changelog entry
---

# Changelog entries

Use the imperative mood and link the PR.
```

- `description` مطلوب.
- `name` اختياري، وقيمته الافتراضية اسم المجلد (في تنسيق `SKILL.md`) أو اسم الملف بدون `.md`.
- المجلدات التي لا تحتوي `SKILL.md` نتجاهلها. والأمر نفسه لأي ملف `.md` منفرد بلا frontmatter (مثل `README.md`): يُتخطى مع تحذير في الـ console بدلًا من أن يفشل التحميل كله. أما الملف الذي فيه frontmatter لكن بلا `description` فما زال خطأ.
- الـ skill ذات التنسيق `<name>/SKILL.md` تحفظ مجلدها في `skill.directory`. بعد ذلك تضيف `load_skill` مسار المجلد وتسرد الملفات المجاورة لـ `SKILL.md` (حتى 50 ملفًا)، وتُسجَّل tool باسم `read_skill_file` (مدخلها `{ skill, path }`) لقراءتها. المسار نسبي لمجلد الـ skill ولا يمكنه الخروج منه: `..` والمسارات المطلقة والـ symlinks التي تشير إلى خارجه كلها مرفوضة. يمكنك قراءة ملفات نصية حتى 256 KB. `defineSkill({ directory })` يضبط الحقل نفسه لـ skill تبنيها في الكود. وإذا كانت لديك tool خاصة بك اسمها `read_skill_file` فإنها تتعارض بالطريقة نفسها التي تتعارض بها `load_skill`.
- تُرجَع الـ skills مرتبة بالاسم، فتكون الـ prompts deterministic.
- الأخطاء من نوع `LOUSHO_SKILL_INVALID` وتسمّي الملف والمشكلة: `description` ناقص، YAML غير صالح، اسم غير صالح، مجلد تتعذر قراءته، أو skill-ان بالاسم نفسه (مع ذكر المسارين كليهما).

```ts
import { createAgent, loadSkills } from 'lousho';

const agent = createAgent({
  instructions: 'You are a release engineer.',
  provider,
  skills: [...(await loadSkills('./skills'))],
});
```

## اختبار الـ skills

استخدم [`mockModel`](/ar/testing) للتأكد من أن الـ model يرى الأوصاف فقط، لا النصوص الكاملة، إلى أن يحمّل skill: الـ system prompt في الطلب الأول يسرد الـ skills، والطلب الذي يلي استدعاء `load_skill` يحتوي النص الكامل في نتيجة الـ tool.
