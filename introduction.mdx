Most agent code starts as a loop around a model call, and then production asks for more: a human has to approve the refund before it is sent, the process restarts halfway through a run, the conversation has to continue tomorrow from another server, and somebody wants a test that fails when the agent stops calling the right tool.

`@lousho/build-ai-agent` is that loop with those answers built in. It is a library, with no web framework and no hosted runtime: a typed tool-calling loop with approvals, sessions, streaming, sub-agents, skills, MCP and a CLI. The same agent runs in a script, a Node server, a Docker container or a Cloudflare Worker (a Worker supports a [subset](/cloudflare-workers#what-works-and-what-does-not) of the providers and tools).

```mermaid
flowchart LR
    A["your code<br/>send() or stream()"] --> B["agent run<br/>model step, tool calls, repeat"]
    B --> C{"tool needs<br/>approval?"}
    C -- no --> B
    C -- yes --> D["run pauses<br/>state is saved to a store"]
    D -- "approved, from any process" --> B
    B --> E["result<br/>text, typed object,<br/>usage and cost"]
```

```ts
import { createAgent } from '@lousho/build-ai-agent';

const agent = createAgent({ model: 'openai/gpt-4.1-mini', instructions: 'You are a helpful assistant.' });
const { text } = await agent.send('Hello!');
console.log(text);
```

## The building blocks

Each block is one function or one option on `createAgent()`. Use the ones you need; none of them requires the others.

| Block | What you write | What you get |
| ----- | -------------- | ------------ |
| [Tools](/tools) | `defineTool()` with a zod `input` | Arguments typed and validated, calls run in parallel |
| [Approvals](/approvals) | `needsApproval`, or `permissions` rules | A run that pauses for a human, then continues with `agent.approvals.resolve()` |
| [Sessions](/sessions) | `agent.session({ id })` | A multi-turn conversation kept in memory, files or SQLite |
| [Memory](/memory) | `defineMemory()` slots | Facts recalled into the prompt across sessions, per user or globally |
| [Structured output](/structured-output) | `output: zodSchema` | A typed, validated `result.object`, with one repair step |
| [Streaming](/streaming) | `agent.stream()` | Typed, versioned JSON events, ready for SSE |
| [Sub-agents](/sub-agents) | `subagents: { researcher, writer }` | One `task` tool for the lead; sub-agents run in parallel, locally or remotely |
| [Skills](/skills) | `loadSkills()` | Instructions the agent loads only when a task needs them |
| [Providers](/providers) | a `provider/model` string | OpenAI, Anthropic, Google, OpenRouter, Ollama or a mock, with retry and fallback; any AI SDK model via `fromAiSdk()` |

The agent is the same object everywhere. What changes is the surface in front of it.

## Compared to other libraries

`@lousho/build-ai-agent` sits one layer above a model call: like the AI SDK 7 agents, eve, Mastra, LangGraph, the OpenAI Agents SDK or the Claude Agent SDK, it runs a full agent loop. It builds on the Vercel AI SDK rather than replacing it: the built-in providers use `ai` and `@ai-sdk/*`, and `fromAiSdk()` wraps any other AI SDK model.

Durable approvals, evals, agent directories and coding-agent harnesses are no longer unique: AI SDK 7, eve and Mastra ship their own. What Lousho still does differently is record/replay with trajectory drift, durable approvals on Cloudflare Workers KV, serving the same agent over ACP and MCP, and running as one self-hosted package. It is weaker where it is young: it is in alpha, has no Postgres store, fewer native providers and no hosted dashboard. The [comparison](/comparison) has the per-project table, dated, with where each rival is ahead.

When something else fits better: if you only need to stream model text in a Next.js route, the AI SDK alone is less surface; if you deploy on Vercel and want its runtime, eve fits it natively; if you want Claude Code's own harness, the Claude Agent SDK gives you exactly that; if your team is on Python or already runs LangGraph Platform, staying there avoids a second stack. Coming from the AI SDK? See [Migrating from the AI SDK](/migrating-from-ai-sdk).
